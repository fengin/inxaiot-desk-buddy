# 工作台数据库显式初始化与平台只读验收记录

> 状态：已完成  
> 日期：2026-08-28

## 1. 调整原因

原技术方案要求项目侧工作台 MySQL 显式初始化，但阶段 5 代码在建立项目连接时自动调用 SQLx Migrator，实际行为与方案不一致。用户确认调整为：

- 本地 SQLite 自动 Migration。
- 项目侧工作台 MySQL 只检查，由用户显式初始化或升级。
- 开发阶段不执行“只加不减”，一切以最终开发结构为准，不保留试验性结构变更历史。
- inxvision_iot_dev 默认禁止结构和数据变更；确需变更数据时逐次取得用户确认。

## 2. 正式实现

### 2.1 Schema 状态

工作台库分为四种状态：

| 状态 | 行为 |
| --- | --- |
| uninitialized | 数据库存在但尚无业务表，允许显式初始化 |
| upgrade_required | SQLx 版本低于当前应用，允许显式升级 |
| ready | Migration 版本和必要业务表完整，允许业务访问 |
| incompatible | 人工未纳管结构、失败版本、缺表或数据库版本过高，阻止自动升级和业务写入 |

### 2.2 执行边界

- project_pools 只建立双 Pool、探测平台能力和更新项目打开时间。
- project_database 在返回业务连接前检查工作台 Schema，未就绪时返回状态冲突。
- initialize_or_upgrade_workbench_schema 是唯一正式 Migration 应用入口。
- 已是最新版本时显式升级为无操作检查，不重复执行 SQL。
- 项目设置显示状态，并在可升级状态下通过二次确认执行初始化/升级。

### 2.3 平台只读

- 基础设施 DualMySqlPools 的平台连接设置 SESSION TRANSACTION READ ONLY。
- 当前生产与活动测试统一使用`infrastructure::database::DualMySqlPools`，平台连接均设置为只读；旧`formal::mysql::ProjectMySqlPools`重复实现已删除。
- 平台适配器继续只提供显式 SELECT，不提供写 Repository 或通用 SQL。
- 本次真实检查只读取平台版本、Schema Capability 和一体机身份快照。

## 5. 开发阶段约束

开发阶段允许对本地 SQLite 和工作台开发库进行重建、脚本调整和 Migration 合并。执行重置前仍需确认精确数据库目标，不能扩大到其他项目库。

正式启用前应完成一次基线整理：

1. 确认最终业务表和索引。
2. 根据需要合并开发期 Migration。
3. 使用空库验证完整初始化。
4. 冻结正式基线。
5. 从正式启用版本开始保留向前 Migration 历史并采用只加不减策略。

平台业务库始终不进入上述自由调整范围。
