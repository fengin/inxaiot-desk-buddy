# 任务显示与日志清空修复验收

> 日期：2026-10-08。当前应用版本：0.2.3。
> 范围：Windows 桌面公共任务、日志面板，一体机与智能屏的本机检查及执行记录。

## 1. 问题与实际原因

实施人员在任务页确认“清空已结束任务记录”后，程序提示已清除 2 条，但列表仍有多条“已成功”记录，日志页也显示为空。

只读检查当时的本机数据确认：当前项目剩余 7 条成功检查记录，均未继续提交执行。旧规则长期保护所有成功但未提交的检查，既限制清理，又把它们显示为已经结束，造成清空不完整。清任务和清日志的命令没有接错，被清理任务的原日志文件仍在；界面改为选择没有过程日志的检查记录，因而显示为空。

一次智能屏在线检查还会显示两条同名任务。只读查询真实本机数据库确认，其中一条是执行任务，另一条是已经提交的检查记录，公共检查中保存的执行任务编号准确指向前者。这是内部检查也被列入活动面板造成的重复展示，并非设备被执行了两次。

## 2. 当前规则

| 操作 | 处理范围 | 保留内容 |
| --- | --- | --- |
| 任务列表 | 成功检查已提交并有效关联同项目、同业务的执行任务后，只显示执行任务 | 内部检查依据和日志；未提交、失败、执行中及结果待核实的检查仍可见 |
| 任务页清空 | 当前项目已结束的任务和检查记录，包括成功但未继续提交的旧检查 | 未结束任务、排队、执行中、结果待核实的任务，以及其他项目和平台结果记录 |
| 日志页清空 | 当前选中的已结束任务日志及其保留标记 | 任务记录、执行依据、结果及其他任务日志 |
| 清除检查后提交 | 原检查失效，提示重新检查；保留 `NOT_FOUND` 错误类型供页面返回检查步骤 | 已创建的排队任务和原操作参数 |

检查确认和创建排队任务仍在同一数据库事务内完成，不允许凭已清除的检查执行操作。任务清空不调用清日志功能；被删除的任务不再作为日志选择项，没有可选任务时显示“暂无可查看日志的任务”。原日志文件按既有本机保留机制处理。

列表先在数据库中排除已关联执行的内部检查，再排序和分页，不根据有没有日志来隐藏记录。清理使用相同的显示规则统计提示数量，并在同一事务内删除全部符合条件的记录；一条可见执行任务和它的内部检查被清理后，提示已清除 1 条。

## 3. 验证结果

### 3.1 清理功能验收（0.2.2）

- 完整前端 397 项通过，包含任务、日志页切换后的真实按钮和确认框点击；一体机检查缺失后返回重新检查的既有用例继续通过。
- 三个 Rust 集成测试目标共 24 项通过；另 1 项需要真实平台的测试按标记跳过。验证清除检查后旧提交被拒绝、重新检查可继续、已排队任务保留、旧缓存不能绕过检查，以及任务和日志独立清理。
- 独立桌面实例使用正式界面和正式命令，在专用本机数据目录构造 2 条已结束任务、7 条成功检查、4 条受保护任务及另一项目的 2 条记录。实际点击清空后准确删除 9 条，保护记录和其他项目保留，15 份日志文件的大小及 SHA-256 均未改变。
- 再选择一个已结束任务清日志，仅该日志被移除，两项目任务、检查结果和其余 14 份日志保持。测试创建的项目、任务及保护记录已清理，测试进程已退出。
- 类型检查、相关代码检查和普通 Windows 程序构建通过。测试未清除当前使用中的真实项目记录，未操作项目平台或设备。

桌面证据位于 `.review-tools/activity-clear-20261008/ui-1791454678979/`，包含结果 JSON 和 7 张截图；前端日志为同级目录的 `frontend-tests.log`。普通验证程序为 `.review-tools/app-config-20261003/portable/inxaiot-desk-buddy-task-clear-20261008.exe`，对应清理功能修复版本 0.2.2。

### 3.2 任务列表显示验收（0.2.3）

- 28 项 Rust 集成测试通过，另 1 项真实平台测试按标记跳过。覆盖检查提交前可见、提交后只显示执行任务、有日志的一体机检查使用同一规则、分页不被隐藏检查占用，以及清理提示 1 条但数据库中的执行和内部检查共 2 条均被删除。
- 并发回归通过：清理开始就取得数据库写锁，避免统计数量后遇到另一个任务更新进度而无法删除。测试在计数时暂停，以另一连接尝试写入，再继续清理，确认清理成功且运行中的任务可以继续更新。
- 活动任务、待核实结果和其他项目记录保留；检查关联缺失、格式异常或不匹配时不隐藏，旧检查不能绕过提交校验。
- 对真实本机数据库执行只读对照，同一次智能屏在线检查由原查询的 2 条变为新活动查询的 1 条，内部查询仍保留 2 条；未删除或改写真实任务、日志及设备数据。
- 独立 Windows 桌面实例使用正式界面、正式命令和新建本机数据库，6 组界面验收全部通过。原 9 条清理、活动与待核实保护、项目隔离及单独清日志场景重新验证通过。
- 在第三个测试项目构造同名的已提交检查和正式执行记录：检查没有日志，执行有 2 条日志。数据库保留 2 条，公共列表只显示正式执行 1 条；点击底栏“任务与日志”或该任务行，均正确显示执行日志。
- 实际点击清空后提示“已清空 1 条已结束任务记录”，数据库中的执行、关联内部检查及其目标和检查快照均已删除。原日志文件、另外两个测试项目的任务和日志均保持不变。
- 测试结束后独立项目、任务及保护记录均为 0，测试进程已退出。未访问使用中的真实数据目录，未连接平台或设备。

本次桌面证据位于 `.review-tools/activity-clear-20261008/ui-1791464542140/`，包含 `result.json`、11 张截图及清理前后的数据库和日志摘要。第 08～11 张截图分别记录任务去重、底栏打开执行日志、任务行打开执行日志及按 1 条提示清理结果。

包含全部修复的普通 Windows 程序构建通过，文件版本为 0.2.3，不含桌面测试接口。本机验证程序为 `.review-tools/app-config-20261003/portable/inxaiot-desk-buddy-task-panel-20261008.exe`；多平台发布构建以 GitHub Actions 结果为准。

## 4. 技术定位

- Rust 文件 `src-tauri/src/infrastructure/local_sqlite/task_repository.rs`：区分内部完整任务查询与活动列表查询，分页前排除有效关联的已提交检查；同事务统计可见清理数量并删除允许清理的终态记录，保留检查和入队校验。
- Rust 文件 `src-tauri/src/interface/commands/task_activity.rs`：活动面板使用专用列表查询，清理返回可见记录数量；可清理标记与实际删除规则一致，日志仍通过独立命令清理。
- Rust 模块目录 `src-tauri/src/infrastructure/smart_screen/`：已清检查给出明确提示；提交被拒绝时清理尚未入队的临时快照。
- Vue 组件 `src/shell/ActivityPanel.vue`：说明清理检查后的重新检查要求，区分没有任务和当前任务没有日志；开发适配器按同一规则处理。
