# 关闭屏睡眠实施与验收

日期：2026-11-03。状态：独立操作源码、自动化、隔离浏览器视觉及本机隔离正式后台双屏任务验证通过，两台设备原值均已恢复；已纳入[0.2.19 Windows本地交付](../52-0.2.19Windows交付记录.md)，成品版本、架构、哈希及隔离工具自检通过。前置机制试验、功能路径与成品自检分开记录；已注册平台资产、共享库实机及打包桌面完整点击尚未覆盖。源码尚未Git提交、推送、打标签或GitHub发布，既有0.2.18正式附件不包含新增操作。

## 1. 业务目标与使用范围

实施人员使用运维电脑上的INX实施工作台，先选定项目中需要维护的屏，检查哪些设备尚未关闭系统自动休眠，再只对检查通过的目标执行。预期结果为屏在持续供电时不因空闲自动息屏，人员能逐台看到已关闭、无需修改或不可执行的原因。

“关闭屏睡眠”与校准时间、保持ADB端口等系统维护操作并列，不放入“修改小新配置”。允许4寸、10寸混选，按设备实际能力分别检查；安装小新及修改小新配置的原同尺寸批次规则保持。未注册屏使用本机维护能力，已注册屏仍沿用项目就绪、登录、身份和共享占用保护。

本功能只修改`inxaiot-desk-buddy`（实施工作台桌面工程）。无需升级`xiaoxin-app`（智能小新屏端应用工程）、H5业务网页或平台服务，不增加平台业务字段、数据库迁移或屏端常驻组件。

## 2. 当前操作规则

| 阶段或状态 | 业务行为与完成依据 |
| --- | --- |
| 选择设备 | 在独立操作中选单台或多台屏，保留筛选外已选范围；不因为选择10寸而整批禁止检查 |
| 开始检查 | 只读核对设备身份、当前系统设置、现有权限、供电及设备管理约束，不先修改任何屏 |
| 待关闭 | 以橙色显示；尚未关闭且条件通过，默认纳入可执行目标，确认后才写入 |
| 已关闭 | 以绿色说明无需重复设置，不勾选、不写、不唤醒；当前屏被手动息屏不等于自动休眠被重新开启 |
| 不可执行或未知 | 以红色显示权限、未接电、管理限制、连接或读取原因，不能勾选，不隐藏其他设备的有效检查结果 |
| 全部已关闭 | 明确提示无需执行，不创建空任务，不以空批次显示关闭成功 |
| 执行前再核对 | 检查原设备、占用、取消和系统原值；已被其他操作关闭的只读跳过，其他外部变更停止重检 |
| 设置及回读 | 只修改接电保持唤醒设置，分别确认保存值及运行中的生效状态；明确已休眠且本次需要点亮时只唤醒一次 |
| 取消、断连与重开 | 保留实际阶段；后续核实只读，不再次写设置或补发唤醒，不自动撤销已经确认的关闭结果 |

正式动作不修改原自动息屏时长、系统睡眠超时、亮度、H5屏保或小新配置，不设置或解除设备OWNER，不自动提权，不重启屏或小新。当前连接未具备所需设置权限时说明原因，不通过其他管理动作绕过。

接电保持唤醒依赖当前供电类型和设备管理策略，仍可能调暗屏幕，不等同于锁定亮度或禁止明确电源键动作。H5闲置遮罩是独立页面功能。大整数超时不作为永久关闭自动休眠的依据；未接电、被管理员限制或运行值无法确认时，不能只按命令返回成功宣称生效。

## 3. 技术定位

工作台前后端运行于实施电脑，Android系统设置位于目标屏。读取和写入经既有ADB（Android调试桥）会话完成，不依赖小新配置提供组件或应用是否正在前台。

| 文件或程序值 | 职责 |
| --- | --- |
| `sleep_off`（工作台操作类型程序值） | 独立系统写操作，使用既有选屏、检查、确认、执行及核实契约 |
| `src-tauri/src/infrastructure/smart_screen/sleep_policy.rs`（新增Rust文件） | 系统设置、当前供电与有效电源策略的读取、权限及条件判断、限定写入 |
| `src-tauri/src/infrastructure/smart_screen/maintenance.rs`（已有Rust文件） | 逐台检查、可执行目标与已有任务生命周期 |
| `src-tauri/src/infrastructure/smart_screen/device_maintenance.rs`（已有Rust文件） | 正式执行、写前保护、阶段证据及只读核实 |
| `src-tauri/src/domain/smart_screen/operation.rs`（已有Rust文件） | 动作名称及写操作登记 |
| `src/shared/model/screen.ts`（已有TypeScript文件） | 前端操作类型与中文名称 |
| `ScreenOperations.vue`、`ScreenPreflightTable.vue`（已有Vue文件） | 沿用系统维护的选屏、逐台结果、可执行勾选与确认布局 |

Android系统全局设置项`stay_on_while_plugged_in`以供电类型位表示保持唤醒条件。当前目标将有效原掩码按位或7，覆盖交流电、USB和无线供电，保留其他原有位。Android系统设置项`screen_off_timeout`、`sleep_timeout`仅用于读取和解释当前状态，产品动作不写入这两项。

检查同时核对系统保存值、有效掩码、当前供电类型和电源服务运行字段`mStayOn`，不用字段缺失、解析失败或大超时值推断已关闭。程序检查状态值`ready`、`skip`、`blocked`分别映射为界面“待关闭”“已关闭”“不可执行”；只提交检查通过目标的子集。已关闭设备无需追加写权限。系统电源与权限输出兼容Windows ADB的CRLF、LF及混合换行，仍要求关键字段格式及唯一值可被可靠核实。

写入前重新核对原值与取消、操作占用；未知响应保留原任务证据。设置保存与运行策略分别回读，必要时使用`KEYCODE_WAKEUP`（Android非切换型唤醒按键）一次点亮，再只读确认。恢复核实不重放设置或唤醒，不使用电源切换键，不循环保活。证据保存于现有任务JSON（任务数据格式）和结果，不成为平台资产的长期业务状态。

## 4. Android系统机制的实机事实

本节是工作台功能接入前的独立机制试验，不等同于通过新界面执行的产品验收。

| 项目 | 4寸屏 | 10寸屏 |
| --- | --- | --- |
| 测试地址与固件 | `192.168.3.74`；Android8.1、API27，`px30_evb`（设备型号），480×480 | `192.168.3.42`；Android10、API29，`Smart touch panel`（设备型号），800×1280 |
| 既有ADB身份 | 已有管理员会话 | 普通ADB shell会话，具备所需系统设置权限 |
| 原接电保持唤醒值 | 0 | 0 |
| 原自动息屏时长 | 60000毫秒 | 2147483647毫秒，约24.9天 |
| 试验条件 | 保留原60秒超时 | 经明确授权，临时将自动息屏设为60秒作对照；系统睡眠超时仍保留原2147483647毫秒 |
| 对照事实 | 原状态为系统休眠、显示关闭 | 保持唤醒关闭时，约66秒采样确认自然休眠、显示关闭；对应睡眠与唤醒时刻差约60秒 |
| 开启值及重启前观察 | 值7；无输入观察约131秒，保持唤醒、显示开启 | 值7；无输入观察约131秒，保持唤醒、显示开启 |
| 普通重启后的观察 | 启动编号变化、同一设备；未重写设置，再无输入观察约131秒通过 | 启动编号变化、同一设备；人工恢复网络后，未重写试验设置或补发唤醒，再无输入观察约131秒通过 |
| 最终恢复 | 保持唤醒恢复0，原60秒超时不变，读取的8项设置与基线一致，并观察到自然休眠及显示关闭 | 保持唤醒恢复0，自动息屏恢复2147483647毫秒，系统睡眠超时未改，读取的8项设置与基线一致 |

两种屏均为当前交流电供电、设备管理未强制最大息屏时间、无其他窗口或屏幕常亮锁的条件。各段观察中的用户活动计时保持稳定，不靠点击或重复唤醒维持显示。已确认系统设置在本次普通重启后保留，但没有验证其他固件、其他供电状态或断电场景。

10寸屏重启后没有自动联网。原始记录保留连接及恢复超时，人工恢复联网后完成同设备续验并最终恢复原值。电源策略及重启保持验证通过，自动联网恢复不记为通过，不将网络现象归因于本次休眠设置。

本机已有证据文件位于工作台工程忽略目录：4寸为`.review-tools/sleep-20261103/run-900bc59b-4825-4838-bc76-695494149db8/verification.json`；10寸为`.review-tools/sleep-20261103/ten-inch/run-b4c719ed-963c-481b-8b9c-12ecbbb9f3f6/verification.json`与同目录`completion.json`。后者记录网络恢复后的续验及最终恢复，不能只用原始中断记录判断当前恢复状态。

## 6. 验收标准

1. 操作与校准时间、保持ADB端口等并列，选屏及说明排版沿用现有页面；4寸与10寸可混选。
2. 检查阶段只读，逐台展示待关闭、已关闭及不可执行，检查完成不显示为已经执行成功。
3. 默认只勾选检查通过的待关闭屏；已关闭不写不唤醒，全部已关闭时不创建空任务。
4. 当前无供电、权限不足、管理限制、身份或关键草稿问题均显示具体原因，不按尺寸统一猜测可执行。
5. 原值外部变化、取消、断连和待核实均保留真实状态；已确认关闭的设备不因补存或核实重复写入。
6. 仅修改接电保持唤醒项，保留原其他供电位；原超时、系统睡眠超时、亮度、H5、OWNER及应用配置保持，不重启或自动提权。
7. 结果分别确认设置保存与运行生效，必要时只唤醒一次；不能只按退出码成功判定，也不宣称亮度恒定或H5已无屏保。
8. 自动化、手工机制试验、正式工作台实机任务及成品发布分别记录，原值恢复责任有明确结论。
