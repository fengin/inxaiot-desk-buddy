# 部署时钟核对与自动校准验收

> 功能验证日期：2026-11-02；正式发布核验日期：2026-11-03。状态：源码自动化、四个平台构建发布及正式附件下载校验通过，Windows正式附件隔离自检通过，见[0.2.18发布记录](../51-0.2.18发布记录.md)。未开展实机校时、部署或平台注册验证。

## 1. 业务目标与适用范围

实施人员通过工作台对 Linux 一体机执行首次部署、整包升级或单服升级时，自动检查目标一体机与当前电脑的系统时间，避免一体机时钟偏差导致平台请求签名被判定过期。当前电脑为本次操作的时间基准，实施人员需先确认电脑时间准确；平台服务器时间由平台运维人员独立维护。

三类正式部署都在文件上传完成后、执行安装或升级脚本前核对时钟。偏差超过 5 秒时，工作台以当前电脑即时读数校准一体机，再读取一体机时间确认；偏差不超过 5 秒则不改写。选择与检查确认区域说明该规则，执行阶段显示“核对并校准时钟”，不增加操作开关或确认弹窗。

需要校准时，`root`（Linux 管理员账号）直接设置系统时间，其他 SSH 账号自动尝试 `sudo -n`（Linux 免交互提权命令）。选择与检查确认区域同时说明自动提权，不弹出密码输入或额外确认；权限不足时停止该台后续部署。实施人员在选择范围和提交前均可看到具体权限行为。

## 2. 当前规则与限制

| 情况 | 预期结果 |
| --- | --- |
| 一体机与电脑时间偏差不超过 5 秒 | 记录核对结果，不写系统时钟，继续部署 |
| 偏差超过 5 秒，校准和回读确认成功 | 记录估算偏差及校准结果，继续后续部署 |
| 读取格式异常、单次读取往返超过 2 秒 | 停止该台部署，不基于不可靠读数校时 |
| 当前 SSH 身份没有校时权限，且不能无需交互提权 | 记录具体权限错误，停止该台后续部署 |
| 写入失败或回读仍超差 | 记录失败，不执行后续安装、升级或首次注册 |
| 用户取消或节点租约失效 | 沿用现有取消及占用保护，不继续发起后续写入 |

仅调整一体机的系统时间，保留时区、NTP 自动校时及 RTC 硬件时钟配置。功能不校准平台服务器，不证明电脑时间准确，不承诺重启或断电后的硬件保时。校时失败沿用既有节点失败隔离和本次上传目录处理规则，不扩展为部署回滚或平台注册重试。

## 3. 技术定位

源码在 `inxaiot-desk-buddy`（桌面工程名称）中，桌面后端在实施人员电脑运行；命令经现有 SSH 会话在目标一体机运行。

| 文件或代码 | 职责 |
| --- | --- |
| `src-tauri/src/infrastructure/deployment_clock.rs`（新增 Rust 文件） | 远端系统时间读取、可靠性判断、超差校准及回读确认 |
| `src-tauri/src/infrastructure/deployment_remote.rs`（已有 Rust 文件） | 在上传完成、安装或升级脚本前串接时钟步骤，复用取消与租约保护 |
| `src/features/aio/operations/AioOperationsView.vue`（已有 Vue 文件） | 选择与检查确认页的自动校时说明、部署任务中文阶段 |
| `src/features/aio/taskPresentation.ts`（已有 TypeScript 文件） | 底部任务面板的中文阶段名称 |

时间比较使用 UNIX 时间；写入前即时采样电脑时间，不使用预检或上传前保存的时间值。工作台以 SSH 读取请求发出和返回的本机时间中点估算时差，日志使用“估算偏差”表述。单次读取往返超过 2 秒即停止且不写时钟；在允许时长内，非对称延迟带来的采样误差最多约 1 秒，5 秒为估算偏差容差，不构成高精度授时保证。

阶段代码 `clock_sync` 表示时钟核对与校准；日志事件代码 `CLOCK_CHECK_STARTED`、`CLOCK_DRIFT_DETECTED`、`CLOCK_SYNC_VERIFIED` 分别记录核对开始、超差和回读确认。自动提权仅允许 `sudo -n`（Linux 非交互提权命令），不传递交互式提权密码。本专项只修改工作台工程，不修改部署脚本协议、一体机设备服务或平台服务。

## 4. 验收标准

1. 选择和检查确认区域均说明超过 5 秒时以当前电脑为准校准，以及非 root 的 SSH 账号自动尝试免交互提权、不弹密码或额外确认、权限不足停止该台；运行任务显示中文阶段，不直接显示程序代码。
2. 首次部署、整包升级、单服升级均在上传完成后进入时钟步骤，再执行后续脚本。
3. 时钟正常不发写命令；一体机时间快、慢两种超差情况均能校准并回读确认。
4. 读数不可靠、权限不足、写入失败、回读仍超差均停止该台后续步骤，并保留具体失败原因。
5. 校时前取消或租约失效时不新增时钟写入；校时失败不发起首次注册。
6. 时区、自动校时和硬件时钟配置保持；无平台服务器校时请求。
