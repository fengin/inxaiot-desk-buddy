## 1. 业务目标与实施顺序

项目实施与维护人员在同一个桌面工作台内管理一体机和智能屏，网关为后续扩展范围。各业务共用项目上下文、任务、日志和操作记录，各自维护设备身份、通信方式和操作规则。平台与共享数据操作使用项目连接和登录；未登记智能屏仅保存在本机实例，可在平台不可用时独立维护。

公共代码中的一体机专属判断已按 TD-01—TD-04 完成分离。智能屏已通过这些公共接口接入正式任务、结果保存、未完成记录处理和界面展示，本机资产及限定平台写入按 TD-05—TD-06 实现。

已完成的实施顺序及对应交付为：

1. 完成并确认[智能屏运维管理需求设计](智能屏/01-智能屏运维管理需求设计.md)。
2. 根据确认的首期功能，先完成本清单 TD-01—TD-04 的公共架构优化和一体机回归；这是智能屏正式接入的前置门槛。
3. 开发智能屏批量运维、本机资产注册、已注册资料草稿与缓存、人工关联合并，以及限定的平台状态覆盖能力；应用安装升级仅支持小新应用。
4. 基础运维之后接入小新配置管理和屏端配置保存、读取改造；常用配置的单台、批量修改及按需重启已完成。
5. 按实际交付功能分别完成设备能力验证、跨工程集成验证和真实桌面操作验收。

本清单记录的是研发技术债，不在产品中增加“技术债处理进度”等业务字段。各项是否完成以条目状态和对应验证记录为准。

[智能屏整体技术方案](智能屏/05-智能屏技术方案设计.md)第 3 节规定公共代码优化及通过标准，第 12 节规定实施顺序；逐步开发范围、验收用例和状态见[智能屏开发与验收计划](智能屏/06-智能屏开发与验收计划.md)。真实智能屏业务与专用演示原型是两套适配器；不能把原型不连接平台或设备的限制套用到正式功能。

同版本操作占用、接手与旧任务写入保护，已用同一电脑的两个独立进程连接真实共享库验证，不代表已验证不同物理电脑的网络与系统差异。本机与工作台数据库使用已有迁移脚本；跨版本运行和回滚按[发布说明](16-Windows可信发布与回滚说明.md)核对，不承诺任意旧版与新版并行使用。

## 2. 保持的架构边界

- 保持一个桌面应用和当前 Rust 工程，通过模块划分职责；当前没有拆分微服务、多仓库或插件平台的需求。
- 前端页面通过状态管理和业务适配器调用后端；正式桌面数据与开发演示数据继续隔离。
- Rust 应用层依赖领域规则和端口，具体数据库、进程、文件与协议操作在基础设施层实现。
- 项目连接、认证、任务队列、并发、日志和租约复用现有能力；屏身份、应用安装、时间、远程管理和配置下发独立建模。
- 工作台只与项目侧平台协作，云平台不参与运维链路。平台登录认证保留既有 HTTP；业务查询与已确认写操作采用项目数据表直连，SQL、字段映射和必要结构检查集中在工作台适配层，不依赖平台业务接口或后端类。
- 本机保存执行过程、完整日志及未登记屏的临时资产和维护历史；平台已登记资产继续使用项目工作台专用库的共享配置、操作摘要和结果。
- 普通平台连接保持只读；智能屏另设限定写通道，分别处理注册及资料更新、确认覆盖数据库表 `smart_terminal_screen` 的字段 `status`、已注册屏安装结果或独立读取确认后的 `app_version` 更新，以及人工合并选源确认的业务字段同步。白名单按 TD-05/06 和智能屏需求约束，仅注册用例允许受控新增；不调用平台业务接口，不开放任意字段编辑、资产删除或空间目录修改。
- 资产只保存注册属性与确认后的最终业务事实；执行阶段、进度、取消和失败原因保存在本机任务、结果与日志，不写成平台资产或项目中间状态。
- 已有 `formal`（Rust 模块目录）和 `stage75*`（Rust 适配器文件）仍参与正式运行，不能仅凭阶段名称视为废弃代码。
- 不为外观整齐先整体搬迁目录，也不抽象尚无第二个使用场景的通用设备模型。

## 3. 必要技术债

### TD-01：项目公共就绪条件与业务可用条件分离

**业务影响**：实施人员已经连接项目并登录后，应能进入该项目支持的业务。某一种业务表不兼容，应准确指出受影响的功能；平台不可用时，本机未登记屏的设备维护仍可进行。

**当前实现**：前端路由按 `projectAccess` 声明本机、平台或共享要求。本机项目可不配置远端连接；平台只读连接不依赖共享库，一体机表检查在一体机业务中执行。平台登录成功后，共享库不可用不再丢弃有效会话；本机功能仍按自身条件使用。

**改造范围**：

- 区分本机项目归属、项目连接、工作台库版本和登录状态；本机维护所需上下文不通过填写无效连接参数来伪造。
- 将平台业务数据的必要表字段、类型和枚举含义作为兼容检查范围；平台无关字段或业务接口改动不触发全局阻断。数据语义变化需更新相应适配与测试，不额外建设平台配套服务。
- 按路由和具体动作声明访问要求：未注册屏设备维护及两类屏的只读设备检查不要求平台或共享库可用，结果保留本机；平台读写和已注册屏设备写操作仍要求对应项目就绪、登录及共享保护。
- 业务所需平台表和字段按业务能力核查；是否支持缺少一体机表的项目，以智能屏适用环境为准，不额外建设动态插件系统。

**技术定位**：

- 前端文件：`src/shell/DesktopShell.vue`、`src/stores/projects.ts`、`src/app/router.ts`。
- Rust 文件：`src-tauri/src/infrastructure/project_context.rs`、`database.rs`、`stage75_adapter.rs`，以及 `src-tauri/src/domain/common/project.rs`、`src-tauri/src/formal/project_repository.rs`。
- 数据库表：`op_edge_aio_server`，现有平台一体机表。

**验收**：未连接、未登录、会话失效时，平台与共享操作正确阻断，本机临时屏可继续进行符合设备条件的维护；已就绪项目可进入对应业务；切换项目后的迟到响应不能覆盖新项目状态。

### TD-02：区分通用任务提交机制和一体机部署快照

**业务影响**：批量安装应用、校时等屏操作需要统一排队、取消和记录，同时保留各自的执行条件。

**当前实现**：本机任务仓库接收明确的检查操作类型，核对项目、业务、目标与检查内容后，在同一事务中占用检查结果并创建任务，不再限定一体机目标。检查被正式执行任务消费后，面板只显示执行任务。已结束且没有待核实或待保存结果的记录可以清理；未提交检查被清理后必须重新检查，已排队任务不受影响。任务清理与日志清理独立，提示数量按面板可见任务计算。

**改造范围**：

- 保留通用队列和任务标识，屏操作通过独立业务处理器接入。
- 将一次性消费检查结果、创建任务的原子性与一体机快照内容分开。
- 仅对需要检查后执行的操作复用检查提交机制；查询列表等短操作不强制套用部署流程。
- 任务固化目标来源和标识；平台屏按项目与平台记录使用共享租约，本机临时屏按本机临时标识使用本实例互斥。设备身份核对与任务资源键分别处理，不能直接用 IP 作为稳定设备身份。
- 大多数屏操作支持批量目标、逐台条件检查和结果。写操作混合本机临时屏与平台屏时，平台、登录或共享条件不满足就整批阻止并提示；需要离线维护时由用户单独选择本机未注册屏。只读设备检查按自身条件执行。

**技术定位**：`src-tauri/src/runtime/task_queue.rs`、`src-tauri/src/infrastructure/local_sqlite/task_repository.rs`、`src-tauri/src/infrastructure/task_handlers.rs`。

**验收**：一体机与屏任务均进入同一队列；并发受控；重复提交被拒绝；取消排队任务不会产生设备操作；跨项目和跨业务的任务、目标与日志不串用。

### TD-03：结果保存、失败补写和启动恢复按业务处理

**业务影响**：设备操作已经完成但数据库暂时不可用时，应补写已有结果，不能重复安装、重启或校时。

**当前实现**：公共结果处理按业务与操作类型查询注册方法，一体机部署结果保存逻辑放在 Rust 文件 `aio_task_recovery.rs`，智能屏使用自身的结果核实和补存方法；未知业务保留结果并提示，不读取一体机文件。两类业务的真实任务均已接入，安装、注册、配置或共享记录不确定时先核对已有事实，不自动重放设备动作或旧业务字段。

**改造范围**：

- 公共运行时管理状态、调度和恢复路由；具体业务负责结果载荷、持久化和核实策略。
- 为屏操作区分“设备执行失败”“设备结果待核实”“本机记录保存失败”和“共享记录待补写”；本机临时屏无需创建共享操作记录，正常本机保存后即可完成任务。
- 重启恢复不自动重放可能已发生副作用的操作。
- 保持设备最终结果、共享记录及租约释放的一致性；屏业务不写入一体机版本表。

**技术定位**：

- Rust 文件：`src-tauri/src/infrastructure/task_runtime.rs`、`deployment_finalization.rs`。
- Rust 结构体：`ExecutionCoordinator`，位于 `src-tauri/src/application/execution_coordinator.rs`。
- 通用数据库表：`operation_record`、`operation_target_result`、`resource_lease`。

**验收**：模拟设备操作后数据库断连、程序退出及重启；两类业务均按自身载荷恢复；本机临时屏任务不因平台不可用停留在共享补写状态；补写不重复设备操作；未核实结果不显示成功；成功记录不会被旧任务覆盖。

### TD-04：公共任务面板与业务阶段、操作历史解耦

**业务影响**：屏任务应显示“安装应用”“等待设备重新连接”等准确阶段，历史不能混入一体机部署记录。

**当前实现**：公共任务面板从业务配置读取阶段文案和结果补存能力，一体机文案放在自身功能目录。公共历史查询按项目与业务参数读取，一体机查询保留为调用公共能力的薄封装。任务清理能力由后端返回的 `clearable` 字段决定，不按一体机操作名判断。

**改造范围**：

- 由业务提供阶段描述及支持取消、重试、补写等能力，公共面板负责显示。
- 业务操作记录按业务域查询，共用存储机制，保持项目隔离；本机临时屏历史显示本机来源，不混充多人共享历史。
- 业务页面、状态处理及局部样式放入相应功能目录；只抽取确实复用的表格、选择和结果组件。
- “智能屏操作”页使用操作下拉框、单行优先且最多两行的说明及按动作变化的步骤，左选屏右参数；首步动作在右参数面板底部，不设跨栏操作底栏，后续检查和结果页保留必要动作。历史从标题右侧按钮打开抽屉。运维筛选保留已选目标，切换操作重置步骤与检查，不增加场景选择器、历史标签页或左侧操作卡片。

**技术定位**：`src/shell/ActivityPanel.vue`、`src/stores/activity.ts`、`src/shared/api/operationsAdapter.ts`、`src-tauri/src/infrastructure/stage75b_query_adapter.rs`。

**验收**：不同业务进度、状态、操作按钮和历史准确；长文本、批量部分失败、窗口缩放均保持可用；一体机现有交互不回退。

### TD-05：支持本机资产注册、已注册资料草稿与人工关联合并

**业务影响**：未登记屏先在当前工作台整理资料并维护，资料齐备后注册到平台；已注册屏编辑资料时保留独立草稿并更新原平台记录。注册或人工合并后继续沿用维护历史，重开或断平台仍可识别同一已注册屏，无需重复建档。

**当前实现**：智能屏已有正式本机资产、平台缓存、资料草稿、绑定关系和历史别名。注册或人工合并成功后保留旧本机标识和历史关联，列表收敛为一条记录；通用任务已固化的资源键不被直接覆盖。平台完整刷新确认删除的资产会同步清理对应本机关联、草稿和缓存，历史结果仍可追溯。

**改造范围**：

- 为未登记屏生成本机临时标识，保存于本机 SQLite；记录本机项目归属、连接信息和已采集身份，操作与历史只在本实例可见。
- 已注册屏资料草稿绑定原平台主键，保留平台基准值和草稿差异；不新增未注册行，不产生疑似重复候选。平台刷新不得静默丢弃草稿，提交时核对基准，成功回读后收敛对应草稿。
- 注册预览分类新增、更新、无变化、需核对，要求当前项目真实有效空间；自动采集 MAC，失败逐屏确认可信历史或暂不填，真实冲突不能绕过。仅无平台主键且无未解决候选的记录可以新增；已绑定记录不能退回新增路径。
- 注册回读成功后，一致保存旧本机 ID 到平台主键的映射、平台缓存、资料来源和历史索引，显示一条已注册视图；未注册减一、已注册加一、总数不变。重开或平台暂不可用仍显示缓存已注册屏及读取时间，不丢身份或重复计数；缓存不冒充实时完整平台清单。
- 新增或更新超时、回读失败、本机映射保存失败时保留待核实依据，恢复先查询远端事实再补本机关联或结果，禁止直接再次插入。IP/MAC 没有唯一约束，不能按相同地址自动认定恢复目标；正式适配须落实可核实创建身份与条件。
- 智能屏使用一个完整空间树并保存唯一实际节点 ID，任意有效层级可选，列表按楼幢/楼层及全部后代归类。楼幢直属有效，未关联或真正失效才待定；目录暂不可用保留 ID/路径待核验。通用树、路径和项目空间查询已同时供一体机使用，网关尚未接入。数据库查询参考平台 HTTP 接口 `/api/edge/building/space/list` 的项目过滤、字段和排序实现，但继续直连数据库；完整选树不套用图片、设备或核心空间筛选。
- 导入使用系统 `/` 完整路径，规范输出不添加分隔符两侧空格，在当前项目唯一匹配；兼容旧输入两侧空白但保留名称内部空格。空值待定，无匹配/歧义不能提交或静默降级。默认选中全部含错误行，支持树修正、批量分配、路径复制/导出，人员须修正或取消错误行；提交重校验目录和项目，隔离过期异步响应。旧原型按已有空间 ID、旧楼层 ID、旧楼幢 ID 的优先级迁移，失效 ID 不退回祖先，不凭名称关联，历史保留。
- 拉取平台记录后，仅对尚未绑定平台主键的本机记录按相同 IP 或标准化 MAC 提示候选。用户核对名称、IP、MAC、尺寸、所在空间、详细位置和小新版本七项，可逐项或整侧选源，预览后确认；MAC 冲突先核实，不能自动合并。空间按同侧实际节点 ID 和路径整体采用，不拆选楼幢/楼层，确认节点属于当前项目且有效。该合并用例不新增或删除平台记录，主键不变，已注册草稿更新使用独立注册更新用例。
- 确认前复核两侧记录及预览旧值，平台限定字段更新并回读成功后才同步本机采用值、建立关联及保存历史索引；平台失败、回读未确认或并发变化时不合并本机、不丢原记录。平台可能已更新而本机保存失败时保留恢复依据，先读当前事实再完成本机同步，不自动重放平台更新。
- 保留临时标识到平台记录主键的映射、来源及合并前本机历史；原日志仍在本机，不自动将旧历史上传共享库。合并后的新任务采用平台资产的共享机制。
- 存在活动任务、待核实结果或待补写时延后合并；不改写任务中已固化的目标，不让临时记录和已匹配的平台记录在本实例并行执行冲突操作。
- 本机临时资产不提供跨电脑同步或互斥承诺；本机删除不修改平台资产，合并只在人工预览确认后按 TD-06 写入明确选择的字段，不改变历史采集事实。

**技术定位**：Rust 文件 `src-tauri/src/infrastructure/local_sqlite/screen_repository.rs` 保存本机屏资产、缓存、草稿及绑定；目录 `src-tauri/src/infrastructure/smart_screen/` 下的 `assets_service.rs`、`registration.rs`、`merge.rs` 实现资产、注册和合并。迁移位于 `src-tauri/migrations/local/`，公共空间读取位于 `src-tauri/src/infrastructure/project_spaces.rs`，具体表与字段见智能屏技术方案。

**验收**：平台不可用时未注册资产仍可批量维护，已注册缓存与草稿保留；注册预检、有效空间、MAC 失败决定及冲突提示正确；已注册编辑不生成新行或合并候选；新增回读后单条展示、分类数量转移且总数不变，重开及断平台不重复，旧 ID/历史可查；超时先核实不重复插入。独立合并保持七项选源、原主键及平台记录数，活动任务与并发变化保护有效。

### TD-06：为屏业务字段建立按用例限定的写权限

**业务影响**：实施人员可注册新屏及更新资料；平台自身按 Ping IP 判断在线，工作台可经人工确认覆盖本机检查结果；安装成功并回读后记录实际小新版本；人工合并同步逐字段选择值。各用例均以平台写入与回读确认作为成功依据，失败不伪造已保存值，不把登记成功当成设备实测在线。

**当前实现**：普通平台查询连接保持只读，注册、资料更新、状态覆盖、应用版本同步和合并分别使用正式受控写通道。工作台按业务表已有 `app_version` 字段接入，不负责平台增列。空间变更已独立于布点处理：确认目标空间有效并保留原布点及配置，不因已有布点禁止换空间。

**改造范围**：

- 保留普通平台只读连接，增加供屏专用用例使用的独立写通道和限定权限；注册允许受控新增，资料更新仅写 `smart_terminal_screen` 的 `name`、`ip`、`mac`、`size`、`building_id`、`install_address`；状态覆盖只写 `status`，安装结果与独立版本同步只写 `app_version`，合并允许资料字段及双方选源的 `app_version`。实际空间 ID 映射已有 `building_id`，不新增空间列、不编辑目录表、不提供通用 SQL。小新版本专用字段 `app_version` 按平台已具备处理；已有 `version` 保留为尚未实现选择功能的 H5 样式版本，不读取为应用版本，不参与运维写入。工作台不负责其他项目增列或平台表升级，直接读写业务表，不依赖平台实体、DTO或查询接口改造。
- 注册更新必须校验真实空间、平台有效记录和重复候选。自动采集结果及失败决定按屏进入确认快照，暂不填 MAC 不清空平台原值；冲突不静默覆盖。更新保留原主键并使用草稿基准及预览旧值作为并发条件。空间变更单独确认并保留原布点，不顺带修改图片、类别、样式、别名、状态或版本。新增主键、项目归属及必要初始值按所连接平台契约实现，不使用本机观测推断默认在线或版本。
- 平台读写要求项目连接与登录就绪；写通道权限单独校验，无权限时保留检查结果并说明无法覆盖，不影响本机临时屏维护。
- 逐台预览平台状态、本机 Ping 结果、检查地址和时间，明确“本机 Ping 结果 → 平台状态”，由用户选择并确认差异目标，本机结果不变；可重新进入检查后再比较与确认。屏不可达是可能结果；检查程序未运行成功或被取消属于无法判断，不写成离线。状态覆盖不依赖 ADB 连接或 MAC 采集成功。
- 安装用例的版本写入只允许已注册屏小新安装升级成功、设备回读版本及启动检查通过后进行；目标版本不能在选包、排队或安装中提前写入。失败不覆盖平台旧版本；未注册屏只保存本机实际版本。
- 人工合并由 TD-05 的字段选源确认单独处理，可采用双方已有的小新版本记录，但不能据此声称完成设备安装或获得新实测；不覆盖本机 Ping 和原始采集事实。扩展合并写权限前核实字段关联、缓存及派生数据影响。
- 按平台记录主键、检查/执行地址、未删除条件和预览旧字段值等条件更新。条件变化时不覆盖，重新读取并提示；小新 `app_version` 不是并发控制序号，没有可靠并发版本字段时不得承诺完整的先后顺序保护。
- 更新并回读确认后才刷新对应平台最终业务值，记录操作人、目标、来源与时间、前后值和写入结果；合并另存字段来源与关联依据，平台确认后再同步本机记录。平台后续 Ping 仍可更新状态；回读不同应展示已确认当前值，不反复强制覆盖。
- 写入失败和结果待核实只在结果界面及本机历史保留，不保存成平台资产或项目状态。恢复先核实或补写已有证据，不自动重放新增、安装或旧字段更新。注册回读成功前本机未登记记录保持原身份；可能已经创建的目标先核实，再按 TD-05 收敛映射和缓存。

**技术定位**：Rust 目录 `src-tauri/src/infrastructure/smart_screen/` 下的 `write_context.rs`、`platform_write.rs`、`registration.rs`、`value_updates.rs`、`merge.rs` 和 `shared_results.rs` 分别处理写入条件、限定字段、具体业务及共享结果。业务数据库表 `smart_terminal_screen` 保存屏的最终资料、状态和应用版本，数据库表 `t_project_building` 只读校验空间；不新增平台业务接口。结果摘要与本机过程记录仍分库存储。

**验收**：普通平台池仍拒绝写入；注册只在确认后受控新增，资料更新不改原主键、状态、版本及空间配置，状态/安装/合并各守白名单；失败或回读不确定保留旧值与本机资料，先核实不重复插入或安装。缺权限、记录删除、IP、空间或预览条件变化和部分失败均准确呈现；无 ADB/MAC 不阻断离线状态比较，登记 MAC 失败按逐屏决定处理但冲突不能绕过；不写目录表、白名单外字段及过程阶段。

版本维护与安装执行分离：先安装后注册、同版本跳过以及平台版本缺失时，均能重新读取设备版本、预览并确认同步，不依赖再次安装。正式写入核对目标身份、实际 IP、设备版本和平台原值，读取失败不清空旧值，回读未确认先核实。

草稿与操作快照分离：IP、MAC、尺寸待提交时不执行设备写操作；普通名称和位置草稿不阻断。只读动作可检查确认地址并说明草稿尚未生效。预检、确认及派发前目标变化均需重新检查，不能静默把草稿合入执行参数。

## 4. 智能屏开发配套能力

以下能力均已接入正式智能屏业务；具体业务规则以产品和技术方案为准，实机适用范围以验收记录为准。

| 能力 | 实施边界 | 验收重点 |
| --- | --- | --- |
| Android 设备连接 | Android 调试桥（ADB）为设备管理工具；在基础设施层提供受控操作，按 Windows、macOS、Linux 实际支持的运行环境交付 | 目标序列号绑定、连接超时、取消、路径含中文空格、多设备隔离；不结束用户其他任务共用的 ADB 服务 |
| 小新应用安装升级 | 一个 APK 批次只含同一种明确屏尺寸，预检和执行均校验全部目标及文件绑定，不按处理器架构推断尺寸；正式能力仍检查包名、版本和逐设备兼容性，已注册屏成功后按 TD-06 记录平台版本 | 混选、未知尺寸及隐藏目标不能绕过限制，尺寸变化须重新选包；同尺寸不代表架构兼容，未安装设备可首次安装，成功回读后更新最终版本，失败保留旧值 |
| 屏身份、注册更新与平台关联 | 分清本机临时标识、平台记录主键、当前网卡 MAC、应用设备标识和 ADB 连接标识；按 TD-05 分别注册、更新草稿或人工合并 | 自动采集失败可逐屏确认，冲突阻断；有效空间、单条身份转换、缓存保留、数量守恒和超时防重复；本机历史保留 |
| 平台状态覆盖 | 本机 Ping 与平台状态不一致时，按 TD-06 经用户确认直接写入限定字段 | 管理端口不可用不等于 Ping 失败；记录条件变化不覆盖；无平台记录仅保存本机结果 |
| 小新应用配置 | 已通过 ADB 调用小新受限管理组件，读取与修改常用配置，按需重启并回读 | 白名单字段、其他配置保留、单台和批量、同值不重写、不确定结果核实；不直接改应用私有存储文件 |
| 屏操作结果 | 按各操作定义成功证据及中断后的核实方式 | 安装版本回读、重启后连接恢复、系统及硬件时间双回读、配置生效确认；4 寸断电保时限制单独说明 |

## 5. 实施门槛和回归范围

公共前置优化与智能屏正式接入已完成。后续增加新业务时继续沿用以下门槛；NTP 时间服务器设置和服务端部署属于尚未实施的后续工作。

架构优化结束时必须具备：

1. 关键变更的契约、状态及隔离测试。
2. 一体机列表、项目切换、配置、检查提交、任务与结果恢复的针对性回归。
3. 不依赖一体机模型的第二业务测试处理器，覆盖排队、取消、本机结果保存与共享结果补写；测试处理器不伪装已实现的智能屏功能。
4. 本机维护与平台访问隔离、业务结果保存及中断后核实的公共契约检查；智能屏注册更新、草稿、缓存、关联及合并已有真实验收，新增业务需提供自身证据。专用原型不连接真实库或 ADB，不能替代正式业务测试。
5. 当前源码的能力清单与文档保持一致。

正式智能屏验收须使用实际支持的 4 寸、10 寸设备分别验证。模拟器或桩测试不能证明固件权限、安装器、持久 ADB、系统时间和屏端配置已经可用。

完整重跑真实部署只在改动影响对应链路时安排；不因技术债整理而自动清空测试环境或重新部署。
