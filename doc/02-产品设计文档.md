# INX 实施工作台公共产品设计

> 状态：公共产品基线；智能屏基础运维与屏端配置管理已实现，验证范围见各自验收记录。
>
> 更新日期：2026-10-10。适用范围：`inxaiot-desk-buddy` 桌面工程的公共工作台能力，代码基线 v0.2.9。
>
> 事实依据：现有桌面框架、项目管理、任务日志和一体机实现；各业务验收记录独立限定验证范围。

## 1. 业务目标与使用环境

INX 实施工作台面向项目实施与维护人员。使用人员在自己的电脑上选择项目，对设备进行资产维护、配置、批量操作和问题定位。读取平台资产、更新平台状态及使用项目共享能力前，需要连接相应项目环境并完成平台登录；智能屏设计中的本机未登记设备允许在平台不可用时独立维护。

同一项目可以由多名实施人员在不同电脑上维护。应共享的项目配置、平台已登记资产的运维关联和操作结果进入项目工作台数据库；当前电脑的执行进度、临时文件和完整日志保留在本机。未注册一体机清单，以及未登记智能屏的临时资产和维护历史，只保存在建立它们的电脑，不作为多人共享资产。工作台不是长期在线监控或告警服务，设备实时状态必须来自明确的实际观测。

工作台的业务交互对象为项目侧平台，云平台配置并同步项目信息属于上游过程，不参与设备运维链路。平台登录认证沿用既有能力；平台业务数据通过数据库直接查询，已明确的运维字段更新也直接操作项目表，减少对平台页面和业务接口发布的依赖。工作台自身的共享库、平台业务库和设备通信分别承担职责，不能混为一种数据操作。

目前一体机、智能屏基础运维和小新常用配置管理已有正式页面、数据读写和设备执行链路，实际验收范围见各自开发计划和记录；独立演示原型只用于交互核对。屏端配置范围见[智能屏需求第 6 章](智能屏/01-智能屏运维管理需求设计.md#6-屏端配置数据管理)。网关管理保持不可操作的“规划中”菜单。

## 2. 公共与业务专属范围

屏端配置管理由工作台通过 ADB 调用小新内部配置服务，开放常用环境、地址和名称字段。实际配置保存在屏上，电脑保存快照、草稿和过程，项目工作台库保存已注册屏的结果，不向平台业务库复制小新配置。只更新明确修改的字段，不做配置版本冲突；需要时保存后重启小新并回读。当前配套小新版本为 2.0.10，完整包数字版本为 5022，分架构包数字版本按实际文件读取；验证范围见[配置管理验收记录](智能屏/19-屏端配置管理实施与验收.md)。

| 范围 | 负责内容 | 说明文档 |
| --- | --- | --- |
| 公共工作台 | 项目连接、平台登录、项目切换、桌面框架、设置、任务、日志、共享操作结果的基础约束 | 本文、[公共技术方案](03-技术方案设计.md)、[界面规范](01-桌面工作台界面设计规范.md) |
| 一体机管理 | 一体机身份与导入、发布配置、镜像、部署升级、服务检查 | [一体机产品详细基线](一体机/02-产品设计文档.md)、[一体机文档索引](一体机/README.md) |
| 智能屏管理 | 设备范围、资产来源、设置与运维动作、升级方式及异常边界 | [智能屏运维管理需求设计](智能屏/01-智能屏运维管理需求设计.md)，按其文档状态确认 |

## 3. 项目、登录与切换

实施人员先在本机建立项目连接信息，配置项目平台地址及数据库连接。连接测试用于检查实际可达性与兼容性。项目工作台数据库的表结构初始化或升级由人员明确触发，普通打开项目不应暗中执行表结构变更。

平台访问地址允许使用 HTTP 或 HTTPS，由实施人员按项目实际配置填写。工作台不根据 IP 网段或域名强制要求 HTTPS；项目内网使用 `192.171.32.x` 等地址时同样允许保存和测试连接。平台地址与数据库主机独立填写，数据库连接加密仍由已有的 MySQL TLS 开关控制。

一体机现有业务，以及智能屏的平台读写和共享操作，需要当前项目连接就绪并具有有效的平台登录会话。数据库不可用、表结构不兼容或会话过期时，应准确说明受影响的操作。同一项目重新登录或恢复平台访问条件后，智能屏页面自动刷新平台数据和提示，不要求人员手工切换页面。

本机未登记智能屏只要求明确的本机项目归属、已核对的目标和对应设备能力，允许执行首期支持的批量运维；不以平台或项目共享库不可用、平台会话缺失为由阻断直接设备操作。其本机记录与平台资产在页面上明确区分，不将本机临时设备计入平台已登记屏总数。

需要平台保护的设备写操作中，若一批同时包含已注册和本机未注册屏，而平台连接、登录或共享记录不可用，整批不执行并给出原因。需要单独维护本机屏时，由人员重新选择本机未注册屏发起一批，不由程序暗中拆批执行。

项目切换改变当前查看和操作的项目。页面草稿、查询结果、预检结果及选择项必须按项目隔离，旧项目的延迟响应不得覆盖新项目。已经提交的后台任务仍属于提交时的项目，不因导航切换改变目标。

删除本地项目连接信息不等于删除项目平台或工作台数据库。数据目录维护、退出程序等公共动作需要遵守已有活动任务保护。

## 4. 数据职责

| 数据位置 | 保存的业务事实 | 不应承担的职责 |
| --- | --- | --- |
| 本机 | 项目连接信息、会话与界面偏好、任务过程、完整日志、临时制品、本机检查记录、未注册一体机清单、未登记屏资产及历史，以及已登记屏资料草稿、平台缓存和身份映射 | 将仅本机保存的临时设备和历史显示为其他电脑已经可见，或将草稿和缓存冒充已同步的实时平台事实 |
| 项目工作台数据库 | 共享业务配置、已部署设备的运维关联、操作摘要、目标最终结果、配置版本和执行互斥信息 | 存放大文件、全部实时日志，或复制第二套可编辑资产主数据 |
| 项目平台业务数据库 | 已注册一体机和智能屏的业务资料；一体机登记与资料编辑，智能屏注册更新、状态确认覆盖、最终应用版本及人工合并选源确认的字段 | 作为工作台任意增删改资产、空间和业务配置的通用写入目标 |
| 目标设备或其受控服务 | 实际运行版本、连接结果和执行结果；屏端配置扩展中的小新实际配置仍保存在屏上 | 用工作台旧缓存代替当前观测，或把屏配置强制复制到平台业务库作为主数据 |

普通平台数据访问保持只读。智能屏设计按用例限定写入：注册新屏或更新既有屏资料；将本机 Ping 结果经确认后覆盖平台在线状态；记录已注册屏安装结果或独立读取确认的版本；人工合并时同步逐字段选源确认的业务值。资料更新仅含名称、IP、核实后的 MAC、尺寸、所在空间和详细位置；状态及安装结果分别只更新数据库表 `smart_terminal_screen` 的字段 `status` 或 `app_version`；合并可额外选用双方已有的小新版本。具体字段及目录映射见智能屏需求第 3.2、3.5、8 节。各用例分别限定新增或条件更新并回读，不调用平台业务接口，不连接云平台。状态覆盖方向为本机到平台，本机检查结果不变；平台后续 IP 探测仍可改变状态。

小新应用版本保存到平台已具备的数据库字段 `smart_terminal_screen.app_version`；工作台不负责其他项目增列。已有字段 `version` 用于屏内 H5 样式版本，功能尚未实现；它与空间页面配置字段 `screen_version` 均不作为小新应用版本使用，也不由本期运维操作修改。

这些写入要求项目连接与登录就绪、具备对应用例的限定权限，并核对平台主键、执行地址和预览旧值等条件。条件已变化时不覆盖，重新读取并提示；写入与回读确认后才展示平台最终值。安装失败不提交版本更新；数据库拒绝或回读未确认时，资产保留最近确认值，失败详情只进入结果界面及本机操作历史，不伪造平台成功，也不重放新增、安装或过期更新。合并仅可选用双方已有业务值，所在空间的实际节点 ID 与完整路径整体采用一侧并验证有效性，不拼接祖先。仅“注册/更新到平台”允许按确定条件新增屏；不授权删除平台记录、编辑空间目录、改变既有主键或执行任意 SQL。正式桌面已实现上述限定写入；独立开发原型只模拟这些规则。

注册更新采用“选择设备与资料 → 检查并预览 → 提交结果”三步。检查自动采集 MAC，失败逐屏确认可信历史或暂不填，身份冲突不能绕过；必须选择当前项目真实有效空间。修改空间不受已有布点坐标阻挡，不自动清除或移动布点，不修改空间图片、屏样式和设备类别；实际布点由人员到平台另行调整。已绑定屏的资料修改保存为独立本机草稿，与平台当前值比较后更新原记录，不新增未注册行、不走疑似重复合并。新增并回读确认后，只保留一条已注册视图，未注册数减一、已注册数加一、管理记录总数不变；旧本机 ID、映射、历史和平台缓存保留。重开或平台不可用时显示带时间的缓存已注册屏；缓存不代表实时或完整清单，写入仍需恢复连接。新增超时先核实是否已创建，不能因结果未确认直接再次插入。

一体机新增和导入先保存本机清单，部署时再注册到平台。详情允许修改名称、IP、所在空间和安装位置：未注册时保存本机，已注册时直接更新平台原记录；MAC 用作身份核对，不能在普通资料编辑中随意替换。空间选择保存数据库字段 `op_edge_aio_server.building_id` 对应的实际空间 ID，详细位置保存字段 `addr_alias`。已注册资料以平台为准，项目工作台库保留部署与结果关联。具体规则见[一体机产品设计](一体机/02-产品设计文档.md)。

未登记智能屏由工作台生成本机临时标识。后续拉取平台记录时，相同 IP 或经标准化核对的相同 MAC 只生成合并候选；用户逐字段选择本机或平台的值，也可一键采用一侧，再预览并确认同步合并。MAC 冲突先核实为同一设备并明确选取保留值，不自动合并。平台限字段更新并回读成功后，本机对应字段同步为相同值，再建立关联；平台失败、结果不确定或预览期间数据变化时不合并本机、不丢原记录。活动任务及待核实、待补写结果处理完毕前延期；保留原本机标识、采集来源和历史，不自动上传旧历史，后续新操作采用平台已登记资产的共享规则。

公共数据表只表达通用项目、任务、操作和资源关系。各领域的设备身份、导入过程、配置和状态模型由其独立设计，不向一体机表中增加其他设备的业务含义。

## 5. 公共桌面交互

顶部提供项目切换及任务、设置、关于等公共动作；左侧按业务域组织导航；中间显示当前业务页面；底部展示项目状态与非模态任务日志面板。颜色、字号、密度、组件行为遵循[桌面界面规范](01-桌面工作台界面设计规范.md)。

业务页面承担“用户要对哪些设备做什么”，公共任务面板承担“操作是否执行、进度如何、能否取消、日志与最终状态是什么”。新增业务不再单独建立一套任务中心。

“智能屏操作”页沿用一体机布局：标题最右为历史抽屉按钮，上方操作下拉框、单行优先且最多两行的说明与专属步骤，下方左侧筛选表格选屏、右侧参数。首步主动作位于右参数面板底部，不设跨栏操作底栏；后续检查和结果页保留必要的返回、确认及后续动作。正常、失败、平台不可用等测试条件不作为顶部场景选择或可保存的项目状态。“新增智能屏”使用单一完整空间树，可选任意有效层级，保存实际节点 ID；列表仍只按楼幢/楼层简化筛选并包含全部后代。楼幢直属不算待定，未关联或真正失效才归待定；目录暂不可用保留已有 ID/路径待核验。

一体机和智能屏的新增、导入均使用项目业务空间。新增时从完整树选择，导入使用系统 `/` 完整空间路径，规范输出不添加分隔符两侧空格；空值允许暂不关联，非空须在当前项目唯一匹配。智能屏预览可用树修正、为选中行批量分配，并复制/导出项目路径；一体机预览沿用自身导入规则。提交前重新核对目录及项目，不能静默跳过错误或自动建空间。网关空间业务尚未接入。

一体机和智能屏列表均可逐行选择、表头全选，并从固定分页区的“批量操作”转入对应操作页，默认带入所选设备。未选择时按钮使用中性样式并禁用，已选择时为蓝底白字，右侧保留斜向箭头。一体机右上角提供“新增一体机”，名称、IP、MAC 必填，空间和安装位置可选；保存效果与合法导入记录一致。

“注册/更新到平台”预览分为新增、更新、无变化、需核对，显示资料差异与逐屏 MAC 来源或失败决定；无变化不写，需核对不自动跳过。已注册屏编辑明确区分本机草稿和平台确认值，保存草稿不提示平台成功；空间未选择、失效或待核验时不能提交登记。

浏览器中的开发演示只能用于界面评审。真实设备业务通过桌面程序执行，不能用演示数据表现连接成功、检查通过或操作成功。

智能屏版本维护支持“先安装、再注册、重新核对版本并同步平台”，无需为补齐记录重复安装；普通刷新和旧缓存不替代本次读取。平台断开时，两类屏均可按确认地址执行只读设备检查并保存本机结果，平台写入与已注册屏设备写操作继续遵守连接与共享保护条件。

已注册资料草稿不改变实际设备目标。IP、MAC、尺寸有待提交差异时，设备写操作先核对更新平台或放弃修改；名称与位置等普通修改不阻断。界面明确显示本次连接地址，只读检查可使用确认地址，提交和派发前再次校验，不静默使用草稿值。

## 6. 任务、日志与操作结果

长任务由本机后台执行，页面退出或切换不应成为任务执行者。任务必须能识别所属项目、业务域、操作类型和目标资源；显示真实进度与明确终态，禁止按时间模拟完成率。

本机任务面板展示当前项目的任务和完整日志。检查已经提交且关联到正式执行任务后，面板只显示执行任务，避免一次操作出现两条记录；原检查依据和日志仍留在本机。未提交、失败、执行中及结果待核实的检查继续显示。平台已登记资产的“平台结果记录”只记录其他实施人员需要理解的操作摘要与目标最终结果，不保证能够读取另一台电脑上的原始日志。本机未登记智能屏的操作结果与历史保存在本机，不因没有共享记录而显示任务未完成。

“清空已结束任务记录”清理当前项目可清理的终态任务和检查，提示数量按面板可见记录计数；运行中、排队和结果待核实记录保留。已清理但尚未提交的检查需要重新进行。该操作不清空日志文件；“清空日志”只处理当前选中的已结束任务，独立确认且不删除任务记录。任务删除后不再出现在日志选择项中，无可选任务时明确显示空状态。

业务结果页只保留“任务与日志面板”按钮，打开对应原任务的日志，不另设重复的“本次日志”。智能屏在线检查按本次观测显示“在线 / 离线”，未执行显示“未检查”，没有可靠结果显示“未知”，程序异常在结果原因中说明；在线检查、设备检查和 MAC 检查结果提供“查看屏详情”。结果表、固定操作区及逐台配置差异的显示遵循界面规范。

取消、部分成功、执行中断、结果待补写等状态必须保持准确。结果补写不能隐含重复执行设备动作。可清理范围由任务状态及其仍需保留的业务依据决定；业务模块不能通过清理记录破坏有效的待提交或待恢复结果。

智能屏资产只呈现注册属性和确认后的最终业务事实。检查、排队、安装、等待回连等中间阶段仍在本机任务与日志中用于进度、取消和恢复，不写入平台资产字段，也不成为项目状态；平台版本或状态更新失败不改写旧业务值。

多实例维护共享配置时，应检测编辑冲突；对同一资源具有写影响的任务，应按业务资源定义互斥范围。平台资产使用共享互斥机制；本机临时屏使用本实例互斥，不能宣称已阻止其他电脑操作同一未登记设备。智能屏在真正提交或执行设备写操作时占用资源，打开资料或预览不长期占用；遇到他人占用时显示操作者，人员确认“接手并继续”后重新读取最新数据并重新检查，原操作者不能继续提交。具体资源键由业务域确定，不在公共规范中固定为某一种设备标识。

## 7. 异常与限制

- 平台、数据库或设备连接失败时显示实际原因及后续操作；不以本地旧数据宣称远端写入成功。
- 页面收到过期结果、项目不一致结果或失效预检时，不能继续据此提交写操作。
- 运行状态、最近检查状态和历史操作结果分别标明来源及时间，不能混用。
- 凭据不进入日志、错误摘要和前端长期缓存；人员能否查看或编辑某类业务凭据由业务范围确定。
- 桌面平台的构建通过不等于目标操作系统已完成原生验收，发布与回滚遵循[交付说明](16-Windows可信发布与回滚说明.md)。

## 8. 扩展与验收

智能屏先确认业务对象、使用场景、执行环境、操作与结果，再形成技术方案。跨业务接入前需要处理的导航、任务展示和恢复等结构问题，见[跨业务扩展技术债与实施顺序](20-跨业务扩展技术债与实施顺序.md)。

智能屏应用安装升级只管理小新应用，各主要操作按批量使用设计。未登记屏本机维护、注册更新、已注册资料草稿与缓存、未绑定记录的人工关联合并、确认后的平台状态覆盖，以及配套小新版本支持的配置管理均已实现。工作台原生读取 APK 基本信息，签名和覆盖安装条件交由 Android 安装过程判断，不自动卸载旧应用或清空数据。

校准时间已同时设置系统时间和启动使用的硬件时钟，按两项回读判断成功。已验证 4 寸和 10 寸固件的软重启保时；10 寸已有一次无公网断电验证，已测 4 寸完全断电仍会丢时。NTP 时间服务器配置及服务器搭建尚未实施，详见[校时验收](智能屏/28-系统与硬件时钟同步校准验收.md)。

新增业务的完成证据至少包括：用户能在对应项目或本机维护范围内进入功能；操作目标和协议已验证；任务、日志及结果可以追溯；切换项目和页面不会串用状态；失败、取消、并发和恢复规则经过针对性验证。本机未登记屏还需证明断开平台后可维护且历史不丢失，平台状态覆盖需证明权限、条件更新和审计有效。底层方法可用、组件测试通过或历史一体机验收通过，均不能替代智能屏自己的用户验收。
