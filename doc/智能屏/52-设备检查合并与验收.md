# 设备检查合并与验收

日期：2026-11-04。适用工程：`inxaiot-desk-buddy`（Windows实施工作台程序）。

## 1. 使用方式

实施人员选择智能屏后，统一使用“检查设备”。默认检查网络、管理连接、系统及小新基础信息；勾选“仅检查网络连通性”时只从当前电脑检查IP可达性，无需设备ADB连接可用。

首屏左侧保留标题、筛选、选择状态和设备列表；右侧依次为说明、仅网络选项、并发台数、已选数量和检查模式/进度，开始按钮固定底部。运行期间仍在首屏，左侧列表禁用，右侧显示后台真实在读设备和完成数，并可取消本次检查。预检或任务创建失败留首屏；任务结束后进入结果页，包含部分失败、离线及取消结果，不增加配置确认步骤。

并发取值1—3，开始后冻结本批选择、地址、检查方式和并发。4寸与10寸允许混选。原有关键资料草稿提示保留，读取当前确认地址，不使用尚未提交的IP。

## 2. 检查内容和结果含义

| 模式 | 内容 | 结果 |
| --- | --- | --- |
| 完整检查 | IP连通性、ADB管理连接、有线MAC核对、Android版本/型号/固件/架构、可用空间、系统时间及小新安装/运行/版本 | 分开显示网络、管理连接、系统/小新信息与检查结果 |
| 仅网络 | 当前电脑对目标IP执行Ping | 显示网络可达性；ADB及设备信息明确标为本次未检查 |

完整检查直接复用已有检查中的Ping，不先额外执行一次快速检查。网络正常不可达时仍尝试ADB，因为禁用Ping不等于ADB不可连接。

“检查完成”表示取得本次检查结果，不表示设备必定在线或所有状态正常。Ping正常无回应可形成离线结果；本机检查程序异常显示未知，不能自动当离线。ADB未授权、连接失败或信息不完整，不得覆盖已取得的网络事实。小新未安装或未运行也是可读取的状态，不等同于检查程序失败。

表格仅使用本任务保存且与目标IP一致的观测，不用当前资产缓存填充历史结果。保留“查看屏详情”，该详情仍展示本机最新资料，并非旧任务当时的全部快照。

完整检查同时保留“查看平台状态差异”和“核对版本并同步平台”；仅网络保留状态差异操作。它们继续进入原确认流程，检查完成不自动覆盖平台状态或应用版本。检查会保存本机观测，已注册屏按既有条件保存共享操作记录；共享保存异常与设备检查事实分开。

## 3. 实现范围

改动运行在工作台，不升级屏端应用或平台服务。已有后台操作类型`inspect`表示完整检查，`ping`表示仅网络，继续保留以兼容历史和重试；菜单只显示统一的“检查设备”。旧网络检查重试、状态差异页的重新检查进入同一页面并自动选中仅网络模式。

| 工作台文件 | 职责 |
| --- | --- |
| `src/features/smart-screen/ScreenInspect.vue`（新增Vue组件） | 统一首屏、选项、并发、进度、取消与结果切换，复用已有首屏共用组件 |
| `ScreenOperations.vue`（已有Vue组件） | 统一菜单、旧网络任务与重试接入、关键资料草稿及原结果确认事件 |
| `ScreenTaskResults.vue`（已有Vue组件） | 分别展示网络、管理连接、设备信息与检查结果；窄窗仅表格自身横向滚动 |
| `src/shared/model/screen.ts`、`screenOperationFlow.ts`（已有TypeScript文件） | 统一菜单与检查名称、结果步骤；不删除旧操作类型 |
| `src-tauri/src/domain/smart_screen/operation.rs`（已有Rust文件） | 将新网络任务的显示名称统一为“检查设备（仅网络）”，执行逻辑不变 |

一体机页面、部署逻辑及共用任务队列没有因本次合并而修改。未改变屏检查命令、权限、设备身份核对或平台写入规则。

- 仅网络记录中的ADB默认false不当作连接失败，旧完整检查历史保留。
- 每模式前后身份、11项设置、持久/运行端口、时区、启动编号、应用PID及本机资产资料一致；未启动应用、修改设置或重启。
- 目标为本机未注册屏，没有平台业务状态、版本或共享库写入，隔离队列已关闭。
