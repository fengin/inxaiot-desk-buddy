# 本地时区显示修复与回归

> 日期：2026-10-21。状态：当前未发布开发代码已修复，所列自动回归、隔离数据库及真实桌面验证通过。

## 1. 业务目标与适用范围

实施人员在 Windows 工作台查看本机任务、平台共享历史、日志及检查时间时，同一时刻应按当前电脑的本地时区显示。北京时间下，本机历史的 `13:39:11` 与平台历史应一致；电脑使用其他时区时，按该时区和该时刻的夏令时规则换算，不固定增加八小时。

此前本机任务使用时间戳，界面按本地时区显示；平台共享历史返回带 UTC 偏移的文本，公共格式化函数却只去掉偏移后缀，保留了 UTC 钟点。由此同一操作在两处分别显示 `13:39:11` 和 `05:39:11`。问题发生在显示转换，原任务时刻及共享存储值一致。

本次修改在工作台工程 `inxvision-assistance/inxaiot-desk-buddy` 中完成，程序运行在运维电脑。小新应用、设备时间、NTP 设置及数据库存储时刻均不需要修改。

## 2. 显示规则与兼容范围

| 时间来源 | 当前规则 |
| --- | --- |
| Unix 时间戳，包含秒、毫秒、微秒和纳秒来源 | 按既有位数约定识别单位，以原时刻转换为电脑当地时间；高精度字符串先按整数处理 |
| 带 `Z` 或明确时区偏移的日期文本 | 按原时刻转换为电脑当地时间，兼容现有 Rust 数据库时间文本 |
| 工作台自有共享库的一体机服务观测和最近操作时间 | 读取时明确 UTC 标记，再由公共格式化函数转换；保留原秒精度及空值 |
| 旧平台仅返回日期钟点、没有时区的字段 | 保留来源钟点，不猜测为 UTC；例如数据库字段 `op_edge_aio_server.last_sync_time` 来源为边缘程序当地时间 |
| 空值、未知文案或非法日期 | 沿用空值提示或保留原文，不自动纠正日历或猜测时区 |

只在展示时转换。原始记录、排序依据、配置预览指纹、会话有效期和操作占用判定继续使用原始时间。

### 2.1 页面覆盖核查

以下是对工作台当前源码的整体核查范围，正文、悬停提示及详情弹层采用相同规则。除已修复的公共函数及两处一体机 UTC 读出外，未发现新的结构化时间漏接位置。

| --- | --- |
| 智能屏校准时间 | 当前电脑时间；检查详情中的设备时间、读取时电脑时间；详情按钮的悬停提示 |
| 智能屏列表与详情 | 列表检查提示；MAC 采集、最近检查、ADB 检查、版本读取、设备及电脑时间、平台读取、缓存读取及最近操作 |
| 小新配置与 NTP 设置 | 配置读取列表和详情、NTP 读取详情 |
| 注册与平台同步 | 注册预检时间、状态同步检查时间、版本核对检查时间 |
| 智能屏任务结果及历史 | 任务开始时间、本机历史、平台共享历史列表与详情、共享目标实测时间提示 |

| 一体机操作及发布配置 | 部署升级历史、完成时间、发布参数最后修改时间 |
| 公共任务和日志面板 | 任务更新时间、每条日志时间 |

原始诊断 JSON 及导出的设备日志属于取证原文，保留原时区标记；其中设备日志可能只有月日和钟点，没有年份及来源时区，不能整体改写为电脑当地时间。时长、时间偏差、缓存年龄和系统启动内毫秒也不作为日期换算。
