## 1. 文档定位

### 2026-09-02补充确认：免安装交付与既有RSA私钥

- Windows交付可直接双击运行的Release EXE，不以NSIS安装、卸载为前置条件；仍使用用户应用数据目录和系统WebView2运行时。“免安装”不代表零运行时依赖或所有数据随EXE移动。
- macOS交付完整`.app`，复制到“应用程序”目录即可使用；不交付PKG安装器。原生Mac构建与实际运行需单独验证。
- Linux交付当前架构的独立可执行文件，由目标Linux发行版原生构建和验证；系统需要Tauri对应的WebKitGTK等运行依赖。
- 发布参数必须接受已有RSA私钥内容，无需替换一体机已配置的公钥。用户在界面录入后保存到专用工作台库的发布配置中，继续加密存储，不能改为明文列、日志或文件。
- 阶段8使用干净提交生成、通过完整性校验的Windows免安装Release进行真实桌面验收；旧文档中的“必须NSIS安装”和“RSA必须换为Ed25519”要求由本次确认取代。
- 阶段8现场反馈补充：表单输入提示统一中文；登录界面只展示账号、密码和验证码，不展示或要求用户填写会话标识等内部协议字段。
- 主机指纹属于自动运维观测，不设人工采集或确认入口。首次连接自动记录；发现变化提示并记录新旧值，继续采集与连接，不作为部署预检阻断条件。SSH账号/密码/私钥认证失败仍正常阻断；该策略不提供严格主机身份认证保证。

本文档定义 `inxaiot-desk-buddy` 的产品定位、数据职责、信息架构、核心流程、页面职责、业务状态和验收口径，作为后续技术方案设计和重构实施的产品基线。

事实与决策优先级：

1. 本文档记录的已确认重构决策。
2. `重构背景.md` 中的现状、目标和用户确认。
3. `01-桌面工作台界面设计规范.md` 中与业务无关的界面基线。
4. 原 `inxaiot-edge-workbench` 的当前能力、流程和历史文档，仅用于复用已经验证的业务能力。

若本文档与原工作台“数据全部本地保存”“不直连平台数据库”“必须生成报告”等旧结论冲突，以本文档为准。

本文档回答“产品做什么、用户怎样使用、数据在产品层如何分工”；数据库表、认证协议、Rust 模块、SSH 库和 Tauri IPC 等实现细节留到技术方案设计。

## 2. 重构背景

### 2.1 当前产品问题

原工作台已经实现一体机清单、发布包、首次部署、整包升级、单服升级、日志和报告等主流程，但产品模型存在以下问题：

1. 项目、配置、清单和历史数据全部保存在每个桌面实例本地。
2. 同一项目由多名实施人员维护时，数据无法共享，配置容易不一致。
3. 更换电脑或运行实例后，需要重新创建项目、导入清单和填写参数。
4. 部署升级步骤过多，预检、渲染、执行、检查和报告被拆成过多页面阶段。
5. 报告生成成本高、实际使用价值低，真正需要的是可检索的操作历史。
6. 产品后续需要扩展智能屏和网关管理，继续使用完全本地化数据会放大同步问题。
7. 原界面信息排版、视觉层级和工程组织不适合继续扩展。

### 2.2 重构方向

重构版采用以下产品方向：

- **项目数据平台化**：项目共享配置、资产和操作记录进入项目侧数据库。
- **本地实例轻量化**：本地只保存项目连接入口、项目会话、界面偏好、执行临时数据、日志和本次选择的镜像文件位置。
- **工作台直连数据库**：不要求项目平台为工作台新增配套业务接口。
- **平台账号认证**：继续使用项目侧平台后台管理的同一套账号密码。
- **流程简化**：将部署升级收敛为选择、检查、执行和结果四个阶段。
- **历史替代报告**：取消报告生成，以项目共享的部署升级记录替代。
- **能力渐进扩展**：首期完成一体机管理；智能屏和网关只保留产品边界和菜单位置。

## 3. 产品定位

### 3.1 一句话定位

INX 实施工作台是面向项目实施与维护人员的桌面工具，用于共享项目发布配置、管理项目资产，并通过本机直接连接目标设备完成批量部署、设置、升级、检查和问题定位。

### 3.2 产品价值

- 同一项目的实施配置、平台注册资料和部署结果由多个工作台实例共享；未注册的一体机清单只保存在录入它的电脑。
- 更换电脑后只需恢复项目连接并登录，不需要重建全部项目资料。
- 实施人员不需要记忆 SSH、Docker、Compose 和配置渲染命令。
- 首次部署、整包升级和单服升级使用统一、简化的操作框架。
- 每次操作有项目级历史记录，可查询谁在何时对哪些对象执行了什么版本。
- 为后续智能屏和网关实施能力提供统一的项目、认证、任务、日志和并发控制基座。

### 3.3 产品边界

工作台负责：

- 管理本机可访问的项目连接入口和独立登录会话。
- 直接读写工作台项目库。
- 按需读取项目平台业务库中的既有业务数据。
- 维护工作台专属的项目配置、资产关系、版本元数据和操作历史。
- 通过 SSH/SFTP 和远端 Agent 执行部署升级。
- 从平台、工作台记录和一体机实际环境组合展示实施状态。

工作台不负责：

- 替代项目平台后台的日常业务管理。
- 要求项目平台为每个新增工作台功能同步开发接口。
- 把大型发布包和镜像上传到项目数据库或平台文件服务。
- 提供长期、全天候的一体机在线监控服务。
- 在首期实现角色、字段权限和凭据脱敏。
- 迁移原工作台本地项目、SQLite 数据和历史报告。
- 在首期实现智能屏和网关的具体管理功能。

## 4. 用户与使用场景

### 4.1 目标用户

| 用户     | 主要目标                        |
| ------ | --------------------------- |
| 项目实施人员 | 导入待实施清单，完成首次部署，检查节点结果       |
| 项目维护人员 | 查看一体机状态和版本，执行整包或单服升级，定位失败节点 |
| 临时支援人员 | 在新电脑上连接已有项目，使用共享配置快速接手实施或升级 |

首期不区分角色。任何能够完成项目平台登录并持有数据库连接配置的工具使用人，均可查看和编辑工作台项目数据、发布参数和凭据。

### 4.2 核心场景

1. 新项目第一次建立工作台项目库和发布配置。
2. 从表格导入一批新一体机并执行首次部署。
3. 在已有项目中追加一批一体机。
4. 对多台已部署一体机执行整包升级。
5. 选择本地单个镜像，对目标服务执行单服升级。
6. 新工作台实例连接已有项目并继续维护。
7. 接管已经在平台存在、但没有旧工作台历史的一体机。
8. 多名实施人员同时查看数据，避免配置覆盖和重复执行。

## 5. 产品概念与术语

| 术语     | 产品含义                                                     |
| ------ | -------------------------------------------------------- |
| 本地实例   | 当前电脑上运行的一个工作台程序实例                                        |
| 本地项目入口 | 本地保存的项目名称、平台地址和数据库连接配置                                   |
| 工作台项目库 | 部署在项目数据库服务器上的工作台专属数据库，库名固定，不与平台业务库混用                     |
| 平台业务库  | 项目侧平台已有的业务数据库，包含平台管理的一体机、智能屏、网关等业务对象                     |
| 项目会话   | 当前项目对应的平台登录状态；每个项目独立保存                                   |
| 待实施资产  | 已在当前电脑新增或导入、平台尚未注册的一体机                              |
| 已部署资产 | 已在平台注册的一体机；工作台是否保存部署历史不影响维护能力 |
| 导入批次   | 一次清单导入、校验、匹配和确认形成的数据集合                                   |
| 发布配置   | `.env`、`docker-compose.yml`、`host-info.json`三个模板，Agent及平台/MQTT/SSH/authKey等项目参数 |
| 本地镜像文件 | 当前电脑为本次操作选择的Docker镜像归档；不要求准备Release目录或manifest |
| 操作记录   | 项目共享的部署或升级历史摘要，不等同于完整执行日志或报告文件                           |

## 6. 产品级系统与数据职责

### 6.1 三层数据职责

| 数据层    | 保存内容                                          | 不保存内容                 |
| ------ | --------------------------------------------- | --------------------- |
| 本地实例   | 项目连接入口、登录会话、界面偏好、未注册一体机及编辑资料、导入预览、镜像位置、执行临时数据、服务检查、本机完整日志 | 已注册一体机的正式业务资料、共享发布配置 |
| 工作台项目库 | 部署模板、Agent替换、发布参数、部署成功后的设备结果关联、预期镜像和版本、操作结果、审计及执行锁 | 未注册的一体机清单、服务检查快照、导入预览、大型镜像、完整本机日志 |
| 平台业务库  | 平台既有业务对象、平台对象 ID、业务位置和平台侧在线状态                 | 工作台执行过程、工作台配置版本、工作台锁  |

一体机自身是运行事实来源，工作台在执行前和查看版本时可通过 SSH 或本地接口读取服务、镜像和运行状态。

### 6.2 数据来源优先级

不同问题使用不同事实来源，不能把所有字段压缩到一张“主表”后静默覆盖：

| 用户问题             | 事实来源                       |
| ---------------- | -------------------------- |
| 这是不是同一台一体机？      | 规范化后的 MAC                  |
| 平台中是否已经存在该一体机？   | 平台业务库                      |
| 平台当前显示在线还是离线？    | 平台业务库及其状态时间                |
| 本次能否执行部署升级？      | 实时数据库连接、项目会话、执行锁、SSH 和远端检查 |
| 上次由工作台发布了什么版本？   | 工作台项目库操作记录                 |
| 一体机当前实际运行什么镜像？   | 一体机远端实时检查                  |
| 当前项目使用什么模板和发布参数？ | 工作台项目库                     |
| 当前电脑能否提供目标镜像文件？  | 本地实例                       |

当“记录版本”和“一体机实际版本”不一致时，界面显示版本偏差，不自动用任一方覆盖另一方。

### 6.3 数据库直连决策

重构版工作台直接连接项目数据库服务器：

- 项目本地入口保存数据库主机、端口、账号、密码和平台业务库名。
- 工作台项目库使用固定库名，具体名称在技术方案中确定。
- 工作台读写自身项目库，并按已确认的数据边界读取平台业务库。
- 不要求项目平台为工作台新增保存配置、导入清单或部署历史等接口。
- 数据库连接失败时，项目业务功能不可使用。

工作台仍使用项目平台现有账号体系完成用户登录，不在产品层另建一套用户和角色。

## 7. 一体机身份与资产生命周期

### 7.1 唯一身份

一体机使用 MAC 作为项目内稳定身份：

- 匹配键为“项目 + 规范化 MAC”。
- MAC 比较时忽略大小写、冒号、短横线和空格。
- 已在平台登记的一体机，重新部署时保留平台中 MAC 的原有写法，继续使用同一条平台记录；不能因为冒号等写法不同而重复登记。平台存在多条相同 MAC 的记录时，部署检查提示先处理重复记录。
- 规范化结果必须是 12 位十六进制字符。
- IP、名称和位置可以变化，不作为唯一身份。
- 同一项目内出现重复 MAC 时，导入或保存必须阻止并提示冲突来源。
- 页面显示可统一格式化为 `AA:BB:CC:DD:EE:FF`，同时保留原始导入值用于问题定位。

### 7.2 部署状态

实施人员通过列表判断一体机是否已在当前平台注册，以及是否存在需要处理的资料问题。部署状态采用以下四种显示，不以工作台有无部署历史区分维护能力。

| 状态 | 判定规则 | 操作说明 |
| --- | --- | --- |
| 待实施 | 当前电脑有待实施清单，平台尚未注册 | 编辑资料、检查并进行首次部署 |
| 已部署 | 平台存在对应的一体机记录，且没有身份冲突 | 查看、编辑、检查服务及部署升级；执行前仍需通过既有检查 |
| 待处理 | 存在身份冲突、MAC 缺失、格式异常等资料问题 | 列表提示或详情显示具体原因，修正后刷新；异常节点不能被选择执行 |
| 待确认 | 当前资料不足或状态无法识别，不能明确判定 | 核实资料和刷新，不把未知状态推定为已部署 |

资料冲突优先显示“待处理”。“已部署”表示平台已注册，不等于当前在线、服务健康或最近一次操作成功；这些事实分别由平台状态、最近服务检查和任务结果展示。“待确认”不用于表示没有服务检查记录。

状态筛选和统计采用同一判定规则。“待处理”将可识别节点的冲突和平台异常记录统一分页展示，异常原因保留原始中文诊断。MAC 无效的记录只在待处理视图中列出，不计入可识别资产总数，也不能带入部署选择集。全部一体机、在线和离线的数量仍以可识别节点为范围。

从列表带入的部署目标按用户选择保留；未传入目标时，部署页默认选择最多四台无冲突且平台在线的已部署一体机，不区分工作台是否有历史记录。

### 7.3 导入与本机待实施清单

CSV 只作为导入介质：

1. 本机选择 CSV。
2. 工作台解析并校验字段。
3. 按 MAC 与当前电脑的待实施清单、平台业务库进行匹配。
4. 生成新增、已存在、重复和冲突预览。
5. 用户确认后，在同一次本机保存中更新待实施清单并结束导入预览，不向项目工作台库或平台业务库新增设备记录。
6. CSV 文件本身不成为后续资产事实来源。

### 7.4 首次导入和追加导入

首次导入和追加导入使用相同流程。追加导入不得创建第二套一体机主数据：

- 新 MAC：加入待实施资产。
- 本机待实施清单已有 MAC：显示已有资料和字段差异，不重复创建。
- 平台已有 MAC：不再导入为本机待实施记录；查看或修改资料时使用详情页面。
- 同 MAC 关键字段冲突：进入冲突处理，不静默覆盖。

### 7.5 已部署一体机维护

已在平台注册的一体机直接显示为“已部署”，无需额外接管。实施人员补齐当前项目发布参数、模板及 SSH 连接配置后，即可选择镜像、检查执行条件并按需要执行整包或单服升级。

工作台保留实际产生的操作记录和成功部署版本，不为平台已有设备补造历史。尚无工作台记录不会限制查看、编辑、服务检查和通过预检后的部署升级。

## 8. 项目、登录与切换

### 8.1 本地项目入口

本地项目入口至少包含：

- 项目名称。
- 项目平台访问地址，用于平台账号登录。
- 数据库主机和端口。
- 数据库账号和密码。
- MySQL TLS连接开关；默认关闭，目标数据库已配置TLS时由用户显式启用。
- 平台业务库名。
- 固定的工作台项目库名，只读展示。

新增或编辑项目时提供连接测试。TLS关闭时界面明确显示“连接未加密”，建议仅用于可信内网；启用后连接失败不得自动降级为明文。项目入口只解决“怎样进入项目”，不在本地复制项目清单和发布配置。

工作台会在项目切换和编辑时自动检查项目可用性。兼容时不显示结构版本、状态标签或手动检查入口；需要初始化、升级或存在不兼容时，才显示“工作台版本和平台表结构不兼容”及必要的处理操作。页面不向使用者展示当前版本、可用版本或其他底层结构细节。

### 8.2 项目登录

- 每个项目独立保存平台登录会话。
- 登录账号密码与项目侧平台后台管理使用同一套账号密码。
- 切换到从未登录、会话缺失或会话过期的项目时，必须重新登录。
- 切回仍具有有效会话的项目时，直接恢复项目工作区。
- 会话有效期服从平台已有认证规则，工作台不自行延长。
- 编辑平台地址或其他会影响认证身份的连接信息后，原项目会话失效。
- 工作台只新增本地项目会话管理，不要求平台新增工作台专用角色。

### 8.3 项目就绪条件

一个项目只有同时满足以下条件才进入业务工作区：

1. 本地项目连接配置完整。
2. 工作台项目库连接正常。
3. 平台业务库可读取。
4. 项目平台账号会话有效。

任一条件不满足时，左侧项目业务菜单禁用，并在主区域显示失败位置、原因和重新连接或登录入口。

智能屏和网关菜单首期显示“规划中”标记，不进入可操作页面，不展示模拟数据和不可用按钮。

左侧导航不再显示“业务功能”“后续能力”等分组说明。一体机管理作为可展开一级入口，三个业务页面作为二级入口；智能屏管理和网关管理与一体机管理同为一级入口。

## 10. 全局工作台设计

### 10.1 顶部项目区域

顶部左侧直接显示项目名称和连接状态，项目名称在应用栏内垂直居中，不再额外显示“当前项目”文字。点击后打开项目选择器：

- 查看本地已保存项目入口。
- 切换项目。
- 新增项目。
- 编辑当前项目连接。
- 删除本地项目入口；该操作不删除平台业务库和工作台项目库数据。

### 10.2 顶部全局功能

| 功能  | 作用范围                    |
| --- | ----------------------- |
| 任务  | 所有当前运行或近期任务，可按项目识别      |
| 设置  | 主题、字号、密度、减少动画、列表条数、工作台数据目录等本机偏好 |
| 关于  | 应用名、主要功能、版本、客户端标识符、本地数据目录和作者 |

客户端标识符用于定位发起操作的电脑，统一为`完整电脑名-MAC12位大写无分隔符-IP`，例如`LF-PC-001122AABBCC-192.168.3.142`。“关于”、导入、部署升级、发布参数修改审计及资源占用信息共用这一字符串。每次启动采集一次，本次运行保持一致；重启后重新采集。无需独立身份模型、注册表、本机序号或额外唯一键；同一电脑多开不再通过该标识区分进程。人员仍使用已有平台账号字段。MAC与IP取自同一网卡，缺失时直接显示`未知MAC`或`未联网`，历史记录保留当时保存的原字符串。

数据目录不是界面偏好字符串：

- 设置页展示Rust进程当前实际使用的数据目录。
- 用户可以选择“迁移当前数据后切换”或“使用新的空白目录”，均在退出并重新打开应用后生效。
- 迁移失败或目标目录非空时保持原目录，不覆盖目标内容；迁移成功后可明确回滚到上一目录。
- 存在活动任务时禁止登记切换或回滚。

### 10.3 底部状态栏与任务日志

状态栏必须展示真实状态：

- 数据库已连接、连接中或失败。
- 平台已登录、会话过期或未登录。
- 当前项目名称。
- 当前活动任务数。

点击最右侧“任务与日志”后，从底部向上展开非模态面板。面板标题栏直接提供“任务”“日志”切换，替换重复标题；完整交互遵循《01-桌面工作台界面设计规范》。

任务页可清空当前项目中已结束的本机任务记录；日志页可清空当前选中且已结束任务的本机日志。两项操作都需要确认，运行、排队、检查失败、最终补写，以及检查通过但尚未提交的预检任务不得清空。上传大文件时，日志展示开始、文件完成、整体完成或失败等关键节点，字节进度继续驱动执行页和任务面板进度条，但不逐条占用日志列表。

项目共享操作记录不等同于本机完整日志：其他工作台实例可以看到任务结果和失败摘要，但不保证读取另一台电脑上的完整原始日志。

## 11. 一体机列表

### 11.1 页面目标

一体机列表回答：项目中有哪些一体机、哪些在线、哪些已部署、服务是否正常、是否存在版本或数据冲突。

### 11.2 页面头部与摘要

页面头部只显示“一体机列表”和右侧操作，不重复显示“一体机管理”上下文标签，也不显示能够由列表直接理解的说明文字。右侧提供：

- `查看镜像和版本`。
- `导入清单`。
- `+ 新增一体机`：位于“导入清单”右侧，打开单台新增表单。

标题下方固定展示六张等高紧凑摘要卡：

- 一体机总数。
- 平台在线数。
- 平台离线数。
- 待实施数。
- 信息冲突数。
- 平台待处理记录数：平台一体机缺少有效 MAC 的记录不参与资产匹配；悬停卡片显示名称、IP、平台编号和当前 MAC，点击卡片筛选下方列表为这些待处理记录，并提示在平台补齐或修正后刷新。

摘要卡只让图标使用状态色，标签文字保持统一中性色；数字使用深灰主文字，口径说明放在数字同行。即使数量为 `0` 也保留卡片，避免筛选入口和页面布局跳动。

搜索和筛选工具栏不再重复显示“项目一体机”及总数。表头固定，滚动条只覆盖数据行区域。存在未处理导入批次时，优先提示继续处理批次。

### 11.3 表格字段

| 字段     | 说明                     |
| ------ | ---------------------- |
| 选择     | 位于名称左侧；表头勾选当前页可操作的一体机，每行可单独勾选 |
| 名称     | 工作台或平台显示名称             |
| IP     | 当前 SSH 和服务访问地址         |
| MAC 地址 | 稳定身份，使用统一格式显示          |
| 位置     | 平台业务位置或导入位置            |
| 部署状态   | 待实施、已部署、升级中、部分失败等工作台状态 |
| 平台状态   | 在线、离线、未知，并显示状态时间       |
| 最近服务检查 | 当前电脑的真实检查结果与整机检查时间；区分正常、异常、版本偏差、部分检查和检查失败 |

支持按名称、IP、MAC 搜索，按资产状态、部署状态和平台状态筛选。列表默认分页，必须支持 300 台级项目。

选择遵循以下规则：

- 表头全选只影响当前页可操作的记录；部分已选时显示半选状态，取消全选只取消当前页的选择。
- 翻页、搜索或筛选时保留已选一体机，并显示总已选数量；切换项目时清空选择，防止带入其他项目。
- 信息冲突和缺少有效身份的记录不能勾选；选中记录刷新后出现此类问题时，从选择中移除。
- 勾选框只负责选择，点击其他行内容仍可打开详情。
- 在底部“每页 N 条、共 M 条”右侧放置“批量操作”按钮。没有选择时禁用；点击后进入部署升级页，默认勾选刚才选择的有效一体机。
- 跳转只带入选择，不检查或执行设备命令。新操作仍默认“单服升级”，用户继续选择镜像、检查条件并确认执行。

### 11.4 行详情

点击行打开右侧检查器，展示：

- 工作台资产状态。
- 平台对象信息和关联 ID。
- 最近一次工作台操作。
- 平台共享的已部署镜像与当前电脑最近采集的实际镜像。
- 逐服务的运行/健康状态、实际镜像ID、检查时间、来源和原因；生效配置镜像不同时单独展示。
- “检查服务”只读任务入口，进度与日志进入底部任务面板。
- 数据冲突及处理入口。

详情只展示与当前一体机有关的信息，不在列表中塞入完整执行日志。

服务卡片标题区的检查状态使用无底色、无边框的图标及 `12px` 中性文字，所有结果采用同一布局：未检查或未知为灰色问号，正常为绿色勾，异常为红色叉，版本偏差为橙色感叹号，状态判定和文案沿用既有规则。状态仅展示结果，不提供点击或按钮式悬停效果；“检查服务”保留明确的操作按钮外观。

一体机详情与智能屏详情采用相同的 `min(640px, 94vw)` 抽屉宽度和紧凑内边距。资产信息按两列字段排列，每个字段的标签和值同行；服务卡片按两列排列，四个服务占两行。长镜像名称和其他长值单行省略，悬停可查看完整内容。

以 `1280×800`、标准字号、常规资产信息和四个服务时一屏查看完整详情为布局目标。服务较多、错误或差异信息较长、窗口较矮时保留内容区滚动；检查失败、版本差异、数据冲突及相应操作不因紧凑布局而隐藏或裁剪。

## 12. 清单导入、单台新增与匹配

### 12.1 支持字段

首期继续支持：

- 必填：名称、IP、MAC。
- 可选：建筑、区域、地址别名、楼层、位置、备注等项目字段。

最终模板列名和平台字段映射在技术方案及数据设计中固化。

### 12.2 导入流程

```text
选择文件
→ 解析与格式校验
→ MAC 规范化和重复检查
→ 匹配工作台项目库
→ 匹配平台业务库
→ 分类预览
→ 处理冲突
→ 确认写入工作台项目库
```

分类预览至少包含：

- 新增待实施。
- 工作台已存在，无变化。
- 工作台已存在，有字段变化。
- 平台已注册，使用详情查看或修改资料。
- 重复或格式错误。
- 信息冲突，需要处理。

用户确认前不修改项目共享数据。写入时使用配置版本校验，避免覆盖其他实例刚完成的修改。

### 12.3 单台新增一体机

实施人员无需准备 CSV 文件，也可以从一体机列表点击“+ 新增一体机”，在浮动表单中登记一台设备：

- 名称、IP、MAC 为必填项；空间位置、具体位置、备注为可选项。空间位置从项目空间树选择并保存编号，列表显示完整路径；具体位置填写机柜、门口等文字，与空间关联分开保存。
- 表单采用紧凑两列布局，标签、输入值与其他操作表单使用同一字号和常规字重。
- 确认新增时，使用与清单导入相同的字段校验、MAC 规范化、平台匹配、权限检查和资产保存规则。
- 全新 MAC 保存为本机待实施资产；平台已有相同 MAC 时提示已注册，使用详情编辑，不再重复新增。
- 工作台已有相同 MAC 时提示记录已存在，不重复新增，也不通过新增表单修改已有资产；字段冲突说明具体原因，不静默覆盖。
- 如果当前项目还有未处理的 CSV 导入预览，提示先完成或放弃该批次，保留原预览和选择。新增过程不能替换已有 CSV 批次。
- 保存成功后关闭表单并刷新列表与统计。未注册资料只保存在当前电脑；部署时使用该资料注册到平台。确认平台已有对应记录后，列表使用平台资料，并清理本机待实施记录。
- 删除本机项目时会同时删除该项目的本机待实施清单，确认提示应明确这一点；不删除平台已注册资料。

切换项目后关闭新增表单。旧项目的请求结果不得填入新项目页面；保存失败时保留表单内容并显示可处理的原因。

清单导入支持可选的“空间路径”列，格式与智能屏一致，例如“项目/一号楼/一层/办公区”。必须从项目根填写完整路径；不存在或匹配到多个空间时，该行不能应用。导入界面提供空白模板和当前项目中可唯一匹配的空间路径清单，预览表显示空间位置及校验问题。旧清单的英文名称、IP、MAC 列继续支持。

清单的“位置”列填写具体安装位置，不填写空间编号，也不从空间路径自动生成。

### 12.4 详情编辑

实施人员在一体机详情中点击“编辑资料”，可修改名称、IP、空间位置和具体位置；MAC 保持不变。未注册设备保存到当前电脑；已注册设备直接更新平台业务库，并在工作台专用库保留本次操作结果。保存失败保留输入内容并说明原因，不能用本机资料代替失败的平台保存。

本机一体机有排队、执行中或结果待核实的任务时，先处理该任务再编辑。已注册一体机被其他操作占用时，页面显示占用电脑，经用户确认接手后重新读取最新资料再保存。编辑不修改布点坐标、连接凭据、在线状态或心跳。部署取得占用后会复核最新资料，检查通过后修改了 IP 等信息的，必须重新检查。

## 13. 镜像和版本查看

### 13.1 页面入口

“镜像和版本”不是左侧独立一级菜单，从一体机列表头部进入弹窗、抽屉或专用视图。

### 13.2 展示内容

- 按服务聚合的记录镜像名和版本号。
- 各版本覆盖的一体机数量。
- 版本未知或尚未检查的一体机数量。
- 工作台记录版本与远端实际检查版本不一致的节点。
- 最近检查时间和检查来源。

平台侧只记录镜像名和版本号，不上传镜像文件。实际镜像文件始终由执行操作的本地实例选择。

## 14. 发布参数

### 14.1 页面目标

发布参数页统一维护当前项目部署升级需要的共享配置。页面头部只显示“发布参数”、同行的校验状态/最后修改信息/凭据可见提示，以及右侧版本和编辑操作；不显示重复业务眉题和开发过程风险说明。

### 14.2 配置内容

#### 配置模板

- 当前环境使用的 `.env`、`docker-compose.yml` 和 `host-info.json` 三份模板；新建配置时均提供内置内容。
- 内置 `.env` 和 Compose 内容对应工程已有 `test/templates/env.template`、`test/docker-compose.yml` 中的标准一体机部署配置，凭据仍从发布参数填写，不写死在模板中。
- 已保存的项目模板优先使用原内容，打开、编辑或取消编辑不会被内置模板覆盖。
- 模板支持直接编辑、校验和保存。
- 保存后其他工作台实例读取同一版本。

保存和显式校验时必须解析Compose YAML，检查`services`、服务名、每个服务的`image`变量、`.env`变量引用、重复变量、宿主机端口以及三个模板占位符。`host-info.json`使用样例值渲染后必须是JSON对象，`mac`、`ip`、`hostname`、`authKey`必须分别引用对应节点/项目变量。任一问题都定位到对应模板，禁止保存。

#### 发布参数

- 平台 IP 或域名。
- 平台 API 地址。
- 平台 API AuthKey。
- 平台 MQTT 主机和端口。
- 平台 MQTT 账号和密码。
- 一体机 MQTT 账号和密码。
- SSH 用户名。
- SSH 密码，可选；与SSH私钥至少填写一项。
- SSH 私钥，可选；与SSH密码至少填写一项。
- SSH 超时、远端目录等经产品评审确认的必要参数。

数据根目录默认值为`/opt/data`，部署根目录默认值为`/opt/data/deploy`。部署根目录保存可切换的发布版本、`.env`和`docker-compose.yml`，不与一体机业务数据目录混用。

“远端目录”下方展示当前生效的一体机脚本名称、版本和来源，并提供“更换”“查看”操作。默认使用工作台内置脚本，不向项目库保存重复副本；用户确认更换后，经过校验的脚本内容、版本、协议和SHA-256保存到当前项目的`inxaiot_desk_buddy`，其他工作台实例读取并使用同一脚本。更换前必须二次确认，明确提示非必要情况下不要更换，并要求脚本已经过充分验证。查看操作使用系统文本编辑器打开当前生效脚本，不在工作台内建设代码高亮编辑器。

页面采用“项目发布参数 + 部署模板”左右布局，参数区略宽。参数标签和输入框同行，标签右对齐、输入内容左对齐；默认窗口和紧凑密度下不应因表单排版产生页面滚动。

人工回归确认：点击“校验配置”或“保存配置”发现缺失或格式错误时，对应输入框标红并在下方说明原因，不能只给出“参数或凭据不完整”的总提示。一次展示所有已确定的字段错误；SSH密码与私钥均为空时同时标记，仍保持至少填写一项的既有规则。模板错误标记对应编辑框并切到出错模板。修改字段后清除该字段的旧提示，重新校验确认结果；修改已通过校验的内容后，不再显示旧的“校验通过”。

### 14.3 凭据可见性

首期不设计角色和字段脱敏：

- 所有完成项目登录的工具使用人均可查看和编辑完整值。
- 密码、AuthKey、SSH 和 MQTT 凭据允许通过界面查看。
- 不针对不同账号隐藏部分配置。

发布凭据写入工作台项目库时加密保存，不提供“项目接管密钥”、口令包或密钥导入导出操作。该机制用于避免凭据以明文方式存放，不能替代项目登录、数据库账号和可信内网访问控制；已采用旧格式保存的测试配置需要在发布参数页重新填写。

凭据怎样存储以及如何避免进入日志，由技术方案设计；该技术安全设计不能改变“首期所有登录用户均可查看”的产品结论。

### 14.4 配置并发

发布参数和模板使用版本校验：

- 打开编辑时读取当前版本。
- 保存时提交所基于的版本。
- 版本未变化时保存并产生新版本。
- 版本已被其他实例更新时拒绝静默覆盖，提示修改人和更新时间。
- 用户重新加载最新内容后再编辑；首期不提供无条件强制覆盖。

## 15. 部署升级

### 15.1 支持模式

打开部署升级页新建操作时，默认选择“单服升级”。用户可以切换首次部署或整包升级；恢复已有任务时仍展示该任务原来的模式。

| 模式   | 适用对象               | 本地输入              | 核心行为                         |
| ---- | ------------------ | ----------------- | ---------------------------- |
| 首次部署 | 待实施或确认重装的一体机       | Compose中全部服务的镜像文件和标签 | 一体机还没有部署过软件时，第一次部署整体软件包：渲染共享配置、自动生成内部发布包、加载镜像、启动服务、平台注册和检查 |
| 整包升级 | 已部署的一体机 | Compose中全部服务的镜像文件和标签 | 一体机已部署过软件，调整过docker-compose或环境变量等时，备份必要配置、应用共享模板和多个镜像、重建服务、检查结果 |
| 单服升级 | 已部署且目标服务存在的一体机 | 单个镜像文件、服务名、镜像名和版本 | 单服务镜像升级，只升级对应服务的镜像包、更新目标变量、重建并检查目标服务 |

### 15.2 简化流程

原工作台的预检、渲染、执行、注册、检查和报告步骤收敛为：

```text
1. 选择
   模式、目标范围、按Compose服务选择本地镜像并确认RepoTag、批次和并发参数

2. 检查
   项目配置、执行锁、目标状态、SSH、Docker/Compose、模板、发布文件和渲染结果

3. 部署/升级
   上传、远端执行、服务检查；首次部署和需要时完成平台注册

4. 结果
   展示成功、部分成功和失败节点，自动写入项目操作记录
```

不再增加“生成报告”步骤，也不生成 summary CSV 和 detail JSONL 报告。

### 15.3 选择阶段

用户需要确认：

- 部署模式。
- 目标一体机范围。
- 批次名称，可自动生成并允许修改。
- 一批台数和并发数；必须满足`并发数 ≤ 一批台数 ≤ 已选目标数`，同时一批最多20台、并发最多5台。
- 首次部署和整包升级为Compose中的每个服务选择一个镜像文件并确认完整镜像标签。
- 单服升级从Compose服务列表选择一个服务，再选择该服务的镜像文件和标签。
- 目标选择区提供“选择全部”“选择全部在线”和“清空”；节点列表填满可用高度，不保留无意义底部空白。

部署模式和四阶段步骤条合并在同一横向区域：左侧以“部署模式”与三行单选项展示首次部署、整包升级、单服升级，右侧四个阶段等宽分布；模式选项上下留白收紧，组合区域整体高度约`64px`。选择阶段下方约`55:45`分配目标列表和本次执行设置，收窄节点搜索框，为镜像配置保留更多宽度。目标一体机按选择框、名称、IP、位置和状态单行分列显示，缩短单行高度以增加同屏节点数。每个服务的镜像文件和镜像标签同行展示，镜像设置区不使用独立纵向滚动条；大量节点只在目标列表内部滚动。

镜像文件不上平台。项目参数和三个模板已共享，换电脑后只需准备本次需要的镜像文件。每个服务只能选择包含一个逻辑镜像的tar；如果tar中包含多个镜像，直接提示“只能选择单镜像Tar，请重新导出镜像”。单个镜像可以有多个RepoTag，用户通过选择入口切换；只有这个单镜像没有RepoTag时才允许手工填写目标标签。

### 15.4 检查阶段

2026-09-02现场确认：用户只查看业务结果，不把内部技术保护逐条展开。检查页固定按以下层级显示：

- 公共检查：镜像文件、RepoTag与Compose服务是否逐项一致；发布参数、三个模板及平台API/MQTT地址和连通性。
- 每台一体机单独一组，以名称和IP识别：连通性（SSH连接、登录验证及一体机到平台API/MQTT）；环境准备（系统、Docker服务、Docker Compose、数据/部署目录可写、剩余空间和服务端口）。

用户通过页面输入校验并发起“检查执行条件”后，工作台为本次检查创建一条独立的本地预检任务。检查页与任务面板显示同一套“已完成事项 / 总事项”和进度条。首次部署、整包升级的总事项数为`3 + 2N`，单服升级为`3 + N`，其中固定三项依次为检查参数、检查镜像和检查批次，`N`为本次实际目标一体机数量；首次部署和整包升级还要为每台一体机分别完成远端条件检查和模板渲染，单服升级不渲染整套模板，只为每台计算远端条件检查。

一个事项开始时，页面必须立即更新当前事项文案并让进度条保持动态运行；只有收到该事项的真实完成结果后才增加完成数和确定百分比。不得用定时器、预估时长或固定步进制造假进度。公共三项属于任务级事项，不得以内部目标的方式计入目标一体机数量。每个逻辑事项的结果和具体失败原因写入本地任务日志；事项开始可以使用瞬时事件，SSH、Docker、目录、空间和端口等内部子探针汇总到对应一体机的远端条件事项，不逐探针刷日志。

预检任务只记录在发起检查的本机，不创建项目共享操作记录，也不申请资源租约。检查通过时，后端把执行快照摘要绑定到本地预检任务；用户提交后直接使用该快照创建部署任务，不再重复检查发布参数、镜像归档、批次、逐台远端环境或模板渲染结果。提交只校验预检任务属于当前项目且已通过、目标集合一致、快照摘要一致并且尚未被提交，这些本地一致性校验不读取镜像、不连接一体机。部署工作线程随后只为实际上传生成不可变镜像快照和节点配置文件，不把这一制品生成过程包装成第二次预检。

数据目录、空间和服务端口检查沿用Go老版实际能力并合并到“环境准备”，不新增独立卡片。初装检查服务端口占用；升级允许已有服务占用端口。每组只显示上述两项，成功用简短摘要；失败直接以警告色展示具体原因及处理入口，不再额外显示“请处理以下问题后重新检查”这类重复说明。未执行的后续检查显示“未检查”，不能假成功。一台异常不改变另一台已完成的检查结果。

整包升级和单服升级必须在上传前检查目标一体机的当前发布基线。整包升级要求部署根目录下的`current`可解析为现存目录，并包含`docker-compose.yml`、`.env`、`manifest.json`，同时数据根目录下存在`config/host-info.json`；单服升级要求有效`current`及其中的`docker-compose.yml`、`.env`。当前版本不存在或链接失效时直接阻断并提示“当前一体机尚未完成首次部署，请选择首次部署”。首次部署不要求存在`current`。

进一步交互确认：结果使用紧凑分组列表，不使用卡片。公共组及每台一体机的组名前放通过/不通过两态图标，组内不再放状态图标；分组名加粗，检查项名称使用黑色常规字重，以区分层级。通过组默认折叠，不通过组默认展开，用户可点击组名手动切换；重新检查后按新结果重置默认展开状态。检查未完成不得标为通过；已完整完成且仅有非阻断提示的组仍为通过，折叠行保留“有提示”文字，不新增第三种状态。折叠时不挂载内部检查项，适应数百台节点的一次检查。

项目数据库连接、Schema初始化/升级和登录状态应在登录/切换项目时检查并提示；未就绪不得开放业务入口，不在部署页重复列项。平台会话、资源租约、主机指纹、CPU架构不作为独立用户检查项。内部登录授权、资产一致性、互斥与发布物/环境兼容性保护保留，异常用业务语言提示；指纹自动观测，变化只作连接提示，不阻断或增加操作步骤。

检查阶段必须用当前发布参数和每台目标一体机的真实字段完整渲染`.env`、`docker-compose.yml`和`host-info.json`并校验格式；渲染失败时不得开始上传。目标服务存在性及执行前状态重新确认仍由执行链负责，不得把没有真实探测的内容预先标为通过。

### 15.5 执行阶段

- 当前模式、阶段、总体百分比、已形成最终结果数量和“执行中”状态合并在同一执行概览区；总体进度条位于状态标签之前，不拆成重复卡片。
- 总体百分比和完成数直接读取部署任务的目标进度，不由页面按时间估算。任务事件到达时立即刷新，页面同时保留`5秒`轮询作为事件遗漏和后台恢复的兜底；两条路径读取同一任务事实。
- 进入部署/升级阶段后继续显示进度条；当前上传、执行或服务检查事项开始时更新阶段文案和动态状态，后台形成真实进度后再更新确定百分比，不允许以定时动画替代实际任务进度。
- 后台工作线程取得任务后立即结束“排队中”并进入“准备发布文件”。本地准备占总体进度前`10%`，依次反馈配置读取、镜像快照复制、内部发布包生成和逐台配置渲染；镜像复制与发布包生成按真实处理字节推进。远端连接、上传、执行和服务检查映射到剩余`90%`，全过程百分比只能单调前进。准备过程及失败原因同时写入本机任务日志。
- 按一批台数和并发数调度。
- 每台一体机独立展示当前阶段和结果。
- 失败节点不阻止其他独立节点继续，但可能影响同一批次最终状态。
- 用户可以查看当前节点日志和失败原因。
- Agent返回结构化失败事件时，结果页和任务错误直接显示经过脱敏的具体原因；不能只显示退出码并要求用户在原始日志中查找。已失败目标从本机失败步骤读取同一原因。
- 取消操作停止派发新节点；已进入远端不可中断步骤的节点在安全边界结束。
- 首次部署完成后按 MAC 关联平台对象。
- 单服升级只影响目标服务，不全量停启其他服务。
- Docker未配置Healthcheck的服务继续以容器处于running为通过；配置了Healthcheck的服务必须在限定等待时间内变为healthy。持续starting或unhealthy按部署失败处理并进入现有回滚，回滚后的旧服务也允许在同一期限内恢复健康。

### 15.6 结果阶段

结果分为：

- 全部成功。
- 部分成功。
- 全部失败。
- 已取消。
- 应用异常中断。

页面直接显示失败节点、失败阶段、原因摘要和重试入口。完成后自动写入操作记录，不要求用户额外点击“生成报告”。

如果一体机上的部署已经完成，但当时项目工作台数据库暂时不可用，本机任务保留已经形成的最终结果并显示“结果待补写”。数据库恢复后，用户可在任务日志页点击“补写结果”，该操作只补写记录，不重新连接一体机或重复部署。原执行锁只是超时且没有被其他任务接管时可直接补写；检测到另一台电脑或另一项任务已经接管时，工作台必须先展示占用电脑和任务，再由用户线下确认并明确同意“强制接管并补写”。未经确认不得抢占；已经结束的较新任务不得被旧结果覆盖。

首次部署和整包升级成功后，项目共享的服务版本清单以本次生效Compose为完整事实：新增服务写入，已从Compose删除的服务同步移除。部署失败不改变原清单；单服升级只更新目标服务，不删除其他服务。

四阶段步骤条进入最终结果后不再显示蓝色步骤编号：全部成功显示绿色勾，部分成功、失败、取消或中断显示警告色图标，使步骤状态与最终结果一致。

## 16. 操作历史

### 16.1 入口

部署升级页面提供“查看历史记录”入口。历史记录不占用左侧一级菜单。历史行整体可点击，右侧箭头进入详情；详情展示操作摘要、执行范围和节点最终结果，并提供返回历史列表入口。

### 16.2 记录内容

项目共享操作记录至少包含：

- 项目。
- 操作类型。
- 批次名称。
- 操作用户。
- 发起工作台实例标识。
- 开始和结束时间。
- 目标 MAC 范围和数量。
- 镜像名和版本号。
- 成功、失败和取消数量。
- 每个节点的最终状态和失败摘要。

完整命令输出和连续日志主要保存在发起操作的本地实例，不强制上传项目数据库。

### 16.3 历史原则

- 记录一旦完成不得被普通配置编辑覆盖。
- 已在平台存在但没有工作台历史的一体机显示“无工作台历史”。
- 不根据当前平台状态反向伪造历史结果。
- 历史用于查询和追踪，不提供旧版报告导出功能。

## 17. 多实例并发与冲突

不同类型操作采用不同并发策略，不能用一个永久锁解决全部问题。

### 17.1 配置编辑：乐观版本控制

适用于：

- 发布参数。
- `.env` 模板。
- `docker-compose.yml`。
- `host-info.json`模板。
- 一体机可编辑信息。
- 项目共享设置。

保存时检查版本。发生冲突时拒绝静默覆盖，提示重新加载。

### 17.2 部署执行：带租期的独占锁

适用于首次部署、整包升级和单服升级：

- 每个目标一体机在同一时间只能参与一个具有写影响的执行任务。
- 批量任务按目标 MAC 获取执行锁，不使用阻止整个项目的单一大锁。
- 锁记录操作类型、持有人、工作台实例、开始时间、最近心跳和过期时间。
- 执行期间工作台续租。
- 工作台崩溃、断网或长时间无心跳后，锁到期释放，避免永久死锁。
- 其他用户仍可查看被锁对象和执行状态，但不能发起重叠操作。
- 正常部署执行期间不提供未过期锁的强制抢占。只有远端工作已经结束、正在补写最终结果时，检测到其他任务接管后才提供人工确认的强制接管。

### 17.3 用户可见反馈

当对象被占用时，界面显示：

- 正在执行的操作类型。
- 操作用户或实例。
- 开始时间。
- 当前阶段。
- 是否仍有有效心跳。

不得只提示模糊的“对象已锁定”。

## 18. 状态模型

### 18.1 项目状态

| 状态   | 含义                  |
| ---- | ------------------- |
| 未配置  | 本地项目连接信息不完整         |
| 连接中  | 正在检查工作台库和平台业务库      |
| 需要登录 | 数据库可用，但当前项目没有有效平台会话 |
| 已就绪  | 数据库和项目会话均可用         |
| 连接失败 | 数据库、网络或权限异常         |
| 会话过期 | 平台认证失效，需要重新登录       |

### 18.2 一体机部署状态

| 状态     | 含义                    |
| ------ | --------------------- |
| 待实施    | 尚未完成首次部署              |
| 检查中    | 正在检查执行条件              |
| 检查失败   | 存在阻止执行的问题             |
| 可执行    | 最近一次检查通过，执行前仍会确认状态未变化 |
| 部署/升级中 | 远端任务正在执行              |
| 已部署    | 最近一次首次部署成功            |
| 已升级    | 最近一次升级成功              |
| 部分失败   | 批次或节点子步骤部分成功          |
| 执行失败   | 远端执行未完成目标             |
| 状态未知   | 没有工作台历史或实时检查失败        |

旧版“已预检”“配置已渲染”等内部过程状态不作为一体机列表的长期主状态，只在当前任务详情中展示。

### 18.3 服务状态

服务检查是当前电脑最近一次实际观测，不是实时监控。检查快照和尝试记录只保存在本机SQLite，按项目与MAC隔离，不新增平台`aio_node_service_check`表。换电脑后显示“无检查记录”，需要查看时发起只读检查；平台仍共享发布配置、已部署版本和部署/升级操作结果。

- 所有生效服务都有正常观测：绿色“4项正常”；仅时间经过不会自动变为警告，取消原15分钟失效告警。
- 实际容器停止/缺失或配置了健康检查但未通过：明确“X项异常”；实际镜像与一体机生效配置不符：显示“X项版本不符”。
- 只检查过部分服务：中性“已检查X/Y项”；没有记录：中性“无检查记录”。
- SSH、配置或容器信息获取失败：显示“检查失败”和本次失败原因，保留上次逐服务结果与时间，不能把获取失败算成全部服务异常。
- 服务集合来自目标一体机已经生效的Compose；尚未下发的项目模板变化不影响现有服务统计。详情和版本分布排除已不在生效集合中的旧服务。
- 整机检查时间仅由完整采集更新；单服升级只更新目标服务，其他服务时间不变。分别检查过全部服务可以汇总正常，但不能冒充同一时间的整机检查。
- 首次部署/整包升级在既有健康步骤中复用实际采集结果；单服升级仅采集对应服务。不得把计划镜像直接当实测镜像，不再为刷新列表重复远端健康检查。
- 手动“检查服务”通过本机任务队列只读获取当前容器与镜像，并保存本机结果；普通刷新列表或版本记录不触发远端检查。检查正在部署的目标时提示等待完成，避免把部署中间状态记为异常。
- 升级失败与回滚后服务状态分别保留：任务仍是升级失败，真实采集成功后可以显示“回滚后检查正常”。默认内嵌Agent在升级前记录旧容器的实际镜像ID；即使新旧版本使用同一个标签，回滚也必须恢复旧ID并核对旧容器实际镜像。整包新host-info先写入同目录候选文件，镜像全部加载且旧服务成功停止后才生效；后续失败先恢复旧host-info，再启动旧服务。观测解析、缓存或保存失败不篡改部署原执行结果。

检查时间统一存UTC，按既有`YYYY-MM-DD HH:mm:ss`格式显示，整机与单服务时间分别标明。任务详情、进度和完整日志仍只保存在发起任务的电脑。

- 检查中。
- 检查失败。
- 等待执行。
- 执行中。
- 取消中。

## 19. 连接异常与降级

### 19.1 项目不可连接

工作台项目库或平台业务库连接失败时：

- 项目业务菜单不可使用。
- 不基于本地旧缓存继续编辑共享数据。
- 不允许新建部署升级任务。
- 可以查看本机设置、关于和本机已有日志。
- 页面提供重新连接和检查连接配置入口。

平台登录服务不可用或会话无效时，同样不进入项目业务功能。

### 19.2 执行中断连

执行过程中如果项目数据库连接丢失：

- 不再派发新的目标节点。
- 已进入远端原子步骤的节点在安全边界结束。
- 工作台持续尝试恢复连接和执行锁租期。
- 无法恢复时将本机任务标记为中断，并保留本机日志。
- 恢复连接后根据项目记录、锁和远端实际状态决定重试，不自动假设失败或成功。

具体超时、续租和恢复算法由技术方案设计。

## 20. 本地镜像与平台元数据

### 20.1 本地保存

- 镜像tar只在发起操作的本地电脑使用。
- 工作台项目库不保存二进制发布文件。
- 工作台不提供平台制品上传、下载和分发功能。
- 本地最近使用路径可以作为本机偏好保存，但不共享给其他实例。
- 用户不准备Release目录、`manifest.json`、校验清单或模板副本；工作台在任务目录中自动生成内部清单、校验文件和发布包，任务终态后按制品策略清理。

### 20.2 项目记录

项目侧只记录实施人员确认的镜像名和版本号，以及对应操作历史。其他实例看到历史版本后，仍需自行选择本地文件并通过检查才能再次执行。

## 24. 产品验收标准

### 24.1 项目与共享数据

- 两台电脑连接同一项目后读取相同发布参数、模板和一体机关系。
- 任一实例保存共享配置后，另一实例刷新可以看到新版本。
- 两个实例同时编辑同一配置时，后保存者收到版本冲突，不静默覆盖。
- 切换项目时，各项目登录会话互不影响。
- 未登录、会话过期或数据库连接失败时，项目业务功能不可进入。

### 24.2 一体机资产

- 同一项目按规范化 MAC 唯一识别一体机。
- 首次导入能够区分新增、已存在、平台既有和冲突对象。
- 追加导入不会为已有 MAC 创建重复资产。
- 平台既有一体机可以在补齐发布参数并通过远程检查后完成接管。
- 没有旧工作台历史的一体机明确显示“无工作台历史”。
- 300 台一体机列表可以搜索、筛选、分页和查看详情。
- 表头选择仅作用于当前页有效记录，跨页和筛选保留选择，切换项目清空，冲突行不能勾选。
- 点击“批量操作”后，部署升级页仅预选所带入的有效目标，不额外选择其他一体机，也不自动发起检查或执行。
- 单台新增必须填写名称、IP、MAC；非法格式、已有工作台资产和字段冲突不能绕过清单导入规则保存。
- 单台新增与 CSV 导入产生相同的最终资产效果；已有 CSV 预览、其选择和冲突信息不被新增操作覆盖。

### 24.3 部署升级

- 首次部署、整包升级和单服升级均使用四阶段简化流程。
- 首次部署和整包升级的服务列表来自当前项目Compose，不使用工作台内置服务白名单。
- 未配置或无法解析Compose、镜像选择不完整、RepoTag不匹配、模板无法按节点渲染时，在上传前阻断并指出具体问题。
- 检查阶段可以一次看到所有阻断问题。
- “检查执行条件”产生独立本地预检任务，进度按已完成目标数从`0 / N`推进到`N / N`；公共检查、节点分组结果和失败原因可在任务与日志中追溯，组内技术探针不逐条刷日志。
- 预检任务不产生项目共享操作记录或资源租约；检查通过后直接复用已绑定的执行快照创建部署任务，不执行第二次完整预检。
- 创建任务期间显示“正在创建部署任务”；取得真实任务后立即进入部署/升级页，避免额外等待和虚假的`0% / 0台`。
- 部署/升级页面显示的百分比和完成数与真实任务目标一致，任务事件驱动刷新，并由`5秒`轮询兜底。
- 单服升级只重建目标服务。
- 目标 MAC 已被其他任务锁定时，新的重叠任务不能执行，并显示占用信息。
- 执行完成后自动生成项目操作记录，不要求生成报告。
- 本地镜像文件不会上传数据库或平台。
- 其他实例可以看到镜像名、版本和结果，但不会获得本机发布文件和完整日志。

### 24.4 既有项目接管

- 不导入原工作台 SQLite 和历史文件，也能从平台业务库读取已存在的一体机。
- 补齐发布参数、SSH 信息并完成实时检查后，可以选择本地镜像执行单服升级。
- 本次操作作为新工作台第一条历史记录保存。

### 24.5 界面与占位模块

- 顶部项目、左侧业务、底部状态和任务日志职责清晰。
- 智能屏和网关菜单明确显示规划中，不出现误导性可用功能。
- 页面头部无重复眉题和说明；一体机摘要、发布参数表单、部署步骤和执行进度在默认窗口内保持紧凑清晰。
- 表格滚动条只覆盖数据行，悬停显隐不引起内容宽度变化；固定表头与数据列严格对齐。
- 一体机详情与智能屏详情宽度和字段样式一致，资产字段及服务卡片各自按两列排列；长值可查看完整内容，常规窗口核对首屏完整性，多服务或较矮窗口保留滚动并可访问全部异常信息和操作。
- 底部活动面板在标题栏直接切换任务和日志，展开后不遮挡状态栏。
- 连接失败、登录失效、配置冲突、对象锁定和部分成功均有明确文案和下一步。

### 24.6 本机数据与诊断

- 从空白安装通过设置页选择数据目录，重启后SQLite、应用日志、任务日志和任务临时制品的实际路径与界面一致。
- 任务日志与Release副本、Agent、payload和明文渲染文件物理分目录；任务进入安全终态后立即删除临时制品，日志按成功/取消30天、失败/中断90天策略保留并清理。
- 关于页显示应用名、主要功能、版本、客户端标识符、本地数据目录和作者；不展示开发阶段、源码提交、Schema、Agent、运行平台或本机凭据维护等内部信息。
- 所有可见按钮必须有有效动作、明确禁用原因，或作为已标注的确认框/弹出框触发器。

## 25. 已确认产品决策

| 主题       | 结论                       |
| -------- | ------------------------ |
| 一体机稳定身份  | 使用 MAC，项目内按规范化 MAC 唯一    |
| 项目数据访问   | 工作台直接连接数据库，不依赖新增平台服务接口   |

| 部署模板 | `.env`、Compose和host-info按项目保存到工作台项目库，跨电脑复用 |
| 大型镜像 | 仅本地使用，不上传平台              |
| 平台版本记录   | 只记录镜像名和版本号               |

| 项目不可连接   | 项目业务功能基本不可用，只保留本机全局能力和日志 |
| 旧数据迁移    | 不迁移原工作台本地项目和历史           |
| 已部署项目 | 可从平台读取一体机，补齐参数并检查后执行升级 |
| 智能屏和网关   | 首期只保留规划中菜单               |
| 报告       | 取消报告步骤，以操作历史替代           |
