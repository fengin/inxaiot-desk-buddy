# 智能屏资料展示与版本注册回归

日期：2026-10-23。适用工程：`inxaiot-desk-buddy`（实施工作台桌面程序）。归属版本：0.2.14 修订构建；交付以本次标签对应的 GitHub 流水线和发布产物为准。

## 业务范围

实施人员在本机修改已注册屏资料后，主列表和详情应显示相同的待提交值，实际变化字段显示橙色。通过“注册/更新到平台”核对时，小新版本差异也应列入预览；确认提交并完成平台回读后，平台资料与本机展示一致。

本轮只修改工作台。生产数据目录不参与测试，屏端小新应用和服务端没有改动。

## 已实现规则

- 详情的名称、IP、MAC、尺寸、空间和位置使用与列表相同的草稿投影。未编辑项跟随平台最新值；清空、改回原值、放弃修改或平台差异收敛时，颜色与提示同步更新。
- 详情中的平台状态、设备观测和实际维护目标仍使用已确认记录。IP 有待提交差异时保留原地址说明，不把原地址的检查结果当作新地址已通过检查。
- 注册预览增加“小新版本”的平台值、本次拟更新值和核对说明。只有版本变化时也可确认提交；应用版本不开放为可手填的资料草稿字段。
- 历史版本差异仅触发设备重新读取。拟提交版本需要核对当前目标 IP、MAC、安装状态、应用包名、版本名称和数字版本号。旧 IP 观测不能使用；最新卸载或没有读到版本的记录不回退采用更旧的版本。
- 没有版本候选的普通资料更新保留离线能力。版本核对失败时不写历史版本；存在其他有效资料差异时可只提交资料，没有其他差异时提示重新核对。
- 资料与已核实版本在同一平台事务中保存。保存前再次核对设备与平台原值，版本冲突不能留下部分资料更新。回读中断后按原请求核实，必须同时匹配资料和版本，不重复执行设备读取或平台写入。
- 平台在线状态和 H5 样式版本保持原用途；没有拟提交应用版本的新登记保留平台字段默认值。旧注册预览和旧注册任务未包含版本写入意图时，不隐式写入应用版本。

## 后端与隔离数据库验证

Rust 智能屏库单元测试 **140 项通过**，覆盖本轮注册规则及已有资料、设备检查、应用配置、主屏、校时和 NTP 规则。现有实机注册测试已同步版本契约并完成定向编译，本轮未执行该整套实机用例。

新增 Rust 测试文件 `src-tauri/tests/smart_screen_registration_version_real.rs` 在 192.168.3.142 上运行 **1 个真实 SQL 专项测试，包含 10 类验证分支，全部通过**。使用随机命名的两套临时数据库、自建最小测试表、临时本机目录和合成设备观测；没有连接真实屏或平台 HTTP，也没有复制生产行。结束后两套临时库均已删除。

验证包括：只有版本变化时可提交、带后缀的版本名称完整保留、相同版本不重复更新、读取失败时保留普通资料更新、平台原版本冲突时资料回滚、新登记保存已确认版本、无确认版本时保留数据库默认值、回读中断后正确核实、版本不匹配时拒绝假报成功、恢复过程不重新读取设备。

本机证据文件：

- `rust-smart-screen-unit.log`：140 项库测试结果。
- `registration-version-sql-auth-corrected.log`：真实 SQL 专项通过及两套临时库清理结果。
- `rust-registration-existing-compile.log`：既有实机注册测试定向编译结果。

复验命令在工作台工程执行；Rust 命令在 `src-tauri` 目录执行，并设置 `CARGO_INCREMENTAL=0`：

```powershell
npm run build
cargo test --offline --lib smart_screen::
cargo test --offline --test smart_screen_registration_real --no-run
```

真实 SQL 专项默认忽略，只有明确使用授权 142 测试环境并设置环境变量 `INX_SCREEN_REGISTRATION_VERSION_SQL=YES` 时，才可运行 `cargo test --offline --test smart_screen_registration_version_real -- --ignored --nocapture`。连接信息读取已有测试说明，不在报告中复制凭据。
