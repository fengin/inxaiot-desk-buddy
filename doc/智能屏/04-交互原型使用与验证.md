# 智能屏交互原型使用与验证

> 状态：已实现开发预览原型；真实数据库与设备能力尚未接入
> 更新日期：2026-09-28
> 适用对象：项目负责人、实施人员、产品及开发人员，通过实际点击核对需求
> 所属工程：`inxaiot-desk-buddy`（INX 实施工作台）
> 需求依据：[运维管理需求](01-智能屏运维管理需求设计.md)、[界面逻辑流程](03-屏管理界面逻辑流程图.md)

## 1. 打开原型

界面核对优先使用桌面开发窗口。在工作台工程目录执行：

```powershell
pnpm dev:desktop:screen
```

也可执行 `npm run dev:desktop:screen`。命令自动启动 1421 端口的前端服务、编译并打开 Tauri 桌面开发窗口，默认显示“智能屏列表”。首次使用需安装项目依赖，并具备 Rust 和 Windows 桌面构建环境。修改 Vue、CSS、文案和前端交互后通过 Vite 热更新显示；修改 Rust 时会重新编译并重启桌面程序。

桌面原型的项目、设备、配置与任务等业务均使用模拟适配器，不连接真实项目平台或设备。窗口最小化、关闭等桌面操作仍由 Tauri 提供。专用应用标识为 `com.inxaiot.desk-buddy.screenprototype`，Windows 默认数据目录为 `%APPDATA%\com.inxaiot.desk-buddy.screenprototype`，与正式工作台隔离；该目录仅供原型开发，不导入正式数据库或正式数据目录切换配置。

需要浏览器预览时，启动前端开发服务：

```powershell
pnpm dev
```

打开[智能屏列表预览](http://127.0.0.1:1420/#/screen/nodes)。左侧“智能屏管理”提供“智能屏列表”和“智能屏操作”。页面沿用当前工作台的项目切换、导航、主题、字号、密度和任务日志框架。

原型只在开发浏览器模式和上述专用桌面启动方式中开放。普通 `pnpm tauri dev` 使用真实业务适配器，不开放智能屏原型；正式生产构建同样不装配智能屏模拟适配器。界面中的平台、设备和执行结果全部是演示数据。

浏览器预览使用 1420 端口，桌面原型使用 1421 端口，可分别运行。若端口已占用，应先确认对应开发进程；不要结束正在执行真实业务的桌面应用。关闭原型后，可在启动命令所在终端停止开发服务。

## 2. 可体验的交互

| 功能 | 原型行为 |
| --- | --- |
| 项目总览 | 按“管理记录 → 平台已注册 → 平台未注册 → 平台在线 → 平台离线 → 疑似重复”排列；初始 21 条平台资产、6 条本机记录，“平台未注册”仅统计当前电脑尚未关联平台的记录；在线/离线与未注册分别统计，疑似重复未确认前不自动扣数 |
| 查询与选择 | 关键词、楼幢楼层、尺寸、注册状态、平台状态和应用版本组合筛选；表头勾选控件处理当前页全选与取消，“已选 X 台”仅作跨页选中数量汇总 |
| 本机新增与编辑 | “空间选择”和“安装位置”并排两列，与屏尺寸、MAC 地址采用相同布局；空间使用完整树选择任意有效层级并保存实际节点 ID，安装位置独立填写。楼幢直属有效，未关联或真正失效才待定，目录暂不可用保留原 ID/路径待核验 |
| 本机清单导入 | CSV 或粘贴清单使用“空间路径”列，按系统 `/` 完整路径唯一匹配，分隔符两侧不添加空格；可下载项目空间路径清单并复制路径，支持预览树修正及批量分配。预览每页 20 行，默认选中全部记录（含错误行），跨页选择、错误校验、批量修正和提交均作用于全部已选记录；任何选中行仍有错误均不可提交 |
| 详情 | 分别查看平台与采集身份、系统、架构、空间、应用版本、时间和操作历史 |
| 疑似重复 | 同 IP 或有效 MAC 生成候选；逐字段选用本机或平台值，也可通过来源列标题后的复选框采用整列，预览最终值；确认后模拟更新平台再同步本机及关联，保留旧 ID 与历史；MAC 冲突须核实同设备并明确选源，不自动合并 |
| 已注册资料编辑 | “保存待提交修改”保存绑定原平台主键的草稿，列表提示“资料有变更”，详情可“核对并更新”或“放弃本机修改”；平台确认值与差异分别展示，不新增未注册记录，不进入疑似重复合并 |
| 注册/更新到平台 | 选择设备与资料 → 检查并预览 → 提交结果；自动模拟采集 MAC，显示来源与检查时间，失败逐屏确认历史值或暂不填；有效空间后才提交，预览新增/更新/无变化/需核对，冲突不能绕过 |
| 注册后的连续管理 | 模拟写入及回读确认后转换为单条已注册屏，原本机 ID、历史和缓存保留；未注册减一、已注册加一、总数不变，重开或断平台仍显示带读取时间的缓存已注册屏 |
| 批量运维 | “智能屏操作”页通过单一下拉框依次选择安装/升级小新、注册/更新到平台、检查屏在离线、检查设备、获取/核对 MAC、校准时间、保持ADB端口、重启小新应用、重启屏或采集诊断；左选屏右参数 |
| 操作检查 | 展示模拟目标检查及不适用、重复目标、活动任务等原因；安装文件仅检查扩展名和非空，包名、版本、架构及签名尚未解析，不能据此确认同版或安装兼容性 |
| 执行与结果 | 固定目标后模拟分批执行，支持取消后续派发、逐台结果、失败重试和结果待核实后的继续核实 |
| 状态差异 | 明确“本机 Ping 结果 → 平台状态”；确认后模拟更新并回读平台状态，本机结果不变；可重新进入 IP 检查再比较和确认，失败保留本机结果和历史 |
| 安装选包与版本 | 一个 APK 批次仅允许同一种明确尺寸，混选/未知尺寸禁用选包与安装检查并清除旧包；从本机真实选择非空 APK，展示文件名和大小；不解析包元数据，模拟安装保留原版本 |
| 任务与历史 | 本机任务/日志面板展示执行阶段、进度和取消；标题最右侧“历史记录”按钮打开抽屉，资产只展示注册属性及最终业务事实 |

“智能屏列表”的空间侧栏将带前置图标的“待定空间”放在“全部空间”之前，两项图标风格一致。筛选工具栏展示筛选控件和“重置”。表格底部分页栏左侧在“当前显示 N / M 条”后依次显示竖分隔线、“已选 X 台”和“批量操作”，分页控件保持在右侧，不另设独立操作行。疑似重复图标与文案和屏名称同行，位置放在第二行，“详情”使用小字文字操作。

列表滚动遵循一体机的公共样式：固定表头与数据体共用列宽，纵向滚动范围仅为表头下方的数据区，筛选栏、表头和分页栏不随数据滚动。滑块采用低不透明度，鼠标移出数据区后透明隐藏，滚动槽位始终占宽，避免显隐时闪动或列错位。

智能屏与一体机详情复用公共抽屉宽度 `min(640px, 94vw)`、内边距与紧凑字段样式。智能屏详情的字段采用两列布局，每个字段的标签和值同行显示；长值单行省略，悬停可查看完整内容，分区间距和运维按钮使用紧凑尺寸。以 `1280×800`、标准字号下无历史或少量历史时一屏查看完整详情为布局目标；历史较多或窗口较矮时保留内容区滚动，不裁剪字段和操作。

合并包含名称、IP、MAC、尺寸、所在空间、详细位置和小新版本七项，每项仅采用两侧已有值，不自由手填。所在空间整体选择同一侧的实际节点 ID 与完整路径，不拆选楼幢/楼层；所选节点无效或无法核验时不能提交。合并只同步选定业务字段和关联，不改变平台主键或记录数量，不覆盖本机 Ping、原始采集事实和历史。平台更新失败或预览期间数据变化时保留两条原记录，重新核对；真实平台更新与回读尚未接通，当前全部使用模拟数据。

合并表四个列头加粗，整列选择复选框紧跟本机、平台列标题文字，不另设全部选取按钮；部分选中显示半选，已整列选中后不能再次取消为无来源，每个字段始终二选一。本机标题及对应结果值使用信息蓝，平台标题及对应结果值使用操作绿，原始值保持中性；结果下不逐行显示来源提示，保留选中的单选控件和来源数量汇总。状态差异的本机标签、箭头及平台目标状态标签在第一行对齐，平台原值独立放在第二行；全选行与设备行采用相同左侧留白，勾选框同列对齐。

小新远程配置管理按需求后置，原型中仅说明范围，不放置无实际交互的保存按钮。页面没有顶部场景选择器，不把正常、失败、平台不可用等测试条件作为用户维护的项目状态。

## 3. 推荐核对顺序

注册更新应重点核对：先为未注册屏补齐有效空间，从操作页直接进入检查，观察 MAC 自动采集及逐屏失败处理；再编辑已注册屏，确认产生独立草稿、平台原值保留且列表没有新增行。检查预览的四种分类，提交后核对单条已注册展示、数量转移、旧历史及刷新后的缓存。平台不可用时保留缓存及草稿，仍可执行已注册屏只读检查，不伪称已同步；超时或回读未确认时先核实结果，不直接再次新增。

注册更新与疑似合并分别处理：已有平台主键的资料修改始终更新原记录；没有平台主键且没有未解决重复候选时才新增。资料更新只写名称、IP、核实后的 MAC、尺寸、所在空间和位置，不顺带改平台在线状态、小新版本或空间配置。空间修改显示原、新空间并确认，不因已有布点或空间配置而阻止提交；坐标和配置保持原值，由用户在平台另行调整。MAC 失败的“暂不填”仅用于缺失情况，更新时不清空平台已有 MAC，也不能用于跳过实际冲突。平台登记不代表设备实测在线。

新注册或地址、MAC 变化时自动模拟采集；已绑定且地址、MAC 均未变化的纯资料更新可沿用已有确认身份，不要求重新连接设备。预览明确区分采集结果、历史确认、暂不填和无需重新采集，不能把历史值标成新实测。

1. 在“智能屏列表”按楼层或尺寸筛选，通过表头勾选控件体验当前页全选和取消；翻页选择后核对底部分页栏的“已选 X 台”汇总，再从紧邻的“批量操作”进入操作。数量文案不提供下拉菜单。
2. 点击“新增智能屏”，用单一空间树分别尝试楼幢、楼层及深层区域节点，核对完整路径及楼幢/楼层筛选；不选空间时归待定，楼幢直属不归待定。导入时复制系统路径填表，检查空路径、唯一匹配、无匹配和歧义，再通过单行树或批量分配修正；错误行默认保留勾选，须修正或主动取消后才能提交。
3. 打开疑似重复，逐字段选择本机或平台，通过列标题后的复选框采用整列再局部调整；核对半选、整列选中不清空来源、结果配色及数量汇总。检查目录关系及 MAC 冲突核实确认，成功后两侧采用值一致、旧 ID 和历史保留，失败或并发变化时原记录不丢失。
4. 选择安装/升级小新，选择同一种明确尺寸的目标；右侧选择唯一应用“智能小新”和本机 APK，设置同版本覆盖及并发台数，从参数面板底部进入安装检查。核对混选/未知尺寸阻断及重新选包规则，并确认文件名称、大小和“元数据未解析，仅演示流程”提示。
5. 在结果页和底部任务日志中查看模拟阶段、进度、取消和逐台结果；确认当前未知的 APK 版本不会更新到本机或平台，失败重试及从历史重新发起安装均需重新选择本机文件。
6. 按“本机 Ping 结果 → 平台状态”查看差异，选择覆盖或保留；模拟提交并回读成功后核对平台最终状态及本机结果未变，也可重新进入 IP 检查后再次比较与确认。
7. 点击标题最右侧“历史记录”打开抽屉，查看操作结果；关闭后保持当前步骤和参数。

## 4. 操作步骤与数据保留

“智能屏操作”页上方为操作下拉框、单行优先且最多两行的说明和动态步骤；下方左侧筛选表格选屏，右侧操作参数。首步的安装检查及其他动作按钮统一位于右参数面板底部，没有跨栏的已选数量/下一步底栏；后续检查和结果页保留必要的返回、确认和后续动作。动作名称和说明统一遵循[需求设计第 4.5 节的对应表](01-智能屏运维管理需求设计.md)，不改变 Ping 探测、端口配置后的重启验证等业务规则。没有左侧九操作卡，也不设“新建操作/历史记录”标签页。

选屏与参数区域按约 `68.5:31.5` 分配，右参数列最低 `280px`，窄窗口仍保留该下限。首步安装按钮为“安装检查”，其他动作使用各自检查或执行文案；后续底栏按步骤提供“上一步”、明确的执行动作或“新的智能屏操作”。

注册首步右侧提示为“新屏注册到平台，已注册的屏只更新信息，MAC信息会自动获取。”；下拉框旁短描述保持“登记新屏或更新平台资料”。该提示不改变采集失败逐屏确认、身份冲突阻断及预览后提交的规则。

选屏区使用一体机同款图标标题和紧凑浅底工具条。单行工具栏依次显示空间、注册状态、尺寸、搜索、“选择全部”“清空选择”、已选/匹配统计，不显示额外“目标智能屏”前缀；筛选与搜索弹性收窄，搜索占位为“搜索”，悬停提示及可访问名称说明名称、位置、MAC、IP 范围。列表不设独立蓝色表头，设备以约 `38px` 的单行显示选择框、名称、IP、位置、尺寸、注册状态六列。右参数区使用浅底 APK 卡，文件只读输入框与选择按钮同行，并发输入采用同行表单，目标数量及安装动作的应用包就绪数使用公共执行摘要样式；不把文件信息另叠为多层卡片。

常规宽度下选择框与说明列分别为 `170px`、`221px`；窗口不超过 `1120px` 时分别为 `155px`、`184.25px`，步骤使用剩余宽度。说明自动换行并提供完整悬停提示。选择器可访问名称为“选择智能屏操作”，结果页按钮为“新的智能屏操作”，历史抽屉沿用“智能屏运维历史记录”。

运维页改变筛选只缩小候选，已勾选设备保留；工具按钮在“选择全部/取消全选”间切换，只处理当前匹配目标，筛选外选择保留并在图标标题的次行显示“另有 N 台已选”。“清空选择”清除全部已选。切换操作保留选屏，重置步骤与检查结论。屏列表的浏览筛选仍按主需求在条件变化时清空选择，两处不混用。

| 操作 | 页面步骤 | 主要执行按钮 |
| --- | --- | --- |
| 小新安装升级 | 选屏与安装包 → 安装检查 → 安装结果 | 确认安装 |
| 注册/更新到平台 | 选择设备与资料 → 检查并预览 → 提交结果 | 检查并预览，随后确认提交 N 台 |
| IP、设备、MAC、诊断只读检查 | 选屏检查 → 检查结果 | 开始检查或开始采集 |
| 校时 | 选屏与校时 → 校时检查 → 校时结果 | 确认校时 |
| 10 寸持久 5555 | 选屏 → 端口检查 → 重启确认 → 恢复验证 | 确认配置并重启 |
| 重启屏 | 选屏 → 重启确认 → 恢复结果 | 确认重启屏 |
| 重启小新 | 选屏 → 启动结果 | 确认重启小新 |

安装参数只有四项：应用（默认且唯一为“智能小新”）、本机 APK 文件、同版本覆盖复选框、并发台数。文件通过真实选择器选取，显示名称与大小，支持更换；仅检查 `.apk` 扩展名和非空，不解析包名、版本、架构或签名，也不从文件名猜测。目标版本和架构不提供可选下拉框，检查页明确元数据未解析、仅演示流程；模拟安装不上传或安装文件，完成时显示“演示完成”，不把预设版本写为所选包的真实版本，本机与平台版本、原观测版本及检查时间保持不变。

同一 APK 批次只允许一种明确尺寸：全部 4 寸或全部 10 寸，全部已选目标（含筛选外目标）参与判断。混选时在“本地 APK 文件”标题后以警告色提示“一批只能操作同规格尺寸屏”，灰显选包及安装检查；未知尺寸提示先确认，同样阻断。已选包后出现混选/未知尺寸时清空旧包和检查，恢复后重新选包，不自动取消设备选择。零目标可先选文件，首次明确同尺寸时绑定；改为另一尺寸也需重选。预检与执行适配器同时校验，其他动作仍可按能力混尺寸；同尺寸不等于 APK 架构兼容，当前模拟边界不变。

“并发台数”的标签提示说明同时处理上限及其余目标排队；参数区显示目标数量，安装动作另显示 `0/1` 或 `1/1` 个应用包，不重复“最多同时 M 台”。原型任务仅保存文件名、大小和修改时间，不保存 APK 内容；安装失败重试或从历史重新发起时须重新选择本机文件。正式 APK 校验、设备安装、版本回读和数据库写入仍待实现。模拟阶段仅用于观察流程、进度和取消，不是设备性能或耗时证据；错误注入留在适配器与测试中，不提供产品场景切换控件。

本机未注册记录、注册及合并映射、已注册屏平台缓存与资料草稿、确认后的模拟业务值和操作历史按项目保存在当前浏览器或桌面内嵌页面的本地存储；本机任务的执行阶段、日志和恢复记录单独保存。注册回读成功才转换为单条已注册视图，旧本机 ID 与历史仍可追溯；刷新、重开或平台暂不可用不恢复成未注册记录、不再增加一条平台副本。缓存显示来源与读取时间，不冒充完整实时平台清单。失败保留原记录或草稿；写入不确定先核实，不自动重放新增或旧更新。桌面原型与浏览器预览的模拟记录各自保留，不自动迁移，也不跨电脑同步。原型本地存储不等于正式版 SQLite 数据库实现，注册更新、合并、应用版本和在线状态均由模拟记录承载，真实写权限和数据库连接尚未实现。正式应用版本对应平台已具备的数据库字段 `smart_terminal_screen.app_version`，在线状态对应已有字段 `status`；现有原型中名为 `version` 的程序属性只是模拟应用版本，不表示使用平台已有同名列。平台已有 `version` 保留为 H5 样式版本，正式实现统一以 `appVersion` 等明确属性命名。

完整空间选择仅接入智能屏，一体机与网关的空间业务尚未接入。列表仍仅显示楼幢/楼层筛选，但统计含所选节点自身与全部后代，深层路径可搜索。路径统一显示和导出为 `A座/2F/东区/会议室` 形式，不在 `/` 两侧添加空格；导入允许旧输入分隔符两侧空白规范化，但保留节点名称内部空格。空路径明确为待定，非空须完整唯一匹配，不按单名或后缀猜测，不存在或有歧义不能静默降级。导出的清单只含可唯一匹配路径，歧义节点通过树选择具体 ID；共享树对完整路径重复的节点显示“名称（编号 ID）”辅助核对，普通节点不显示编号，实际选值仍为节点 ID。提交重校验空间与项目，目录变化须重新预览，迟到的文件解析或目录请求不应用到新项目。

旧原型记录保留历史及标识：已有前端字段 `spaceId` 优先，没有该字段时采用旧 `floorId`，楼层 ID 为空才采用 `buildingId`；失效 ID 不静默退回祖先，仅有名称不自动关联。目录暂不可用保留空间 ID 和路径待核验，不能因加载失败清空关联。

演示数据复位和故障注入仅为内部测试辅助，业务页面不提供场景或复位选择。清空底部演示任务列表不删除智能屏操作历史；演示面板的清空视图在页面重新加载后可恢复，不能视为正式任务清理实现。

### 版本同步与设备操作核对

- 在屏详情或安装、注册、设备检查结果中选择“核对版本并同步平台”，重新读取模拟设备版本，查看实际 IP、平台版本、本次版本及时间；仅勾选差异并确认后同步版本，不重新安装。同版本跳过的安装检查也提供该操作。
- 未注册屏只保存本机观测；登记后可按原本机 ID 关联到同一平台屏，再核对同步。平台不可用时允许读取、保留本机结果，恢复后重新读取和确认。未安装、读取失败、关键资料待提交及冲突不覆盖平台版本，旧缓存不冒充本次读取。
- 已注册屏在平台不可用时仍可检查 IP、设备、MAC 和采集诊断，结果保存本机；写平台和已注册屏设备写操作仍阻断。
- 为已注册屏保存 IP、MAC 或尺寸草稿后，设备操作首步显示当前值与待提交值，引导查看修改或前往注册更新；写操作预检阻断该屏，其他目标可继续。只读检查使用列表显示的确认地址。名称和位置等普通草稿不阻断操作。

## 6. 验证方式与边界

原型专项检查：

```powershell
pnpm typecheck:screen
pnpm test:screen
```

当前交互验收应覆盖：

- 无顶部场景选择器；操作下拉框、动态步骤、左右分栏及标题右侧历史抽屉一致工作；首步动作位于右参数面板底部，无跨栏底部操作条，后续检查/结果仍可返回或确认。
- 选屏区与一体机的标题、工具条和单行密度一致；常规桌面窗口中，四项筛选、两个选择按钮及末尾数量统计保持同一行，筛选外已选提示位于标题次行。六列业务字段不挤为双行，选择全部/取消全选保留隐藏已选，清空选择清除全部；APK 输入/选择按钮、同行并发及已选摘要复用公共样式。
- 空间树支持任意有效层级，楼幢直属有效；楼幢/楼层筛选包含自身及全部后代。未关联或确实失效才待定，目录暂不可用保留 ID/路径待核验；旧记录迁移不丢历史、不凭名称关联。
- 导入使用系统完整路径，空值待定，非空须唯一匹配；默认全选含错误行，树修正和批量分配后仍须解决全部选中行错误，或明确取消错误行。提交前重校验，目录变化、关闭窗口及项目切换不造成错误保存。
- 每类操作按其专属步骤执行；只读检查不经过无关修改确认，持久端口在确认前不写配置或重启。
- 注册更新使用三步，逐屏区分新增、更新、无变化、需核对。MAC 自动采集，失败须明确选择可信历史或暂不填，不要求切换到另一操作；有效真实空间必需，多网卡、MAC/IP 冲突和疑似重复不能被空值确认绕过。
- 已注册资料编辑独立保存草稿和原平台值，修改后仍一条已注册屏、不生成合并候选；更新保留原主键，只改资料白名单，状态、版本、空间配置和原观测不变，空间修改展示原、新空间并确认。
- 注册成功并回读确认后未注册数减一、已注册数加一、总数不变；原本机 ID、旧任务和历史可查。刷新、重开、平台不可用仍一条缓存已注册屏；缓存带时间，写入和共享操作不绕过平台就绪要求。
- 新增或更新失败保留记录与草稿；超时、回读失败或本机映射未保存时先核实已有结果，不能直接再次插入或重复覆盖；部分失败可分别处理，不将需核实写成平台中间状态。
- 安装只有应用、APK、同版本覆盖和并发四项输入；真实选择文件后核对名称、大小、扩展名及非空校验。检查页不伪称解析了包名、版本、架构或签名，模拟安装不更新未知版本；重试或历史再次发起时重新选包，任务不持久化 APK 内容。
- 安装批次含隐藏目标一起校验尺寸；混选或未知尺寸提示、禁用及清空旧包有效，恢复同尺寸/更换已绑定尺寸均需重选，零目标先选包后可绑定首个明确尺寸。不绕过选择直接取消设备，适配器预检和执行同样拒绝无效尺寸批次；其他动作保留按能力混尺寸的规则。
- 状态覆盖只有提交和回读确认后更新模拟平台最终值，本机 Ping 结果不变，失败保留旧值及本机结果。
- 合并七项选源，空间 ID 与完整路径始终来自同一侧；支持整侧选择和最终预览，MAC 冲突核实后才确认，所选空间有效且属于当前项目。模拟平台更新及回读成功后采用值一致；失败或并发变化不合并本机、不丢原记录，主键、旧 ID 及历史关联保留。
- 阶段、进度、取消和错误只进入本机任务与日志，不新增平台资产或项目中间状态。
- 项目隔离、合并保护、跨页选择、结果核实、生产构建剔除模拟数据，以及浅色/深色和不同窗口尺寸。
- 列表仅数据区纵向滚动，表头与数据列对齐；鼠标移入、移出数据区时滑块按公共样式显隐，内容宽度和列位置不变。
- 详情标签与值同行，长值可查看完整内容；核对常规窗口的首屏完整性，并确认多条历史或较矮窗口下仍可滚动访问全部内容。
- 专用桌面启动默认进入智能屏列表，前端修改能够热更新；普通桌面开发和生产构建不装配模拟适配器，桌面原型使用独立数据目录。
