## 3. 共享凭据加密

为避免数据库备份直接暴露 AuthKey、MQTT 密码和 SSH 私钥，`aio_release_profile` 不设置明文凭据列，改为：

- `credential_scheme`
- `credential_key_version`
- `credential_salt`
- `credential_nonce`
- `credential_ciphertext`

加密流程：

```text
数据库密码 + 每次写入的随机盐
→ Argon2id 派生 256 位密钥
→ AES-256-GCM + 唯一 96 位 nonce
→ 认证密文写入工作台库
```

这不改变“登录用户可查看完整凭据”的产品结论；工作台在内存中解密后通过界面展示。数据库密码变更时必须使用旧密码解密并重新加密，不能直接丢弃旧连接凭据。

### 5.2 fencing token 单调性

采用同一张 `resource_lease` 表，不新增计数表：

- 增加 `lease_state=active/released`。
- 释放时保留资源行并标记 `released`，清空活动令牌并让租约立即过期。
- 下次获取在同一行上递增 `fencing_token`。
- 定期任务不删除计数行，只清理无业务价值的活动字段。

第二个 Migration 已执行，技术方案已同步修订。正式运行保留计数行；仅隔离测试在获得明确授权后按精确资源键或操作 ID 清理。
