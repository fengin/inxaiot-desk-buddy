> 状态：公共架构基线；跨业务扩展事项单独列明。
>
> 更新日期：2026-10-08。适用范围：`inxaiot-desk-buddy` 桌面工程。
>
> 事实依据：现有前端装配、项目上下文、任务运行时、一体机和智能屏执行链路；Windows、两台一体机及三台智能屏的验证范围见[整体实机回归记录](27-整体实机回归记录.md)。

## 1. 目标与范围

实施人员使用同一个桌面程序连接不同项目，并对项目设备执行维护操作；智能屏还支持只保存于本机的未登记屏，在平台不可用时独立执行设备维护。公共架构负责本机上下文、项目与登录、数据连接、任务执行、日志、并发保护和桌面交互，使新业务在保留自身设备规则的同时使用同一套基础能力。

当前工程采用模块化单体：前端组织界面，桌面后端承担受控系统能力和业务执行，不增加独立常驻服务。[公共产品设计](02-产品设计文档.md)说明业务规则；一体机的资产、模板、镜像、脚本和部署流程见[一体机技术详细基线](一体机/03-技术方案设计.md)。

[智能屏整体技术方案](智能屏/05-智能屏技术方案设计.md)定义代码模块、数据存储、任务执行及异常处理。功能可用条件、任务创建、未完成结果处理和任务展示已完成公共能力分离，一体机专用规则保留在一体机模块，并已通过一体机回归。屏业务的过程数据保存在本机，已注册屏的操作结果记录保存在项目工作台专用库，业务结果保存在项目平台业务库。屏端小新配置的读取、修改、按需重启和回读已接入，配置值仍保存在屏端。

与项目平台交互采用认证接口和业务数据直连分工：登录、验证码和会话检查沿用现有 HTTP 链路；平台资产查询、筛选、统计及已明确的字段更新通过工作台数据库适配器完成，不依赖平台业务控制器或接口返回类型。设备自身 HTTP、SSH/SFTP、ADB 等属于受管设备协议，不属于项目平台业务接口。云平台不参与该运行链路。

智能屏已接入真实本机存储、项目数据库和设备操作，安装升级、配置管理、注册更新、共享结果及异常恢复的验证见[整体实机回归记录](27-整体实机回归记录.md)。[开发交互原型](智能屏/04-交互原型使用与验证.md)保留为独立的模拟模式，不连接真实数据库或设备。业务规则见[需求设计](智能屏/01-智能屏运维管理需求设计.md)，公共结构调整范围见[跨业务技术债](20-跨业务扩展技术债与实施顺序.md)。当前接口名称包含“一体机”或实际数据模型限定一体机时，不能仅因为代码位于共享目录就认定为通用接口。

## 2. 运行环境与职责

| 位置 | 职责 | 技术定位 |
| --- | --- | --- |
| 实施人员电脑上的界面 | 项目选择、业务页面、任务与日志显示 | Vue 前端程序，使用 TypeScript；桌面程序由 Tauri 承载 |
| 同一桌面程序的后端 | 项目访问校验、业务用例、数据访问和后台任务 | Rust 程序，使用 Tokio 异步运行时 |
| 本机数据目录 | 过程数据、任务、日志、临时制品；智能屏未登记资产、已登记资料草稿、平台缓存、身份映射与历史 | 正式桌面使用 SQLite 数据库与受控文件目录；开发原型使用独立模拟存储 |
| 项目环境 | 共享配置、平台资产的运维关联与操作结果，以及平台业务数据 | 工作台库读写、平台只读及屏业务限定写连接分开；屏注册更新、状态覆盖、安装版本及合并选源已接入，具体范围见领域验收记录 |
| 目标设备或既有服务 | 执行对应业务协议，提供实际运行事实 | 由业务模块选用已有适配器或新增受控协议适配器 |

Windows、macOS 和 Linux 的打包及运行依赖按照[发布与回滚说明](16-Windows可信发布与回滚说明.md)管理。修改源码所在电脑不等于目标设备运行环境；一体机的 Linux 和 Docker 条件不自动成为智能屏条件。

## 3. 依赖方向

```text
业务界面与状态管理
    → 前端适配器与类型契约
        → 受控桌面命令
            → 应用用例与领域规则
                → 应用端口
                    ← 数据库、文件、认证、通信等基础设施适配器
```

- 桌面命令负责参数校验、用例调用和错误转换，不承担完整业务编排。
- 应用层依赖领域模型与应用端口，避免直接创建具体数据库或网络适配器。
- 领域层定义身份、状态和业务规则，不依赖界面、数据库行结构或网络句柄。
- 前端不直接访问数据库、任意文件、远端命令或平台网络接口。
- 具体业务只能通过受控端口产生外部副作用，不能绕过其操作范围对应的访问保护和任务生命周期；仅本机设备维护不要求平台登录，平台读写与共享能力仍校验项目就绪和登录。

## 4. 前端分层与装配

| 已有目录或文件 | 职责与边界 |
| --- | --- |
| `src/app/` | 应用入口、路由、主题令牌和公共样式 |
| `src/shell/` | 桌面框架、项目切换、设置和统一任务日志面板 |
| `src/features/aio/` | 一体机资产、发布参数、部署升级和服务检查页面 |
| `src/features/smart-screen/` | 智能屏资产、注册更新、安装升级、配置修改、设备维护和结果页面 |
| `src/stores/` | 项目与页面状态、少量查询缓存及响应隔离 |
| `src/shared/api/`、`src/shared/model/` | 前端适配器、命令封装与数据契约；其中已有部分模型仍为一体机专属 |
| `src/shared/model/projectSpace.ts`、`src/shared/components/ProjectSpaceSelect.vue` | 通用空间父链、树、路径和唯一匹配及完整树控件；当前仅智能屏接入，一体机/网关业务留待后续 |
| `src/dev-fixtures/` | 开发浏览器和专用桌面原型模式使用的演示适配器 |
| `src/main.ts` | 真实桌面和开发演示的装配分支 |

现有前端文件 `src/main.ts` 在普通桌面模式装配真实适配器，在开发浏览器或明确启用的桌面原型模式动态加载演示适配器；生产构建禁止演示模式，非桌面生产环境拒绝使用演示数据。专用启动命令 `pnpm dev:desktop:screen` 使用独立应用标识和数据目录，避免桌面后端初始化接触真实项目数据。启动方式与热更新范围见[智能屏交互原型使用说明](智能屏/04-交互原型使用与验证.md)。新增业务保持相同边界，并扩展现有物理隔离检查。

路由通过 `projectAccess` 元信息声明本机、平台读取或共享操作要求，`src/shell/DesktopShell.vue` 按声明判断是否显示页面，不再按一体机路径硬编码。项目可以仅保存本机信息；平台只读连接与共享库连接分开使用，一体机表结构由一体机业务检查。只读页面能否发起请求与共享库状态分开，实际会话和连接由后端再次核对。

业务页面保持项目隔离和请求顺序校验。项目切换后，旧请求、旧文件解析结果及旧任务详情不得覆盖新上下文。主题、密度、字号与组件遵循[界面规范](01-桌面工作台界面设计规范.md)，业务局部样式放入业务目录，避免持续扩大公共样式文件。

## 5. 项目访问与数据存储

本机保存项目连接信息和会话引用。现有项目分别建立工作台数据库读写连接、平台业务数据库只读连接和智能屏限定写连接。智能屏按操作范围划分访问条件：平台数据读写和共享操作要求对应项目就绪及有效登录；本机未登记屏只依赖明确的本机项目上下文、设备身份和连接能力，不依赖远端数据库或平台会话。前端阻断用于解释状态，后端仍按实际操作范围校验，不能用一个全局“未就绪”状态屏蔽整页本机维护功能。

| 数据类型 | 存储边界 | 扩展要求 |
| --- | --- | --- |
| 任务过程、日志、临时文件、检查快照 | 本机 | 保持项目与任务归属，使用公共数据目录和清理机制 |
| 未登记屏资产、关联候选与该阶段的维护结果 | 本机 | 使用稳定的本机临时标识；不自动同步其他工作台实例，不要求共享库才能执行或完成任务 |
| 已登记屏资料草稿、平台缓存与本机 ID 映射 | 本机 | 草稿绑定既有平台主键并保留基准值，缓存保留读取时间；注册回读成功才转换身份，重开和断平台不恢复成未注册、不生成重复行 |
| 共享配置、领域运维资产 | 工作台项目库 | 按领域定义；一体机沿用已有资产表和共享发布配置的版本检查，智能屏不复制平台正式资产为第二套可编辑主数据；小新屏端配置不采用配置版本冲突处理 |
| 操作摘要和目标最终结果 | 工作台项目库 | 复用公共操作结构，以业务域和资源身份隔离 |
| 平台既有设备数据 | 平台业务库普通只读连接 | 通过版本明确的读取适配器理解平台结构 |
| 屏注册更新、状态覆盖、安装版本及合并选源同步 | 平台业务库限定写通道 | 数据库表 `smart_terminal_screen` 的新增及资料更新使用专门用例；`status` 只由确认覆盖用例更新；安装结果或独立读取确认后更新 `app_version`；合并按人工选源更新限定字段，分别限定权限、条件、回读并记录结果 |
| 设备实时运行状态 | 设备协议实际读取 | 记录来源和采集时间，不把缓存视为实时事实 |

本机 SQLite 结构由程序管理；项目工作台数据库结构初始化或调整由用户明确触发。本期按统一工作台版本开发，不考虑其他电脑旧实例的数据兼容或新旧版本并行，保留一体机功能回归和当前研发数据的明确处置。智能屏按新项目平台业务表 `smart_terminal_screen` 已具备 `app_version` 接入；142 环境已由用户完成字段准备，其他项目增列不属于工作台范围。工作台不负责平台表升级，普通查询或项目切换不暗中改表。

已有数据库字段 `smart_terminal_screen.version` 保留为屏内 H5 样式版本，相关选择功能尚未实现。小新应用安装、独立版本同步和人工合并只使用平台已具备的字段 `app_version`，不能将旧 `version` 或空间表 `screen_version` 转成应用版本。具体字段使用约定见智能屏技术方案第5.6节；工作台直接访问业务表，不依赖平台实体、DTO或查询接口改造。

数据库直连的兼容边界是必要表字段、类型、枚举、项目归属、逻辑删除及写入后的关联影响。SQL 和字段映射集中在数据适配器中，进入相应功能时检查所需结构；不因平台新增无关字段而阻断整个程序。平台页面或业务接口改版通常无需工作台同步改动，相关数据含义改变仍需更新适配和针对性测试。新增写入前核实关联表、缓存、事件和派生状态，按具体用例处理一致性，不自动扩大到任意字段写入。

智能屏注册更新、状态覆盖、安装结果与独立版本同步、人工合并分别使用专用写入用例，普通平台连接池继续保持只读会话。资料更新白名单为 `name`、`ip`、`mac`、`size`、`building_id`、`install_address`；新增的主键、项目归属和必要初始值由正式适配器按平台契约落实，不把本机 Ping 或缓存版本当作新实测。状态覆盖仅更新 `status`，安装结果和独立版本同步仅写 `app_version`；人工合并可额外选择双方已有的 `app_version`，不代表执行安装或产生新观测。不向前端暴露通用 SQL，不授权删除资产、改变既有主键或编辑空间目录表。操作前校验平台登录、项目归属及对应权限；资料更新不顺带修改状态、版本、空间图片、设备别名或业务配置，空间修改与布点分开处理，保留原坐标和空间配置。

注册更新使用独立的资料预览、确认执行和结果核实契约，不复用设备安装执行或疑似合并契约。预检按平台主键区分新增与更新，校验真实有效空间并自动采集 MAC；采集失败保留观测和历史，逐屏确认可信历史或暂不填，更新暂不填不清空平台原 MAC。新旧冲突、多网卡不明和重复候选不能绕过。4 寸按已验证固件规则固定读取有线网卡 `eth0`，不按 ADB 连接网卡取值；10 寸只接受唯一、有效的有线网卡 MAC，多候选时要求核实。两种尺寸的 MAC 读取已完成实机验证，注册更新已使用真实屏身份和隔离平台库验证，范围见整体实机回归记录。MAC 来源、采集时间及人员决定进入预览快照，提交时重新验证。

新注册及 IP/MAC 变化触发身份采集；已绑定且两项均未变的纯资料更新可沿用已确认身份，不要求设备在线。原有效平台 MAC 与新值冲突时阻断普通更新，不能用草稿确认替换硬件身份；未绑定重复记录的显式核实合并仍按其独立用例处理。

已注册资料草稿以平台主键为稳定关联，保留平台基准值与待提交字段，平台刷新不得静默吞掉草稿。草稿不新增未注册资产，也不参与疑似重复候选。更新根据原主键及预览条件执行；新增需证明尚无平台关联且无未解决候选。结果不确定保存恢复依据，先查询当前事实再继续，禁止重复插入或把已绑定更新降级为新增。新增任务在执行前确定平台主键并保存请求编号、目标资料和写入状态；恢复时按该主键核对项目归属及目标值。现有表没有 IP/MAC 唯一约束，不能仅凭 IP/MAC 相同认定恢复目标。

平台写入并确认回读后，在本机一致保存平台缓存、草稿结果、本机旧 ID 到平台主键映射与历史索引，再转换统一视图。新注册使未注册数减一、已注册数加一，总数不变；历史目标仍保留旧 ID，查询时沿映射归集。重开或平台断开仍显示一条带读取时间的缓存已注册屏，不恢复成未注册行或重复加入一条平台缓存。本机持久化失败时保留恢复证据，先核实远端再补本机关联，不重放副作用。

执行时以记录主键、检查或执行时的 IP、预览旧字段值及可用并发条件限定未删除记录；源记录变化则停止该目标写入并重新读取。现有表没有专用状态检查版本，不能假定普通更新时间可靠覆盖全部写入，也不能将旧状态相等宣称为完整并发版本保护；应用字段 `app_version` 是小新版本，不作为状态检查序号。更新并回读成功后才刷新资产最终值；平台后续 Ping 可以再次改变状态。安装失败不写平台版本，写入失败或回读不确定时保留最近确认值，失败原因在结果界面与本机历史保存，不因日志或记录失败重放安装或数据库更新。

屏资产模型不保存任务中间阶段。阶段、进度、取消、失败和恢复依据属于本机任务与日志；项目共享记录可保存确认后的操作摘要，但不把本机任务阶段提升为项目状态。开发原型只模拟注册更新、合并、在线状态和应用版本变化，未连接真实数据库或 ADB。正式数据库字段分别为平台已具备的 `status` 和 `app_version`；原型的程序属性 `version` 不表示平台已有同名数据库字段。

未登记屏使用本机临时标识，平台屏使用项目范围内的平台记录主键；两者与实际设备身份分开表达。平台拉取发现尚未绑定的本机记录与平台记录 IP 或标准化 MAC 相同时，只产生待人工核对的候选；已绑定屏的草稿差异不参与。MAC 冲突须核实为同一设备并明确选源后才允许合并。合并保存逐字段来源、双方预览快照及最终值，校验后限定更新平台并回读，成功才在本机一致保存采用值、关联及历史索引。平台失败、回读未确认或并发变化时保留原记录和旧 ID；远端可能已写入而本机保存失败时先核实再恢复，不假定跨库原子事务。合并不新增或删除平台记录、主键不变；不改写已提交任务目标或历史观测，不自动上传旧本机历史。注册身份转换与合并均须等待活动任务及未处理结果完成，后续任务采用平台共享规则。

智能屏以唯一前端空间关联字段 `spaceId` 保存实际节点，路径用于展示和历史快照，楼幢/楼层归类由祖先链派生。新建/编辑的完整树允许任意有效层级；列表仅提供楼幢/楼层筛选，但计算节点自身及全部后代。直接关联楼幢不缺失空间；未关联或完整目录核实失效才归待定，目录暂不可用保留 ID/路径待核验。合并的空间作为单一业务项，整体采用同侧节点 ID 与路径，不拼接祖先。平台通过已有 `smart_terminal_screen.building_id` 保存该节点，不新增空间字段或修改目录表。

导入把系统 `/` 完整路径唯一映射到当前项目节点；规范输出不添加分隔符两侧空格，旧输入可将分隔符两侧空白规范化，节点名称内部空格保留。空值是明确未关联，无匹配或歧义是错误，不能自动降为待定或新建节点。预览默认包含错误行的选择，支持逐行树修正、批量空间分配和路径复制/导出；只有全部选中行通过校验才提交。适配器提交重查项目归属、记录及目录快照，路径或有效性变化时要求重新预览；异步解析、目录请求与提交均绑定项目及操作上下文，失效响应不得覆盖新状态。

真实空间读取参考已有 HTTP 接口 `/api/edge/building/space/list` 的实现：按业务项目和有效标记查询平面节点，按父子关系组成树，并参考空间层级与排序字段。完整选树不启用有图、已绑定设备、核心空间或已有屏筛选，也不把接口 `parentId` 的一层查询当成全部后代查询；工作台仍直接读取数据库，不增加对此 HTTP 接口的运行依赖。

通用树遍历、祖先归类、路径构造和唯一匹配放在不依赖设备业务的公共模型层；当前只接入智能屏，不实现一体机或网关的空间业务。正式桌面已通过数据库适配器读取项目空间，并在屏注册、更新和合并时校验空间及限定写入关联字段；真实平台验证见整体实机回归记录。开发原型的数据转换优先保留已有 `spaceId`，否则将旧 `floorId`、无楼层时的 `buildingId` 转为实际关联，保留历史及路径快照；失效 ID 不退回祖先，仅有名称不自动关联。原型模拟不替代正式数据库验收。

设备只读检查按动作授权，不因已注册身份而依赖平台登录或共享库可用；离线结果保存在本机，不改平台字段或承诺跨电脑互斥。已注册屏设备写操作仍要求共享保护就绪。

TypeScript 模型文件 `src/shared/model/screenMaintenance.ts` 定义只读动作、关键草稿字段、确认目标指纹及版本核对契约。设备操作使用已确认记录而非草稿，IP、MAC、尺寸待提交时阻断设备写操作；检查、提交及派发前校验同一目标。独立版本核对通过 ADB 读取当前设备版本，确认后只更新平台 `app_version`，核对主键、地址与身份、设备版本和平台旧值；结果不确定先核实，不重装。正式端已实现真实读取、限定 SQL 写入及结果保存失败后的核实补存；实机和平台字段核对见整体实机回归记录。开发原型仍将模拟设备版本与可编辑平台字段分开存储。

## 6. 公共任务与领域执行

现有 Rust 结构体 `TaskHandlerRegistry` 按业务域及操作类型登记处理器；Rust 结构体 `TaskQueue` 提供统一队列；Rust 结构体 `JobSupervisor` 管理真实执行句柄与退出协作。相关已有文件为 `src-tauri/src/runtime/task_queue.rs` 与任务运行时实现。

已有执行协调器通过生命周期端口组织开始、心跳、执行、最终结果保存与中断处理。一体机自己的身份、发布物、脚本和平台注册策略留在一体机实现中。新领域应注册自己的处理器并组合公共能力，不能复制一整套队列、取消、日志与并发管理。智能屏业务处理器根据提交时固化的目标来源，选择本机持久化与本实例互斥，或平台资产的共享结果与租约；不得为了复用一体机生命周期而强制本机临时任务依赖共享数据库。

智能屏安装用例按全部目标校验同一种明确屏尺寸及 APK 的尺寸绑定，预检和执行提交均拒绝混合或未知尺寸，不能只依赖前端禁用按钮，也不能按处理器架构推断尺寸。该限制仅属于安装业务，不扩大到其他按能力支持混尺寸的动作。正式端已解析安装包名称、包名、版本、处理器架构和最低系统版本，并校验签名、安装包完整性及逐设备兼容性；同尺寸批量安装、跨版本升级和保留数据已通过本轮实机验证。开发原型只模拟安装过程，不执行真实安装。

前端 TypeScript 接口 `ActivityTask` 和 `TaskEventPayload` 位于 `src/shared/model/activity.ts`，已经包含业务域、项目和资源归属信息。任务面板通过事件刷新真实任务数据，领域页面负责其业务详情与可恢复操作。

公共任务面板从业务提供的阶段配置取得文案和补存结果能力；一体机配置位于 `src/features/aio/taskPresentation.ts`。公共任务查询通过内部检查记录识别预检，不依赖一体机操作名，并返回是否允许清理的 `clearable` 字段。检查已通过但尚未提交时，不允许清空相应任务记录。

结果处理通过 Rust 文件 `src-tauri/src/infrastructure/task_recovery.rs` 按业务和操作类型注册；一体机实现位于 `aio_task_recovery.rs`。公共历史查询和数据结构分别位于 `infrastructure/operation_history.rs`、`domain/common/operation_history.rs`。未知业务不会读取一体机结果文件，补存记录不重新执行设备命令。公共优化范围和验收见[公共能力分离与一体机回归记录](21-公共能力分离与一体机回归记录.md)。

资源互斥采用明确的资源类型和资源键。写任务需要按领域规则验证互斥、过期执行者回写保护及最终结果保存；只读检查是否需要等待写任务结束由真实业务影响决定。本机临时屏只能保证本实例互斥，同一实例发现临时记录与平台记录指向同一设备时也不能并行执行冲突动作；未登记设备跨电脑互斥不作为已具备能力。公共层不固定设备标识或传输协议。

## 7. 通信、文件与凭据

现有工程具备 SSH 远程连接、SFTP 文件传输、受控文件选择、认证、日志和错误转换等基础设施。是否适合智能屏须依据其实际运行环境和既有协议确认，不能因为一体机使用这些能力就强制复用。

文件选择后仍由后端验证路径、类型、大小及业务契约。可重用的是受控文件处理机制；镜像归档、设备安装包和配置文件的校验规则分别属于相应业务。

智能屏安装升级只处理小新应用，安装包校验目标包名和实际设备兼容性。屏端配置管理是已实现的独立扩展：工作台通过 ADB 调用受限 Android 组件，再由小新公共配置服务保存和读取；不新增 HTTP 管理端口、临时凭据或配置版本冲突管理。前台业务逻辑不列入重构范围。具体字段、调用和验收见[智能屏技术方案第 9.3 节](智能屏/05-智能屏技术方案设计.md#93-屏端配置数据管理)及[验收记录](智能屏/19-屏端配置管理实施与验收.md)，该扩展不是已有连接、安装和重启功能的前置条件。

凭据按现有凭据存储与加密边界处理，不进入完整日志、错误摘要或前端长期缓存。技术错误转换为可操作的中文提示，同时保留可定位的错误代码和追踪信息。操作失败、结果保存失败和观察失败必须分开表达，避免将已执行成功误写为未执行，或反之。

## 8. 验证与实施边界

新增领域的验证应贯通“页面 → 状态管理与真实适配器 → 桌面命令 → 用例 → 领域与基础设施 → 任务与结果”。静态架构检查、契约测试及组件测试用于守住层级边界；目标设备联调和桌面用户验收用于确认实际业务闭环。

优先验证项目切换、协议与身份、任务取消、失败隔离、跨实例互斥、结果恢复和完整日志。智能屏还需验证注册更新的 MAC 自动采集与逐屏失败确认、有效空间、草稿不生成新行、回读后单条身份转换、数量守恒、缓存离线及重开保留、超时不重复插入，以及人工合并的选源与冲突规则。各限定写入不能扩大普通平台只读连接的权限，记录失败不得盲目重放新增、安装或旧更新；旧 ID、历史及活动任务边界必须保留。未执行的测试如实记录，不用历史一体机测试数量代替新业务证据。

一体机阶段的表结构、接口、脚本协议、详细状态机、测试记录及版本历史保留在[一体机技术详细基线](一体机/03-技术方案设计.md)。公共验收和全仓审查材料保留在文档根目录，各记录的日期、基线和实际验证范围仍然有效。

2026-10-08 的[整体实机回归](27-整体实机回归记录.md)覆盖 Windows 工作台、两台一体机、两台 4 寸屏和一台 10 寸屏，以及真实项目平台和隔离测试库。Mac 原生运行、现场触摸、麦克风、扬声器和完整业务交互仍需对应环境验收，不能用本机自动测试或远程进程检查替代。
