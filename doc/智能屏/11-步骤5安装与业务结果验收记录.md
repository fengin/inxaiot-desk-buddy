## 1. 交付内容

实施人员选择本机的小新安装包，检查设备后执行安装。工作台读取包内信息，逐台核对身份、系统、架构、签名、剩余空间和数字版本；同版本默认跳过，明确选择覆盖时保留应用数据安装。安装后必须读到目标版本并确认小新进程运行。

未注册屏的结果只保存在当前电脑。已注册屏安装验证成功后，仅更新项目平台数据库字段 `smart_terminal_screen.app_version`，再保存项目操作摘要和业务修改记录。数据库字段 `version` 仍表示屏内H5样式版本，不参与应用安装。

页面分别展示设备、平台数据、操作记录三项结果。记录保存失败时保留任务；再次核实只处理原结果，不再次安装。同版本覆盖的命令回执丢失时，不能仅凭“当前版本相同”就判定覆盖成功，还需检查安装时间或安装路径是否变化。

独立“核对版本并同步平台”重新读取设备版本和身份，确认后只写应用版本。状态覆盖使用有效的Ping结果和已确认地址，只写平台在线状态；ADB失败不会直接变成离线。资料草稿保持独立。

## 5. 技术位置和运行条件

以下均是工作台工程的Rust源码文件，实际运行在实施电脑：

| 文件 | 职责 |
| --- | --- |
| `src-tauri/src/infrastructure/smart_screen/apk.rs` | 调用aapt读取包信息、apksigner完整验签、文件校验和任务副本；读取已安装包的签名证书 |
| `maintenance.rs`（同目录） | 检查、传输、安装、启动检查、逐台结果和中断后的核实 |
| `value_updates.rs`、`platform_write.rs`（同目录） | 独立版本/状态更新、检查原值、限定字段、提交和回读 |
| `shared_results.rs`、`history.rs`（同目录） | 共享摘要、修改记录、按数据源和业务项目限制历史查询 |
| `src/features/smart-screen/ScreenInstallFields.vue` | 正式桌面选择并解析真实APK |
| `ScreenSharedHistory.vue`（同一前端目录） | 项目共享结果查询；注明完整日志保存在来源电脑 |

已安装APK由Android在安装时验证；工作台按[AOSP的APK v2签名结构](https://source.android.com/docs/security/features/apksigning/v2)读取其证书，避免每次从屏上下载整个包。待安装文件仍执行完整验签，不能用证书区读取替代文件完整性验证。

开发环境使用已有ADB、Android构建工具和Java。发布包中的固定版本工具、完整性及分发检查属于步骤7；本记录不代表无需开发工具的发布包已经验收。

隔离测试库和新增项目在测试结束后清理，独立数据库查询确认无本次残留测试库。原业务库未增加字段；工作台始终按 `app_version` 已存在处理。
