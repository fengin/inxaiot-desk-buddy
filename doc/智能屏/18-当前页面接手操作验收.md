# 智能屏当前页面接手操作验收

日期：2026-10-03。工程：`inxaiot-desk-buddy`（桌面运维工作台程序）。验证环境：Windows、142 隔离测试库。

## 1. 用户操作

1. A 打开编辑、保存草稿或检查预览时不加共享操作锁。真正提交平台修改或执行需要保护的设备操作时才加锁，正常完成后自动解除。
2. B 提交时遇到 A 的锁，当前页面弹出确认框，显示屏名称、操作人、电脑和操作名称。
3. B 可以自行判断，也可线下沟通。点击“取消”不解除锁、不继续操作；点击“接手并继续”后，工作台重新读取平台数据并完成必要检查，然后继续原操作。
4. 已选屏、安装包和操作参数保留，不要求 B 到历史记录寻找 A 的任务。若最新的地址、身份、尺寸或已确认资料发生变化，提示重新核对，不自动覆盖。

适用操作：登记更新、安装与设备维护、人工合并、版本同步、平台状态更新。只读检查保留原有流程。

## 2. 确认文案

标题：**该智能屏正在由其他电脑操作**

> 【屏名称】正在由【操作人】在【电脑名称】上进行“【操作名称】”。
>
> 接手后，对方本次操作将不能继续提交更改。请确认现在可以由你继续操作。

按钮：**取消**、**接手并继续**。

原操作涉及安装、校时或重启等设备动作时显示：“已经发送到屏上的操作可能仍在执行。”原操作有多台屏时，显示批次数量及停止后续提交的影响。

## 3. 处理规则

- 等待确认期间不创建 B 的执行任务，也不让 B 持锁等待。
- 确认时再次检查原锁；多个原操作一起核对、一起解除，任一锁已被替换或增加未确认锁时不部分解除。
- A 在等待确认期间正常完成并释放原锁时，B 仍可重新检查后继续。
- 接手留下操作记录，A 的旧操作不能重新取得锁或继续提交更改。已经完成的结果保留，已发给设备的命令不视为已撤销。
- 新提交又遇到其他锁时，重新显示当前持有人，由用户再次确认。真正执行时仍检查锁；极短时间内出现新的竞争时保留失败结果，不自动重放可能已经执行的设备动作。
- 切换项目、离开页面或关闭原操作窗口时，取消尚未确认的接手；已经确认但尚未重新提交时，不继续旧页面的操作。
- 项目共享历史保留独立解除操作锁的功能，但不再是 B 接手的必经步骤。

## 4. 实现位置

以下为工作台工程内的代码位置，程序在运维电脑运行：

| 文件 | 职责 |
| --- | --- |
| Rust 文件 `src-tauri/src/infrastructure/smart_screen/takeover.rs` | 提交前查找锁及原操作信息，核对并解除已确认的锁 |
| Rust 文件 `previews.rs`，位于同一目录 | 在创建执行任务前返回接手确认信息 |
| Rust 文件 `lock_release.rs`、`leases.rs`，位于同一目录 | 复用原有解除、审计及旧操作阻断规则 |
| 桌面命令 `screen_takeover_release` | 校验当前项目与登录状态，处理用户明确确认的接手 |
| TypeScript 文件 `src/shared/api/realScreenAdapter.ts` | 保留原操作内容，接手后重新读取、重新检查并继续提交 |
| TypeScript 文件 `src/shared/api/screenTakeover.ts` | 连接正式适配器与当前页面的确认框 |
| Vue 组件 `src/features/smart-screen/ScreenTakeoverDialog.vue` | 用户确认、过程提示及页面切换处理 |

没有新增平台业务字段、共享表或模拟电脑身份设置。

## 5. 验证结果

| 验证 | 结果 |
| --- | --- |
| 当前页安装接手 | 显示原操作人和电脑；确认前不解除；确认后按“解除 → 读取平台 → 重新检查 → 提交”顺序执行，保留原安装包及目标 |
| 取消及页面切换 | 取消或确认前切换项目不解除锁；重新读取期间离开页面，不继续提交 |
| 最新资料变化 | IP 变化时停止原安装；待提交登记资料变化时停止覆盖并提示核对 |
| 其他业务操作 | 登记使用新预览继续；版本同步再次读取设备版本；状态更新使用新资料修改次数；合并保留字段来源选择 |
| 新持有人 | 继续提交时又遇到另一把锁，重新显示新的操作人供用户确认 |
| 142 实际数据库 | 两个独立客户端连接池验证冲突、取消、过期确认、多个锁整体回滚、原批次数量、原锁正常释放后继续、新操作取得锁、旧操作写入拒绝 |
| 正式登记服务 | 保存草稿和检查预览无活动锁；B 提交遇锁返回确认信息且未创建执行任务；确认后重新读取、重新预览并提交成功 |
| 相关真实业务回归 | 登记、更新、合并、空间独立修改、版本/状态及结果失败恢复通过，H5 版本保留 |
| 前端 | 全量 47 个文件、297 项测试通过；接手新增 11 项交互与调用测试通过 |
| Rust 与公共能力 | 128 项核心库、19 项相关集成测试通过，含公共任务、一体机架构约束及跨业务能力 |
| 构建检查 | TypeScript、ESLint、Vite 和普通 Tauri 桌面构建通过 |

真实数据库用例位于测试文件 `smart_screen_feedback_real.rs`、`smart_screen_registration_real.rs`。写入仅限临时隔离库，测试后清理；测试屏只做读取，不安装或重启。前端测试使用可控的命令响应，验证用户确认和调用顺序，不将其当作两台物理电脑的实机证据。

验证程序及完整工具目录位于工程内 `.review-tools/smart-screen-takeover-20261003/portable/`。运行中的程序未自动替换，退出后可打开该目录中的新程序。
