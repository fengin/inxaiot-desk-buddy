| 属性   | 内容                        |

| 适用项目 | `inxaiot-desk-buddy`      |

## 1. 文档目的

本文档先定义与具体业务功能无关的桌面工作台界面基线，后续产品功能、页面数量和业务流程调整均在此基线上展开。

本文档解决以下问题：

- 统一窗口框架、导航、状态栏、任务与日志面板。
- 统一字体、字号、密度、间距、颜色、圆角和阴影。
- 统一按钮、表单、表格、面板、弹窗和反馈状态。
- 明确浅色、深色、减少动画、列表条数和工作台数据目录等全局偏好。
- 为 Rust/Tauri 重构提供可直接落地的前端结构和验收依据。

本文档不独立决定业务功能；当前项目的菜单层级和核心页面交互以产品设计为准，本文同步记录已经通过 Demo 评审的稳定落地约束。

表格型页面以已实施的一体机列表为公共视觉样板。页面标题、六项概览、筛选工具栏和数据行的尺寸须核对实际页面结构与最终生效样式；基础设计令牌不等于每个组件最终字号或高度。具体实现对应关系见第 16.4 节。智能屏交互原型沿用该基线，原型页面不作为真实设备业务已实现的证据。

## 2. 参考依据与取舍

### 2.1 参考工程

| 参考对象                                            | 主要吸收内容                                                           |
| ----------------------------------------------- | ---------------------------------------------------------------- |
| `D:\code\career\vibe-session-manager`           | 紧凑字体和桌面工作台密度；顶部全局菜单；左侧业务导航；底部状态栏；从底部向上展开的任务/日志面板；主题、密度、减少动画等全局设置 |
| `inxvision-assistance/inxaiot-device-simulator` | 简洁的中性色表面；清晰的边框层级；绿色主操作、浅绿色成功状态、蓝色信息状态、橙色警告状态；克制的圆角与留白            |
| 原 `inxaiot-edge-workbench`                      | 保留现场实施工具对高信息密度、状态可识别、长列表、持续日志和桌面窗口控制的实际需求                        |

### 2.2 吸收原则

1. 结构主要参考 `vibe-session-manager`：顶部管理全局能力，左侧承载业务功能，底部持续展示系统状态。
2. 视觉主要参考 `inxaiot-device-simulator`：浅色中性底、白色内容面、细边框、少阴影、低圆角、语义色明确。
3. 不直接复制任何参考工程的业务名称、数据、页面结构和品牌图形。
4. 不把“重新使用 Tauri”误认为“自动获得更好看的界面”；视觉质量必须由设计令牌、组件规范和页面约束保证。

### 2.3 明确不采用

- 不使用玻璃拟态、背景模糊、发光边框和大面积渐变。
- 不使用 14px 以上的大圆角作为普通面板默认样式。
- 不使用大面积阴影区分普通内容层级。
- 不把所有信息都包装成独立卡片，不形成“卡片套卡片”。
- 不使用超大页面标题、营销式留白和 Web 后台首页式大卡片阵列。
- 不在顶部和左侧重复放置同一组业务菜单。
- 不允许页面通过临时添加颜色、字号和间距破坏统一风格。

## 3. 设计目标

界面风格定义为：**简洁、紧凑、稳定、专业、状态清晰的桌面实施工作台**。

设计时按以下优先级取舍：

1. 当前状态和主要操作是否一眼可见。
2. 信息层级和操作顺序是否清楚。
3. 长时间使用是否舒适，是否避免视觉噪声。
4. 常用操作是否紧凑高效。
5. 不同窗口尺寸、系统缩放和主题下是否稳定。
6. 装饰性效果是否足够克制。

## 4. 整体窗口框架

### 4.1 标准结构

```text
┌─────────────────────────────────────────────────────────────────────┐
│ 品牌 / 项目名称              任务  设置  关于                    —  □  × │ 48
├──────────────┬──────────────────────────────────────────────────────┤
│ 一体机管理     │ 页面标题 / 同行状态说明 / 页面主操作                       │
│  ├ 一体机列表  │──────────────────────────────────────────────────────│
│  ├ 发布参数    │                                                      │
│  └ 部署升级    │                  页面内容                             │
│ 智能屏管理     │                                                      │
│ 网关管理       ├──────────────────────────────────────────────────────┤
│              │ 活动面板标题栏：图标 / 任务 / 日志 / 面板操作                │
├──────────────┴──────────────────────────────────────────────────────┤
│ 运行状态  连接状态  当前项目                              任务与日志  数量 │ 24
└─────────────────────────────────────────────────────────────────────┘
```

### 4.2 区域职责

| 区域     | 只负责                             | 不负责               |
| ------ | ------------------------------- | ----------------- |
| 顶部应用栏  | 品牌、当前全局上下文、任务入口、全局工具、设置、关于、窗口控制 | 具体业务页面之间的重复导航     |
| 左侧导航   | 当前产品范围内的一级业务功能                  | 主题、关于、窗口控制等系统能力   |
| 页面内容   | 当前业务目标、数据、表单和操作                 | 长期运行状态、全局日志入口     |
| 底部状态栏  | 真实运行状态、连接状态、当前上下文、活动数量、日志入口     | 普通提示语、大段错误和业务操作按钮 |
| 底部活动面板 | 后台任务、进度和日志                      | 取代业务页面中的必要结果与错误说明 |

### 4.3 窗口规格

| 项目      | 规范值                             |
| ------- | ------------------------------- |
| 默认窗口    | `1280 × 800` CSS 像素             |
| 推荐工作尺寸  | `1440 × 900` 及以上                |
| 最小窗口    | `1024 × 640`                    |
| 顶部应用栏   | 紧凑 `48px`，舒适 `52px`             |
| 左侧导航    | 紧凑 `176px`，舒适 `192px`，折叠 `52px` |
| 底部状态栏   | 紧凑 `24px`，舒适 `28px`             |
| 主内容最小宽度 | `760px`                         |

当前样式在窗口不超过 `1080px` 时以折叠宽度显示左侧导航；用户手动折叠状态另行保存。顶部在不超过 `1180px` 时隐藏全局菜单文字，保留图标、提示和可访问名称。不得通过无限缩小字号适配窄窗口。

### 4.4 Tauri 自定义标题栏

- 使用单一自定义标题栏，不叠加系统标题栏。
- 品牌区和空白区可拖动；按钮、下拉框、输入框不得属于拖动区域。
- 双击非交互区域执行最大化或还原。
- 窗口按钮固定在最右侧，与全局菜单之间使用左边框分隔。
- 最小化、最大化、关闭按钮宽度统一为 `42px`。
- 关闭按钮仅在悬停和键盘聚焦时使用红色背景，常态保持中性。
- 标题栏不得放置会随页面变化的大标题，页面标题留在内容区。

## 5. 信息架构与排版

### 5.1 顶部与左侧分工

- 顶部回答“当前处于哪个工作环境，以及怎样管理整个应用”。
- 左侧回答“当前要进入哪个业务功能”。
- 若未来存在项目、站点或环境切换，选择器放在品牌右侧，作为当前上下文，不新增一套横向业务菜单。
- “任务”“设置”“关于”等全局入口固定在顶部右侧。
- 左侧导航最多直接展示 7 个一级入口；超过后必须重新分组或收敛信息架构。
- 当前项目不显示“业务功能”“后续能力”等说明性分组标题；一级入口直接使用“一体机管理”“智能屏管理”“网关管理”。
- “一体机列表”“发布参数”“部署升级”作为“一体机管理”的二级入口；“智能屏列表”“智能屏操作”作为“智能屏管理”的二级入口。开发浏览器和专用桌面原型模式中的能力需标明“交互原型”，不得据此将正式桌面未接入的能力标为可用。网关在尚无业务实现时保持“规划中”。
- 顶部项目选择器只显示项目名称、连接状态和展开图标，不重复显示“当前项目”标签；项目名称在标题栏内垂直居中。

### 5.2 页面头部

默认页面头部只包含页面标题和右侧操作。只有信息会直接影响当前判断时，才增加同行状态摘要或一行说明。

规范：

- 页面头部最小高度 `32px`，上下居中，左右内边距 `2px`；标题外边距为 `0`，与右侧动作区间距 `20px`。标准字号下标题为 `22px`、行高 `1.2`（约 `26.4px`），直接沿用公共标题样式。
- 页面头部与内容首块、相邻区块使用 `10px` 间距。公共工作区已提供紧凑 `12px`、舒适 `16px` 的页面外缘留白，业务页面不再叠加一层同值内边距。
- 不重复显示已经由左侧导航表达的业务上下文，不使用“一体机管理”一类眉题。
- “查看项目最终资产……”等能够从页面内容直接理解的说明应删除；必要说明最长一行。
- 校验状态、最后修改人/时间等短信息可紧跟标题同行展示，使用次级字号和语义图标。
- 页面主要操作固定在右上角；同一区域最多出现一个高强调实心按钮。
- 当页面已有页签时，页签紧接页面头部，不再套一层无意义大卡片。
- 交互原型的说明采用标题旁小标记，详细说明放入悬停提示；不增加独占一行的模拟数据横幅、场景切换或重置工具栏。

### 5.3 内容组织

- 一个页面只设置一个主要纵向滚动区域。
- 数据表、日志和长文本可拥有自身滚动区域，但不得与页面滚动争夺同一段内容。
- 普通内容优先采用“分区标题 + 面板”，统计摘要才使用小型指标卡。
- 同一级面板的边框、圆角和内边距必须一致。
- 同一行卡片保持等高；无法等高时改为自然内容流，不强行制造大面积空白。
- 重要信息按“状态 → 主要数据 → 原因/说明 → 操作”排列。
- 路径、哈希、标识符等长内容默认单行省略，悬停显示完整值，并提供复制能力。

## 6. 设计令牌

所有业务页面必须消费统一设计令牌。除图表数据系列外，禁止在业务组件中直接写十六进制颜色。

### 6.1 字体

```css
--inx-font-ui: "Microsoft YaHei UI", "PingFang SC", "Segoe UI Variable Text",
  "Segoe UI", "Microsoft YaHei", sans-serif;
--inx-font-mono: "Cascadia Code", "SFMono-Regular", Consolas, monospace;
```

- 中文界面优先使用系统中文字体，不在线加载字体。
- 全应用按钮、状态标签及原生控件统一继承`--inx-font-ui`；Windows优先使用Microsoft YaHei UI，使中文行框与字形采用一致的字体度量，保持文字上下居中。根节点直接引用该令牌，避免另行维护字体列表。
- 面向使用者描述本地运行位置时统一使用“当前电脑”“其他电脑上的工作台”等业务语言，不使用“实例”作为界面文案。
- 路径、IP、MAC、端口、命令和日志使用等宽字体。
- 正文和表单字段标签默认字重 `400`；次级标题可用 `500`；页面标题和重要数据 `600` 或 `700`。不要把普通字段名写成粗体标题。
- 不使用细于 `400` 的字重，避免 Windows 缩放后发虚。

### 6.2 全局字号

设置中提供三个离散选项，不提供任意滑块：

| 字号模式  | 基础字号   | 表格/辅助文字 | 页面标题   | 适用情况      |
| ----- | ------:| -------:| ------:| --------- |
| 小     | `12px` | `11px`  | `20px` | 高分辨率、大数据量 |
| 标准，默认 | `13px` | `12px`  | `22px` | 日常使用      |
| 大     | `14px` | `13px`  | `24px` | 高缩放或阅读优先  |

上述表格定义全局基础字号。当前列表样板另有固定组件字号：概览标签 `11px`、数字 `21px`、数字旁说明 `9px`；原生表格表头和单元格副行 `10px`。这些辅助字号按第 8.3、8.4 节复用，不将全局基础字号再次覆盖到组件上，也不把 `9px` 扩展为正文或操作按钮字号。字号偏好仍由根节点属性统一驱动，业务页面不得维护自己的全局字号开关。

标准模式下，全工作台常规正文和操作文字以 `13px` 为统一基线，覆盖智能屏、一体机、项目管理、系统设置、关于、弹窗、抽屉与任务面板。按钮、输入框及占位文字、选择器及选项、表单标签、状态标签不得因组件库默认值而出现 `14px` 或更大的常规文字。已有不大于 `13px` 的专用紧凑文字保持其字号，不为统一基线而抬高。

必要的区块标题可使用 `14px`，页面标题和统计数字保留已定义的层级。此规则只约束文字字号，不改图标尺寸、控件高度、行距和边距。用户主动选择“小”或“大”字号时，普通文字继续随全局偏好映射；固定的摘要辅助文字、表头、副行与其他较小专用字号仍遵循各自规范。

### 6.3 间距

使用 4px 基础网格：

```text
2  4  6  8  10  12  16  20  24  32
```

| 场景      | 紧凑     | 舒适     |
| ------- | ------:| ------:|
| 页面内边距   | `12px` | `16px` |
| 列表页面区块间距 | `10px` | `10px` |
| 面板内边距   | `12px` | `16px` |
| 表单行间距   | `8px`  | `12px` |
| 工具栏控件间距 | `6px`  | `8px`  |
| 图标与文字   | `6px`  | `8px`  |

### 6.4 圆角与阴影

| 令牌                | 值      | 用途         |
| ----------------- | ------:| ---------- |
| `--inx-radius-xs` | `3px`  | 状态标记、进度条   |
| `--inx-radius-sm` | `5px`  | 按钮、输入框、导航项 |
| `--inx-radius-md` | `8px`  | 面板、卡片、下拉层  |
| `--inx-radius-lg` | `10px` | 弹窗、抽屉      |

- 普通面板不使用阴影，只使用边框和背景区分。
- 下拉菜单、Popover 使用 `0 8px 24px rgb(15 23 42 / 14%)`。
- Modal 使用 `0 18px 48px rgb(15 23 42 / 20%)`。
- 深色主题阴影透明度可提高，但不得产生明显发光效果。

### 6.7 颜色职责

- **蓝色**：导航选中、链接、焦点、信息、普通配置类主操作。
- **绿色**：连接成功、校验通过、运行正常，以及已满足前置条件的“启动/执行”类主操作。
- **浅绿色**：成功状态背景和低强调正向提示，不作为大面积页面底色。
- **橙色**：需要关注、待确认、部分完成、可重试。
- **红色**：失败、断开、危险和不可逆操作。
- **灰色**：未开始、不可用、禁用和普通辅助信息。

同一操作区只能有一个最高强调按钮。如果当前主要动作是“执行/启动”，使用绿色；如果是“保存/下一步/查询”，使用蓝色。不得同时放置多个绿色或蓝色实心按钮争抢注意力。

## 7. 密度系统

字号和密度是两个独立设置：字号控制文字大小，密度控制控件高度、内边距和行距。

| 元素       | 紧凑，默认  | 舒适     |
| -------- | ------:| ------:|
| 普通按钮/输入框 | `32px` | `36px` |
| 小按钮      | `28px` | `32px` |
| 左侧导航项    | `36px` | `40px` |
| 页签       | `34px` | `38px` |
| 原生列表表头   | `32px` | `32px` |
| 表格行基础高度  | `36px` | `44px` |
| 状态徽标     | `22px` | `24px` |

约束：

- 默认采用紧凑模式。
- 触控不是当前首要目标，但舒适模式的常用交互目标不得低于 `32px`。
- 密度切换必须整体生效，业务组件不得私自定义第三套尺寸体系。
- 不通过缩小字号模拟紧凑模式。
- 一体机列表的筛选框、下拉框和头部按钮使用组件的小尺寸：紧凑 `28px`、舒适 `32px`。工具栏最小高度 `40px`、上下内边距 `5px`；不要用默认 `32px` 控件再叠加宽松内边距来仿制该工具栏。
- 原生表格行的高度是基础值，不是裁切上限；名称副行、时间或状态文字可将实际行撑高。不得统一附加 `22px` 空白来容纳副行，也不能把双行内容压入固定 `36px` 高度导致裁切。

## 8. 核心组件规范

### 8.1 按钮

| 类型    | 用途            | 视觉              |
| ----- | ------------- | --------------- |
| 普通主按钮 | 保存、下一步、查询、创建  | 蓝色实心            |
| 运行主按钮 | 连接、校验、启动、执行   | 绿色实心            |
| 次按钮   | 返回、取消、选择文件、刷新 | 白色/透明底 + 边框或浅底  |
| 文字按钮  | 查看详情、复制、表格行操作 | 无边框，悬停出现浅底      |
| 警告按钮  | 重试、强制继续等需注意操作 | 橙色边框或浅底，执行前解释风险 |
| 危险按钮  | 删除、清空、不可逆覆盖   | 红色；默认不与主按钮相邻混淆  |

- 按钮文案使用动词或动宾结构，如“保存设置”“开始校验”。
- 常规按钮文字在标准字号模式下使用 `13px`；表格行操作等已有较小文字保持原有大小。按钮的尺寸选项控制高度和留白，不自行放大文字。
- 图标按钮必须提供 Tooltip 和可访问名称。
- 加载状态保持原宽度，避免工具栏抖动。
- 禁用按钮必须同时提供不可操作原因，不能只降低透明度。

一体机和智能屏列表底部的“批量操作”采用相同规则：未选设备时使用中性底色和灰色文字并禁用，不保留淡蓝色或绿色底；选中后使用蓝色实心底、白色文字。文字右侧固定显示斜向右上的箭头，表示进入操作页面，点击不直接执行设备任务。

两个列表共用 Vue 组件文件 `src/shared/components/AssetListFooter.vue`。左侧依次为列表统计、分隔线、已选数量和批量按钮，右侧为分页及可选更新时间。底部使用页面表格字号、上下 `6px` 和左右 `10px` 内边距；批量按钮使用 Tiny 紧凑尺寸，分页使用 Small 尺寸，文字、按钮及分页垂直居中。未选择时仍显示“已选 0 台”。窄窗口允许分组换行，不挤压或裁掉分页；底部固定，设备列表独立滚动。

标准字号、紧凑密度下，两处按钮实测高度 `22px`、底栏高度 `35px`、字号 `12px`。浅色和深色主题下，选中、悬停、聚焦和按下的按钮文字均为白色；该规则由共用组件的局部主题控制，不改变其他按钮。2026-10-08 的 27 项交互回归及 16 个界面场景通过，截图和测量位于工程目录 `.review-tools/batch-footer-20261008/`。

### 8.2 输入与表单

- 设置类表单优先使用单列，标签宽度建议 `104px`。
- 业务配置在空间足够时可使用两列，但字段阅读顺序必须从左到右、从上到下自然连续。
- 批量设备操作中的少量参数优先使用紧凑双列，各列共用标签宽度，标签与控件同行并垂直对齐。未读取、空值、加载等常规状态放在控件内，不在每个标签下方增加状态说明行；具体规则见第 14.5 节。
- 发布参数等高密度双列表单采用“标签 + 输入框”同行布局；紧凑模式标签列 `8em`（标准字号约 `104px`）、右对齐，随字号偏好变化，避免短标签只剩一个字另起一行。输入内容保持左对齐，标签与输入框间距 `5px`，表单行间距 `10px`。
- 输入框、选择器和按钮在同一行时高度一致。
- 标准模式的输入文字、占位文字、选择器已选值、下拉选项和表单标签采用 `13px` 常规基线；已有较小的专用说明或紧凑控件保持原有字号。下拉浮层与页面内控件必须核对同一字号，不因浮层独立渲染而回到组件库默认值。

操作表单使用固定的文字层级，智能屏与一体机共用，不按单个字段另定字号：

| 内容 | 小 / 标准 / 大字号偏好 | 字重与要求 |
| --- | --- | --- |
| 字段标签、输入值、占位文字、选择器已选值和选项、复选框/单选框文字、文件选择按钮 | `12 / 13 / 14px`，使用样式变量 `--inx-font-size-base` | `400`，同一表单保持一致 |
| 字段说明、文件大小、安装包版本/架构、校验反馈 | `11 / 12 / 13px`，使用样式变量 `--inx-font-size-table` | `400`，比输入内容小一档，不混用固定 `10px`、`11px` |
| 真正的分区标题与统计数字 | 沿用标题、统计各自的层级 | 可保留必要强调；不能将普通文件字段名误作分区标题 |

“本地 APK 文件”、镜像文件对应的服务名和“一体机脚本”等文件字段名称属于普通标签，不使用 `strong` 的默认粗体。小尺寸文件输入框及其“选择”按钮只保持较小控件高度，文字仍与其他字段一致。表格中的详情等辅助小按钮不因此一并放大；输入框内的撤销、统一等附属动作可用辅助字号。模板编辑区保留等宽字体，输入文字仍使用基础字号，底部校验说明使用辅助字号。
- 路径字段使用“只读输入框 + 选择按钮 + 可选打开目录按钮”。
- Windows底层返回的`\\?\`扩展路径前缀只用于内部文件访问，界面统一显示普通盘符或UNC路径，不向使用者暴露系统路径语法。
- 密码默认隐藏，显示按钮仅切换视觉状态，不把明文写入日志或长期前端状态。
- 必须常显的帮助文字紧贴字段下方，使用次级文字色；仅作补充的解释使用标签提示或详情，不为每项预留空白说明行。校验错误和必须确认的业务影响仍在对应字段附近完整可查。
- 校验错误显示在字段附近，并在页面顶部提供可定位的错误摘要；不得只使用红色边框。
- 智能屏新建/编辑使用单一“空间选择”树，允许选择任意有效层级；完整路径统一以 `/` 连接且不添加两侧空格，如 `A座/2F/东区/会议室`，节点名称内部空格保留。列表筛选仍只展开楼幢/楼层。楼幢直属是有效关联，目录暂不可用时保留已有路径并提示待核验，不显示成未关联。该空间交互本轮仅用于智能屏。
- 智能屏导入预览提供空间路径、匹配结果和树修正，可给选中行批量分配空间并复制/导出当前项目路径。错误行默认勾选，复选框仍可取消；存在选中错误行时禁止提交，不自动略过或将无匹配路径改成待定。明确空路径可标为“待定空间”。

### 8.3 面板与指标卡

- 普通面板采用 `1px` 边框、`8px` 圆角、白色或主表面背景。
- 面板标题栏高约 `40px`，左右内边距 `12px`，必要时右侧放置一个次级操作。
- 列表概览沿用一体机的六列等分布局，列间距 `8px`。智能屏依次使用“管理记录、平台已注册、平台未注册、平台在线、平台离线、疑似重复”六项；平台未注册统计当前电脑尚未关联平台的记录，疑似重复按候选组计数，不能冒充独立物理设备数。
- 每块概览两行：第一行是图标与标签，第二行是数字与同一基线上的简短说明。说明必须紧邻数字右侧，溢出时省略并提供完整提示，不另起第三行。
- 概览最小高度 `58px`、内边距 `7px 11px`、行间距 `3px`；标准字号、紧凑密度下，一体机实际内容高度约 `61px`。以内容自然撑高为准，不把 `58px` 设为固定高度。
- 标签 `11px`，当前样板行高约 `17.6px`；数字 `21px/24px`、粗体；说明 `9px`，行高约 `14.4px`。数字与说明间距 `8px`，按文字基线对齐。不得使用 `24～28px` 大号数字或上下堆叠说明重新制作卡片。
- 数字统一采用深灰中性色，实际颜色为主文字色与次文字色按 `86%/14%` 混合；标签采用次文字色，说明采用弱文字色。在线、离线等含义只给图标着色，不给整块数字或文字上色。
- 图标 `14px`、描边 `2.2px`：全部/平台记录用信息蓝，在线用操作绿，离线用危险红，待处理/本机未注册用警告橙，冲突/疑似重复用危险红与警告橙按 `82%/18%` 混合。
- 流程工具栏和执行摘要中的关键数字使用状态色提高辨识度：当前选择/目标数使用信息色，可用总数使用操作色，未完成的文件数量和预计时长使用警告色，文件齐全后转为操作色；普通表单输入值不按状态指标着色。
- 指标不可用时显示“不可用”或“—”，不得用 `0` 冒充。
- 高度不超过 `700px` 时允许隐藏数字旁说明，保留标签、数字和操作。宽度不超过 `1080px` 时当前公共概览维持六列、每列至少 `125px`，必要时仅概览区域横向滚动；不根据过窄预览窗口把摘要改为高大多行卡片。
- 不给每个面板增加彩色边框；颜色只表达状态或交互。
- 智能屏页面顶部的读取失败、平台认证失败、平台不可用等问题合并到一个提示框，逐条分行显示，每条保留独立图标并与该条首行文字对齐；相同内容只显示一次，有错误时使用错误样式，否则使用警告样式。

### 8.4 表格和列表

- 表头使用次表面背景和细边框，不使用高饱和色。
- 列表样板的原生表头高 `32px`、文字 `10px/600`、左右内边距 `10px`；数据单元格沿用全局表格字号，内边距 `7px 10px`。副行文字 `10px`、上间距 `2px`、弱文字色，不为全部数据行追加固定增高。
- 文本左对齐，数字右对齐，状态居中或左对齐但同列一致。
- 首要标识列可使用 `500～600` 字重，其余单元格保持常规字重。
- 选中行使用浅蓝背景和可见的左侧标记，不只改变文字颜色。
- 悬停行仅使用浅灰蓝背景，不增加阴影或位移。
- 表头在长列表滚动时保持固定。表头可与滚动数据体拆分，但必须共用列宽定义，所有列保持严格对齐。
- 纵向滚动条只属于数据行区域，不延伸到搜索工具栏和固定表头。
- 智能屏列表与一体机列表采用相同规则：表头与滚动数据体分开，共用列宽定义；数据区复用公共细滚动条样式，滑块使用低不透明度，鼠标移出数据区后透明隐藏。滚动槽位始终占宽，显隐不得改变内容宽度或导致列错位。
- 行操作固定在最右侧；直接操作不超过 3 个，其余进入“更多”菜单。
- 智能屏列表的空间侧栏先显示“待定空间”，再显示“全部空间”；两项前置同风格线性图标，保持一致尺寸和对齐。
- 智能屏筛选工具栏展示筛选控件和“重置”。底部分页栏左侧依次排列“当前显示 N / M 条”、竖分隔线、“已选 X 台”和“批量操作”，分页控件保持在右侧。已选数量只作文字汇总，不附加下拉箭头或菜单；全选和取消使用已有表头勾选控件，不另设独立操作行。
- 智能屏名称与疑似重复图标、文案同行，位置说明占第二行；重复提示不单独撑出第三行。“详情”采用小字号文字按钮，降低行操作的视觉权重。
- 默认后端分页，不一次加载全部数据后再由前端过滤。
- 全局“每页条数”支持 `20 / 50 / 100`，默认 `50`；页面因性能需要限制上限时必须明确说明。
- 空状态使用简洁线性图标、一行原因和至多一个主操作，不使用占据半屏的大插画。

### 8.5 页签

- 页面主模式切换使用线型页签，不使用大块胶囊按钮模拟导航。
- 页签数量建议不超过 5 个。
- 页签文字使用 `13px`，选中态以文字色和底部 `2px` 指示线表达。
- 页签切换不改变全局上下文，也不重置用户未提交的输入。

### 8.6 状态标签

- 标签必须包含文字，重要状态可增加图标；不得只用颜色圆点。
- 标签文字使用 `13px` 常规基线或已有较小字号；不同状态和尺寸不因组件默认值放大文字。
- 默认高度 `22px`，圆角 `4px`，左右内边距 `8px`。
- 同一对象存在多个独立状态时可并列多个小标签，不压缩成含义模糊的单一颜色。
- “成功”“运行中”“警告”“失败”“未开始”“不可用”使用固定语义映射。
- 部署任务、目标节点和历史记录必须把内部状态枚举映射为中文；未识别状态统一显示“状态未知”或“处理中”，不得把英文枚举直接呈现给用户。
- 一体机列表“最近服务检查”显示本机真实检查记录及完整检查时间；无本机记录使用中性色，记录时间变旧不能自动变为橙色告警。正常按真实逐项计数，容器异常用红色、版本偏差用橙色、检查未完成用中性色。详情合并服务状态、已部署/生效配置/实际镜像、镜像ID、检查来源和逐项时间，并提供“检查服务”只读任务入口。
- 一体机详情的服务卡片标题区统一使用无底色、无边框的“图标 + `12px` 中性文字”展示检查状态；未检查或未知用灰色问号，正常用绿色勾，异常用红色叉，版本偏差用橙色感叹号，沿用已有状态判定与文案。状态无点击或按钮式悬停效果，“检查服务”保留按钮外观。
- 详情的服务镜像统一使用“镜像版本”一行，优先显示实际采集镜像，未采集时展示已部署记录并通过悬停说明来源。只有实际与已部署版本不同才补充部署版本，生效配置也不同才补充配置镜像，避免正常场景重复占行。服务卡片两列排列、间距 `8px`，卡片内边距 `10px`，字段行距 `4px`，字段区与标题间距 `5px`，标签列 `72px`。镜像长值单行省略并提供完整悬停提示，原因及说明消息保留换行。
- 同一位置的成功、警告和失败标签必须复用完全一致的高度、内容盒和垂直居中规则；中文文字的上下可见留白应一致，不能只校准其中一种状态。

### 8.7 弹窗、抽屉与确认

| 类型     | 建议尺寸         | 用途           |
| ------ | ------------ | ------------ |
| 小确认框   | `420～480px`  | 退出、取消、简单危险确认 |
| 设置弹窗   | `520～640px`  | 全局界面和应用偏好    |
| 复杂配置弹窗 | `720～920px`  | 多分组配置、预览     |
| 普通右侧检查器 | `360～440px` | 简单上下文信息 |
| 资产详情抽屉 | `min(640px, 94vw)` | 一体机和智能屏详情，统一宽度与紧凑样式 |
| 底部活动面板 | 默认 `320px` 高 | 任务和日志        |

- 弹窗标题直接说明对象和目的。
- 页脚按钮右对齐，顺序为“取消/次操作/确认”。
- 危险确认必须展示对象、影响和可恢复性，不仅询问“是否确定”。
- 固定尺寸弹窗在矮窗口中必须让内容区滚动，标题和页脚保持可见。
- 普通详情优先使用非模态检查器，不频繁打断用户。
- 一体机和智能屏详情复用同一抽屉宽度、内边距与字段样式。资产字段按两列排列，每个字段的标签和值同行；长值单行省略并可悬停查看完整内容，分区与动作区保持紧凑。
- 共享详情正文内边距为 `12px 16px`，页脚为 `12px 20px`；字段标签列 `84px`、标签与值间距 `8px`，每个字段上下内边距 `6px`。分区标题为 `14px`，外边距 `14px 0 8px`。
- 一体机服务卡片按两列排列，四个服务占两行；长镜像名称单行省略并提供完整提示。版本差异、检查失败和数据冲突仍完整呈现。以 `1280×800`、标准字号下常规内容一屏查看为布局目标；服务或历史较多、窗口较矮时保留内容区滚动，不为免滚动裁剪信息。
- 智能屏合并表的四个列头加粗，“本机记录”“平台记录”标题文字后分别放整列选择复选框，不另设全选来源按钮。部分字段采用该侧时显示半选，已整列选中后再次点击不能清空来源；每个字段始终保持本机或平台二选一。
- 智能屏合并将“所在空间”作为一行，与名称、IP、MAC、尺寸、详细位置、小新版本构成七项；完整路径与实际节点 ID 整体采用同一侧，不提供楼幢和楼层分别拼配。长路径可完整查看，原始值、采用值和来源保持可辨识。
- 合并来源色仅用于两侧列标题和合并结果值：本机使用 `--inx-color-info` 信息蓝，平台使用 `--inx-color-operation` 操作绿，原始值保持中性。结果单元格不重复逐行显示“保留本机/平台”；选中的单选控件及来源数量汇总仍保留，来源识别不能只依赖颜色。
- 智能屏状态差异在同一表格单元格内依次显示本机结果标签、方向箭头、平台目标状态标签和平台原值，水平排列并垂直居中；平台原值使用较小的次级文字，不混入本机结果标签。全选与逐台选择各自保持对齐，逐台勾选框独立成列。
- 智能屏已注册资料编辑必须区分“平台已确认值”和“本机待提交资料”，保存草稿后保持原平台身份，不显示为新增未注册行或疑似重复。资料差异显示具体前后值，不能只用颜色或“有改动”代替；成功提交并回读后才显示平台已保存。
- 设备操作显示本次实际连接 IP，草稿不静默生效。IP、MAC、尺寸有待提交修改时，靠近操作参数显示涉及目标、当前地址及拟变更地址，提供查看修改与前往注册更新；设备写操作预检阻断该目标，只读检查仍明确按确认地址执行。普通名称、空间、安装位置草稿不阻断。
- 屏详情、安装/注册/设备检查结果以及同版本跳过检查提供“核对版本并同步平台”。版本抽屉并列展示目标 IP、平台原版本、本次读取版本、时间和结果；只对有差异且具备条件的目标开放勾选与“确认同步 N 台版本”。未安装或读取失败不清空平台版本，平台不可用时说明本机观测保留。所有新增文案沿用紧凑字号与语义颜色。
- “注册/更新到平台”检查页按新增、更新、无变化、需核对分类，逐屏显示 MAC 采集来源、失败原因及采用历史/暂不填的明确选择。有效空间与冲突错误靠近对应目标展示；不以整批通用确认替代逐屏决定，不要求返回其他操作先取 MAC。空间移动显示原、新完整路径及布点影响确认。
- 注册结果区分别显示新增、更新、无变化、失败和待核实的结果，不把结果分类保存为平台资产状态。平台缓存带读取时间与来源，平台断开时已注册屏仍保持一条视图；资料草稿提示不覆盖注册状态，不把缓存表现为实时平台数据。

### 8.8 提示与结果反馈

- 成功消息默认 3 秒自动消失。
- 普通信息默认 4 秒自动消失。
- 警告和失败至少保留 8 秒，并允许手动关闭。
- 全局消息使用浮层，不挤压页面内容。
- 页面关键失败必须在相关操作区保留结构化原因和处理建议，不能只依赖 Toast。
- 不展示原始异常堆栈、内部类型名或“操作已返回结果”一类日志式文案。

## 9. 底部状态栏与任务/日志面板

### 9.1 状态栏

状态栏持续显示少量、真实、可行动的状态：

- 桌面运行状态。
- 当前平台、环境或项目上下文。
- 连接和只读/可写状态。
- 后台活动数量。
- 最右侧“任务与日志”入口。

状态栏分段之间使用 `1px` 边框。文字默认 `11～12px`，每段可点击时必须有悬停背景和 Tooltip。数量只能表示真实活动任务数，不能用日志条数冒充任务数量。

### 9.2 展开方式

- 点击状态栏最右侧入口，从底部状态栏上方向上展开非模态停靠面板。
- 面板默认高度 `320px`，允许拖动调整，范围为 `200px～60vh`。
- 面板打开时主内容区可以继续操作，不使用遮罩层。
- 再次点击入口、点击关闭按钮或按 `Esc` 关闭。
- 记住本次会话中的开关状态、活动页签和面板高度。
- “任务”“日志”切换直接位于活动面板标题栏，替换重复的“任务与日志”标题；内容区不再单独占用一行页签导航。

### 9.3 任务页签

- 使用单层纵向列表，不使用横向卡片流。
- 默认排序：运行中、排队中、需要处理、最近完成。
- 每行至少包含状态、任务名称、当前阶段、进度、更新时间和可用操作。
- 任务目标数量与任务名称同行显示，更新时间列固定为可容纳完整日期时间的宽度并禁止换行。
- 任务进度单元格按“百分比 / 进度条”横向排列，百分比固定在进度条左侧；进度列与更新时间列保留清晰的视觉间隔。
- 进度未知时显示当前阶段，不显示虚假的 `0%`。
- 用户发起“检查执行条件”并进入后端检查后，任务页新增一条独立的本地预检任务。检查进度按真实逻辑事项计算：首次部署和整包升级为`3 + 2N`项，单服升级为`3 + N`项，其中固定三项是检查参数、检查镜像和检查批次，`N`是一体机数量；首次部署和整包升级再为每台一体机分别计算远端条件检查和模板渲染，单服升级只计算每台远端条件检查。事项开始时立即更新“正在检查……”文案并保持进度条动态运行，事项真实完成后才增加完成项数和百分比，不按耗时定时推算假进度。任务中的目标数量始终只统计实际一体机，公共事项不得创建会被计入目标数的内部目标。
- 部署/升级执行概览与任务页复用同一后台任务的目标进度，展示真实百分比和“已形成最终结果数 / 目标数”。执行概览分为信息、进度和状态三部分：任务信息上限280px，进度区域使用卡片剩余宽度，状态按文字内容完整占宽。进度区域上行为完成数量，第二行是固定44px并右对齐的百分比与进度条，两者中心线必须水平重合。数字与进度条间隔8px，进度条与状态间隔24px；不使用独立空白占位列或视口单位推算进度条宽度。仅文字内容可省略，图标光晕不得被信息容器裁切。相同窗口下阶段文案和任务编号变化不得改变进度条位置。任务事件触发即时刷新，`5 秒`轮询只作为事件遗漏或页面恢复时的兜底。
- 检查通过后，提交直接复用该次检查生成的执行快照创建部署任务，不再执行镜像归档、SSH、端口和模板结果等完整预检。任务创建期间按钮显示“正在创建部署任务”，取得真实任务后立即进入部署/升级阶段并展示真实进度条；后台为上传生成镜像快照和节点配置属于执行准备，必须显示自身进度。
- 后台工作线程取得部署任务后，页面和任务面板立即从“排队中”切换到“准备发布文件”；配置、镜像快照、发布包和节点渲染均显示中文阶段和真实进度，文件处理按字节更新。远端阶段从本地准备进度之后继续，百分比不得回退。准备或执行失败时保留最后真实进度并直接展示失败结果，日志中必须能找到具体原因。
- 取消、重试等操作必须根据任务真实状态启用。
- 标题栏在刷新前提供清空图标：任务页只允许清空已结束且不再承担后续提交凭据的任务记录，日志页只允许清空当前已结束任务的日志；操作前必须二次确认。运行、排队、检查失败、最终补写，以及“检查通过但尚未提交”的预检任务不可清空。
- 创建部署任务失败时必须显示后端返回的具体原因，并把提交开始、成功或失败事件写入对应预检任务日志；提交成功后“任务与日志”自动切换到新部署任务。若检查记录确实不存在，页面清除失效结果并引导用户重新检查。
- 整包/单服升级缺少远端当前版本时，检查页在对应一体机的“环境准备”中直接显示“当前一体机尚未完成首次部署，请选择首次部署”，不得等上传后才失败。执行阶段仍发生Agent错误时，结果列表直接显示该目标最后一条结构化失败原因，退出码作为辅助信息，不能只显示“失败”。

### 9.4 日志页签

- 使用等宽字体，默认 `12px`，行高 `1.55`。
- 每行结构为“时间 / 级别 / 来源或节点 / 消息”。
- 时间列固定为可完整容纳`YYYY-MM-DD HH:mm:ss`的宽度并禁止换行，级别、来源和正文从其后依次排列。
- INFO 使用中性色或绿色，WARN 使用橙色，ERROR 使用红色；正文仍保持可读的主/次文字色。
- 默认自动滚动到最新日志；用户向上滚动后暂停自动跟随，并显示“回到最新”。
- 支持按任务、级别和关键词过滤，支持复制选中行。
- 长行默认软换行，不产生整面板横向滚动；路径和命令可提供单独复制。
- 大日志使用虚拟列表或分段加载，禁止一次性跨 Tauri IPC 返回全部内容。
- 上传过程保留“开始上传”“文件上传并校验完成”“全部上传完成”和失败等关键日志；字节进度只用于更新进度条，不逐条写入日志列表。
- 部署预检日志按逻辑事项持久化检查结果，并在失败时写入经过脱敏的具体原因；事项开始可以只通过瞬时任务事件更新当前文案，不要求为短暂开始状态增加一条持久日志。SSH 登录、Docker、目录、空间和端口等内部子探针仍汇总到对应一体机的远端条件事项，不为每个子探针逐条生成日志。

## 10. 全局界面设置

设置入口固定在顶部应用栏。设置弹窗至少包含以下与业务无关的选项：

| 设置项  | 选项             | 默认值              |
| ---- | -------------- | ---------------- |
| 主题   | 跟随系统 / 浅色 / 深色 | 跟随系统             |
| 界面字号 | 小 / 标准 / 大     | 标准               |
| 界面密度 | 紧凑 / 舒适        | 紧凑               |
| 减少动画 | 开 / 关          | 跟随系统偏好，用户可覆盖     |
| 每页条数 | 20 / 50 / 100  | 50               |
| 左侧导航 | 展开 / 折叠        | 根据窗口宽度初始化，记住用户选择 |
| 数据目录 | 本机目录路径          | 首次启动使用应用默认目录       |

设置交互要求：

- 主题、字号和密度支持弹窗内即时预览。
- 点击“取消”恢复打开设置前的状态；点击“保存”后持久化。
- 所有偏好由一个版本化的全局 Preference Store 管理。
- 业务页面只能读取偏好，不得私自写入另一套同名配置。
- 多窗口存在时，主题、字号、密度和减少动画必须同步。

## 11. 动效

- 悬停和颜色变化：`100～140ms`。
- 下拉、Popover、导航折叠：`140～180ms`。
- 底部活动面板展开：`160～200ms`。
- 不使用弹跳、过度缩放、长距离滑动和持续发光动画。
- 加载超过 `300ms` 才显示加载反馈，避免快速操作闪烁。
- 开启“减少动画”后，非必要动画和光滑滚动时长设为 `0ms`；进度反馈仍保留静态状态变化。
- 必须同时尊重系统 `prefers-reduced-motion`。

## 12. 图标与品牌

- 全应用只使用一套线性图标语言。
- 普通图标为 `16～18px`，导航图标 `18px`，描边约 `1.6px`。
- 概览卡采用第 8.3 节的 `14px/2.2px` 图标规格，不能用普通图标规格覆盖已形成的紧凑概览。
- 图标用于辅助识别，不替代关键文字。
- 状态摘要允许图标使用蓝、绿、橙、红等语义色，但相邻标签文字保持统一中性色；不得让整段状态名称跟随图标着色。
- 禁止使用 Emoji 作为正式功能图标或状态图标。
- 品牌标记建议采用简洁的 `INX` 方形图形，尺寸 `32px`，圆角 `7px`。
- 品牌区只显示产品名和可选的一行短副标题，不能长期占用两行以上高度。
- 具体 Logo 资产在品牌方案确认后单独设计，本规范不沿用参考工程 Logo。

## 13. 文案与数据显示

- 页面标题使用名词，操作按钮使用动词或动宾结构。
- 状态文案描述事实，如“等待执行”“校验失败”，避免“好像异常”等模糊表达。
- 错误文案采用“发生了什么 + 影响 + 下一步”的结构。
- 日期、时间、数字、百分比和字节使用统一格式化器；用户可见日期时间统一显示为 `YYYY-MM-DD HH:mm:ss`，去掉 `T`、小数秒和时区后缀，不直接展示原始 RFC3339 文本。
- IP、MAC、端口、版本和哈希不翻译、不随意截断原值。
- 数据未知显示“未知”，不适用显示“不适用”，暂不可取得显示“不可用”，空值显示“—”；四者不得混用。
- 表格列名尽量控制在 2～6 个汉字，长解释放入 Tooltip 或帮助说明。

## 14. 响应式、缩放与滚动

### 14.1 宽度断点

| 宽度            | 行为                       |
| ------------- | ------------------------ |
| `≥ 1440px`    | 完整导航、完整顶部文字、可使用多列内容      |
| `1081～1439px` | 标准紧凑布局；不超过 `1180px` 时顶部全局入口只显示图标 |
| `1024～1080px` | 左侧导航按折叠宽度呈现，顶部全局入口只显示图标 |
| `< 1024px`    | 不作为主窗口支持范围，不再继续压缩核心字号和控件 |

### 14.2 高度断点

- 高度不超过 `720px` 时，减少重复说明和面板上下间距。
- 高度不超过 `640px` 时停止压缩核心字号和控件。设备批量操作页按第 14.5 节保留固定区，将剩余高度交给设备列表；长配置表单和详情弹窗使用自己的内容滚动区保证所有功能可达。
- 标题栏、状态栏、弹窗标题和弹窗页脚保持固定，不随正文滚走。

### 14.3 滚动规则

- 主工作区不出现横向滚动条。
- 表格在确实无法收敛列宽时允许表格内部横向滚动，但固定首要标识列和操作列。
- 桌面 WebView 滚动条使用约 `4px` 的细轨道，常态滑块透明或极低对比，悬停滚动区域时增强。
- 滚动容器必须使用稳定槽位，滑块显隐前后内容区宽度不得变化，不得出现鼠标移入时页面闪动。
- 智能屏列表的“所在空间”标题固定，仅下方空间列表滚动。列表复用公共细滚动条，顶部从标题下方开始；右侧内边距为 `1px`，滚动条靠近边框，将宽度留给列表内容。鼠标进入整个空间筛选区域时显示低对比滑块，离开时隐藏，隐藏后仍保留滚动条槽位。
- 原生抽屉内容区可通过公共类 `inx-scroll-area` 复用相同滚动条规则：轨道透明，悬停内容区时显示低对比滑块，鼠标离开内容区后滑块隐藏；标题和页脚不参与内容区悬停判断。
- 表格滚动容器从固定表头下方开始；滚动条按钮隐藏，滚动条高度不得覆盖工具栏和列头。
- 每个页面必须明确滚动所有者，禁止 `body`、页面和内层面板同时产生无边界纵向滚动。
- 部署升级选择阶段将部署模式与四步步骤条放在同一行：模式区随窗口保持约`220～250px`，标题与三行模式选项整体垂直居中，模式文字和右侧单选圆点紧凑排列；组合区域高度约`64px`，步骤条使用剩余宽度。步骤标题、圆点中心和连接线处于同一水平线，说明文字固定在标题下一整行且不得换行，紧凑宽度下使用省略号。内容区按约`55:45`分配目标列表与执行设置，选择阶段外层不滚动，节点列表使用剩余高度并独立承担纵向滚动，镜像设置区不创建独立滚动条。目标节点每行按“选择、名称、IP、位置、状态”五列单行显示，行高约`38px`，长文本省略但可通过标题提示查看完整值。
- “智能屏操作”页顶部依次为选择框、说明和步骤三列。常规列宽为 `170px`、`221px`、剩余宽度；窗口不超过 `1120px` 时为 `155px`、`184.25px`、剩余宽度。选择框与说明前两列宽合计分别为 `391px`、`339.25px`，说明优先单行、必要时最多两行并自动换行，不强行截断，悬停提供完整提示。
- “智能屏操作”页首步内容按左选屏、右参数约 `68.5:31.5` 分配宽度，右列最小 `280px`，窄窗口仍保留该最小宽度。首步不使用跨栏底部操作条；“安装检查”或对应动作按钮固定在右参数面板底部并占满该列，参数内容较多时在面板内滚动。后续检查和结果页保留必要的返回、明确执行及新操作按钮。
- 智能屏操作下拉框依次为“安装/升级小新”“注册/更新到平台”“修改小新配置”，其余动作沿需求表顺序。“注册/更新到平台”沿用操作页下拉框及三步条，步骤为“选择设备与资料 → 检查并预览 → 提交结果”，下拉框旁简述为“登记新屏或更新平台资料”，首步右侧提示为“新屏注册到平台，已注册的屏只更新信息，MAC信息会自动获取。”。首步支持资料编辑并点击“检查并预览”，第二步点击“确认提交 N 台”，数量反映本次选择；不复用合并弹窗的双方选源语义，也不增加顶部场景选择器。已注册草稿用“资料有变更”提示，“保存待提交修改”“核对并更新”“放弃本机修改”分别表达保存本机、进入同步和放弃草稿。布局、字号及滚动沿用公共规则，长空间路径和逐屏错误须完整可查。
- 智能屏安装参数只包含应用、本机 APK 文件、同版本覆盖、并发台数，选包显示名称和大小并允许更换。并发上限及其他目标排队的说明放在字段标签提示中，汇总区显示目标数量，安装动作另显示应用包就绪数，不重复并发上限；包元数据未解析时须明确提示，不能以预设版本、架构或模拟成功外观冒充真实安装结果。
- 智能屏安装按全部已选目标（含筛选外目标）校验同一种明确尺寸。混选时在“本地 APK 文件”标题后以警告色显示“一批只能操作同规格尺寸屏”，未知尺寸提示先确认；均禁用选包与安装检查，清除失效的旧包和检查但不取消设备选择。恢复同尺寸或更换 APK 已绑定的尺寸后重新选包；零目标可先选包并绑定首次明确尺寸，其他操作不套用此安装限制。
- 智能屏操作选择区与一体机采用同一图标标题、紧凑浅底工具条和约 `38px` 高的单行设备样式。智能屏按选择框、名称、IP、位置、尺寸、注册状态六列排列，保留四项筛选，不另加蓝色表头或把名称/位置、IP/尺寸堆成双行；业务列数可以不同，标题、字号、密度和选中样式保持一致。
- 智能屏选屏列表为“空间路径和安装位置”分配更多宽度；名称与位置两列的弹性宽度按 `0.8:1.3` 分配，IP、尺寸、注册状态保持固定列宽。名称和位置过长时仍可通过悬停查看完整内容。
- 一体机选设备工具栏依次为搜索、“选择全部匹配”“选择匹配在线”“清空”，最后显示“目标一体机”及已选/可选统计。智能屏工具栏在常规桌面窗口保持一行，依次为空间、注册状态、尺寸、搜索、“选择全部”“清空选择”、已选/匹配统计，不加“目标智能屏”前缀；筛选框与搜索框允许弹性收窄。智能屏搜索占位文字为“搜索”，完整的名称、位置、MAC、IP 范围通过悬停提示及可访问名称说明；筛选外已选数量放在图标标题的次行，不新增工具栏行。
- 智能屏“选择全部”只作用于当前匹配目标，当前匹配全部选中时切换为“取消全选”，两者均保留筛选外已选目标；“清空选择”清除全部已选。工具栏末尾统计保持完整单行，不因按钮和筛选重排改变选择范围。注册状态框仅轻微收窄，最小宽度保持 `104px` 并完整显示短标签；末尾已选/匹配两个数字各预留 `2ch` 宽度并采用等宽数字，使 `0～99` 变化不挤动筛选框，`100` 及以上允许自然扩宽，此规则仅用于该处统计。
- 智能屏参数内部同样复用一体机的浅底文件卡、文件只读输入框与选择按钮同行、同行表单和执行摘要样式；文件信息不另叠卡片。四项输入和设备校验属于各自业务规则，样式复用不引入一体机镜像或分批参数。
- 服务镜像的本地文件选择与镜像标签必须同行；解析出的标签以可选中复制、不可编辑的只读输入框展示，多标签另提供紧凑选择入口；单镜像归档没有解析出标签时，同一输入框切换为可填写并明确提示。节点搜索框控制在约`140px`并允许在紧凑窗口弹性收窄，“目标一体机”和已选统计保持单行，优先为选择工具文案、执行设置和镜像标签保留水平空间。

### 14.4 系统缩放

至少验证 Windows `100% / 125% / 150% / 200%` 缩放。不得根据截图像素硬编码物理尺寸；布局以 CSS 像素、弹性网格和 `minmax()` 为基础。

### 14.5 智能屏与一体机批量操作页面

实施人员需要在同一窗口核对一批设备、确认本次操作并查看逐台结果。本节适用于智能屏各项操作及一体机部署升级的选择、检查、确认、执行、结果和历史详情页面，目标是让更多设备同时可见，并保持参数、状态和操作按钮的位置稳定。

#### 14.5.1 固定区域与设备列表

| 区域 | 排版和滚动规则 |
| --- | --- |
| 页面标题、操作选择与步骤条 | 固定在上方，使用现有紧凑尺寸；不随设备数量增高 |
| 操作摘要、少量公共参数、必要提示 | 固定显示，重复说明合并；参数不为每台设备重复铺开 |
| 表头、筛选、选择统计 | 固定在设备数据区上方，表头与数据行共用列宽 |
| 设备数据行 | 占用剩余高度，内容超出时单独滚动；一台设备对应一行表格 |
| 分页、返回、确认执行、取消或重试 | 固定在所属操作区域，不能随设备数据滚出窗口；具体显示项沿用业务流程 |
| 操作日志 | 只保留“任务与日志面板”按钮，清除旧筛选并定位当前任务；不另设“本次日志”弹窗，不在设备结果下方追加日志区域 |
| 完整诊断 | 从明确按钮打开独立弹窗或抽屉，保留查看和导出能力；诊断文件与任务日志分开表达 |

- 页面外层、步骤内容和设备表格不得同时滚动同一批数据。纵向滚动条只从固定表头下方开始，到分页或底部操作区上方结束。
- 设备检查、注册预览、执行进度和历史结果统一采用表格；不为每台设备增加独立卡片、卡片标题和整块提示框。名称、IP、时间、状态等同类内容分别成列，同列字号、对齐方式和间距一致。
- 结果标题、时间摘要和批次状态在同一行垂直居中。状态标签使用统一高度，标签内文字保持垂直居中；标题摘要的对齐样式不得改变状态标签的内部排版。
- 从本机历史打开日志时，仍定位所查看的历史任务，面板刷新后也不能跳到其他任务。日志按当前任务分段读取，支持筛选和加载更早内容；日志读取失败或已清理时给出对应提示，不显示其他任务的日志作为替代。
- 设备行首先说明是哪台设备、当前状态以及需要处理什么。失败原因和下一步提示保留简短摘要；长文本可省略，但必须能通过悬停、键盘聚焦或详情按钮查看完整内容，不能只留下“失败”。
- 逐项检查、配置差异和服务明细按需在详情中展示，打开详情不应撑高列表外框或挤走固定操作区。MAC 沿用、空间变更、清空字段、风险操作等已有业务确认必须保留；列表明确标出待确认项，确认仍针对原设备和原字段，不因收紧布局自动通过或取消勾选。
- 一体机的公共检查与逐台检查分开表达，公共检查不计为设备。紧凑列表保留逐台结果及查看明细的方式，不能通过合并文案改变检查计数或执行条件。
- 配置与多数设备不一致时，在对应行显示“配置不同”等文字和状态色，悬停或点击可查看不一致的字段与值；读取失败、未知和未检查分别表达，不能把读取不到视为配置相同。

#### 14.5.2 参数对齐与文案

- 标签与输入控件同行。两列参数共享每列的标签宽度、控件高度和行间距，不让某项多出“当前：尚未读取”一行而导致左右错位。读取状态使用输入框占位文字；复选框、开关等没有占位能力的控件，可在控件所在行显示简短状态。
- 标签沿用被管理应用的实际名称。智能小新配置使用“选择环境”“OTA 地址”“WebSocket(可选)”“H5地址(可选)”“H5检测”，检测项文案为“检查H5地址”。选择环境即表示本次提交时切换环境，不另加“同时切换到此环境”勾选。
- 配置输入直接展示读取的值，修改后使用状态边框，并提供“已修改”提示供悬停或聚焦查看；不为每个输入增加“不修改 / 修改”选择器。没有修改的字段继续保留原有提交语义，视觉上的默认显示不能使其被批量写入。
- 少量参数优先按两列排布；智能小新配置的五项参数与“重新读取配置”共用三行六个位置。其他操作根据真实字段数安排，不强行添加占位项，也不把单服、整包、并发和确认等业务参数删掉以凑齐布局。

#### 14.5.3 滚动边界与例外

- 数据区复用公共约 `4px` 细滚动条：轨道透明，悬停数据区域时显示低对比滑块，移开后隐藏；槽位始终保留宽度。滚动条靠近数据区右边框，固定表头预留相同槽位，避免显隐或翻页导致错列。
- 长配置表单、完整诊断、日志和单台设备详情内容可以在各自面板或弹窗内滚动，标题和必要页脚固定。这些独立内容不属于“一台设备一行”的设备集合；不得为满足设备列表规则而裁掉内容或缩小到不可读。
- 选择阶段右侧参数较多时，沿用该参数面板自身的滚动；设备列表仍独立使用剩余高度。展开公共任务与日志面板后，主页面按剩余空间重新布局，不能遮住确认按钮或分页。

本节只规定显示和交互。操作范围、选择规则、校验、执行顺序、任务进度、取消和重试、接口、存储、权限与锁定逻辑继续使用原业务实现；分页和详情展开不得改变已选设备或待确认状态。

## 15. 可访问性

- 键盘焦点使用 `2px` 聚焦环和 `2px` 外偏移，颜色取 `--inx-color-focus`。
- 所有可点击元素支持键盘操作，语义按钮不得用无角色的 `div` 替代。
- 图标按钮、窗口按钮和折叠按钮必须提供 `aria-label`。
- 对话框打开后焦点进入弹窗，关闭后返回触发元素。
- 错误、警告和选中状态不得只依赖颜色，必须同时使用文字、图标或形状。
- 主文字和背景对比度目标不低于 `4.5:1`，大文字不低于 `3:1`。
- 日志实时更新不得持续抢夺屏幕阅读器焦点。

### 16.2 组件和样式策略

- 交互基础组件统一使用 Naive UI，避免重复手写 Button、Input、Select、Modal、Drawer、Table。
- CSS Variable（样式变量）负责主题颜色和全局字号、密度偏好；组件的最终布局还受公共选择器、页面结构和响应规则控制。实现时读取完整级联，不能只复制变量表或样式文件前段的旧定义。
- Naive UI `themeOverrides` 必须由同一组设计令牌生成。
- 常规字号必须同时映射 Naive UI 的公共字号、各组件尺寸字号及组合控件内部子组件；只设置公共 `fontSize` 不视为完成。选择器、树状选择器、下拉菜单和分页条数选择框须连同已选值、占位文字和弹出选项一起核对，保留已有较小字号和标题专属字号。
- 原生控件、系统设置和关于面板与业务组件消费同一字号基线；不得用全局通配选择器或 `!important` 将所有文字强制改为 `13px`，以免覆盖较小辅助文字、标题、统计数字和用户字号偏好。
- 复用一体机样板时须核对内部结构和最终生效样式。供两类业务共用的样式放在 `src/app/styles.css`，业务组件只补各自的列定义等差异；不能仅挂相同类名而仍依赖另一个组件的局部作用域样式，也不能保留会覆盖公共密度的重复业务样式。
- UnoCSS 或普通 CSS 只负责布局、间距和少量语义类，不大面积覆盖组件库内部结构。
- 标题摘要使用专用 CSS 类限定局部排版，不能用泛指子级 `div` 的选择器影响 Naive UI 状态标签组件 `NTag` 的根容器；保留组件自身的垂直居中、统一高度与不换行规则。
- `DesktopShell.vue` 只组织框架，不承载具体业务状态机。
- 页面按 `features` 拆分，禁止重新形成单个超大 `App.vue` 和不断追加的全局 CSS 文件。
- Tauri Command 用于短请求，Channel 用于日志和有序进度，Event 用于低频全局状态广播。
- 任务和日志数据必须分页、分段或虚拟化。

字号主题映射如下。表中的属性属于 Naive UI 组件库主题配置，令牌由已有样式文件 `src/app/design-tokens.css` 提供，映射集中在已有前端文件 `src/app/theme.ts`；多选标签的内部样式修正在已有样式文件 `src/app/styles.css` 中集中处理：

| 主题属性或文字层级 | 映射与约束 |
| --- | --- |

| `common.fontSizeMini`、`common.fontSizeTiny` | 默认保留 `12px`；操作表单内的紧凑文件控件通过局部主题映射到 `--inx-font-size-base`，只统一文字，不改变高度或表格小按钮 |
| `DataTable.fontSizeSmall` | 保留 `--inx-font-size-table`，小/标准/大偏好分别为 `11px`、`12px`、`13px` |
| `Form` 的左侧与顶部标签小/中/大字号 | `labelFontSizeLeftSmall/Medium/Large`、`labelFontSizeTopSmall/Medium/Large` 均映射 `--inx-font-size-base` |
| `Form` 的小/中/大校验反馈字号 | `feedbackFontSizeSmall/Medium/Large` 映射 `--inx-font-size-table`，保持说明文字小一档 |
| `Message.fontSize`、`Tabs.tabFontSizeSmall`、`Tabs.tabFontSizeMedium`、`Tabs.tabFontSizeLarge` | 映射 `--inx-font-size-base`；卡片正文继承公共字号，不重复覆盖 |
| 多选选择器的已选标签及其弹出标签 | 使用标签自身的组件字号变量 `--n-font-size`，避免内部固定 `14px` 覆盖已配置的较小字号；日志中的极小标签保持 `12px` |
| 局部区块标题、页面标题与统计数字 | 局部区块标题使用 `14px`；页面标题保持 `20px`/`22px`/`24px` 偏好映射，统计数字与较小辅助文字保持各自已有层级 |

普通操作表单中的紧凑文件控件使用新增 Vue 组件 `src/shared/components/OperationFormTheme.vue` 继承全局主题，只在当前表单内覆盖 Tiny/Mini 字号。该组件不增加布局容器，不改变控件高度、字段值、文件选择或提交行为。

选择器等组合控件的内部已选值和弹出列表应继承上述同一主题。若组件有独立字号属性，须在相应主题映射中统一处理，不能仅凭组件外层使用基础字号判定一致。

## 17. 页面设计检查规则

新增或重构页面前必须回答：

1. 这个页面只解决哪个用户问题？
2. 页面唯一的主要操作是什么？
3. 哪些信息是摘要，哪些必须进入详情？
4. 当前状态、失败原因和下一步能否在首屏识别？
5. 页面、表格和日志分别由谁负责滚动？
6. 1024×640、标准字号、紧凑密度下是否仍可完成操作？
7. 深色主题和大字号下是否存在截断、溢出或对比不足？
8. 是否出现了重复指标、重复操作入口或没有真实数据的占位内容？
9. 滚动条悬停显隐时内容宽度是否稳定，固定表头与数据列是否严格对齐？
10. 批量操作的参数、表头、分页和确认按钮是否固定，设备是否逐行展示；必要确认和完整错误是否仍可查看？

## 18. 视觉验收矩阵

每次形成新的 Shell、共享组件或核心页面时，至少完成以下组合验证：

| 维度         | 必测组合                        |
| ---------- | --------------------------- |
| 主题         | 浅色、深色、跟随系统切换                |
| 字号         | 小、标准、大                      |
| 密度         | 紧凑、舒适                       |
| 动画         | 默认、减少动画                     |
| 窗口         | 1024×640、1280×800、1920×1080 |
| Windows 缩放 | 100%、125%、150%、200%         |
| 内容         | 中文、英文、超长路径、长错误、空状态、加载、失败    |
| 数据量        | 空列表、1 条、50 条、100 条、300 条    |
| 日志         | 无日志、持续追加、大量日志、长行、错误过滤       |
| 输入         | 鼠标、键盘 Tab/Enter/Space/Esc   |

### 18.1 必须通过的视觉验收

- 顶部、左侧、内容、状态栏职责无重复。
- 主窗口无整体横向滚动条。
- 页面只有一个明确的主纵向滚动区。
- 主要操作在 3 秒内可被首次使用者发现。
- 所有语义色在浅色和深色主题下含义一致。
- 字号和密度切换后没有文字裁切、按钮抖动和表格错位。
- 标准字号下，智能屏、一体机、项目管理、系统设置和关于等页面的常规按钮、输入框、选择器、标签及正文实际生效字号为 `13px`，已有较小字号保持不变。同时检查主页面、弹窗、抽屉、下拉选项和分页条数选择，不能只检查根节点的字号声明。
- 切换小/标准/大字号后，普通文字按全局偏好变化；标题、统计数字、较小辅助文字保留规定层级，图标尺寸与布局间距不因字体统一被误改。该项与密度切换分别验收。
- 各控件尺寸均核对文字：常规小、中、大、超大尺寸遵循基础字号，微型和极小尺寸保持 `12px`，小尺寸数据表遵循表格字号令牌。标准模式不得残留组件默认的 `14px`、`15px` 或 `16px` 常规文字；必要的 `14px` 区块标题须与正文明确区分。
- 底部活动面板展开后不遮挡状态栏，主页面仍可操作；任务/日志切换位于面板标题栏。
- 滚动条悬停前后内容宽度不变；表格滚动条只覆盖数据行，固定表头和数据列无错位。
- 一体机与智能屏详情同宽，标签和值同行，长值可查看完整内容；常规窗口核对首屏完整性，多服务、多历史和较矮窗口核对滚动可达性，失败、差异和冲突信息不得被裁剪。
- 智能屏详情字段的值与标签使用相同字号、字重和行高，当前为 `11px / 400 / 1.5`，按首行文字基线对齐；字段值保留原文字色或状态语义色。长值换行不改变标签与首行的对齐关系。
- 运行中、成功、警告、失败和禁用状态不只依赖颜色。
- 不存在硬编码浅色背景导致的深色主题白块。
- 不存在大圆角、重阴影、发光和无意义渐变回流。

### 18.2 批量操作页面的回归检查

对第 14.5 节范围内受影响的页面，至少检查 `1280×800` 和 `1024×640` 两种窗口，覆盖空列表、单台、50 台和 300 台，含长名称、长 IP 或路径、长错误、读取中、未检查、部分失败及待确认状态。列表所用地址和值可以来自本机模拟数据，必须明确标识；界面检查不等于实机执行验收。

- 参数两列对齐，输入框和按钮完整可操作；标签没有被常规状态说明挤成不同高度。
- 滚动设备列表时，标题、参数、摘要、表头、分页和操作按钮的位置不变；只有数据行移动。悬停滚动条前后、切换页码与每页条数后，列宽保持一致。
- 长内容能查看完整值；详情弹窗可用键盘进入和关闭。失败、差异、待确认等状态同时具备文字提示，不能仅靠颜色识别。
- 翻页、筛选、打开详情后，设备选择和逐台确认保持原业务规则；提交目标、参数和值与调整前一致。对受影响的选择、确认和提交连接补充或运行已有回归测试。
- 覆盖智能屏安装检查、注册更新、设备维护及结果页，并覆盖一体机首次部署、整包升级、单服升级的检查、执行、结果和历史详情。无需为了检查排版真实安装、重启设备或写入平台。
- 取消、重试、结果核实、日志查看和必要风险确认仍可操作；运行中按钮的禁用条件、进度来源及状态含义没有改变。

实际验收记录应分别写明页面视觉检查、自动化回归和实机验证的范围与结果。尚未运行的检查列为待验证，不能因规范已更新就记为通过。

## 19. 后续设计顺序

产品功能确认后，界面设计按以下顺序继续：

1. 确认产品对象、用户角色和一级业务导航。
2. 绘制完整信息架构和页面职责矩阵。
3. 先实现空数据 Shell、主题、字号、密度、状态栏和活动面板。
4. 选取一个表格型页面和一个流程型页面制作高保真样板。
5. 验证样板后再扩展共享组件和其他页面。
6. 最后接入 Rust 后端真实数据和长任务，不用示例数据掩盖缺失能力。
