# 设置智能屏统一操作与验收

更新日期：2026-11-04。状态：分日期的自动化与界面验证见第5节；三屏15种非空组合、NTP清空/设回、共享单次重启及首屏正式读取并发已取得实机通过证据，见[三屏实机回归](51-三屏设置与小新配置实机回归.md)。小新配置已覆盖范围、原失败与独立切主屏本轮未覆盖分别记录。现有0.2.19 Windows交付包不包含统一设置，本轮未升版、打包、提交或发布。

## 1. 使用目标与范围

实施人员在Windows工作台选择需要维护的智能屏，通过“设置智能屏”统一处理保持ADB端口、NTP服务器、校准时间和关闭屏睡眠。允许4寸、10寸混选，按各屏已验证固件和实际权限确定可执行项目。“修改小新配置”继续用于小新应用设置。

仅修改`inxaiot-desk-buddy`（实施工作台桌面工程），界面、检查与任务编排运行在运维电脑；Android系统设置和设备命令在目标屏执行。使用现有项目上下文、设备身份检查、操作占用及任务记录，不新增平台业务字段。

## 2. 检查与交互

流程为首屏选屏并读取、第二屏设置内容、设置结果。首屏左侧固定保留标题、筛选选择和设备列表；右侧依次为说明、必要输入、并发台数、已选屏类型与数量及输入状态，读取按钮固定在右侧底部。共用布局见[界面规范第14.5节](../01-桌面工作台界面设计规范.md#145-智能屏与一体机批量操作页面)。

- 读取全程停留首屏，显示完成、在读与失败数量，整批完成后才进入设置页；全部失败时留在首屏说明原因。开始读取时冻结1—3台并发，用于本批读取和后续执行，不承诺跨页面全局限流。
- 默认勾选保持ADB端口、校准时间和关闭屏睡眠。初查读取四项状态，按这三项目标显示逐屏待处理数量。每个功能计一项，系统与硬件时钟共同归入校时项。
- 第二屏将前三项与“☐ NTP服务器”及输入框放在同一行。NTP默认不勾选，输入禁用；即使显示已读取的旧地址，也不修改、不计入待处理数量。勾选后输入启用，空值表示清除自定义地址，非空有效地址表示设置该地址，不另设恢复系统默认选项。多台原值不同显示混合值提示，不擅自采用一台的地址。
- NTP输入固定240px并保持最小宽度。两类配置页的底部采用设备数量、修改情况、只读并发三组摘要，分页和主按钮位于同一底部区域；原列表下方的重复统计行合并到该处。已选数用信息蓝，待处理或需重启数用橙色，零修改及无需重启用绿色，失败或阻断用红色。
- 初查三项均满足的屏仍保留，允许进入设置页填写NTP。最终所选项目均满足时不创建空任务。
- 待处理使用橙色，已满足使用绿色，不可执行或无法确认使用红色，未选使用灰色。详情逐项显示当前值、目标值、判定及原因；读取失败不能显示为已满足。
- 第二屏不显示并发设置控件、“重新读取”“重新检查”或“检查设置内容”按钮；本批并发值只在底部摘要展示。唯一主操作“设置智能屏”先自动执行真实预检，再提交待处理目标；存在不可执行目标时留页显示原因，整批不写；待处理与已满足并存时只提交待处理，全部已满足不创建任务。
- 勾选、目标地址、项目或设备范围变化后，原确认计划失效，下次主操作重新检查；结果必须与请求的项目、设备范围及顺序相对应。过期读取或本机草稿不能直接写入，重读时保留明确修改，失败后保留原因与可修正状态。
- 提交前显示实际处理设备数和重启影响。已满足项目不重复写入，未选项目不产生设备修改。

## 3. 逐屏执行规则

| 阶段 | 行为与完成依据 |
| --- | --- |
| 保持ADB准备 | 先检查运行端口和开机配置。已验证4寸固件已有厂家开机5555配置时只读跳过；需要修改的已验证10寸固件保存持久端口并回读，再允许后续保存 |
| NTP准备 | 仅处理明确选择的目标；保存服务器与自动校时设置并回读，保留时区。未勾选ADB且重启后管理端口无法确认时，不允许进入需要重启的NTP流程 |
| 共享重启 | ADB、NTP有待生效修改时，在必要保存通过后最多发送一次系统重启；记录重启前后启动编号，分别核实端口、NTP生效和授时结果 |
| 校准时间 | 重启及NTP处理后重新读取系统时间、启动使用的硬件时钟及自动时间设置。两项偏差均不超过15秒才只读跳过；否则沿用现有系统和硬件校时及回读 |
| 关闭屏睡眠 | 沿用接电保持唤醒的读取、限定写入与系统运行状态回读；已满足只读跳过，必要时只唤醒一次 |

各屏内部顺序执行，不同屏沿用最多3台并发。进度仅统计本次勾选项目，未选项目不计入完成比例。任一项失败停止该屏后续新操作，其他屏继续。共享重启前已经保存的两个子项必须保留各自真实状态；其中一项核实失败，不得把另一项已经发生的保存显示为未执行。

整台屏在设置和共享重启期间持续保持操作占用，避免其他工作台同时修改。重启请求已记录但新启动编号或开机完成状态尚未确认时，整台仍为待核实；某个子项已读到目标值不能提前结束共享重启的核实。

取消后停止未开始的操作；已经提交的写入或重启保留核实依据。断连、退出或命令响应不明确时只读核实，不重复写入、唤醒、重启或自动接续尚未执行的子项。已成功内容保留，重试仅带入原来失败或未执行的选择，再根据当前实际状态判断是否需要修改。

保存阶段记录失败时停止后续副作用。每次真实写入及共享重启前重新核对取消与设备占用，不能将此前一次检查视为整段操作持续有效。

## 4. 技术定位

`screen_settings`（统一操作类型）使用一个批量任务，每台屏保留四个子项结果与共享重启证据。`screen_settings_read`、`screen_settings_preflight`（Tauri桌面命令）分别提供当前状态读取和最终计划检查，执行、取消及核实继续使用既有任务通道。

逐屏设置保存在维护计划中，子项记录保存在既有本机任务JSON中；共享记录仍沿用现有工作台任务保存机制。NTP的新生效证据只需读取统一任务格式，没有存量独立NTP任务的迁移要求。历史其他独立动作的展示与核实行为保留。

原有时间、NTP、端口和睡眠的固件限制、设备命令及回读要求继续复用。为合并重启，NTP保存与生效等待分开；校时增加独立只读检查，避免伪造写入阶段判断已满足。组合任务在NTP之后重建时间项基准，防止合法的自动校时变化被误判。
