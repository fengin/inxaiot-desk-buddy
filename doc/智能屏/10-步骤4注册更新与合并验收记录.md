# 步骤 4：注册、更新与合并验收记录

> 状态：开发助手验收通过；用户人工复检留在步骤 1—6 完成后。
> 验收日期：2026-09-29。
> 代码范围：基线 `6021af1` 加当前工作区修改，未创建提交。

## 1. 交付结果

实施人员可从工作台登记本机屏，或提交已经保存的资料草稿。新登记及 IP/MAC 变更自动读取网卡地址；采集失败时明确确认历史值或暂空，身份冲突不能绕过。

人工合并按字段采用本机或平台资料，保留平台编号，并保存本机关联。原本机编号、实测与历史保留，不上传未注册阶段的旧操作。普通更新只修改资料字段；版本选源仅在明确的合并操作中使用应用版本字段，H5 版本保持原用途。

平台可能已经写入而本机保存失败时，保留原请求和平台编号。核实后补存关联及记录，不重新插入。提交期间的新草稿继续保留，包括人员明确改回旧值的情况。

## 2. 实现位置

| 位置 | 职责 |
| --- | --- |
| 新增 Rust 模块 `domain/smart_screen/registration.rs` | 登记预览、确认及字段定义 |
| 新增 Rust 模块 `infrastructure/smart_screen/registration.rs`、`merge.rs` | 登记、更新、合并和原结果核实 |
| 新增 Rust 模块 `write_context.rs`、`platform_write.rs`、`leases.rs` | 独立写连接、限定 SQL、多工作台占用与事务内校验 |
| 现有屏本机仓库及前端界面 | 同一事务保存关联、缓存、草稿处理和请求确认；正式界面不显示模拟提示 |
| 新增本机迁移 0004、0005 | 通用待核实结果保护，以及删除本机项目时清理其关联关系 |

写连接与原有只读连接分开。当前项目连接使用同一 MySQL 实例中的业务库和工作台专用库；写业务数据时，在该事务内校验并锁住对应操作占用，避免条件检查后被其他操作替代。

平台原保存方法还会修改空间展示配置及设备别名。工作台不调用这些附带修改，只写确认的字段；已有布点时阻止直接换空间。
