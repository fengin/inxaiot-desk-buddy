## 1. 使用目标与操作规则

项目实施人员在 64 位 Windows 运维电脑上使用 INX 实施工作台，对 Linux 一体机执行首次部署、整包升级或单服升级。工作台在文件上传完成后、安装或升级脚本执行前，自动核对一体机与当前电脑的系统时间；估算偏差超过 5 秒时，以电脑即时读数校准一体机，再读取一体机时间确认，减少设备时钟偏差导致平台注册请求签名被判定过期的情况。

当前电脑是本次校准的时间基准，实施人员应先确认电脑时间准确。平台服务器时间仍由平台运维人员独立维护，工作台校准一体机不等于平台时间已经正确。

- 估算偏差不超过 5 秒时，只记录核对结果，不写入一体机时钟。
- 需要校准时，`root`（Linux 管理员账号）直接执行校时；其他 SSH（远程登录协议）账号自动尝试 `sudo -n`（Linux 免交互提权命令），不读取或传递提权密码，不弹出密码输入或额外确认。
- 选择范围与检查确认区域均显示自动校时及提权规则；任务执行时显示“核对并校准时钟”。没有校时权限或免交互提权失败时，停止该台后续部署。
- 时间读取异常、单次读取往返超过 2 秒、电脑时间在核对期间发生明显跳变、写入失败或回读仍超差时，停止该台后续步骤，不继续执行安装、升级或首次注册。
- 取消及设备占用检查沿用既有任务机制，校时写入前再次检查取消状态与租约。校时失败不新增平台注册重试，也不恢复原先错误的系统时间。

只调整一体机系统时刻，保留时区、NTP（网络授时机制）自动校时配置及 RTC（硬件时钟）配置；不承诺重启或断电后的硬件保时。本版本只修改 `inxaiot-desk-buddy`（实施工作台桌面工程），不要求升级一体机设备服务、平台服务或智能屏应用，不增加数据库迁移。

## 2. 升级与使用

1. 等待旧工作台的活动任务结束，正常退出旧程序。
2. 核对本地交付程序的版本及校验值；使用压缩包时先完整解压。
3. 使用已核验的0.2.18 Windows免安装程序替换原程序，再正常打开，当前本地文件名及压缩包内名称见第3节。继续使用原工作台数据目录，项目连接、资产、凭据、任务历史和诊断无需重新导入；不要覆盖仍在运行的程序。
4. 部署前确认当前电脑时间正确、目标一体机身份及本次发布参数，按正常流程检查并提交部署。校时或权限失败时依据任务日志处理该台设备，不将失败结果视为平台注册成功。

既有 Windows 运行环境及回滚要求见[发布与回滚说明](16-Windows可信发布与回滚说明.md)。交付构建与成品自检不启动普通桌面实例，不打开或复制 `D:\data\com.inxaiot.desk-buddy`（生产实例数据目录）。

## 4. 技术定位与构建边界

桌面前端和后端运行在实施人员电脑，时间读取和系统时钟写入命令通过现有 SSH 会话在目标一体机执行。时钟步骤位于三类正式部署的公共远端执行链路，不在“检查执行条件”的只读预检中修改设备。

| 代码或文件 | 职责 |
| --- | --- |
| `src-tauri/src/infrastructure/deployment_clock.rs`（新增 Rust 文件） | 时间采样、可靠性检查、系统时钟校准、写前权限方式及回读确认 |
| `src-tauri/src/infrastructure/deployment_remote.rs`（已有 Rust 文件） | 上传完成后连接时钟步骤，复用任务日志、取消及租约检查，确认通过后执行后续脚本 |
| `src-tauri/src/domain/aio/deployment.rs`（已有 Rust 文件） | 三类部署的时钟步骤定义，不新增部署脚本协议动作 |
| `src/features/aio/operations/AioOperationsView.vue`（已有 Vue 文件） | 选择和确认区域的自动校时及提权说明、执行阶段中文展示 |
| `src/features/aio/taskPresentation.ts`（已有 TypeScript 文件） | 公共任务面板的时钟阶段中文名称 |
| `scripts/build-windows.mjs`（已有 Node 构建脚本） | 准备并内嵌 ADB（Android 设备调试程序），构建 Windows 单文件程序并执行独立包自检 |

时间比较使用确定时刻的毫秒时间戳，不依据双方显示时区。工作台以读取请求发出与返回的本机时间中点估算偏差；允许的读取往返时间不超过 2 秒，在此范围内非对称网络延迟可能带来最多约 1 秒采样误差。5 秒为估算偏差容差，不作为高精度授时保证。

本地构建调用已有 Windows 构建脚本，并由一次性辅助脚本直接运行类型检查和前端生产构建程序，避免通过包管理命令自动安装依赖。没有跳过前端类型检查或生产构建，不使用调试模式或桌面自动化专用构建。

独立成品验证使用 `--verify-package`（已有命令行参数），仅运行内嵌 ADB 版本检查及可选的本机 APK（Android 安装包文件）解析。验证进程的本机应用数据目录及工具路径指向新建隔离目录，不连接设备或项目数据库；该验证不能替代一体机部署及平台注册实测。
