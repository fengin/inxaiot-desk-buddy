## 3. 本次修复

### 3.1 部署结果缺少平台一体机 ID

首次部署已成功注册，但工作台保存结果时仍使用部署前的资料，其中平台一体机 ID 为空。现将注册后核对得到的真实 ID 随执行结果保存；已有工作台记录也能补齐关联，不覆盖已有名称、空间和位置。

技术定位：工作台 Rust 文件 `src-tauri/src/infrastructure/deployment_service.rs` 保存注册后的资料；Rust 文件 `deployment_finalization.rs` 在保存结果的同一事务中写入数据库表 `aio_node` 的字段 `platform_aio_id`。本机待补写文件同时保留该 ID。

### 3.2 首次注册补报覆盖空间

具体位置留空时，工作台需要在设备完成注册后补齐平台空间。实机发现设备第一次保存后还会补报注册资料，过早补齐的空间可能被旧的空空间值覆盖。

现先通过设备 HTTP 接口 `/api/aio/server/info` 核实设备身份及同步完成状态，再核对并保存平台空间。等待最多 90 秒，支持取消；没有确认完成时不能显示部署成功。本次没有修改或部署平台服务和一体机服务程序。

技术定位：工作台 Rust 文件 `src-tauri/src/infrastructure/device_api.rs` 等待设备同步状态；Rust 文件 `aio_registration.rs` 负责在当前操作占用下核对平台记录并补齐空间。
