# 配置保存、应用启动核验与设置页更新回归

## 业务目标和适用范围

实施人员通过工作台修改小新配置时，应分别确认配置是否已保存、应用是否完成所需的重启。配置管理组件独立运行时仍可读写配置，但该组件的进程不能作为主界面已经启动的依据。

屏端设置页保持打开期间，如果远程修改了语音参数，人员在屏上保存其他字段后，页面应显示合并保存后的最新数值。保存失败时应保留未提交输入；连续输入不应被控件重建打断。

本记录为 2026-10-22 的针对性回归，覆盖工作台与三台无线测试屏。配置读写继续使用独立的 Android 原生配置仓库，公共协议、字段定义、数据格式和语音启停业务规则保持不变。

## 实现规则与技术位置

| 工程 | 代码位置 | 实现 |
| --- | --- | --- |
| 实施工作台 `inxvision-assistance/inxaiot-desk-buddy` | Rust 文件 `src-tauri/src/infrastructure/smart_screen/app_config.rs` | 先确认配置回读，再独立核验重启。需要重启时，必须有本次请求证据、新进程及主界面运行证据；最多等待 15 秒 |
| 同上 | Rust 文件 `src-tauri/src/infrastructure/smart_screen/device_maintenance.rs` | 配置任务与普通重启复用只读的进程及主活动核验；区分等待结束与查询失败 |
| 小新 APP `inxvision-xiaoxin/voice-on-demand/xiaoxin-app` | Dart 文件 `lib/ui/pages/settings_page.dart` | 仅在成功接受读取或保存快照时更新控件标识，使五个语音数值输入框及采样率下拉框显示新值；普通输入、其他控件重建和保存冲突不触发替换 |
| 同上 | Dart 测试文件 `test/settings_page_test.dart` | 使用真实设置页面验证外部变更、输入焦点、冲突保留及小屏浮层 |

重启核验不足时保留“配置已保存并回读一致”，单独记录应用启动未确认。连接中断或读取超时保留待核实状态。结果核实仅查询，不重新保存配置或补发启动动作。无需重启的保存不要求主界面存在。

这里的启动核验确认新进程与 Android 主活动状态；业务 H5 初始化、语音引擎就绪及声学效果分别验证，不由配置回读推断。
