# 语音启动配置兼容与回归

> 日期：2026-10-21。范围：开发代码与本机隔离验证。三屏安装和后续实机结果见[语音启动配置实机联测](32-语音启动配置实机联测.md)；尚未发布。

## 1. 业务范围

实施人员在运维电脑的“智能屏操作 → 修改小新配置”中，读取一台或多台屏的实际配置，修改语音引擎是否随小新启动，检查影响后确认提交。前三个勾选按“检查H5地址、固定小新为主屏、语音引擎随应用启动”排列在左侧，重新读取按钮和进度在右侧，用间距区分。

语音启动开关是应用全局设置，切换查看环境不会改变编辑意图。读取、重读和恢复没有该字段的旧草稿均不自动修改设备。多屏值不一致时显示半选，明确操作后只对实际不同的屏生成变更；撤销后各自保留。

保存改变下次应用启动的行为。工作台复用原任务，在保存成功后重启小新一次并回读；与其他需要重启的配置组合仍只重启一次。同值无需重复操作。回读一致表示配置已保存，不证明语音已经就绪；权限、网络和业务准备仍按小新既有生命周期处理。

## 2. 新旧版本兼容

| 使用情况 | 处理规则 |
| --- | --- |
| 新工作台与支持新字段的小新 | 能力名单包含新字段、实际读取值为布尔类型时允许编辑 |
| 新工作台与旧小新 | 新项显示不可改及原因，原有地址、名称等配置仍可修改 |
| 能力声明存在，但值缺失、为 null、字符串或其他类型 | 新项保持未确认；不可用缺省关闭代替，不阻断其他配置 |
| 同批包含支持与不支持的屏 | 本批次禁用新项；取消选择不支持的屏后可编辑支持的屏 |
| 已编辑后重读发现不再支持 | 不提交原草稿中的语音字段，其他已编辑字段继续走原流程 |
| 旧工作台与新小新 | 既有局部保存请求不含新字段，新字段保持当前值 |
| 中断、保存结果未知或部分失败 | 沿用原保存、重启、回读独立记录；核实只读，不重放保存或重启，不把部分失败改判为全部成功 |

是否支持以字段能力为准，不能只看版本号。此前已生成的 2.1.0 APK 不会因工作副本代码更新而自动增加能力；实际使用需重新构建包含本次修改的小新包。

## 3. 技术定位

工作台工程是 `inxvision-assistance/inxaiot-desk-buddy`，运行在运维电脑。小新源码工程是 `inxvision-xiaoxin/xiaoxin-app` 工作副本，运行在 Android 屏。项目平台不新增业务字段或数据迁移。

| 位置 | 职责 |
| --- | --- |
| 工作台 Vue 组件 `src/features/smart-screen/ScreenAppConfig.vue` | 三个勾选与读取组的布局、批量选择、能力判断、编辑与草稿恢复 |
| 工作台 TypeScript 文件 `src/shared/model/screenAppConfig.ts`、`screenAppConfigEditor.ts` | 可选布尔值、能力检查、字段名称、差异和重启判断 |
| 工作台 Rust 文件 `src-tauri/src/domain/smart_screen/app_config.rs` | 字段白名单、严格类型校验、重启判断与共享结果 |
| 工作台 Rust 文件 `src-tauri/src/infrastructure/smart_screen/app_config.rs` | 安全读取、提交前校验、草稿模式、保存收据和回读核实 |
| 小新 Dart 类 `RemoteConfigHandler` | 允许字段名单和安全配置读取 |
| 小新 Kotlin 类 `WorkbenchConfigProvider` | 公告支持字段；继续使用原调用身份检查 |
| 小新已有 Dart 类 `ConfigService` 及配置保存实现 | 既有全局开关的校验、持久保存及下次启动规则，本次不重构生命周期 |

`autoStartVoiceEngine`（配置协议顶层字段）只接受布尔值。关闭通过 `set` 中的 `false` 提交，不能通过 `clear` 清空，也不能放进环境配置中。管理 URI 仍为 `content://chat.xiaoxin.app.workbench.config`，继续使用 `getCapabilities/readConfig/saveConfig`（已有管理方法）和协议版本 1，无新增 ADB 方法、端口或权限。`voiceMode`（工作台可选草稿字段）只允许 `keep/on/off`。

“固定小新为主屏”继续走 Android 系统持久主屏策略，与普通应用配置分别处理。新开关不改变主屏设置、激活和核实的执行顺序。
