## 1. 业务目标

实施人员在项目现场使用一台运维电脑，连接项目平台和目标屏，完成设备资料整理、注册或更新到项目平台、设备核对、应用安装升级、远程管理通道配置、校时、重启和故障检查。维护人员可以按楼幢、楼层、尺寸快速找到设备，了解平台记录与现场检查结果，批量操作并追踪每台屏的结果。

工作台服务于部署和维护。甲方业务平台继续负责空间、设备业务绑定、页面内容、业务布局和日常使用；工作台负责设备是否能维护、应用是否安装正确、配置是否符合项目要求，以及操作是否实际生效。

本功能只与项目侧平台协作，屏及小新应用是受管终端。云平台配置和同步项目信息属于上游过程，不参与工作台查询、状态覆盖或设备维护。工作台除登录认证链路外，项目业务数据采用数据库直连，查询和已明确的字段更新不依赖项目平台业务接口；具体设备操作使用设备自身协议。

预期结果：

- 平台已登记屏从平台读取；实施前期未登记屏先在当前工作台实例管理，资料齐备后从工作台注册到项目平台；已存在的平台记录通过明确关联更新，疑似重复另行人工核对合并。
- 现场脚本变为可选设备、可检查、可批量执行、可查看逐台结果的桌面功能。
- 4 寸和 10 寸屏可统一查看，执行时按真实系统能力和应用兼容性处理。
- 不要求运维人员理解命令行、进程返回码和内部协议字段。
- 平台关联屏的操作摘要按工作台既有机制项目共享；未登记屏的资产、检查与操作历史先保留本机，关联平台后保持可追溯，完整日志始终注明所在电脑。

本需求中的“小新应用版本”统一对应数据库表 `smart_terminal_screen` 的字段 `app_version`，工作台按平台已具备该字段接入。它表示已安装小新 APK 的版本名称，不是 Android 系统版本。已有字段 `version` 保留为屏内 H5 样式版本，功能尚未实现，本期不读作应用版本、不修改、不复制到应用版本字段。空间表已有 `screen_version` 也属于页面配置。字段使用约定见[整体技术方案](05-智能屏技术方案设计.md)第5.6节。

## 2. 首期范围与运维建议

### 2.1 核心需求

| 编号 | 功能 | 运维人员得到的结果 | 实现前提 |
| --- | --- | --- | --- |
| S01 | 项目概览、列表、详情 | 平台已注册、本机未注册、在线/离线和疑似重复数量；按名称、位置、MAC、IP、楼幢楼层和尺寸查找屏 | 本机项目可用；平台信息按连接情况读取 |
| S02 | 安装、升级小新应用 | 单台或批量安装小新应用，回读版本并确认启动结果 | 屏可管理、小新安装包兼容；其他应用不在首期范围 |
| S03 | 10 寸屏保持远程管理 | 5555 端口在重启后仍可连接，显示实际验证结果 | 当前已有可用管理连接，固件支持所需权限 |
| S04 | 校准系统时间 | 查看偏差、校准并回读验证 | 设备允许设置系统时间 |
| S05 | 获取、核对 MAC | 读取真实网卡地址；区分缺失、匹配和冲突 | 已验证的固件采集方式 |
| S06 | 在线检查与平台状态覆盖 | 本机检查 IP；与平台不一致时提示，用户确认后直接写表覆盖并回读 | 覆盖只适用于已关联平台屏，具备所需字段写权限 |
| S07 | 重启屏 | 发送重启并等待重新连接、开机完成 | 屏可管理；有恢复验证方式 |
| S08 | 管理小新应用配置（后续） | 读取配置、预览变更、修改并验证生效 | 需修改小新应用以提供管理通道；不作为首期交付门槛 |
| S09 | 批量任务与操作记录 | 进度、逐台原因、部分成功、取消、失败重试和历史 | 公共架构优化完成 |
| S10 | 本机未登记屏管理与合并 | 本机新增/导入未注册屏并执行运维；拉取平台数据后对相同 IP 或 MAC 提示合并 | 本机持久化、疑似匹配与人工确认规则落实 |
| S11 | 注册/更新到平台 | 未注册屏新增平台记录，已注册屏预览并更新资料；自动采集 MAC，确认后保存并回读 | 平台连接与登录就绪，空间有效，字段写权限、冲突检查及恢复规则落实 |

S01—S07、S09—S11 属于首期；S08 后置。平台注册更新、状态覆盖等通过工作台专用的受限数据库写入能力实现，不要求新增平台接口。小新应用本地设置页面继续保留，首期不提供未接通的远程配置按钮。

### 2.2 建议纳入首期的补充能力

| 建议功能 | 重要性 | 控制范围 |
| --- | --- | --- |
| 设备与应用检查摘要 | 区分平台在线、远程管理可用、应用已安装、应用可运行，直接指导故障处理 | 读取系统版本、处理器架构、剩余空间、应用版本、设备时间和管理权限；融入详情及操作检查，不增加独立复杂巡检系统 |

### 2.3 后续候选与不在首期的能力

后续可评估屏幕截图辅助远程诊断；小新远程配置按第 6 节推进。其他应用安装、系统 WebView 更新和修复暂不纳入本需求首期。

首期不建设远程桌面、任意命令终端、全网自动扫描、固件刷机、恢复出厂、通用应用商店或全天候监控服务。现有出厂优化脚本涉及系统应用、默认桌面和设备管理权限，不整体合并到普通运维按钮中。

## 3. 屏资产、身份与状态规则

### 3.1 两类资产与本机管理

列表合并展示当前项目的平台有效屏记录和当前电脑尚未关联平台的智能屏本机记录。未注册不影响安装小新、检查、校时、重启等设备运维；是否可执行由设备连接、身份和操作所需能力决定。

| 记录类型 | 保存位置与标识 | 管理规则 |
| --- | --- | --- |
| 平台已注册 | 平台资产以项目范围和平台屏主键定位 | 平台值保留为已确认事实；资料修改先保存独立本机草稿，通过“注册/更新到平台”预览差异并更新原记录，不生成新的未注册行。资产删除和业务布局仍由平台管理 |
| 平台未注册 | 本机 SQLite，使用项目内稳定的本机记录 ID | 支持单台新增、表格导入/批量录入、编辑和移出本机列表；名称、IP、尺寸及位置先在本机维护，MAC 可后续采集；重启工作台后保留 |
| 已注册或已合并关联 | 保存本机记录 ID 与平台主键的映射及已确认平台缓存 | 列表显示为一条平台关联屏；本机历史、采集信息和草稿仍归属该屏，重开或平台暂不可用时保持一条带读取时间的缓存已注册记录 |

- 本机未注册记录属于当前电脑，不自动同步到其他工作台。换电脑后不能假设会出现这些记录，后续如需迁移另行设计。
- 本机新增至少提供可连接的 IP，名称、尺寸可录入或后续补齐；导入需先预览格式与重复项，再确认保存。
- 新增或编辑本机未注册的智能屏时，使用一个“空间选择”树选择当前项目的有效节点；楼幢、楼层、区域、子区域及更深层级均可选择，不限定叶子节点。保存唯一实际空间节点标识，完整路径用于显示，楼幢/楼层由祖先链派生；详细位置仍是独立自由文字，不用于推断目录。
- “待定空间”只承接未关联空间或关联确实失效的记录。直接关联楼幢属于有效空间，不因没有楼层而归入待定。目录暂时不可用时，已有空间 ID 和路径保留并标注待核验，不自动清空或判为失效；新记录可明确留空，待目录恢复后再选择。
- 批量导入使用“空间路径”列，不再拆为楼幢和楼层。系统以 `/` 连接完整路径且不在分隔符两侧添加空格，例如 `A座/2F/东区/会议室`；导入可容忍旧输入分隔符两侧空白并规范化，节点名称内部空格保留。在当前项目内按任意深度完整、唯一匹配后保存空间 ID，不能用单个名称、路径后缀或模糊匹配猜测关联。
- 在本地项目下可进入本机管理模式，平台未就绪或暂时断开时仍可管理未注册屏，查看已注册屏缓存并保存资料草稿。两类屏均可按当前确认地址执行 IP、设备、MAC、诊断和应用版本等只读检查，结果保留本机。缓存不能冒充实时平台数据；平台注册更新、版本同步、状态覆盖以及已注册屏的设备写操作仍要求相应连接、登录和共享保护就绪。
- IP 是连接地址；本机记录 ID 和平台屏主键是记录身份，均不代替物理设备核对。尺寸也不保证固件能力。
- 本机列表移除只移除本机管理记录，不操作设备或平台；存在活动任务时暂不允许移除，已有操作历史保留当时的目标快照。

导入可复制或导出当前项目的空间路径清单，供实施人员填表；清单只包含可唯一匹配的文本路径，歧义节点通过空间树明确选择。空间路径为空表示明确暂不关联，预览显示“待定空间”；填写路径却未匹配或存在同名歧义时显示错误，不能自动创建节点或静默转为待定。预览中可为单行通过空间树修正，也可将一个空间批量分配给选中行；空间修正不掩盖 IP、尺寸或重复记录等其他错误。

导入预览默认勾选全部行，包括有错误的行。任何选中行仍有错误时禁止提交，人员须修正或明确取消该行；不自动跳过错误行。提交前重新校验选中数据、空间有效性、项目归属及预览期间目录变化；变化后重新预览确认。切换项目、重新解析文件或关闭窗口后，旧异步结果不得覆盖新项目或继续提交旧清单。
- 首次对设备执行有副作用操作前核实目标设备。只读采集和在线检查不要求已经取得平台主键。

### 3.2 平台拉取与疑似重复合并

平台连接成功、刷新平台清单、通过“导入智能屏”新增本机记录或重新采集 MAC 后，执行同项目的匹配检查。已经建立明确关联的记录直接更新展示；其本机资料草稿与平台值的差异属于第 3.5 节的更新流程，不参加疑似重复合并，也不产生新的本机未注册记录。未关联记录按以下规则提示，不自动合并。

| 匹配情况 | 展示与处理 |
| --- | --- |
| IP 相同 | 显示“疑似同一台屏：IP 相同”，展示两边名称、位置、尺寸、MAC 和采集来源 |
| 已核实的有效 MAC 相同 | 显示“疑似同一台屏：MAC 相同”；即使 IP 不同也提示可能已改地址 |
| IP 和 MAC 均相同 | 提示匹配依据充分，仍由用户确认合并 |
| IP 相同但有效 MAC 冲突 | 显示身份冲突，不自动合并；重新采集或现场核实为同一设备，并明确选择保留哪一侧 MAC 后，才允许确认合并。身份未核实时不向该地址执行设备写操作 |
| 对应多个候选 | 逐项选择实际对应记录，禁止按排序取第一条或自动多对多合并 |
| 空、占位、来源不明的 MAC | 不用作确定匹配；可按 IP 提示疑似项，并要求核实 MAC 含义 |

用户可以选择“确认合并”“暂不合并”“确认不是同一台”。暂不处理时保留两条记录和提示；确认不同屏时记录本次判断，关键 IP、MAC 或关联对象变化后重新核对。仅两个未注册记录互相重复时，同样提示整理，但不能因此标记为平台已注册。

确认合并的含义：用户逐字段选择本机或平台的值，预览最终结果后确认，将选定业务字段保存到既有平台记录，并把本机对应记录同步为相同值，再建立关联、合并列表展示及历史索引。不创建或删除平台记录，不改变平台主键；旧本机记录 ID、本机采集事实、旧名称/地址快照、操作历史和完整日志保留，并显示来源。

合并包含名称、IP、MAC、尺寸、所在空间、详细位置和小新版本七项。每项只能从当前两侧已有值中二选一；本机与平台列标题文字后的复选框用于一次采用该侧全部字段，再逐项调整，不另设“全部选本机/平台”按钮。部分选中显示半选，整列已选时再次点击不能取消为无来源，每项始终保留一个来源。最终预览显示每个采用值，通过选中的单选控件和来源汇总识别来源，不提供自由手填。平台状态、本机 Ping 结果和设备实际观测不属于这次字段同步范围。合并小新版本只核对已有记录值，不执行安装，也不把选定版本当成新的设备实测。

合并表四个列头加粗。本机来源以蓝色、平台来源以绿色区分，仅两侧列标题和合并结果值使用来源色；原始值保持中性，结果下不逐行重复“保留本机/平台”提示，保留选中控件与数量汇总以避免只依赖颜色。

“所在空间”作为整体选源，采用同一侧的空间 ID 与完整路径，不拆开选择楼幢、楼层或拼接两侧祖先。确认前校验所选节点有效性、项目归属及预览路径；待核验或失效关联不能作为有效空间提交。平台以已有单一空间关联字段保存该节点，不新增楼幢或楼层字段。一个平台记录已有本机关联时，不允许再建立互相冲突的关联；同一屏的多个本机别名需要明确核实并共同归入已有身份。

双方存在活动任务、结果待核实或结果待补写时，先完成对应处理再重新核对和确认合并，防止执行途中变更目标或丢失日志关联。提交前重新核对两侧记录、身份和预览旧值；并发变化时刷新差异并重新确认。平台限定字段更新及回读成功后，才在本机一致保存同步值、关联和历史索引；平台失败或结果未确认时不合并本机、不丢弃原记录。平台可能已写入而本机保存失败时保留待核实依据，恢复后先读当前事实再处理，不盲目重写平台、不重放设备操作，也不自动上传合并前本机历史。正式桌面已接入限定字段写入、回读、关联保存和结果补存，演示原型使用独立模拟数据。

平台刷新成功后，核实已知屏是否被逻辑删除或物理删除。确实删除时，清理对应的本机屏资料、平台注册关联、草稿、列表缓存及检查缓存；保留原任务、日志和未确认写入的核对依据。不反向通知平台，不转为未注册屏，不自动重新注册。记录仅移到其他空间或业务项目不视为删除，网络故障或读取不完整不清理本机资料。

智能屏所属空间可以独立修改，不以屏布点、空间图片、屏样式、设备类别或设备别名作为登记或空间变更的拦截条件。只校验空间有效、属于当前项目，以及原资料是否发生并发变化。工作台保留原布点坐标和空间配置，用户自行在项目平台调整布点。

### 3.3 MAC 与应用标识

本需求中的设备 MAC 指实际网卡地址；平台历史 MAC 字段的填充口径需在接入项目时核实。小新应用设备标识、Android 调试桥（ADB，设备管理工具）的连接标识分别显示，不能因为外形相似就互相替代。

1. 平台已填写且确认属于物理网卡的 MAC：采集后做标准化比较。相符时显示“核对一致”；不符时显示两个值和采集来源，阻止安装、配置修改等可能作用于错误设备的操作。历史值口径不明或实际是应用标识时，先显示“标识口径待核实”，不直接断言接错设备，也不自动覆盖。
2. 平台未填写 MAC：允许先执行只读采集。取得可信设备标识后，由运维人员结合名称、位置、IP、设备信息核对并建立关联；不要求手工重复输入已读取的地址。名称、位置和 IP 本身不足以建立永久可信身份。
3. 多个网卡：显示接口类型、名称和采集来源，按已验证型号及固件的网卡规则选择，不按管理连接 IP 所走网卡决定。现有 4 寸脚本固定读取有线接口 `eth0`，不回退到无线接口 `wlan0` 或 ARP；即使 ADB 通过无线连接，仍按该规则采集。10 寸须另行验证网卡选择；多候选或无法判定时提示核实，不取首条冒充确定结果。
4. 未知、空、占位或随机化地址：显示原因，不能自动作为唯一身份。可使用经过该固件验证的其他稳定且可区分设备的标识建立关联，具体来源由设备适配方案确定；若没有可靠替代标识，保持只读采集和状态检查，阻断设备写操作，并提示现场核实。不得直接以小新生成的应用标识代替物理身份。
5. 本机或平台不同记录关联到同一实际设备、同一 IP 指向不同预期身份时，列为疑似重复或冲突；同一次批量操作不能向该地址重复派发。按第 3.2 节核实后再执行。
6. 普通 MAC 采集只保存本机观测及来源，不自动回填平台。第 3.2 节人工合并或第 3.5 节注册更新在人员预览确认后，才可限定写入平台 MAC；在线状态覆盖和安装版本记录不获得该权限，原始观测不因采用值变化而改写。
7. 更换硬件时使用明确的重新核对流程；不能把新设备自动当作原设备继续执行旧任务。

现场样本中平台 MAC 存在未填写情况，因此“平台有 MAC 就核对”与“平台缺 MAC 就采集关联”两条流程都必须支持。原有 `version` 的空值统计与小新安装情况无关，小新版本单独按 `app_version` 和设备实测处理。

### 3.4 注册状态、在线状态与应用状态

注册状态独立显示为“平台未注册”“平台已注册”，疑似重复、身份冲突和关联同步问题作为附加提示。平台未注册不能等同于离线。

资产列表只展示注册属性和已确认的最终业务事实，不设置“执行中”“检查中”“安装失败”等资产状态，也不把它们保存为项目状态。执行阶段、进度、取消和失败原因仅用于本机任务、结果界面与操作日志。原型顶部不提供“正常项目”“平台不可用”“执行失败”等场景选择器。

| 展示名称 | 来源与含义 | 不代表什么 |
| --- | --- | --- |
| 平台状态 | 已注册屏在平台保存的在线/离线状态；平台本身按 IP 检查 | 未注册屏显示“无平台记录”；不保证当前电脑能通过 5555 连接 |
| 本机 IP 检查 | 当前电脑对设备 IP 执行 Ping，显示可达、不可达或检查异常及时间 | 本机和平台网络视角可能不同；与平台不一致时只提示，由用户决定是否覆盖 |
| 本机管理连接 | 本机主动探测得到的可连接、未授权、连接失败、未检查等结果 | 不直接替代平台在线状态 |
| 应用检查 | 应用安装、版本、进程/启动等实际检查结果 | 设备网络可达不保证应用健康 |

显示平台数据读取时间和本机检查时间。平台没有专用在线检查时间时，显示“平台检查时间未提供”，不把通用记录更新时间当作最后心跳时间。

平台状态值无法识别时列为“未知”，读取失败时显示加载失败或带时间的旧数据，不把整项目标记为离线。平台已注册数 = 平台在线数 + 平台离线数 + 平台未知数；本机未注册数单独统计。

### 3.5 注册/更新到平台

实施人员完成屏资料整理后，在“智能屏操作”选择“注册/更新到平台”。该操作支持同批未注册屏和已注册屏，按“选择设备与资料 → 检查并预览 → 提交结果”三步处理，首步按钮为“检查并预览”。首步可编辑名称、IP、MAC、尺寸、所在空间和详细位置；已注册屏的改动只保存在绑定原平台主键的本机草稿中，平台已确认值单独保留。编辑按钮“保存待提交修改”只保存草稿，列表提示“资料有变更”，详情可“核对并更新”或“放弃本机修改”；不新增未注册记录，刷新平台时不得静默覆盖草稿。

**检查与预览**：

1. 校验项目、平台登录及写权限、目标记录、必要资料和实际空间。必须选择当前项目内真实有效的空间节点；“待定空间”是列表分组，不能作为平台空间写入。空间目录暂不可用、节点失效或归属不明时，保留本机资料并提示处理，不能注册或更新。
2. 新注册或地址、MAC 发生变化时自动尝试采集 MAC，并显示接口、来源、时间及与已有值的比较，不要求先退出本操作去执行“获取/核对 MAC”。已绑定且地址、MAC 未变的纯资料更新可沿用已确认身份，不要求重新连接设备。有效且无冲突时预填到本次预览；采集失败时保留原值，逐屏允许明确选择经核实的历史值，或确认本次暂不填 MAC。新增可留空；更新暂不填不等于清空已有平台 MAC。没有任何选择时不自动继续。
3. MAC 新旧不一致、多网卡未明确、有效 MAC 被其他记录使用、IP 重复或存在多个疑似平台候选时，列为“需核对”。采集失败的确认不用于跳过身份冲突；已注册屏的原有效 MAC 与新值冲突时阻断资料更新，不能用普通资料编辑替换设备身份。尚未绑定的重复记录按独立合并流程显式核实，不能自动覆盖另一屏或任选第一条记录。
4. 预览按“新增、更新、无变化、需核对”分类。新增列出拟登记资料；更新并排展示平台当前值与本机草稿及实际变化字段；无变化不重复写；需核对项给出具体原因，不自动丢弃。人员可修正后重新检查，或明确只选择已经具备条件的目标提交。
5. 已绑定平台主键的屏始终更新原记录。修改所属空间按普通资料更新处理，展示原、新空间并确认；不检查或修改布点、图片、样式、设备类别和别名。空间已删除、属于其他项目或资料发生并发变化时拒绝提交。

**限定写入与成功结果**：

- 点击“确认提交 N 台”后，再核对目标资料、空间、MAC 决定、平台旧值及项目上下文，N 为本次可提交且已选择的数量。新增只用于尚无平台主键且无未解决疑似重复的屏；更新以原平台主键定位，条件变化后重新预览，不把更新退回新增。
- 资料更新白名单为名称、IP、经核实的 MAC、尺寸、所在空间和详细位置，对应数据库表 `smart_terminal_screen` 的字段 `name`、`ip`、`mac`、`size`、`building_id`、`install_address`。不顺带更新字段 `status`（平台在线状态）、`app_version`（小新版本），不修改空间目录、布局或设备业务配置。新记录的主键、项目归属和必要初始值在正式数据库适配中按平台契约落实，不能把本机 Ping、缓存版本或任务阶段当作新增事实写入。
- 平台写入并确认回读后，才将未注册屏转换为一条已注册视图，持久保存原本机 ID 到平台主键的映射、平台缓存、资料来源及历史索引。本机未注册数减一、平台已注册数加一，管理记录总数不变；不显示“本机一条 + 平台一条”的重复。
- 旧本机 ID、本机采集记录、操作历史和日志不删除，旧任务仍可追溯；已注册屏更新成功后用回读结果刷新平台缓存并收敛对应草稿，后续仍按同一平台主键管理。重开工作台或断开平台后，继续显示一条注明读取时间的缓存已注册屏，不退回未注册。
- 失败时保留本机记录或草稿及最近确认的平台值。超时、断连、写入可能成功但回读失败、本机映射保存失败时，仅在结果和历史中保存待核实依据；恢复后先查询并确认是否已创建、是否已更新，再补齐本机关联或结果，禁止直接再次插入或重复提交旧更新。IP、MAC 在现有表中不是唯一约束，不能单凭相同地址认定待核实结果已找到。
- 存在活动任务或未处理的结果时，先完成核实再切换注册身份。执行进度和失败原因不写成平台资产或项目中间状态；取消只阻止尚未派发的目标，已提交目标保留实际核实结果。

正式能力直接访问项目侧数据库，不连接云平台、不新增平台 HTTP 接口。正式桌面与演示原型分开，真实功能的验收依据见开发计划和对应测试记录。

### 3.6 待提交资料与实际设备操作目标

平台资料草稿不改变设备操作的实际地址和身份。设备列表、检查页及执行记录均显示本次连接 IP，使用平台已确认资料；未注册屏使用已保存的本机资料。不能静默改用草稿 IP，也不能把草稿中的尺寸或 MAC 当作已生效事实。

- IP、MAC、尺寸存在实质差异的待提交修改时，安装、校时、保持 ADB 端口、重启应用和重启屏对该目标暂不可执行；预检说明涉及字段及当前确认地址，并提供查看修改、前往“注册/更新到平台”的操作。人员须先核对提交或在编辑器放弃修改，再重新检查。批次中其他符合条件的目标可继续。
- 名称、空间及安装位置等普通资料草稿不阻断设备维护。空间迁移本身仍按第 3.5 节核对业务关联影响。
- 只读检查仍可针对当前确认地址执行，明确显示当前 IP 与待提交 IP，结果注明来源地址。存在关键资料待提交修改时，不将该读取结果直接同步为平台版本；先处理修改，再重新读取确认。
- 检查确认后固定设备记录、实际 IP、MAC、尺寸等目标依据；提交和派发前再次验证，变化时不连接新地址、不沿用旧检查，提示重新检查。平台资料更新与设备网络配置仍为不同操作。

## 4. 页面与信息组织

### 4.1 一级导航

“智能屏管理”下设置“智能屏列表”“智能屏操作”两个二级页面。列表提供“新增智能屏”“导入智能屏”“刷新平台”“疑似重复”入口；新增与导入均先保存为本机未注册记录，平台未就绪时仍可查看和维护本机未注册屏。后续配置编辑从屏详情或所选屏的操作进入，首期不展示不可用的配置编辑按钮。

“智能屏操作”页标题最右侧提供“历史记录”按钮，点击打开历史抽屉；页面不划分“新建操作/历史记录”标签页。执行中的任务与日志继续使用全局本机任务面板。

### 4.2 智能屏列表与项目总览

顶部概览按“管理记录 → 平台已注册 → 平台未注册 → 平台在线 → 平台离线 → 疑似重复”排列，并展示 4 寸/10 寸分布。“平台未注册”仍统计当前电脑尚未关联平台的本机记录。平台未知状态非零时单列。

当前管理记录总数 = 平台有效记录数 + 本机尚未合并的记录数；确认合并后仅计一条。疑似重复尚未确认时不擅自扣除，明确显示“含待合并记录”，因此该数量不承诺等于物理设备台数。平台在线/离线仅统计平台已注册屏，本机未注册屏不并入这两项。

总览代表当前已成功读取的项目范围；符合条件的记录数量保留在表格底部分页栏。点击注册状态或在线状态卡片可切换对应筛选。平台不可用时保留已确认平台缓存及读取时间，与本机未注册记录一起展示；缓存数量明确为已缓存范围，不冒充完整实时统计。没有任何平台数据时显示“未获取”，不把平台总数显示为 0。注册成功只在两类数量间转移，不改变管理记录总数。

列表字段建议：名称、注册状态、平台状态、本机检查摘要、楼幢/楼层/所在空间、安装位置、尺寸、IP、MAC 核对情况、小新应用版本、最近检查时间、操作。默认紧凑展示，来源和完整错误在详情/提示中展开。疑似重复图标与文案紧跟屏名称同行显示，点击可展开候选比较；所在位置放在第二行，“详情”使用小字号文字操作。

筛选工具栏展示筛选控件和“重置”。表格底部分页栏左侧按“当前显示 N / M 条、竖分隔线、已选 X 台、批量操作”排列，分页控件保持在右侧。“已选 X 台”只显示当前选择数量，不附加下拉箭头或菜单；数量后紧跟“批量操作”。全选与取消选择使用已有表头勾选控件，不另设独立操作行。

筛选规则：

- 关键词同时匹配名称、安装位置、空间路径、平台或已确认采集的 MAC、IP；MAC 支持忽略大小写及常见分隔符。
- 列表及操作选屏的空间筛选只展示楼幢、楼层，沿完整空间树归类。选择楼幢包含其自身及全部后代，选择楼层包含其自身及全部后代，不能只按屏直接关联的空间 ID 等值筛选。直接挂楼幢的屏计入该楼幢，不计入任一楼层；深层节点按祖先归类，完整路径仍可搜索。仅有位置文字且未关联空间的记录归入“待定空间”，不凭名称自动建立关联。
- 左侧空间区域将“待定空间”放在“全部空间”之前，两项均在文字前使用同一套线性图标，尺寸、对齐和间距一致；该排列不改变空间归类规则。
- 尺寸为全部、4 寸、10 寸、未识别；未知值保留资产但限制不适配的操作。
- 保留全部、平台未注册、平台已注册、平台在线、平台离线、疑似重复分类，以及空间、尺寸、关键词和小新版本筛选。已注册屏的版本筛选按平台登记值，未注册屏按本机实测值。平台未知不计作离线，已注册统计同时注明未知数量。首期不另加本机 Ping 或实测版本专用筛选。
- 不同筛选条件之间取交集；更换条件回到第一页。空间未选择或完整目录核实关联已失效时归入“待定空间”，仍可搜索和核对；目录暂不可用保留原关联并提示待核验，不能按未关联统计。
- 后端完整读取当前业务项目的屏和空间，前端基于完整快照关联去重，再统一筛选、计数和分页，每页可选 10/20/50 条。不能从两个来源各取一页拼接，也不能只筛选当前页。
- 列表、符合条件数量和勾选目标使用同一筛选条件，不能只在当前页前端过滤。

“刷新列表”读取可用的平台数据及本机/共享运维记录，不主动连接所有屏；刷新后执行疑似重复检查并在列表提示。

### 4.3 选择与批量操作

- 支持单台、当前页多选，以及通过表头勾选控件全选或取消当前页；底部分页栏“已选 X 台”持续显示全部已选数量，包含跨页保留的选择，不提供重复的下拉菜单。
- 屏列表修改筛选条件时清空已有选择，避免隐藏目标被误操作；翻页可保留同一筛选下的选择。“智能屏操作”页的候选筛选与选择保留规则见第 4.5 节。
- 执行前将匹配结果解析为明确的设备 ID 清单，并展示楼层、尺寸和数量摘要。之后新出现的匹配设备不自动加入该任务。
- 项目切换后页面选择和输入草稿按项目隔离；已开始任务保留自己的项目上下文。
- 平台记录显示某台屏离线，不自动禁止对该屏进行运维检查；需要设备管理连接的动作仍核对本机实际连接结果。此规则不等于平台服务或共享库断开后可以绕过已关联屏的访问和租约条件。
- 同一批次可包含已注册和未注册屏；按各自记录与日志范围保存结果。重复候选未处理时不得把同一目标地址或已核实物理设备执行两次，检查阶段列出需要处理的目标。

主要设备操作都支持多选批量执行。两类屏的只读检查不依赖平台登录或共享库可用，按已确认地址及设备连接能力检查，本机已有活动任务互斥仍生效；平台暂不可用时结果只保存本机。未注册屏的设备写操作按本机项目和本机互斥执行，已注册屏的设备写操作仍要求平台登录、共享资源保护和对应数据连接条件。平台状态覆盖和版本同步只面向已注册且连接权限就绪的目标。

### 4.4 屏详情

无检查记录显示“未检查”，平台未知仍显示“未知”，不能推断为离线、ADB 不可用、0MB 或时间无偏差。Ping 不覆盖已有 ADB 检查结果。详情补充型号、固件、MAC 来源和时间、应用安装与运行状态、版本读取时间、设备与电脑时间、时区及自动校时设置。平台不提供检查时间时明确说明，不以读取时间代替。

详情按“资产信息”“设备与应用”“最近操作”组织，提供资料编辑、注册/更新到平台、查看/检查、安装升级、校时、重启应用、重启屏等明确动作。本机未注册资料直接保存本机；已注册资料保存绑定原平台主键的独立草稿并显示平台差异，不改成未注册行。疑似重复详情支持比较和合并；应用配置编辑在后续功能交付后开放。

设备与应用信息包括平台及采集身份、系统版本、处理器架构、应用版本、可用空间、设备时间/时区和偏差、管理连接及权限、10 寸屏持久端口状态。未检查项显示“未检查”，不使用示例值。

## 5. 设备运维功能

### 5.1 安装与升级应用

实施人员选择一个本地小新 Android 应用安装包（APK 文件），选择屏，检查后安装。首期仅支持小新应用，校验应用包名为既有小新包名 `chat.xiaoxin.app`；其他应用明确提示不在当前范围，不提供通用应用安装入口。

安装参数只有四项：选择应用（默认且唯一为“智能小新”）、从本机选择 APK 文件、相同版本覆盖安装选项、并发台数。选包后显示文件名和大小，并可更换；不提供手选目标版本或架构的下拉框。

同一 APK 的一次安装/升级只允许同一种明确尺寸的屏，即全部为 4 寸或全部为 10 寸；判断范围是全部已选设备，包含当前筛选外的隐藏目标，不能只检查可见行，也不自动取消任何目标。混选尺寸时，在“本地 APK 文件”标题后以警告色显示“一批只能操作同规格尺寸屏”，禁用选包和“安装检查”；存在未知尺寸时提示先确认尺寸，同样禁止继续。

已选包后出现混合或未知尺寸，清除旧文件与检查结论；恢复同尺寸后必须重新选包。尚未选择目标时允许先选 APK，首次形成明确的同尺寸目标集时绑定该尺寸；已经绑定后，即使改选的目标仍为同一尺寸，只要该尺寸与原绑定不同，也必须重新选包。选择区、业务适配器预检和执行提交都应校验批次尺寸及文件绑定，不能只依靠按钮禁用。

正式安装检查由工作台直接从 APK 读取包名、版本名称、版本号、所需 Android 版本和处理器架构，并比较屏实际环境；不从文件名猜测版本或架构。工作台不提前验签或比对屏上应用证书，由 Android 安装过程检查签名并返回失败原因。同尺寸只是批次要求，不代表处理器架构兼容；屏尺寸也不能由应用二进制接口（ABI，即应用适用的处理器架构约定）反推。当前资料中的 10 寸为 32 位、4 寸安装资料为 64 位，不构成所有同尺寸设备的架构保证，仍需逐设备检查。

正式桌面自行解析包名、版本、架构、最低系统要求和启动页面，不依赖外部 APK 工具或 Java；安装前核对设备条件与文件是否变化，执行后读取实际版本和应用运行状态。独立演示原型只演示交互，不能用模拟完成证明安装成功。

- 未安装目标应用：执行首次安装。
- 已安装同包名较低版本：保留应用数据覆盖升级。
- 已是相同版本：默认跳过，可明确选择重新覆盖安装。
- 所选版本较低：首期默认阻断，不自动卸载、清数据或强行降级。
- 签名冲突、空间不足、版本不兼容：给出具体原因，不自动卸载原应用规避问题。
- 兼容性检查不重复无变化的大文件读取；文件变化、目标变化或快照失效时重新检查。

成功标准为设备安装器返回成功、回读到目标包及版本，并执行小新启动检查。界面分别呈现安装与启动结果：安装成功但应用未恢复不能显示全部成功，也不能把可能已经成功的安装自动重复执行。未注册平台不构成安装阻断条件。

对已注册屏，安装升级成功并回读确认后，将实际确认的小新版本通过限定写入路径更新到平台数据库表 `smart_terminal_screen` 的字段 `app_version`，并回读平台字段；不得在选包、检查、排队或安装过程中先更新版本。写入应核对平台主键、执行地址及预览旧版本等条件，条件变化时先重新核实，不盲目覆盖。

安装失败、设备版本回读不确定或应用恢复未通过时，不提交平台版本更新，保留平台旧版本。设备已成功但平台版本写入或回读失败时，在结果界面和本机操作历史分别保留设备成功事实与平台更新失败/待核实，不把拟写版本展示为平台已成功保存。恢复后先核实当前设备和平台版本，仅处理尚未完成的记录更新，不重复安装。未注册屏只保存本机实际版本，不尝试写平台。

安装包留在实施电脑，不存入项目数据库。共享安装结果保存包文件名、版本名称、数字版本号和 SHA-256 校验值，便于识别同名不同内容的包；完整文件路径和日志留本机。重试必须重新选择文件，不能仅凭历史文件名恢复安装包。

#### 5.1.1 独立核对应用版本并同步平台

实施人员可先安装小新再注册屏；登记成功后，通过“核对版本并同步平台”补齐版本，无需再次安装。同版本安装跳过、平台版本缺失或过期时也使用此功能。屏详情、安装结果、注册结果和设备检查结果提供该操作；安装检查中跳过的目标也可直接进入版本核对。

打开后重新读取每台设备当前安装的小新版本，展示名称、实际 IP、平台原版本、本次读取版本、读取时间和结果。设备检查得到的版本作为本机观测保存；普通刷新、旧缓存或选包文件名均不能冒充本次读取结果。应用包尚未解析的安装原型仍不产生新的安装版本事实。

- 已注册、当前读取成功且存在版本差异的目标，支持勾选后“确认同步 N 台版本”；值一致则无需写入。同步只更新数据库表 `smart_terminal_screen` 的字段 `app_version`，不安装、不修改在线状态、MAC、地址、空间或其他资料。
- 未注册屏只保留本机观测；注册后重新读取并确认。平台不可用时，已注册屏也可读取版本并保留本机，恢复后重新获取平台当前值、读取版本并确认同步。
- 未安装、采集失败、设备身份冲突、关键资料待提交、活动任务或结果待核实时，不更新或清空平台版本，也不使用旧观测填补失败结果。
- 提交前核对平台主键、实际地址及身份、平台原版本、当前设备版本与连接条件；变化后重新检查。单台失败不覆盖该台原值，其余独立目标可继续；结果与来源时间进入本机历史。写入或回读不确定时先核实原提交，不通过重新安装补救。

安装自动写入版本与独立同步是两个受限用例。安装失败不自动更新版本；人员随后主动重新读取到实际安装版本，可明确确认将该事实同步到平台，应用是否正常启动仍单独展示。

### 5.2 10 寸屏持久开启 5555

操作名称使用“保持ADB端口”，相邻说明为“10 寸屏重启仍保持 5555端口”；重启确认步骤说明配置端口及重启验证的影响。

前提是当前已经能够通过 ADB 连接，并具备固件所需权限。完全没有可用连接时，提示在屏上开启临时调试或按设备支持方式进行现场接入；工作台不能隔空开通已关闭的通道。

执行步骤：读取当前配置 → 核实能力 → 保存持久端口 → 回读 → 重启 → 等待连接恢复和系统启动完成 → 再次回读。当前 10 寸现场脚本使用设备提权方式写入端口，避免重启调试服务导致中途失联，桌面实现须保留该行为边界。

- 验证通过才显示“重启后有效”；只写入成功、回连超时显示“配置已写入，重启后未能确认”。
- 已配置且本次未做重启验证时，显示“已配置，待验证”，不能代替持久性验证。
- 超时可继续检查，不自动反复重启。
- 不连带执行出厂禁用应用、改默认桌面或调整语言等动作。
- 4 寸屏不直接开放此动作；其固件能力经单独验证后再明确适用范围。

### 5.3 时间检查与校准

先展示电脑时间、设备时间、时区、自动校时设置和偏差；默认以实施电脑当前时间为基准，并提示先确认电脑时间正确。

时间换算统一按时间戳处理。默认保留设备时区和自动校时设置，避免校时顺带更改显示规则。需要改时区或自动校时策略时另列显式选项并验证，首期不隐式处理。

工作台同时校准系统时间和启动时使用的硬件时钟。先确认固件、管理员权限和唯一的受支持硬件时钟，再执行修改；未知固件或硬件时钟无法确认时，不先改一部分时间。执行后分别读取两处实际时间，绝对偏差均不超过 15 秒且原设置保持，才显示成功。只有系统时间正确、硬件写入或回读失败时，应明确显示未完成或待核实，不能显示整项成功。

执行中断后的“核实结果”只读取设备实际状态，不再次写时间。旧任务没有硬件校时记录时，提示重新执行校准，不能将旧的系统校时成功当作新的两项成功。

已验证的 4 寸和 10 寸固件在同步硬件校时后均能正常软重启；10 寸测试屏还通过了一次无公网断电保时测试。已测 4 寸固件完全断电后仍会丢时，界面需说明这一限制，不能承诺通过一次校时解决硬件断电保时问题。本项不新增 NTP 时间服务器配置，不修改小新应用。

批量校时在每台实际执行时取当前基准时间，不使用任务开始时的同一个固定时间。

### 5.4 重启屏与重启应用

两者分为独立操作，确认页展示目标数量及可能短时不可用的影响。

- 重启屏：记录操作前系统启动标识或运行时长；执行后等待重新连接、开机完成并核实发生了重启。操作前已安装且预期运行的小新应用还需检查恢复；尚未安装应用的屏，以设备重启和管理连接恢复为成功标准，不误报应用失败。
- 重启应用：只停止并重新启动指定应用，不改设备系统、不清应用数据；确认目标应用恢复。
- “命令已发送”只是进度；重连失败显示待核实及失败阶段，不把发送成功当作完成。
- 已发出重启后无法撤销；取消只停止后续设备的派发，当前设备保留恢复核实结果。

### 5.5 本机在线检查与确认覆盖平台

平台本身通过检查 IP 维护在线状态。工作台普通刷新只读取平台状态；用户主动检查时，从当前电脑对所选屏执行 Ping，不以 ADB 是否开放或小新是否运行代替 IP 在线结果。

本次检查结果与本机历史的逐屏“在线状态”列显示业务结果：可达为“在线”，不可达为“离线”，无法判断为“未知”；等待执行和取消未检查的屏显示“未检查”，执行期间显示“检查中”。程序异常原因放在“实际结果 / 处理建议”中。完成检查不等于屏在线，不能用“已成功 / 失败”代替在线状态；历史行采用该次任务保存的结果，不随之后的检查变化。

| 动作 | 行为 | 平台是否更新 |
| --- | --- | --- |
| 刷新平台 | 读取平台保存的状态 | 否 |
| 检查 IP 在线 | 本机 Ping，记录来源、地址、时间和结果 | 不自动更新；已注册屏有差异时显示覆盖选择 |
| 检查管理连接 | 检查 ADB、权限及必要设备信息 | 否，不把管理端口失败写成离线 |
| 覆盖选中差异 | 用户查看并确认后，工作台直接更新对应平台屏的状态字段并回读 | 是，不经过平台 HTTP 接口 |

具体规则：

1. 未注册屏只保存本机在线检查结果，显示“平台未注册”，不尝试平台写入。
2. 已注册屏的本机结果与平台一致时，无需写表；不同则按“本机 Ping 结果 → 平台状态”展示覆盖方向，第一行的本机结果标签、箭头和平台目标状态标签垂直居中，平台原值另放第二行，不影响第一行对齐；同时显示检查时间、名称/位置和 IP。全选行与设备行采用相同的左侧留白，所有勾选框同列对齐。确认只把本机结果写入平台，本机检查结果不变；需要新观测时重新进入 IP 检查，再比较和确认覆盖。
3. Ping 正常执行且超时或明确无响应，可显示“本机不可达”，允许用户确认后覆盖平台为离线；可达则可覆盖为在线。本机和平台网络视角可能不同，差异不自动判定哪一方错误。
4. 命令无法启动、参数错误等没有形成有效检查结果时，在线状态显示“未知”，实际结果说明异常原因；取消且未取得结果时显示“未检查”。这些情形不生成可覆盖的在线/离线值。
5. 支持一次勾选多条有效差异并确认；不勾选、取消或拒绝的记录保持平台原值。确认后只更新选择的目标，不形成长期自动同步规则。
6. 覆盖前重新核对平台记录仍有效、IP 与检查地址一致、状态仍为确认时的值；只在这些可比较条件仍匹配时更新。状态已等于目标值时无需重复写；地址、记录或状态发生其他变化时刷新差异并重新确认，不自动重试旧覆盖。现有表没有专用检查序号，不承诺锁定平台检查的先后顺序或阻止平台随后更新。
7. 本操作的可写范围只限数据库表 `smart_terminal_screen` 的字段 `status`，以及数据库已有的自动更新时间行为。按具体主键和条件更新，不修改 MAC、IP、名称、空间、尺寸或业务配置，不插入或删除平台屏记录。应用版本字段 `app_version` 的安装结果更新遵循第 5.1 节，人工合并选源遵循第 3.2 节，不由在线状态覆盖顺带修改。
8. 普通读取连接保持只读，覆盖使用明确隔离的状态写入路径。无写权限或数据库不可用时显示“本机检查完成，平台覆盖失败”，本机结果保留；不自动提权或扩大 SQL 权限。
9. 成功提交并回读确认后，资产列表才展示确认后的平台最终状态，并记录操作人、电脑、目标、原值、目标值、检查及确认时间、写入与回读结果。平台自身的后续检查仍可再次改变状态，工作台不阻止平台检查，也不持续覆盖。
10. 写入失败或回读未确认时，失败原因仅保留在结果界面和本机操作历史，资产保留最近已确认的平台值及读取时间，不将拟覆盖值当成平台成功，也不新增“覆盖失败”等平台资产或项目状态。写入可能已发生时显示“覆盖结果待核实”，恢复后先读当前事实再收敛记录；不能重放过期检查、再次覆盖新状态。

在线状态覆盖定位的是平台记录与本次检查地址，不要求离线屏先取得 ADB 权限或采集 MAC。记录对应关系有冲突时先核实关联，不能把结果写入有歧义的目标。

## 6. 屏端配置数据管理

> 状态：本扩展已实现，独立于基础运维步骤 1—7；Windows 与两种 Android 屏的配置验证结果见[验收记录](19-屏端配置管理实施与验收.md)。
> 更新日期：2026-10-04。适用对象：运行智能小新应用的 Android 4 寸、10 寸屏；工作台先在 Windows 验证，macOS 保持确定支持目标。

### 6.1 业务目标与范围

实施人员在运维电脑上读取小新当前设置，修改服务地址、运行环境等常用配置，确认保存及生效结果，减少逐台在屏上进入设置页面的操作。

小新自身保存正式配置。工作台发送明确的修改，由小新校验和保存；工作台不直接编辑应用私有文件。即使业务服务地址填错，只要屏的管理连接仍可用，也能再次修正。

首批开放范围如下：

| 配置 | 本次能力 | 批量规则 |
| --- | --- | --- |
| 当前运行环境 | 切换测试、预发或生产环境 | 用户明确选择目标，不自动把不同环境统一成同一个环境 |
| 指定环境的授权／配置服务地址 | 读取、设置；不可清空必填地址 | 每批明确修改哪一套环境，不同时覆盖全部环境 |
| 指定环境的手动语音连接地址 | 读取、设置、明确清空 | 未编辑不修改；清空后沿用小新已有的服务端下发规则 |
| 指定环境的手动业务网页地址 | 读取、设置、明确清空 | 同上；服务端也没有地址时，沿用小新已有默认页面规则 |
| 指定环境的网页启动检查开关 | 读取和设置 | 只修改选定环境，保留其他环境 |
| 小新自定义设备名称 | 读取，单台或逐台设置、清空 | 不用一个名称自动覆盖全部屏；不自动修改平台的屏名称 |
| 服务端下发地址、当前实际使用地址及来源 | 只读显示 | 帮助判断实际使用的是手动值、下发值还是默认值，不从这里直接改下发值 |

批量修改可以选择不同尺寸的屏，但每台小新都必须支持本次字段。此规则只适用于配置修改，不改变安装升级的同批同尺寸要求。

本次不开放语音高级参数、采样率、热词、自由编辑业务扩展参数、设备标识、客户端标识、授权码、管理密码和独占模式的远程修改。平台空间、布点、页面布局及网页内部选定空间也不属于本功能。本次不建设共享配置模板、配置版本历史或一键恢复管理功能。

### 6.2 页面与操作流程

“智能屏操作”和屏详情均使用“修改小新配置”名称，排列在“注册/更新到平台”之后。复用现有选屏、任务和日志界面，不增加独立顶层菜单。

操作步骤为：**选择智能屏 → 配置修改 → 修改结果**。

1. **选择智能屏并读取配置。** 用户选择单台或多台屏，点击“读取配置”。逐台读取小新能力和实际值，显示读取时间、当前运行环境和失败原因。旧版小新不支持时提示先升级，不自动安装；连接失败不允许用旧缓存直接提交。
2. **编辑和确认。** 用户选择其他环境时，本次修改同时包含运行环境切换，不再提供切换勾选。首次读取后自动显示的环境只用于展示，不算修改；用户改回所有已选屏当前使用的环境时，取消环境切换。地址输入框直接显示读取值，不增加“不修改／设置／清空”下拉框。只有实际编辑的字段才参加提交，已修改字段用输入框边框颜色标记。
3. **查看修改内容。** 下方紧凑列表逐台显示屏名称、IP 地址、检查时间、检查状态及配置差异。不同于表单代表值的屏使用颜色和“配置不同”等文字标记；悬停差异提示或点击详情，可查看不同的配置项和真实值。详情同时提供地址来源、修改前后值、是否需要重启及逐台“设备名”编辑；不支持或读取失败的目标列出原因，由用户移除或处理。
4. **保存及核对。** 点击“检查修改内容”，核对逐台检查结果及重启数量，再点击“确认修改”。保存、重启和回读分别显示结果，继续使用任务与日志面板查询，不将请求已发送当作保存成功。

配置修改页按以下方式组织：

- 顶部表单每行两项，共三行。五个配置项为“选择环境”“OTA 地址 *”“WebSocket(可选)”“H5地址(可选)”“H5检测”，名称与小新设置页一致；第六项放“重新读取配置”。不提供“重新选屏”按钮。
- 各项标签和输入内容对齐，标签下方不增加当前值、未读取或修改状态说明行。“尚未读取”等提示放在输入控件内。环境使用下拉选择，H5 检测使用勾选，勾选文案为“检查H5地址”；三个地址直接使用输入框。
- 多台读取值一致时直接显示该值；存在唯一最多的值时，以该值作为表单代表值，并在列表标出其他值。同票、无法确定代表值时显示“多个值，输入后统一修改”，不随意取第一台的值。代表值只用于展示，默认不统一其他屏。
- 输入与读取代表值不同才记为修改；改回代表值时取消该字段的修改。存在不同值时，用户可明确点击输入框内的“统一”，将代表值应用到本次选中的屏。未编辑也未选择统一的字段保留每台原值。撤销和统一操作与输入框同行，不增加说明行。
- 用户删空允许清空的手动地址或逐台设备名时，记录为明确清空，并在修改确认中显示；OTA 地址不可清空。未读取、读取失败或初始空白不自动成为清空操作。
- 顶部表单、列表表头、分页和提交区固定；只有屏列表的数据行区域滚动。滚动条沿用工作台细滚动条样式，鼠标离开列表区域时隐藏滑块并保留宽度，避免内容左右跳动。提交区持续显示本次修改数量、预计重启数量和提交操作。

修改结果页沿用第 7 节的紧凑表格。保存、重启、回读作为同一设备行中的独立列显示，不在表格下方再逐台增加卡片；“新的配置操作”固定在底部。

读取快照和未提交修改自动保存在当前电脑。继续本机草稿时，必须重新读取屏端当前值后才能检查和提交；重新读取保留用户明确编辑的字段，刷新未编辑字段的展示值。草稿不加操作锁，不直接作为设备当前配置使用。未读取或读取失败的屏不得提交。

每次提交只写用户明确修改的字段，未编辑字段保留屏端当前值。不增加配置版本号、版本冲突比较或新旧值合并流程；同一字段以后一次实际保存的值为准。预览原值用于说明本次修改，不作为拒绝覆盖的条件。

### 6.3 配置来源和生效规则

手动填写的语音、网页地址优先于服务端下发地址。清空手动值时，仍保留下发值，并显示清空后将使用的地址来源；不能把“清空手动值”理解为删除全部地址配置。

这里的下发值是小新当前保存的服务端返回值，不代表本次读取已经访问或验证该服务。读取配置不主动触发激活、重新授权或服务端配置刷新。

每次只修改一套环境配置。用户明确选择其他环境时，同时将其作为运行环境；只编辑当前展示环境的地址或检查开关，不会因为表单自动显示了代表环境而切换其他屏。其他环境的配置不变，设备标识及授权资料不因普通配置保存而重置。

| 本次实际修改 | 生效方式 |
| --- | --- |
| 只修改小新自定义设备名称 | 保存并回读，不主动重启 |
| 修改非当前环境，且不切换过去 | 保存并回读，提示该环境尚未启用，不主动重启 |
| 切换当前环境，或修改当前环境的地址、网页启动检查开关 | 提交前提示会短暂中断页面和语音；保存成功后重启小新一次，再读取确认 |
| 新值与当前值一致 | 显示无需修改，不重复保存或重启 |

重启的是小新应用，不是 Android 系统。本次不增加语音引擎、网页等功能的运行中动态重载。原屏上设置页面保持原有使用方式和生效规则。

“已保存并重启”表示配置已保存、小新已重新运行且读回值符合本次修改；不等于网页或语音服务必然可访问。业务服务不可用时另外说明，不能丢失配置已保存的事实。

### 6.4 前置优化与小新改动边界

先独立完成小新配置校验、保存和读取的公共能力整理，再接入远程调用。

- 屏上设置、服务端下发、现有网页参数写入及远程修改共用配置服务，各自只能修改原本允许的字段。
- 保留现有存储格式、默认值、读取方法、手动配置优先级及旧数据，用户无需重新填写原配置。
- 把全部输入校验放在写入之前；输入有误时不保存前面已通过的字段。
- 检查实际保存结果，使内存值和存储值一致；不把保存失败或部分保存显示为全部成功。
- 设置页面只调整校验和保存调用。语音、对话、网页业务、设备控制、离线缓存和独占模式不列为业务逻辑重构对象，但纳入回归验证。

现有存储使用多个配置项，不承诺跨所有配置项的整体成功或整体回滚。正常流程完整保存；出现存储异常时显示哪些字段已保存、哪些未保存，部分保存不自动重启，先由用户处理。

### 6.5 连接、权限与操作锁

工作台复用 Android 调试桥 ADB（设备管理工具），直接调用小新增设的受限管理组件。小新检查 Android 系统提供的调用者身份，再交给内部配置服务处理。无需新增 HTTP 管理端口、账号体系、临时访问凭据或扫码配对流程；现有 ADB 的连接和授权要求保留。

人员身份及项目权限继续由工作台现有能力管理。读取配置不加共享操作锁；已注册屏在真正保存或启动、重启应用时，复用已有操作锁和当前页面接手流程。未注册屏复用本机任务保护，不新增配置层的多电脑冲突管理。

平台不可用时，已运行小新的配置仍可只读查看；已注册屏的配置写操作继续遵守现有平台登录、共享记录和操作锁要求。包含已注册屏的混合写入批次在这些条件不可用时整批不执行，提示可另选未注册屏单独处理。

小新未运行或未初始化完成时明确提示，提供“启动小新并重试”或稍后重试的处理方式；启动动作按现有设备写操作规则执行。不能为读取配置而绕过应用权限或改读私有文件。

### 6.6 数据保存位置

| 位置 | 保存内容 |
| --- | --- |
| 智能屏上的小新应用 | 实际运行配置，继续使用既有存储格式 |
| 运维电脑本地 | 读取快照、未提交修改、逐台执行过程、完整日志及待核实结果；注明所属项目、设备和读取时间 |
| 项目工作台专用库 | 已注册屏的操作人、来源电脑、修改字段、必要的非敏感前后值及保存／重启／回读结果 |
| 项目平台业务库 | 本功能不新增配置字段，不把小新配置复制为平台主数据，不顺带修改屏资产、状态或应用版本 |

未注册屏的配置操作记录只保存在本机。普通日志和共享摘要不记录密码、授权信息或完整原始配置报文；地址中包含敏感部分时，日志和摘要按现有规则隐藏敏感内容。

### 6.7 失败、取消和验收

| 情况 | 用户看到的结果与处理 |
| --- | --- |
| 旧版小新不支持、连接失败或无调用权限 | 明确原因，该台不保存 |
| 输入错误或包含不支持的字段 | 显示错误字段，小新不写入 |
| 只保存了部分内容 | 列出已保存和未保存字段，不自动重启，不显示全部成功 |
| 保存请求超时或断线 | 显示待核实；重新连接后先读取，不盲目重发或连续重启 |
| 保存成功，重启失败 | 显示已保存、重启未完成；只处理未完成步骤，不重复保存 |
| 重启成功，回读失败或值不符 | 保留保存和重启事实，显示回读未通过及原因 |
| 用户取消 | 停止后续目标；已发出的保存或重启不宣称已撤销 |

验收必须覆盖：未修改字段保留、明确清空、环境隔离、地址来源、旧配置兼容、错误输入不写入、部分保存、断线后的核实、重启后保留、权限拒绝及批量逐台结果。4 寸和 10 寸分别完成原有功能回归；macOS 工作台连接与调用另做实机验收。

技术实现、接口约定和实施顺序见[技术方案第 9.3 节](05-智能屏技术方案设计.md#93-屏端配置数据管理)及[开发计划第 11 节](06-智能屏开发与验收计划.md#11-后续扩展屏端配置数据管理)。

## 7. 批量执行、失败与历史

各操作使用第 4.5 节定义的步骤，围绕选屏、必要检查、明确执行和结果组织；不为所有动作套用相同步数。只读检查直接执行，有副作用操作通过清楚的目标摘要与执行按钮确认影响。

- 按设备区分可执行、无需执行、条件不满足和结果待核实。
- 安装/升级必须先满足同批同一明确尺寸，不允许从混合尺寸任务中自动挑出部分设备继续安装。其他动作仍可混合尺寸，按实际能力检查并明确列出不适用目标，由用户确认执行范围；同尺寸安装的包兼容性仍需另行检查，不能静默跳过不兼容设备。
- 默认建议并发 3 台，并遵守工作台全局上限；分批执行，避免一层设备同时全部重启。具体上限通过现场验证确定。
- “并发台数”表示同时处理的设备上限，其余已选设备排队，说明放在该字段标签提示中。参数区显示目标摘要，安装动作附应用包就绪数，不再重复显示“最多同时 M 台”。
- 同一屏不能并行执行安装、校时、持久端口修改、配置修改和重启；不同业务不得误用同一个资源身份。
- 本机未注册屏使用本机任务互斥，不依赖平台库或共享租约；该机制不能保证两台电脑之间互斥，现场应由一个实例负责同一未注册屏。已注册屏的设备写操作继续使用工作台共享资源保护；只读检查可独立执行，但仍检查当前电脑的活动任务占用，离线检查不承诺跨电脑互斥。确认合并时等待原任务结束再切换关联，不能把运行中的本机任务改成另一个平台目标。
- 进度反映真实阶段，上传按实际字节、批次按已完成设备数；不生成定时假百分比。
- 取消停止后续派发；对已开始的安装或重启解释当前边界。取消不等于设备状态已经回滚。
- 单台设备失败可继续其他独立目标。包含已注册屏的设备写操作，若开始前平台连接、登录或共享记录不可用，整批不执行，提示单独选择本机未注册屏重新操作。执行中断线保留已经完成的事实，停止不再满足条件的后续写入。独立的本机未注册屏批次仍可离线维护。
- 重试重新核实目标和结果，不自动重放操作。安装和设备维护重试保存原操作编号；两次操作都有共享记录时也保存共享关联。登记重试仍按当前资料重新预览，暂不额外关联原操作。

结果逐台展示执行动作、目标版本或关键参数摘要、开始结束时间、成功证据、失败阶段及下一步建议。批次总结果区分全部成功、部分成功、失败、取消和待核实；配置已保存/安装已完成等事实不能因后续记录失败而丢失。这些属于操作结果与本机任务记录，不写入平台资产字段，也不保存为项目业务状态。

操作结果页及本机历史中的逐台结果采用以下展示规则：

- 使用紧凑表格，每台屏一行，名称和 IP 地址分列；同时显示状态、实际结果和处理建议。配置操作另列保存、重启、回读结果，未保存字段仍可查看。
- 概览、进度、操作按钮、表头、分页和底部新操作按钮固定；仅设备数据行区域滚动。表头和数据列保持对齐，滚动条沿用细轨道、低对比度、移出区域隐藏滑块并保留宽度的规则。
- 长名称和结果说明使用省略显示，鼠标悬停可查看完整内容。分页只改变展示范围，不改变任务目标和各操作原有的适用范围。
- 结果标题、时间摘要和批次状态同行居中，状态标签内的文字垂直居中并保持统一高度。
- 日志只保留“任务与日志面板”按钮，点击后清除旧筛选并定位当前任务；从本机历史打开时定位所查看的历史任务，后续刷新不跳到其他任务。不另设“本次日志”弹窗，也不在设备表格下追加日志滚动区。完整诊断仍可独立查看和导出。

有副作用操作必须形成历史。未注册屏的操作、检查和日志持久保存在本机，平台断开不影响记录；关联屏的新操作按现有机制保存项目共享摘要。摘要包含操作人或本机操作来源、发起电脑、设备、操作类型、关键参数和逐台结果，未登录平台的本机操作不伪造平台账号。

注册或确认合并后，旧本机记录 ID 保留为历史关联，旧操作可在同一屏的详情查询，日志路径不迁移或丢弃。原本机历史不自动伪装成平台共享记录；其他电脑可见共享的新记录，不保证可见原电脑旧历史或完整日志。单纯刷新列表不新增操作记录；平台注册更新和状态覆盖分别记录确认内容与结果。

打开编辑、保存本机草稿和检查预览不加共享操作锁；真正提交平台修改或执行需要保护的设备操作时才加锁，正常完成自动释放。B 提交时发现 A 的操作锁，当前页面直接显示屏名称、A 的操作人、电脑和操作名称。B 点击“接手并继续”后，工作台解除已确认的锁，重新读取平台数据并完成必要检查；资料和执行条件仍符合原确认时，保留已选屏、安装包及参数继续原操作。B 不需要跳到历史记录找 A 的任务。

接手由 B 操作者自行判断，也可线下沟通，软件不核验沟通过程。点击取消不解除 A 的锁、不执行 B 的操作。确认前切换项目或离开页面时取消等待；确认后发现 IP、MAC、尺寸或待提交资料发生变化，提示重新核对，不自动覆盖。新的锁或新的持有人不能顺带解除。A 已正常释放原锁时，B 仍可重新检查后继续。

确认框标题为“该智能屏正在由其他电脑操作”，正文显示“【屏名称】正在由【操作人】在【电脑名称】上进行【操作名称】。接手后，对方本次操作将不能继续提交更改。请确认现在可以由你继续操作。”按钮为“取消”“接手并继续”。原操作涉及安装、校时或重启等设备动作时，补充“已经发送到屏上的操作可能仍在执行。”原操作包含多台屏时，显示批次数量和停止其后续提交的影响。项目共享记录中的手动解除功能保留，作为独立处理方式。

## 8. 数据职责与跨工程协作

| 数据或能力 | 所属位置 | 规则 |
| --- | --- | --- |
| 平台屏资产、空间树、在线状态及小新版本 | 新项目平台 | 普通读取只读；注册更新按第 3.5 节限定新增与资料字段；状态覆盖只更新 `status`，安装结果或独立读取确认后只更新 `app_version`；人工合并仅更新第 3.2 节选源确认的字段。各用例分别限定权限、条件与回读，不开放任意写入 |
| 未注册屏资产、物理身份核对、本机历史 | 当前运维电脑的 SQLite | 归属本机项目，重启后保留；不以平台连通、平台登记或共享库可用为前提 |
| 智能屏本机记录与平台记录的合并映射 | 当前运维电脑的 SQLite | 平台选定字段更新及回读成功后同步本机采用值，保存两侧标识、确认依据和字段来源；不改平台主键，旧本机 ID 与历史保留 |
| 已注册屏平台缓存、资料草稿与注册映射 | 当前运维电脑的 SQLite | 缓存保留平台已确认值及时间，草稿按平台主键独立保存；注册回读成功后转换为单条已注册视图，重开或断平台不丢身份、不重复计数 |
| 平台关联屏的操作摘要、实际安装结果 | 项目工作台专用库 | 多电脑共享；明确数据来源、采集时间，不伪装平台数据 |
| 连接检查、诊断、执行步骤、进度、失败详情、临时安装包路径 | 当前运维电脑 | 用于操作结果、任务与日志，不作为资产或项目状态；不要求共享原始日志或大文件 |
| 应用实际配置及生效状态 | 屏上的小新应用 | 屏端校验、保存并回读；工作台缓存不能代表屏端最新值 |
| 配置读取快照与未提交修改 | 运维电脑本地 | 保留项目、设备和读取时间；恢复草稿后重新读取实际值；不建设共享配置模板或另一份配置主库 |

不复制平台整套屏资产作为另一个可编辑主数据源。本机维护未注册资产、已注册屏资料草稿、必要缓存及运维信息；草稿与平台已确认值分离，平台记录按明确关联形成统一视图。只有尚未关联的疑似重复才进入人工合并。查询需先关联、再筛选计数和分页，保留来源，不能先各取一页再拼接。

已注册数量、平台状态只依赖平台成功读取或回读确认的范围；未取得实时数据时保留注明读取时间的缓存已注册记录，不把缓存或本机记录伪装为完整平台清单。平台断开时可以查看、筛选缓存、保存草稿并执行只读设备检查；平台写入和已注册屏的设备写操作仍须恢复相应连接、登录与共享保护，本机未注册屏的独立设备维护不受影响。

在智能屏页面完成当前项目登录后，自动重新读取平台资料、空间及统计；读取成功后消除原认证失败和平台不可用提示，无需手动点击刷新。保留当前筛选、有效选择和操作页面；读取仍失败时显示实际原因。退出登录或会话失效后重新确认可用范围，保留已有缓存，不继续显示过期的可用状态。

如项目数据库含多个业务项目，需要在项目连接中确定业务项目范围，查询、空间树、统计和操作一致限制在该范围；不能默认同库全部屏都属于当前项目。当前采样环境仅关联一个业务项目，不能据此推定所有部署都如此。

首期注册更新、状态覆盖、安装结果与独立核对的版本记录及人工合并均不要求新增平台 HTTP 接口；需验证现有字段、关联影响和数据库账号权限，工作台分别实现限定新增或条件更新、回读和操作记录。资料更新白名单见第 3.5 节；合并可额外选用双方已有的 `app_version`，不代表设备安装。前端空间关联字段 `spaceId` 保存实际节点，映射到平台已有字段 `building_id`，不修改空间目录表，空间修改与布点分开处理，保留原坐标和空间配置。跨平台写入、本机保存和操作记录不能假定处于同一事务，按第 3.2、3.5、5.1、5.5 节先核实再恢复，不能因记录失败重复插入、安装或覆盖平台值。演示原型仅使用模拟数据，不连接真实库。

旧原型数据迁移保留记录 ID、操作历史和原路径说明：已有 `spaceId` 优先；否则旧前端字段 `floorId` 非空时保留为实际空间 ID，没有楼层 ID 时才采用 `buildingId`。失效 ID 保留待修正，不静默退回祖先；仅有名称的旧记录不自动匹配目录。本轮只将完整空间能力接入智能屏，公共层提供通用树和路径逻辑，一体机、网关的业务接入留待后续。真实空间读取参考已有 HTTP 接口 `/api/edge/building/space/list` 的项目过滤、父子关系和排序实现；工作台继续直读数据库，完整选树不按图片、已绑定设备或屏过滤。

平台页面、控制器或查询接口的改版不作为工作台同步发版的默认条件；工作台只维护必要表字段、状态含义、空间关系和更新规则的兼容性。SQL 和字段映射集中在数据适配层。若这些数据约定改变，应更新对应适配和验证，不把直连理解为无兼容要求。

小新配置管理需要配套的屏端应用版本，当前为 2.0.10-5022。配置协议、字段范围、结果确认和重启规则见第 6 章，实际验证边界以验收记录为准。

## 9. 交付顺序

公共架构优化及一体机回归完成后，按“数据基础 → 真实资产管理 → 设备只读检查 → 注册更新与合并 → 安装和业务结果 → 其他设备维护 → 整体联调”实施。步骤编号、开发范围及验收记录统一见[智能屏开发与验收计划](06-智能屏开发与验收计划.md)，实现方式见[整体技术方案](05-智能屏技术方案设计.md)第12节。

首次交付本机资料、草稿、平台缓存、空间树及统一列表。随后完成设备身份、系统和版本读取，再接入注册和安装。每步先完成单台流程，再验证批量、部分失败及平台不可用的场景；4 寸和 10 寸按实际支持固件分别验收。

小新配置后置，配套修改屏端应用并单独验收；其他应用不纳入首期。平台状态覆盖须通过实际工作台的差异确认和受限更新链路验收，不以人工直接改数据库代替产品功能。

## 10. 验收标准

| 场景 | 验收结果 |
| --- | --- |
| 项目概览 | 平台有效记录与本机未合并记录分项计数，确认合并后仅计一条；未注册不计平台离线；疑似重复未处理时提示数量口径；平台未获取不显示为0 |
| 本机未注册 | 平台不可用时可新增/导入、编辑、查询并执行支持的设备运维；重启工作台后资产和历史仍在；不自动写入平台 |
| 注册更新预览 | 三步流程支持新增、更新、无变化、需核对分类；有效真实空间必需；MAC 自动采集，失败须逐屏确认可信历史或本次留空，冲突不能绕过；无变化不写，未选择的不提交 |
| 已注册资料草稿 | 保存草稿不改平台确认值、不新增本机未注册行、不生成疑似合并候选；按原平台主键预览差异，允许独立修改空间，保留布点坐标和空间配置，不顺带改状态、版本或配置 |
| 注册成功与恢复 | 回读确认后只显示一条已注册屏，未注册数减一、已注册数加一、总数不变；旧本机 ID、历史、映射和缓存保留，重开或断平台仍一条；失败保留资料，超时先核实再恢复，禁止重复插入 |
| 疑似匹配 | IP 相同或有效 MAC 相同均提示；空/占位 MAC 不误匹配；多候选、IP相同但MAC冲突不自动合并 |
| 确认合并 | 七项信息二选一，所在空间按同一侧 ID 与完整路径整体采用，不拼接祖先；支持整侧选择和最终预览，节点有效且属于当前项目；MAC 冲突核实后可确认；活动任务或待核实/补写期间延期；平台失败或并发变化不合并本机、不丢原记录，成功后采用值一致；主键、旧 ID、历史和采集来源保留 |
| 组合查询 | 名称/位置/MAC/IP、楼幢楼层、尺寸、状态可组合；跨页结果和数量一致 |
| 空间归类 | 单一空间树可选任意有效层级，楼幢直属不算待定；楼幢/楼层筛选包含自身和全部后代，深层路径可搜索；未关联或真正失效才待定，目录暂不可用保留 ID/路径待核验；迁移旧 ID 不丢历史，不按名称自动关联 |
| 空间导入 | `/` 完整路径按当前项目唯一匹配，规范输出无分隔符两侧空格，兼容旧输入空白但保留名称内部空格；空值明确待定，无匹配/歧义行默认仍选中且阻断提交，须修正或主动取消；支持树修正、批量分配和路径复制/导出；提交重校验，目录变化或迟到异步结果不污染其他项目 |
| 批量选择 | 智能屏列表通过表头选择或取消当前页，跨页选择保留、改筛选条件清空；智能屏操作页支持全部匹配选择及清空已选，改筛选条件保留已选目标；已注册和未注册可同批执行，重复目标不派发两次，开始执行后目标不随查询结果变化 |
| MAC 核对 | 已有地址一致、不一致、缺失、多网卡、重复身份、历史口径不明分别有准确行为；无可靠身份时保留只读并阻断设备写操作；应用标识不冒充物理 MAC |
| 安装批次尺寸 | 每个 APK 批次全为明确的 4 寸或 10 寸，包含筛选外目标校验；混选/未知尺寸禁用选包和安装检查并清除旧包/检查，不自动取消目标，恢复后重新选包；零目标先选包可绑定首个明确尺寸，变更已绑定尺寸需重选，适配器预检和执行也拒绝无效批次 |
| 安装升级 | 只接受小新包名；逐台检查架构、系统版本和可用空间；保留数据覆盖安装，由 Android 判断签名是否兼容，工作台解释失败原因且不自动卸载；核实设备版本和运行状态后，已注册屏再更新并回读 `app_version`。首次安装不作为本期验收前置，实机验收范围见对应记录 |
| 重启后远程管理 | 支持的 10 寸固件重启后 5555 恢复、持久配置和系统启动状态回读通过；至少两次连续重启验证其稳定性 |
| 时间校准 | 系统时间、启动使用的硬件时钟两项回读偏差均不超过 15 秒；时区和自动校时设置保持；两种尺寸无公网软重启验证；断电保时能力单独记录 |
| 重启 | 区分命令发出、设备完成重启、应用恢复；未安装应用的屏不因缺应用误判重启失败；回连超时不显示成功 |
| 在线覆盖 | 明确“本机 Ping 结果 → 平台状态”，本机结果不改；与平台不一致时才提示，未确认不写，批量仅覆盖勾选项；可重新检查后再确认；ADB 失败不代替 Ping 结果；本动作只写 `status`，提交并回读成功才更新平台资产展示；失败只保留结果与本机历史 |
| 运维组织 | 智能屏操作页提供单一操作下拉框、单行优先且最多两行的说明和动作专属步骤；左选屏右参数，首步动作在右参数面板底部，无跨栏底部操作条；后续步骤保留必要返回与确认；标题右侧历史抽屉，无历史标签页或左侧操作卡片；无顶部场景选择器 |
| 状态边界 | 执行阶段、进度、取消和失败原因可在本机任务与日志查看，不新增平台资产过程字段或项目中间状态；注册更新、在线覆盖、安装结果及人工合并分别保存确认后的最终事实，严格遵守各用例的写入范围 |
| 应用配置（后续） | 不阻断首期；后续验收旧版应用提示、未编辑字段保留、直接保存更新、重启要求及生效来源；不做配置版本冲突处理 |
| 异常恢复 | 安装中断、重启断连、结果补写失败、程序退出均不自动重复副作用操作；待核实结果能继续检查 |
| 多实例 | 平台关联屏共享结果及资源保护有效；本机未注册资产和历史不会假装跨实例共享；本机互斥不声称提供跨电脑保证 |
| 跨平台 | Windows 为当前实机验证环境；macOS 为确定支持目标，保留 Intel 与 Apple Silicon 构建。各系统分别验证工具、中文路径、超时及取消。macOS、Linux 尚未实机验收，不以 Windows 结果代替 |
