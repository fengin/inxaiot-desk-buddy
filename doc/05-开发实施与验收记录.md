## 3. 阶段 0：高风险技术 PoC

### 3.1 资料回顾

- 技术方案 33 章要求先验证双 MySQL、平台登录、SSH、SFTP、Agent 和租约/fencing。
- 原工作台提供 CSV、Release、模板、Agent 协议和真实闭环测试样本。

### 3.3 实际环境发现

1. 当前平台 RSA 公钥响应是 Base64 编码的 DER SubjectPublicKeyInfo，不是 PEM；认证适配器必须兼容两种格式。
2. 当前测试 MySQL 不能与 Rustls 协商 TLS 1.2/1.3；平台现有开发配置也明确关闭 SSL。测试连接必须显式使用未加密模式，并在产品界面显示“连接未加密”，不能伪装为安全连接。
3. 两台一体机均可使用所给私钥连接，主机指纹固定流程可用。
4. 现有 Agent v1 协议的三个只读命令可由 Russh 调用，JSON Lines 输出保持兼容。
5. Russh SFTP 支持当前服务器，实现分块进度、取消清理和临时文件原子改名可行。
6. MySQL 事务行锁、租约过期接管和单调 fencing token 在当前数据库版本可行。
