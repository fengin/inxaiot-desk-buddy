# 2026-10-22 语音配置联测说明

> 状态：本轮联测工具与隔离数据初始化方法已准备。本文规定执行范围、安全门禁和恢复步骤，不作为实机通过记录；实际结果须按设备、构建和测试阶段另行记录。

## 1. 目标与环境

测试人员使用 Windows 工作台，通过正式“修改小新配置”流程，验证小新提供的字段定义能够驱动语音配置显示、检查、保存、按需重启及回读。产品规则见[需求第 6 章](01-智能屏运维管理需求设计.md#6-屏端配置数据管理)，协议和代码定位见[技术方案第 9.3 节](05-智能屏技术方案设计.md#93-屏端配置数据管理)。

本轮只使用授权测试屏和仓库下新建的隔离本机库，不连接项目平台数据库，不使用或修改 `D:\data\com.inxaiot.desk-buddy`。实机写入前核对以下 IP 与稳定序列号组合；地址或硬件变更时应重新核实并调整测试白名单，不能仅换环境变量绕过校验。

| 测试屏 | IP | Android 稳定序列号 |
| --- | --- | --- |
| 10 寸 | 192.168.3.106 | 9c000c3c3643071205d |
| 4 寸 A | 192.168.3.74 | A47A4AK02040 |
| 4 寸 B | 192.168.3.82 | A47A5CK00524 |

正式任务仍按产品规则读取设备身份；序列号白名单是测试附加条件，不替代正式身份检查。4 寸与 10 寸须分别读取和修改配置；同一批次仅包含一种明确尺寸，同尺寸的新旧小新版本继续按实际能力处理。

## 2. 桌面验收内容

1. 主行左组显示“检查H5地址”“固定小新为主屏”“语音配置 >”，右组为重新读取及进度；窄窗口按组换行，主屏附属勾选及括号保持紧邻。语音浮层将启动说明放在勾选右侧，参数说明、范围及默认值合并显示；在默认窗口和最小 1024×640 窗口确认全部现有设置可见且不出现内容滚动条。
2. 语音浮层显示启动开关和 8 个音频参数，分组、名称、单位、范围及选项与屏端定义一致。打开、关闭和“完成”均不直接保存；主页面检查后确认修改才执行。
3. 同值不形成多余修改；改回原值后颜色和待修改数量恢复。清空语音数字或选项表示保留各屏原值。混合布尔值按“保留各自原值 → 统一开启 → 统一关闭 → 保留”循环。
4. 已固定但尚未切到小新主屏时，附属的“切到小新主屏”勾选独立记录待执行意图；勾选、取消均不立即切屏，正式确认后才执行。
5. 4 寸和 10 寸混选时显示橙色提示且禁用读取，尺寸待确认时先补齐尺寸；检查覆盖筛选隐藏的目标，旧混尺寸草稿不能绕过。对同尺寸的新旧版本混选，旧版只显示已支持的配置，仅阻止不兼容字段，其他字段仍能编辑。不同设备默认值不会自动覆盖实际值；字段规则不同则分批修改。
6. 主界面和语音都未启动时，新版小新仍能读取和保存配置；反复打开设置、切换界面和语音启停后重复检查。保存生效要求、配置读写可用性和语音是否正在运行分别判断。
7. 检查修改内容、确认修改、结果和历史显示正确参数名称；保存、重启、回读分别呈现。同值不重启，改动多个需重启字段只重启一次。
8. 测试后恢复原配置，再验证语音启动、欢迎语、普通对话和原有网页行为。参数回读通过不能代替现场声学验证。

### 创建桌面隔离项目

Rust 集成测试文件 `src-tauri/tests/smart_screen_voice_schema_real.rs` 提供 `voice_schema_gui_seed_local_only`（测试函数）。它只创建本机项目“语音配置隔离回归”和三台本机屏，MAC 初始为空，不连接设备或平台。

目标目录固定为工作台仓库下 `.review-tools/voice-schema-20261022/data`。已有 `local.db`、其日志文件或种子结果文件时拒绝覆盖；测试人员应先保留旧证据，不能通过指向生产目录解决冲突。

在工作台的 `src-tauri` 目录执行：

```powershell
$env:INX_VOICE_SCHEMA_GUI_SEED = 'YES'
cargo test --offline --test smart_screen_voice_schema_real voice_schema_gui_seed_local_only -- --ignored --exact --nocapture
```

结果文件 `gui-seed-ids.json` 仅保存本机项目和屏编号等测试标识。桌面测试进程必须明确使用该隔离数据目录；数据库初始化完成不等于桌面或设备联测已通过。

## 3. 正式链路实机测试

同一测试文件提供 `voice_schema_formal_real`（测试函数），默认跳过。普通运行只执行门禁和候选值的本地检查，不连接设备。

| 模式 | 验证内容 | 设备写入 |
| --- | --- | --- |
| `old-read` | 旧版无字段定义仍可读取基础配置；新音频叶子在正式预检被拒绝；没有执行任务，配置、进程和主屏策略保持 | 无 |
| `voice-roundtrip` | 新版返回 23 项定义及 8 个有效音频值；依次修改热词增强分数和静音判定时长，每次通过正式读取、预检、任务提交、独立回读；同值任务跳过保存和重启 | 有，结束时正式恢复 |
| `restore` | 使用原隔离用例的恢复记录，只恢复本轮修改且当前仍可确认的值，并核对全部公开配置 | 仅恢复所需写入 |

每次新用例生成 `.review-tools/voice-schema-real-20261022/<UUID>`（隔离目录）。恢复记录仅保存原音频数值、原启动布尔值、其他公开字段的 SHA-256 摘要、主屏策略和阶段状态；不保存服务地址原文。正式任务自身按原产品规则在隔离库保存执行证据，因此配置含带凭据、查询串或片段的地址时提前拒绝，不进入正式预检和写入。

示例为 10 寸新版本回归，在 `src-tauri` 目录执行；其他测试屏必须同时替换 IP 和对应序列号：

```powershell
$env:INX_VOICE_SCHEMA_REAL = 'YES'
$env:INX_VOICE_SCHEMA_TARGET = '192.168.3.106'
$env:INX_VOICE_SCHEMA_EXPECTED_SERIAL = '9c000c3c3643071205d'
$env:INX_VOICE_SCHEMA_MODE = 'voice-roundtrip'
$env:INX_VOICE_SCHEMA_ALLOW_WRITES = 'YES'
Remove-Item Env:INX_VOICE_SCHEMA_CASE -ErrorAction SilentlyContinue
cargo test --offline --test smart_screen_voice_schema_real voice_schema_formal_real -- --ignored --exact --nocapture
```

旧版本只读验证把模式设为 `old-read`，无需写入门禁；必须实际安装不提供字段定义的旧版应用，不能用新版模拟旧版成功。旧工作台对新版小新的兼容还须另用真实旧工作台验证，不能由本用例代替。

测试按设备当前范围选取小幅不同值，不写死现场参数。每步确认只有目标字段变化、启动开关及主屏策略保持；按字段定义需要重启时，必须确认应用进程编号变化而系统启动编号不变。同值步骤必须确认未保存、未重启。最后核对原 8 项音频值、原启动开关、全部 23 项公开可写配置及主屏策略一致。

本工具实际改值只覆盖上述两个参数，其余参数的类型、范围、选项和兼容由自动化协议测试及桌面用例补充；不能把两项实机改值解释为所有参数均已现场调优。

## 4. 中断和恢复

测试在第一次可能写设备前，将 `restoreRequired: true`（恢复责任字段）及候选值写入 `restore-state.json`（隔离恢复记录）。失败只输出固定阶段，避免底层错误中的地址进入终端报告；已建立恢复责任时会尝试安全恢复。

原任务仍在排队、运行或取消时不并发恢复。结果未知、完成落盘失败或受保护时先调用正式“核实结果”，仅回读原结果，不重放保存或重启。无法确定原任务结果时保留恢复责任。若当前值不是原值或本轮候选值，或其他配置、主屏策略被外部修改，也停止自动恢复，不覆盖其他人的修改。

重新执行恢复时保持相同 IP、序列号及两道门禁，只使用原用例 UUID：

```powershell
$env:INX_VOICE_SCHEMA_MODE = 'restore'
$env:INX_VOICE_SCHEMA_CASE = '<原隔离目录的UUID>'
cargo test --offline --test smart_screen_voice_schema_real voice_schema_formal_real -- --ignored --exact --nocapture
```

恢复仅接受固定证据根目录的直接子目录，不接受任意路径。只有全部原值及其他字段摘要核对一致，才清除恢复责任。保留失败阶段、隔离任务结果和恢复记录，不人工改数据库终态伪造成功；无法恢复时明确记录原因并交由测试负责人处理。
