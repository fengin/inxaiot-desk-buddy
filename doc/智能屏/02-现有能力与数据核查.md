## 1. 业务对象和环境

实施人员从当前电脑的运维工作台读取项目侧平台数据并维护 4 寸、10 寸屏。管理范围包括平台已登记屏，以及尚未登记、先保存在当前工作台实例的屏。项目数据来自项目平台，设备操作直接作用于受管屏及其小新应用。

本功能的系统协作范围为运维工作台与项目侧平台，不涉及云平台业务、云数据库或云接口。就本场景而言，云平台配置并同步项目信息到项目平台属于上游既有过程；工作台只使用项目侧已有数据，不参与该同步过程，也不因执行屏运维而连接云平台。

本机资产、资料草稿、平台注册更新、人工合并及状态覆盖的真实能力属于待实现设计，当前交互仅使用模拟数据。本文数据库事实来自已记录的授权只读核查；屏端源码和脚本用于核实受管终端能力，不表示新增一个云端管理系统。

### 1.1 已有一体机访问方式

当前重构版工作台对项目平台的业务数据使用数据库直连，平台认证仍使用既有登录链路。各类调用分别如下：

| 交互对象 | 当前代码行为 | 含义 |
| --- | --- | --- |
| 项目平台认证服务 | 获取公钥、验证码、登录并检查会话有效性 | 属于登录认证链路，不用作一体机资产、部署或历史查询接口 |
| 项目平台业务数据库 | 直接查询一体机数据库表 `op_edge_aio_server`；当前连接为只读 | 平台资产查询不依赖平台业务列表接口；不能据此写成工作台当前已直接修改全部平台业务表 |
| 项目工作台专用数据库 | 直接读写共享配置、工作台资产、操作摘要、最终结果和租约 | 数据部署在项目环境，但属于工作台自己的库，不与项目平台业务表混为一谈 |
| 一体机设备 | 使用 SSH/SFTP、设备脚本，以及一体机自身的 HTTP 注册接口 | 这是受管设备通信，不是调用项目平台业务管理接口 |

当前 Rust 代码在首次部署注册阶段调用目标一体机自身的 6002 端口，先检查本地注册状态，再按需提交注册信息；一体机服务随后按自身链路向项目平台同步。该设备链路不能因为采用项目数据直连而被误删；工作台也没有通过这一动作直接写平台一体机业务表。设备本地注册成功与平台已经同步成功需分别判断。

智能屏沿用“登录认证使用平台既有能力、业务数据直接访问项目表、设备操作走设备协议”的分工；在线状态直接更新是智能屏新增的明确写入范围。

### 2.1.1 版本字段的业务含义与当前代码

数据库表 `smart_terminal_screen` 的已有字段 `version`，在 Java 实体类 `SmartTerminalScreen` 和 DTO 类 `SmartTerminalScreenDto` 中仅注释为“客户端版本号”；SQL 映射文件 `SmartTerminalScreenMapper.xml` 映射并查询该列，保存命令类 `SmartTerminalScreenSaveCmd` 没有该字段。已核对的屏保存服务和屏端代码中，未找到安装小新后更新此列或根据此列切换 H5 样式的实现，不能用这个笼统注释认定它保存 APK 版本。

已确认业务定义：`version` 用于屏内网页容器展示的 H5 样式版本，相关选择功能尚未实现。小新 APK 版本使用数据库字段 `app_version`。此前数据库抽样和已读平台实体未包含该字段；2026-09-29 用户确认 142 环境已增加该列，这是环境补充说明，不表示本次重新查询过数据库。工作台按字段已存在接入，不负责其他项目增列，也不依赖平台 Java 实体增加属性。

已有空间字段 `t_project_building.screen_version` 表示多菜单版、简洁版等页面配置，`screen_style_type` 表示地图或设备卡片等展示方式，也不是 APK 版本。屏端网页 TypeScript 文件 `src/utils/versionCheck.ts` 中的本地存储键 `app_version` 保存网页构建版本，与平台数据库的同名字段无关。

### 2.3 空间结构与归类

数据库表 `t_project_building` 使用 `id`、`parent_id` 构成空间树，`project_info_id` 指向业务项目，`area_level` 表示空间层级。源码定义 3 为楼幢、4 为楼层、5 为分区、6 为子分区。

本次 `mysql_142` 有效屏关联 6 个有效空间、1 个业务项目，其中：

- 5 台直接关联楼层。
- 16 台关联分区。
- 未发现失效空间关联。
- 空间数据中有 2 条记录的 `area_level=5`、`building_level=4`。

因此楼幢/楼层归类要沿父链处理，筛选要包含下级空间。数据库字段 `building_level` 在所查屏查询中用于排序，不能等同于 `area_level`。

两个库的空间表所查字段基本一致，但 `screen_version` 默认值不同：一个为空，一个为 `simplified`。该字段属于平台空间屏页面配置，不能作为小新 APK 版本或桌面程序版本。

### 2.3.1 空间接口的实现参考

已有 HTTP 接口 `GET /api/edge/building/space/list` 由 Java 控制器类 `EdgeTenantBuildingSpaceController` 提供。它从当前登录用户取得业务项目编号，默认不按图片过滤，调用 Java 服务类 `ProxyEdgeBuildingSpaceServiceImpl`、`TProjectBuildingServiceImpl`，最终执行 SQL 映射 `TProjectBuildingMapper.selectProjectBuildingListByProjectId`。

实际查询以 `project_info_id` 和 `delete_flag='0'` 限定空间，返回平面节点，按 `area_level`、`building_sort` 排序。平台前端已有 TypeScript 方法 `getSpaceList` 取得列表后，用 `setTree(0, data)` 按父节点组成树。接口可选的图片、设备、核心空间及已有屏过滤不适用于工作台完整空间选择；`parentId` 条件只取所选节点及直接子节点，不代表全部后代。

工作台参考这些数据规则自行查询并使用已有树工具，不运行平台前端的模块级可变数组，也不新增对此 HTTP 接口的运行依赖。共享基础库源码位于 `inxvision-cloud/weef-iot-edgexfoundry(inxaiot_dev)/weef-iot-edgexfoundry/weef-service-device/`；代码随项目平台运行，源码位置不表示调用云端。

### 2.4 代表性只读查询

表结构通过 MCP 的 `describe_table` 工具查询；下列 SQL 仅为本次数据核查方式，不是产品最终查询实现。

```sql
SELECT size, status, COUNT(*) AS screen_count,
       SUM(CASE WHEN COALESCE(TRIM(mac), '') = '' THEN 1 ELSE 0 END) AS missing_mac_count,
       SUM(CASE WHEN COALESCE(TRIM(version), '') = '' THEN 1 ELSE 0 END) AS missing_version_count
FROM smart_terminal_screen
WHERE delete_flag = 0
GROUP BY size, status;

SELECT b.area_level, b.building_level, COUNT(*) AS screen_count
FROM smart_terminal_screen s
LEFT JOIN t_project_building b
  ON b.id = s.building_id AND b.delete_flag = '0'
WHERE s.delete_flag = 0
GROUP BY b.area_level, b.building_level;
```

未导出真实设备名称、IP、MAC、账号、令牌或应用授权信息到文档。

工作台直接读取项目平台数据库，不把平台已有页面接口作为智能屏列表、搜索、详情或统计的实现前提。

| 楼幢/楼层归类 | 数据库表 `t_project_building` 的空间类型和父子关系 | 解析父级路径与全部下级空间，不调用平台空间服务来完成筛选 |

| 本机与平台屏合并展示 | 平台屏主键、IP、MAC，加本机关联映射 | 疑似匹配、人工合并、历史保留与两类来源统一分页 |

Java 查询类 `SmartTerminalScreenQry`、SQL 映射文件和应用服务仅用于核查字段含义、空间关系及业务规则，工作台不引用它们的 Java 类型或复用其 HTTP 接口。平台当前查询是否提供关键词和尺寸筛选，不限制工作台自行实现这些查询。

普通平台访问保持只读；注册更新资料、用户确认后的屏状态覆盖、已注册屏安装结果或独立读取确认后的版本记录，以及人工合并时选源确认的字段同步，分别通过限定写入用例处理。目标规则见第 6 节，查询和真实写入能力均不能仅因已有数据库字段或模拟交互而视为已经实现。

### 3.2 在线状态维护

Java 类 `EdgeSmartTerminalScreenServiceImpl` 的方法 `screenIpPingOffline` 声明每 10 分钟触发，读取屏 IP，调用 Java 方法 `InetAddress.isReachable`，超时参数为 2000 毫秒，成功保存在线、失败保存离线。

平台自身通过 Ping IP 检查在线状态，这是当前需求采用的业务规则；它代表平台服务器网络视角的 IP 可达性，不是 ADB 检查，也不是应用心跳或业务健康检查。本轮文档设计不继续审查定时任务部署，源码中的调度声明也不作为现场固定检查周期的验收结论。

工作台本机 Ping 后，对与平台不一致的结果按“本机 Ping 结果 → 平台状态”提示用户，确认后直接更新 `smart_terminal_screen.status`，本机检查结果不变；需要新结果时重新检查再确认覆盖。更新须进行条件校验、回读和审计，不调用也不要求新增平台状态接口。专用写入能力尚未实现，本轮没有执行数据库写入。

### 3.3 平台数据写入边界

项目平台的屏保存业务还涉及空间图片、屏页面配置和设备别名。读取这些服务源码用于辨认关联影响，不表示工作台要调用其保存接口，也不表示直接改一个字段就完成了对应的复杂业务操作。

平台已有记录可读，不等于工作台已具备核实 MAC、保存实际版本或更新在线状态的完整能力。本期目标分为四类受限写入：注册新屏或更新既有屏资料；用户确认后的 `status` 覆盖；已注册屏安装结果及独立读取确认后的 `app_version` 更新；人工合并时按逐字段选源结果同步既有平台记录。各类用例分别限定字段、目标条件及回读证据，写入不确定先核实，不伪造平台成功、不重复插入或安装。

人工合并包含名称、IP、MAC、尺寸、所在空间、详细位置和小新版本七项，对应已有数据库表 `smart_terminal_screen` 的字段 `name`、`ip`、`mac`、`size`、`building_id`、`install_address`、`app_version`。所在空间整体采用一侧的实际节点 ID 与完整路径，映射到平台单一字段 `building_id`；不拆开楼幢和楼层选源，不新增空间字段、不改空间目录表。应用版本列 `app_version` 按平台已具备处理，原有 H5 `version` 不参与合并。正式接入前仍需核实相关业务、缓存和派生数据的一致性影响。字段选源是记录核对，不执行设备安装或改写原始观测；MAC 不由状态覆盖、安装结果更新或普通采集自动回填。

平台注册更新的资料白名单为 `name`、`ip`、`mac`、`size`、`building_id`、`install_address`，不顺带改 `status`、`app_version` 或空间配置。已有平台主键的屏修改资料，属于同一记录的本机草稿与平台差异，不属于两条资产的疑似重复合并。新增成功须回读后保存本机关联及平台缓存，保留旧本机 ID 和历史；平台短暂不可用不使它退回未注册。

平台 Java 命令类 `SmartTerminalScreenSaveCmd` 没有 MAC 字段；Java 服务类 `AppSmartTerminalScreenServiceImpl` 的保存逻辑按屏主键区分新增和更新，并要求 `buildingId` 大于零且空间存在。数据库 `mac` 可空，当前已有保存流程不以 MAC 为必填依据，因此工作台可在采集失败后逐屏确认采用可信历史值或暂不填 MAC；不能由此跳过重复或身份冲突检查。现有保存代码包含 IP 判重，但更新分支在排除本记录后又判断相同主键，不能直接视为可靠的更新判重保证；工作台需按项目范围、有效记录及明确目标实现独立重复检查。

上述保存事务还可能更新空间图片、设备类别、屏版本、样式及设备别名。资料直写不复用这些扩展字段；修改空间关联可能影响原空间布点及呈现，这是依据源码的关联影响推断，正式接入前须核实实际项目的数据关系。原型只提供空间移动影响确认，不能据此声称已经完成真实布点迁移或一致性验证。

### 4.2 10 寸屏持久 ADB

已有 Windows 批处理文件 `10寸屏设置持久网络ADB_5555.bat`，位于 `inxvision-assistance/deploy/smart-kit/智能屏ADB工具/`：

- 输入并绑定单个设备地址，要求当前 ADB 已经可连接。
- 使用设备提权方式 `su 0`，不通过 `adb root` 重启调试进程。
- 写入并回读持久端口，重启设备。
- 最长等待 120 秒，检查连接恢复、持久/运行端口均为 5555、系统开机完成。

它不能远程打开一个完全没有连接通道的屏；4 寸固件是否适用需另外验证。出厂脚本 `optimize_device.bat` 还处理语言、默认桌面、设备所有者权限和系统应用，不能作为普通端口维护的替代流程。

### 4.3 校时、安装、重启和 MAC

- 已有 Windows 批处理文件 `10寸屏校准屏端系统时间.bat` 以电脑 UTC 时间校准，优先系统校时命令、失败后尝试兼容方式；需要相应权限，回读偏差不超过 15 秒；保留设备时区和自动校时设置。已有 4 寸验证记录显示原校时验证未通过，不能直接套用。
- 4/10 寸资料均有覆盖安装应用的 ADB 命令依据，但未形成工作台的批量检查、安装、版本回读、启动及结果记录闭环。
- 已有重启后连接和开机验证代码可以作为规则参考，不能把发送命令当作设备已恢复。
- 已有 Windows 批处理文件 `4寸屏获取以太网MAC地址.bat` 通过网络 ADB 连接检查后，固定读取有线接口 `eth0`；检查非无线、以太网类型及合法单播地址，不回退到 `wlan0`、ARP 或 ADB 连接所走的网卡。其采集前提是屏的网络 ADB 与授权可用，不要求以太网已经配置 IP。
- 该工具目录的 `验证记录.md` 记录了 2026-09-14 对 PX30、Android 8.1 的一台 4 寸屏读取成功；记录明确未验证跨重启或出厂烧录地址一致性。因此当前依据是运行时有线接口地址，不是已证明永久稳定的硬件编号。本轮没有重新连接设备，10 寸网卡选择与采集仍需独立验证。
- 注册更新应把采集放在预检内。失败保留历史及来源，允许逐屏确认可信历史或暂不填；已有值冲突、多网卡不明确和疑似重复必须先核实，不能借空值确认绕过。普通采集不自动写平台。

## 5. 小新应用配置可行性

### 5.1 已有配置

Dart 页面类 `SettingsPage` 的保存方法涉及环境、设备授权/配置服务地址、语音和业务网页地址、启动检查开关、应用设备标识、设备名、授权信息、业务扩展参数以及语音参数和热词；另有管理密码、网页缓存和锁定模式操作。

### 5.2 外部管理通道

本次检查 Android 清单、原生主活动、配置与协议模块，未发现供工作台使用的完整 HTTP 配置服务、自定义配置广播、深层链接配置协议或文件导入通道。

网页与应用之间的 JavaScript 桥接方法 `getConfig` / `setConfig` 仅覆盖少量字段：读取语音地址和应用标识，写入当前环境语音地址。这是应用内网页桥接，不是完整的外部运维接口。

配置管理需要修改屏端应用，优先级安排在基础运维功能之后，不能只在工作台添加表单就宣称可以远程保存。直接篡改应用私有文件会绕过现有校验和内存处理。配置管理后置不阻断本期小新应用安装升级、校时、持久端口、检查和重启等能力。

### 5.3 应用标识不是物理 MAC

Dart 方法 `_generateMacAddressFromHardware` 使用 `androidInfo.id` 计算一个 MAC 格式字符串，设置页允许人工修改该应用设备标识；该过程没有读取网卡 MAC。

本机已解析的依赖 `device_info_plus 12.4.0` 的 Android 实现将该属性取自 `Build.ID`（系统构建编号），不是 Android 唯一设备标识。相同构建编号存在生成相同应用标识的可能，但本轮没有读取设备验证是否实际重复。

需求必须分别命名平台主键、平台 MAC、物理网卡 MAC、应用设备标识和 ADB 连接标识。自动重生成应用标识可能影响授权或绑定，不能作为普通“核对 MAC”动作的一部分。

## 6. 已确定的目标规则与现有差距

### 6.1 项目数据直连原则

工作台通过直接访问项目侧数据表降低对平台页面、控制器、业务查询参数和服务发布节奏的依赖。平台登录认证保留现有链路；资产查询、空间筛选和统计不经平台业务接口，已明确的运维字段更新也由工作台直接执行受控 SQL。

直连将兼容边界收敛到数据，而不是消除兼容工作。最低维护范围为：

- 明确依赖的表、字段、数据类型、枚举含义、项目隔离和逻辑删除规则；例如屏状态 0/1、尺寸字符串及空间父子关系。
- 将 SQL 和字段映射集中在工作台数据适配层，业务页面不散落 SQL，也不依赖平台后端类名和接口返回格式。
- 连接或进入相应功能时检查必要表和字段，缺失或含义无法确认时提示具体不可用项；平台新增无关字段不应导致整个工作台不可用。
- 每个写操作列明字段、目标条件和成功证据。本期分别限定注册更新资料、在线状态覆盖、小新安装结果与独立读取确认后的版本记录及人工合并选源字段同步；新增只用于无平台主键且无未解决候选的屏，更新保留原主键，不开放删除、空间目录修改或通用数据库写入。
- 在新增写入范围前核实该数据是否伴随关联表、缓存、事件或派生状态更新。存在这些行为时，把一致性规则纳入工作台对应功能设计，不能只因能够执行 SQL 就认定业务已经完成。
- 条件更新、回读和操作记录由工作台统一实现；针对依赖的表结构和字段含义保留兼容性检查及针对性测试，不要求每次平台页面改版都联动修改工作台。

上述规则优先使用已有数据库适配层和检查机制，不引入额外平台配套服务或大型版本管理框架。

本机 Ping 已正常执行但设备不可达，可以形成离线检查结果；探测程序异常或取消属于无法判断。状态差异展示检查来源与时间，由用户确认是否将本机结果覆盖到平台；本机结果不反向修改，可重新检查后再比较。状态覆盖不要求目标先通过 ADB 或 MAC 采集；未登记屏没有平台主键，只记录本机检查结果。记录删除、IP 或预览状态变化时停止覆盖并重新读取，不把旧结果用于更新新目标。

现有表未提供专用在线检查时间或可靠并发版本；数据库字段 `app_version` 表示小新应用版本，原有 `version` 表示 H5 样式版本，二者都不能作为状态序号。条件更新可防止预览值已变化时盲写，但不能宣称阻止所有先后竞争；平台后续 Ping 仍可改变状态。写入、回读和结果分别记录，连接中断后先核实，不自动重放新增、旧更新或设备安装。人工合并同样校验预览期间两侧记录及目录条件，平台更新与回读未确认前保留本机原记录；平台可能已写入而本机未完成时先核实再恢复关联，不把跨数据库操作当成同一事务。各限定用例均不是通用平台数据库修改授权。

资产只呈现注册属性和确认后的最终业务事实；执行阶段、进度、取消和失败原因属于本机任务、结果界面与历史，不写入平台资产或项目状态。开发原型不提供顶部场景选择器，注册更新、合并字段、版本与状态变化均为模拟数据，不执行真实数据库写入。原型新增记录的模拟平台默认状态不代表设备实测在线，本机 Ping 结果仍独立。

### 6.3 版本闭环与设备检查边界

先安装后注册的屏通过独立版本核对补齐平台记录，同版本跳过也无需重装。原型提供“核对版本并同步平台”，从独立模拟设备状态重新读取，显示地址、来源时间与差异；只在确认后限定更新平台版本，失败保留旧值。真实设备读取和数据库写入尚未接通。

已注册屏在平台不可用时仍可执行 IP、设备、MAC、诊断和版本等只读检查，结果保留本机；平台写入与已注册屏设备写操作仍需恢复相应连接和共享保护。草稿 IP、MAC、尺寸不作为实际执行目标，存在关键差异时阻断该屏设备写操作并引导处理，普通资料草稿不阻断。检查确认和派发前校验实际地址与身份，迟到结果不应用到新项目或新目标。
