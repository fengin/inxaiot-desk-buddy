# 三屏设置与小新配置实机回归

日期：2026-11-04。结论：新增合并系统设置、首屏读取并发及所列小新配置范围通过；独立“切到小新主屏”的普通任务前置本轮未成立，单列未覆盖。人工界面验收由实施人员另行确认。

## 1. 业务目标与运行环境

实施人员在Windows工作台选择智能屏，先检查，再按选项修改系统或小新应用配置。本轮验证实际保存、生效、回读、并发和异常停止，结束后恢复原配置，时钟保持准确当前时间。

测试对象为10寸屏192.168.3.42、4寸屏192.168.3.74和4寸屏192.168.3.82。核对用户提供的无线MAC、设备序列号和工作台使用的有线接口标识；42实际经Wi-Fi连接。

源码工程为`inxaiot-desk-buddy`（实施工作台程序），界面及正式后端运行在Windows，设备命令在三台Android屏执行。实机任务使用隔离本机项目、SQLite数据库和内存凭据存储，未使用生产数据目录，也没有由工作台写入平台业务库或共享库。既有服务地址的连通性探测、屏端应用自身联网均实际存在，不能称零平台网络访问。

业务规则见[统一设置方案](50-设置智能屏统一操作与验收.md)，界面规则见[桌面交互规范](../01-桌面工作台界面设计规范.md)。本次回归没有修改屏端应用或平台服务代码，也没有为通过测试放宽设备执行成功条件。

## 2. 合并系统设置

15种非空选项组合逐屏均有正式任务成功回读，或已满足的只读跳过证据，包含各项单选、混选和全选。先前失败及后续独立补测分别保留，不表示15个整批任务首次运行都成功。

| 验证项 | 实际结果 |
| --- | --- |
| 保持ADB端口 | 10寸真实保存持久端口并重启回读；两4寸按已验证厂家配置只读跳过，没有重复写端口 |
| 校准时间 | 系统和硬件时钟均真实校准、回读；NTP已使两者准确时，后续手动校时正确跳过 |
| 关闭屏睡眠 | 实际设置接电保持唤醒并核对运行状态，必要时唤醒一次；保留原息屏时长及屏保配置 |
| NTP选项 | 未选不发对应修改；明确地址、同值跳过、清空自定义地址和设回142均已验证 |
| 清空与设回 | 三屏清空后均取得固件默认源同步成功证据；随后三屏正式设回192.168.3.142并重新确认授时 |
| 共享重启 | ADB与NTP同时变化时先保存ADB，再保存NTP，共用一次系统重启；每个产品任务每台屏最多一条重启请求 |
| 已满足 | 同值复检为跳过，未创建空执行任务；未选项不主动下发对应修改命令 |
| 失败处理 | 失败或未知时停止该屏后续，其他屏继续；只读核实不重放设置、启动、重启或接续未开始项目 |

NTP自动授时及系统重启会自然影响时间和运行状态；“未选不修改”按对应配置、校时或输入命令核对，不把这些自然变化误判为工作台越项写入。

首屏正式读取接口另外实机执行并发1、2、3各一批，每批三台单设备请求，共9次读取。实际峰值分别为1、2、3，返回设备、顺序及四项状态正确，NTP均为未选；42默认三项已满足，两4寸仅关闭睡眠为待处理。任务数0→0，561条审计确认零设备写入；前后关键设置、端口、时区、启动编号及睡醒状态一致。此项是正式读取接口实测，不是仅以预检代替首屏读取。

## 3. 小新配置与本轮未覆盖项

已真实覆盖同尺寸分组并发读取、两4寸批量及10寸单批改名、非当前环境OTA/H5地址、可选地址清空、WebSocket输入和清空、环境切换与返回、H5检查、语音启动、8项音频字段、固定主屏开关、锁定与解锁，以及需要重新激活时先解锁的依赖检查。

读取并发设置1、2、3时，两4寸组实际峰值为1、2、2，10寸单台组为1、1、1；不称3台小新配置同时读取。4寸与10寸混选被正式门禁拒绝，没有配置写入。既有设备管理权限（Owner）仅只读核对，不新设、撤销或清除应用数据。

独立“切到小新主屏”的普通任务→系统主屏任务分支本轮未实机执行。当前设备未安全形成所需前置：74旧单Main任务638已确认退出，随后真实查询得到新任务639，仍为HOME且仅一个本应用任务；82、42也未形成standard前置。因此没有伪造查询或放宽判定。

相关三个后端文件相对fe22db2没有差异。10月23日已有两种尺寸完整真实证据：10寸普通任务103→HOME104，4寸普通任务624→HOME625，均有匹配请求、原任务移除和HOME运行回读成功，普通配置未保存或重启、主屏策略未重复保存且最终恢复。当前前端独立勾选、目标筛选、草稿和提交载荷测试也通过。历史实机及组件测试与本轮未覆盖分开记录，不能替代本轮实机验收。

同值零任务的实机脚本过滤标为QA辅助证据，产品界面行为另由组件自动化佐证。音频验证保存、应用重启和回读，不包含现场识音、音质或H5业务登录验收。小新配置阶段未发送Android系统重启命令，内核启动编号持续保持不变。

## 4. 失败事实与恢复

| 事实 | 处理和结论 |
| --- | --- |
| 系统设置原默认三项组：82硬件校时后的读取命令返回非零 | 该屏后续睡眠未执行，其他屏成功；正式只读核实不重放，独立补测通过，原失败保留 |
| 10寸NTP＋校时组：重启后180秒内未取得连接成功回复 | 未进入开机完成检查，后续校时未执行；用户手动连接网络后恢复。后续正式只读核实只确认当前状态，未接续校时；独立补测通过，不反推原超时窗口成功 |
| 74切回原应用环境：一次任务在保存前的设备检查阶段失败 | 后续独立正式恢复任务成功；现有日志不能唯一定位原失败命令，不归因为平台写入或确定网络故障 |
| 74第二次锁定：目标保存且系统进入锁定，但应用前台就绪未确认 | 系统事件证实失败窗口内发生60秒屏保和超时休眠。原任务未重发；临时接电保醒0→7回读后，对应锁定和解锁补测成功，随后恢复原0及Asleep/OFF，不改息屏时长或屏保 |

测试辅助程序的取时、查询参数和前置构造问题保留在本机原报告及修正后的独立记录中，不作为产品功能成功证据。所有原失败快照保持原样。

10寸重启后曾需要人工点击连接Wi-Fi。当前证据没有确定其自动连接失败根因，也不能说明屏普遍存在硬件故障。恢复联网后端口仍保持5555；有重启请求返回非成功码，但新启动编号、身份和设置生效均被随后确认的成功案例，没有因此补发产品重启。离线期间存在观测空白，不能声称排除了所有外因重启。

本轮工具审计中的重启请求均有归属，累计数量来自不同测试用例，不代表单个操作多次重启：

| 42／10寸 | 16 | 1 | 17 |

42的那次额外收尾请求用于原NTP运行源恢复，发生于13:49；后续三段补测没有额外收尾重启。42在“NTP＋睡眠”和最后“设回142”两组的命令回执为1，均由后续真实启动及生效证据确认成功，各自仍只有一次产品请求。

## 5. 最终恢复与界面检查

系统设置最后一组完成后，三台均恢复原11项设置、持久及运行端口、时区、身份和应用运行状态，NTP为原142且有当前运行源成功证据。系统时钟偏差分别为0、-1、-1秒，硬件时钟分别为0、-1、-2秒。42、82为原Awake/ON；74为原接电保醒0、60000毫秒、Asleep/OFF。其后的三批只读检查没有改变这些状态。

经明确授权，142服务器已持久及运行时允许192.168.3.42授时；原其他许可保留，没有修改服务器时钟、上游或重启服务。该新增许可在测试后保留。

“修改小新配置”第三行按选项实际宽度布局，“语音配置 >”及附属“切到小新主屏”保持同行；说明文字位于右侧12像素间距之后，保留左对齐及空间不足时的完整悬浮提示。1920×1080、1280×900、1024×640的18个布局场景，以及两种语音字段定义的30张隔离截图检查通过；启动开关、8个参数和完成按钮完整可见。最新前端类型检查、生产构建及差异检查通过。这是组件和隔离浏览器证据，不称打包桌面完整点击验收。

最后重新启动了原隔离开发验证窗口，实际观察到“修改小新配置”首屏正常渲染，并发设置位于首屏，读取按钮位于右侧底部。原有“继续本机未提交修改（1台）”仍可见，没有操作或提交该草稿；此轮原生窗口检查没有发送设备修改。

一体机业务运行时代码相对fe22db2没有变化，按本轮范围没有增加一体机写入实测。现有0.2.19交付包仍按原交付记录使用；本轮没有升版、打包、提交或发布。
