# 任务临时制品清理与诊断保留验收

日期：2026-10-24。状态：两步开发、自动回归及限定测试环境实机验收均完成，调整纳入 0.2.16；交付状态见[0.2.16 发布记录](47-0.2.16发布记录.md)。

实施人员使用工作台批量安装智能屏应用，或对一体机执行首次部署、整包升级、单服务升级时，程序会复制安装文件，保证同一批设备使用相同内容。任务安全结束后，应释放这些任务内的临时副本，减少运维电脑及测试一体机的磁盘占用；原始安装文件、操作日志、诊断报告、回滚依据和待核实任务数据继续保留。

修改所在工程为 `inxaiot-desk-buddy`（实施工作台程序）。第1步代码运行在实施人员的运维电脑；第2步修改工作台内嵌的一体机部署脚本，脚本实际运行在目标一体机。小新 APP、H5、平台业务数据库结构不属于本轮修改范围。

本轮使用独立本机数据和测试说明指定的设备、数据库。`D:\data\com.inxaiot.desk-buddy`（生产实例数据目录）不作为测试或清理目标；原因分析使用的生产实例副本也不由新清理功能直接启动处理。本轮源码调整随 0.2.16 交付，本文保留实际功能测试范围，构建产物与正式包验收另行记录。

## 2. 第1步已实现的本机保留规则

| 数据或任务状态 | 当前规则 |
| --- | --- |
| 人员选择的原始 APK、镜像 tar | 保留原路径文件，只回收程序创建的任务副本 |
| 智能屏安装批次已结束，且设备、平台及共享结果均不再待核实 | 只删除本次任务目录内固定名称的 `xiaoxin.apk`（已有任务安装包文件）；同批全部目标结束前不删除 |
| 一体机首次部署、整包升级、单服务升级已安全结束 | 保留既有临时目录清理能力，释放本次镜像快照、内部发布包和临时渲染文件 |
| 排队、执行中、取消处理中、结果待核实或仍有结果保护的任务 | 保留任务副本，不根据文件年龄或体积提前删除 |
| 一体机任务状态为 `Interrupted`（已有中断状态） | 保留记录、目录和日志，不论是否已生成待补写文件；中断可能发生在远端动作之后、恢复依据写入之前，需要后续核实 |
| 智能屏诊断报告及其他非安装操作文件 | 保留原文件；任务结束及工作台重开后仍能查看、导出诊断 |
| 安装计划、包名、版本、SHA-256摘要及逐台执行结果 | 保留数据库中的追踪依据，不因安装包副本回收而删除 |
| 任务日志 | 与临时制品分开管理，继续使用已有保留规则；成功、部分成功及取消为30天，其他可安全收尾状态为90天。待核实、中断一体机任务不因本轮清理启动日志过期处理 |
| 未知业务、未知操作或受管范围以外的文件 | 保留，不将其解释为可删除的安装缓存 |

旧版本曾给一体机中断任务写入日志过期标记时，启动及任务清理会只撤销该标记，保留日志正文；带结果保护的中断任务也进入这一保留处理。若候选查询或文件保护失败，当次日志过期扫描暂停，程序继续启动，避免旧标记仍使待核实日志被删除。

一体机完整部署期间会同时形成镜像快照和内部发布 tar，过程中的本机临时占用仍约为所选镜像总量的两倍，同批多台设备共享这些文件。本轮不改动打包、上传和镜像校验流程来降低过程峰值。

### 清理时机与异常处理

智能屏在整批结果保存与核实完成后执行清理，原任务的结果核实完成后使用同一规则。复制安装包后提交失败时，先查询任务和计划的实际保存状态；已经入队、仍受保护或引用关系不明确的副本保留，不因为提交命令返回错误就删除执行输入。

“清空已结束任务”先按任务类型处理临时制品，再按数据库原有规则删除可清理记录，日志和诊断文件不随之删除。一体机中断状态在最终数据库计数、删除条件中再次排除，避免候选枚举后发生状态变化导致误删；任务列表的可清理状态和清空日志限制保持一致。

文件被占用、权限不足、路径异常或清理失败时记录应用日志，保留后续重试机会；不把已经成功的安装、部署改写为失败，也不重放设备操作。清历史时临时文件清理失败不改变原业务结果；残留文件仍受后续启动补清的范围和引用检查约束。

### 工作台启动补清与旧残留

工作台持有本机数据目录实例锁、任务执行器尚未启动时，补清已有安全终态任务的临时文件。对已没有任务记录的旧目录，只识别项目、任务两层目录下的固定安装包，以及既有镜像快照目录内的 tar 文件；不递归猜测其他文件的用途。

旧残留回收前检查数据库任务、执行计划、结果保护、任务参数、最近安装文件引用和屏端写入意图。任何引用存在或查询失败均保留文件。路径检查拒绝符号链接、Windows目录连接及越出受管范围的路径；待补写文件或未知文件继续保留。

一体机的镜像源路径可能只保存在 `deployment-input.json`（已有一体机执行输入文件）的正文中，数据库只保存该文件位置。因此只要还有带执行输入的一体机活动、中断或待核实任务，整次孤儿副本扫描保守延后；待任务安全结束后的下次启动再处理，不为释放空间解析或跟随任意文件路径。

## 3. 第1步验证记录

### 自动回归

第1步共有373项独立 Rust 自动测试通过，其中库回归329项、集成回归44项，覆盖任务仓储、公共任务接口、SQLite确认、错误日志、事件日志及临时制品接线。最终源码的库回归、任务仓储和9项清理集成回归已复验；未变更的其余集成结果沿用同轮已通过记录，重复执行不重复计数。

一体机中断状态无条件保留、旧日志过期标记撤销、结果保护先于清理、数据库事务内排除中断任务，以及任务列表和日志清理限制，均已纳入回归。文件安全测试包含Windows文件占用和目录连接，不能仅按普通文件删除成功推断安全边界已覆盖。

自动验收范围包括：

- 整批完成后释放安装副本，活动、取消中和待核实任务保留。
- 本机原始安装文件、数据库元数据、任务结果、日志和诊断文件保留。
- 一体机完整发布的镜像快照与发布包均可清理，未改变单服务升级清理能力。
- 一体机中断且没有待补写文件时，任务、目录、日志仍保留，列表不提供清理。
- 启动补清中的数据库引用、独立执行输入、待补写文件及未知目录保护。
- Windows文件占用、符号链接和目录连接保护，删除失败不改变业务成功状态。
- 清历史不会遗留正常可清理的安装副本，也不会删除待核实任务的数据。

## 4. 第2步实现与验证结果

第2步当前源码的默认一体机部署脚本版本为0.1.14，只处理本次创建的镜像tar副本，适用于首次部署、整包升级和单服务升级。代码在镜像导入及服务健康检查成功后清理，保留版本清单、校验信息、配置、操作记录、业务数据库备份，以及Docker中运行和回滚使用的镜像。清理函数失败只输出提示，不改变已确认的服务启动结果；失败部署不进入新增清理，原有成功回滚删除失败新版本目录的行为保持。
