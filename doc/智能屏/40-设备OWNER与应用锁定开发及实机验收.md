# 设备 OWNER 与应用锁定开发及实机验收

日期：2026-10-23。适用对象：实施人员使用 Windows 上的 INX 实施工作台，管理运行智能小新的 Android 4 寸、10 寸屏。

本轮开发、自动回归、三屏正式任务及 Windows 桌面操作验证已完成。三台屏的原配置已核对恢复，保留小新的设备 OWNER（Android 设备所有者权限）。工作台使用独立标识和隔离本机数据，未修改生产数据目录或写入平台业务资料。两端代码尚未提交发布，屏上保留本轮修复测试包。

本记录的锁定及恢复核验没有覆盖取消锁定后的系统栏视觉结果；该问题的后续修复和全屏专项见[42 号验收记录](42-取消锁定后全屏修复验收.md)，不扩展本报告原通过范围。

## 业务行为与适用规则

- “修改小新配置”增加设置小新为设备 OWNER 和“锁定应用”。已有小新 OWNER 只读显示；尚无所有者时可明确加入本次设置；其他应用持有或状态未知时阻断依赖操作。设置成功后不提供取消、替换或移除 OWNER。
- 锁定保存项原本不存在时，默认勾选并以橙色表示待提交；明确保存过关闭值的屏照实显示。多屏不同值支持保留、全开、全关；未读取成功时不推定目标。
- 勾选仅加入本次修改。检查并确认后分别保存设置、应用系统状态及回读；单独锁定或解锁不重启小新。只有真正的系统锁定模式和小新任务身份同时符合目标，才报告成功。
- 普通配置及锁定设置的读取、保存独立于主界面和语音。冷保存不会启动它们；实际开启锁定需要有效前台，已确认的工作台任务可按需唤醒并启动小新。
- 明确关闭锁定先执行；普通配置和必要重启随后独立确认；主屏设置、主屏激活完成后才开启锁定。当前锁定开启且需要重新激活主屏时，须先明确解锁。
- 切到系统主屏可能重新打开小新页面并结束当前语音对话。界面在存在本次激活意图时提示这一影响；重新打开后仍按原“语音引擎随应用启动”设置处理，不改写该设置。
- 取消或结果不确定时只读核实，不自动重放 OWNER 设置、保存、任务退出、HOME 动作、锁定应用或重启。普通配置、主屏、锁定分别保留已完成事实。

现场先保留数据升级配套小新，再重新读取能力。锁定仍通过“修改小新配置”明确保存，不增加安装结束自动锁定步骤。

## 本轮处理的技术问题

### 普通应用任务转换为系统主屏

实机证据显示：系统已响应 HOME（Android 系统主屏）请求，但复用了小新的普通任务，系统主屏栈仍为空。因此不能把“小新在前台”直接视为“系统主屏已激活”。

工作台现在先从系统转储确认任务类型。已是主屏时不退出任务；只有确认属于默认用户、默认显示屏的小新单一普通任务，才请求小新准备转换。小新再次核对有效前台、根活动、请求任务编号、任务首尾活动、活动数量、OWNER、锁定保存目标及系统解锁状态，随后仅请求移除该任务。工作台只读确认旧任务消失，再发送一次系统 HOME 并严格核验新主屏任务。身份不明确、多活动或未就绪时停止，不强行搬移任务或处理其他应用。

该动作只用于明确的主屏激活，不进入普通配置读写或单独锁定路径；不改全局活动启动模式，不清空数据，不停止其他应用。

### 分阶段结果准确记录

普通配置保存及必要重启在主屏、锁定步骤之前完成原有的新进程与运行状态核验并记录检查点。后续步骤失败时，前序已成功的保存、重启和回读结果仍然保留，不被显示为未确认。

## 验收边界

- 三台测试屏原本都有小新 OWNER，实际验证的是识别、保留及重复设置不产生写入；没有为测试撤销 OWNER。无所有者首次设置、其他所有者及未知状态通过模拟测试覆盖，尚未在无 OWNER 的真机执行首次设置。
- 本轮没有重新进行真人欢迎语、正常对话及播放中打断验收；离线音频测试不能替代现场声学验证。主屏重开对当前对话的影响已明确提示。
- 结论覆盖上述 Android 8.1/10 固件及 Windows 桌面；不外推到其他固件、macOS 或平台注册/共享库的完整联测。共享结果字段的透传与旧记录兼容由自动测试验证。
