# 单屏远程查看与辅助操作验收

日期：2026-10-26。状态：已完成开发、自动回归、共享库故障恢复，以及Windows真实工作台对4寸和10寸屏的查看、辅助输入、H5登录与休眠唤醒验证，功能已随0.2.17发布。此前发布的 `v0.2.16`（Git发布标签）不包含本功能；正式构建与交付状态见[0.2.17 发布记录](../49-0.2.17发布记录.md)。

## 1. 业务目标与适用环境

实施人员在运维电脑上选择一块Android智能屏，查看其当前显示的内容，并在必要时通过鼠标点按、按键和文字输入协助完成屏内H5登录及空间选择。该功能使用屏已有的ADB管理连接，不要求升级小新APP或H5，也不新增屏端常驻服务。

修改工程为 `inxaiot-desk-buddy`（实施工作台程序），代码运行在运维电脑；输入动作由Android系统在目标屏上执行。小新的原生配置协议、主界面与语音引擎生命周期、H5认证接口和平台业务表不在本轮修改范围内。偶发退出H5登录的原因不在本功能中自动修复。

本轮使用独立工作台数据及测试环境。实际生产数据目录 `D:\data\com.inxaiot.desk-buddy` 不作为启动、复制或测试目标；设备现有配置和192.168.3.44的H5地址保持。测试中的账号、密码、令牌和私钥不得进入说明文档、任务计划或提交。

## 2. 使用流程

1. 从单屏详情点击“查看屏幕”。窗口显示屏名称、实际连接IP、采集时间和最新画面，默认只查看。
2. 需要再次观察时点击“刷新画面”；“自动刷新（1秒）”默认关闭。自动刷新在上一轮采集及图片显示完成后再等待1秒，不积压截图请求；实际画面更新间隔还包含截图、传输及图片加载耗时。后台刷新时仍可操作已经显示的有效画面。
3. 点击“开启辅助操作”，取得设备操作条件和占用后才能发送输入；先等待开启后的新画面显示完成。屏幕休眠时只开放“唤醒”，显示“屏幕已休眠，请点击唤醒”；唤醒并确认小新回到当前前台、显示新画面后，才开放其他操作。
4. 在画面上点选账号、密码或其他输入框，再在工作台输入区填写内容并点击“发送输入”。先看本屏显示的输入说明：插入方式在当前光标处追加，原内容需要先清除；替换方式会覆盖当前输入框的全部内容。
5. 根据本屏显示的能力使用“退格”或“清空输入框”，以及“返回”“唤醒”；登录需点按画面里的登录按钮，不提供回车提交。每次发送完成后自动取得新画面，显示完成才能继续下一条输入；人员根据屏端登录错误、空间选择或业务页面判断结果。
6. 操作结束后停止辅助操作或关闭窗口。已经送达的点击、输入和网页请求不会被撤销；工作台只停止后续输入并收尾占用。

“操作已发送”只说明这次Android输入命令已完成，不等于H5账号认证成功。工作台不单独承诺登录成功，也不以工作台自身的平台会话替代屏内H5会话。

### 查看与输入规则

| 项目 | 当前行为 |
| --- | --- |
| 实际连接地址 | 使用屏的已确认资料，窗口显示后端实际连接IP；本机未提交的IP草稿不直接成为设备操作地址 |
| 图片 | 获取当前整屏PNG图像；前端保留当前图片及至多一张待加载图片，新图加载完成后替换并释放旧图，不写图片文件或截图历史 |
| 更新失败 | 保留上一张画面时明确标明旧图及错误，停止自动刷新；旧图不能继续用于输入 |
| 切屏、切项目、关窗 | 取消旧会话、清除旧画面和本机输入，迟到响应不得覆盖新屏 |
| 点击位置 | 按实际图像内容区域换算像素坐标；边缘留白、越界位置不发送 |
| 可用画面 | 辅助操作只接受本会话、当前控制任务及输入代次对应的有效帧；没有已显示的有效图、过期或状态不明时禁止输入。后台采集和加载新图不使当前有效图立即失效 |
| 并行与顺序 | 截图与输入可以并行，截图自身和输入自身各最多一项在途；输入不排队、不重发。上一条输入完成后，必须显示操作后采集的新图才能继续输入，跨操作的迟到图不能恢复输入权限 |
| 文字 | 一次1至128个可打印ASCII字符，包括英文、数字、空格和常用半角符号；中文、Emoji、换行及制表符在执行前拒绝，不静默改写 |
| 输入方式 | 根据屏端系统版本选择并明确显示插入或替换；插入方式配“退格”，替换方式配“清空输入框”。失败不自动切换方式或重发 |
| 密码 | 工作台输入区默认掩码；发送后、关闭或切换目标时清空，不记住账号密码，不写入工作台任务、历史或日志 |
| H5自身存储 | H5原有认证及记住登录信息的行为保持，不能将“工作台不保存输入”理解为改变了H5既有存储规则 |
| 唤醒 | 休眠且设备身份可信时可以开启仅唤醒模式，无需先有前台活动；仅发送一次明确的点亮按键，再只读核实。未确认小新可操作则结束辅助、提示稍后重新开启；不自动解锁、重启或启动其他应用。H5自身待机遮罩通常还需要人员点按画面 |
| 空闲回收 | 辅助操作5分钟没有成功输入时结束；截图刷新不延长这段期限 |
| 未确认输入 | 停止后续输入，提示人员查看屏端；不自动重发文字、点击或登录请求 |

当前只提供低频截图式辅助操作，不提供视频传输、连续拖动或任意Shell命令。点按、文字及其他普通输入限于亮屏且已确认的小新当前前台；系统弹窗、其他应用、身份或方向无法确认时不能继续发送。仅唤醒模式不依赖当前前台，但仍核对身份、方向、有效帧及操作占用。

## 3. 操作保护与结果记录

仅查看画面不创建运维任务，不要求共享操作库在线。本机未登记屏的辅助操作按本实例保护；已登记屏还要求项目会话与共享占用条件可用，以便其他工作台识别该屏正在被操作。

辅助操作在短临界区核对现有任务、目标和同IP占用，再登记不含输入内容的会话任务。普通安装、重启、配置修改仍能通过既有本机任务查询看到占用；注册屏复用业务项目和屏ID对应的共享租约。设备网络调用及整个人工操作过程不长期持有全局提交锁，也不占用部署任务队列的工作线程。

每次输入前重新核对目标资料、共享占用、设备身份、电源状态、当前前台、分辨率、方向和画面标识。仅明确休眠可以不依赖当前前台建立仅唤醒会话；普通输入要求电源已唤醒，当前活动和窗口焦点均属于小新，不能用历史活动替代。正方形屏幕或180度方向变化也会停止输入，不能只用宽高相同判断位置仍可用。平台资料或项目连接改变、关键资料未提交、租约失效时保留已发生事实并停止后续动作。

关闭、取消和空闲到期先拒绝新输入，等待已经发出的有界短命令收敛，再保存会话摘要和释放占用。共享保存或释放失败时保留本机保护与可核实状态；核实只补存已有摘要、释放本操作占用，不再次发送输入，也不释放其他操作后来取得的租约。

持久记录只包含会话归属、目标、已确认发送次数、结束状态及必要的未确认摘要。图片、账号密码及其他输入正文不进入这些记录。输入使用独立内存请求，不能加入会被完整序列化的普通操作参数。当前页面的登录结果仍由人员观察，不把输入任务完成状态表示成登录成功。

## 4. 架构与技术定位

前端、后端各使用独立模块，仅在单屏详情、应用装配及任务恢复能力中做接线。不新增数据库迁移，不改变旧ADB文本返回方法，也不将H5账号密码塞入小新的配置读取或保存接口。

| 文件或方法 | 运行位置与职责 |
| --- | --- |
| Vue组件 `src/features/smart-screen/remote-screen/ScreenRemoteDialog.vue` | 运维电脑的远程屏幕窗口；负责画面和受限操作控件，不保存输入正文 |
| TypeScript文件 `screenRemoteSession.ts`、`screenRemoteInput.ts`，位于同目录 | 截图与输入分别限并发、旧响应隔离、内存图片释放、画面期限及输入坐标／字符校验 |
| TypeScript文件 `src/shared/api/screenRemoteAdapter.ts`、`realScreenRemoteAdapter.ts` | 独立接口及真实桌面调用；开发原型使用不可用适配器，不连接真实设备 |
| Rust文件 `src-tauri/src/interface/commands/screen_remote.rs` | 单屏会话、截图和辅助操作的受限桌面命令；调用者绑定真实工作台窗口 |
| Rust目录 `src-tauri/src/infrastructure/smart_screen/remote_screen/` | 会话及资料绑定、图片校验、ADB字节和标准输入通道、辅助任务生命周期与恢复 |
| Java类 `FocusedText`、`TextProtocol`，位于 `src-tauri/resources/remote-input/src/com/inx/remote/` | 随工作台内嵌的短生命周期辅助程序，在适用Android系统中只替换或清空小新当前可编辑焦点节点；协议正文通过标准输入读取 |
| Rust方法 `ScreenRepository::confirmed_asset` | 仅读取已确认的目标资料，避免每帧重新构造整个资产列表 |
| Rust结构体 `JobSupervisor`及方法 `tasks::submission_lock` | 托管辅助会话的取消、关闭和异常收尾；提交锁仅保护登记阶段 |
| Rust结构体 `HeldScreenLeases`与`ScreenSharedResults` | 复用注册屏共享互斥及结果摘要，保存和释放分别核实 |

截图使用Android命令 `adb exec-out screencap -p`，不先在屏端生成图片文件。新字节通道限定输出体积、超时和取消，并校验PNG结构及尺寸；旧文本命令的UTF-8处理不参与图像传输。前端保留当前图和至多一张待加载图的内存引用，按比例显示；新图加载并核验尺寸后才替换旧图，不积累历史图片。待加载图和刷新提示均不拦截当前图片的点击。

后台截图互斥只保护截图，不被输入动作占用。Rust结构体 `FrameHistory` 保留最多32条短期帧元数据，不保存图片，帧期限从采集开始计算。Rust结构体 `FrameAction` 随单条输入持有已核验的帧信息，输入开始和结束均推进代次、清除旧授权；失败、超时及取消也执行收尾。跨输入过程取得的图片可以查看，但桌面返回字段 `inputReady` 为否，不能授权下一条输入。桌面返回字段 `inputGeneration` 与前端本地代次共同阻止迟到响应恢复输入权限。输入结束后要求一次新的采集，若已有截图在途则待其结束后补取，不丢失必要刷新，也不排队点击。

辅助操作只接受点按、有限按键和经过校验的文字。文字经ADB标准输入传递，不拼入本机ADB进程的参数；设备输出与错误不回显输入内容。Rust输入类型不提供普通调试输出或序列化能力，内存中的秘密值尽可能在请求结束时清理，但不声称能够控制操作系统或H5自身的全部存储行为。

文字通道按已读取的Android系统属性 `ro.build.version.sdk`（API级别）选择。当前代码对Android 7—9（API级别24—28）使用系统输入命令，在当前光标处插入并支持退格；Android 10及以后使用系统无障碍节点设置动作，覆盖当前焦点输入框并支持独立清空。系统版本超出校验范围、焦点不存在或不唯一、节点不可编辑时拒绝操作，不自动尝试另一种输入方式。实际设备兼容证据仅涉及本轮Android 8.1和10测试固件，不能由分支范围推断所有设备均已验收。

后者使用工作台内嵌的 `focused-text.jar`（Java辅助程序的DEX容器文件），不安装APK、不修改输入法、不使用剪贴板。工作台按内容哈希在屏端 `/data/local/tmp` 缓存并校验一份无凭据代码，当前产物4275字节；这不是截图或输入正文文件。文字仍单独经过标准输入，辅助程序只输出固定状态。旧系统的标准输入脚本最终调用Android命令 `input text`，正文可能短暂出现在该设备命令的内存参数中，不意味着工作台将正文写入文件或日志。

辅助组件及二进制请求先进行Base64文本编码，再通过ADB标准输入发送；屏端流式解码，输入正文不经过临时文件。该规则避免Windows ADB文本模式在`0x1a`处截断二进制数据。完整组件和包含NUL、`0x1a`、CRLF及所有字节值的样本，均已在真实ADB通道核对哈希一致；屏端组件写入后还需通过SHA-256校验才能处理文字。

辅助程序采用设备单调时钟规定4秒发起期限，实际设置节点前再次核对；准备后时间不足则不发送。已发起的动作结果不明时，工作台等待设备期限及响应余量收敛，再停止会话，不重发。单动作外层等待上限为30秒，具体发送使用更早的截止点；普通停止等待在途动作收尾，不能撤销已被系统接收的输入。

辅助程序源码、协议测试、构建脚本、产物哈希及源文件哈希清单位于同一资源目录，构建使用独立临时目录和固定JAR时间戳。当前两次独立构建产物哈希一致，4份源文件哈希及实际JAR已只读复核匹配。维护时应同步构建并提交源码与产物，详见[屏端辅助文字组件说明](../../src-tauri/resources/remote-input/README.md)。

本机输入任务类型为 `remote_assistance`（新增操作类型），仅用于单屏辅助会话，不加入批量安装／配置的操作选择列表。默认控制画面期限为30秒；前端从请求发起时间计时并留余量，避免传输和解码延长可点击时间。控制开启后的截图还校验设备序列号，只有与该控制会话一致的画面才能用于输入。

辅助能力和动作回执中的桌面协议字段 `controlMode` 必须为 `full` 或 `wake_only`。前端据此分别启用普通输入或仅唤醒，后端在每次动作时独立复核，不依赖按钮禁用作为保护。唤醒不要求小新已有当前活动；发送一次系统唤醒键后，最多在原动作期限内只读核实6秒。确认亮屏且小新回到当前前台时保持会话，否则以“唤醒已发送，尚未确认小新可操作”结束控制，不重放。模式返回为普通操作后，也必须等唤醒之后的新图显示，迟到的黑图不能重新授权普通输入。

## 6. 固定布局与快速界面验收

远程查看浮层在同一视窗内使用固定总高度，内容区采用纵向弹性布局；辅助控件、反馈和底栏有稳定的位置，画面使用剩余空间。仅查看、开启辅助、发送中、截图更新、结束以及错误均不改变浮层或画面的高度。辅助关闭时显示只读提示，不挂载隐藏的可聚焦输入。长错误保留完整内容，在固定反馈区滚动阅读。

状态反馈与关闭按钮合并为同一行，不再单独预留一块空白反馈区；释放的高度用于屏幕画面。界面不显示截图保存策略和像素尺寸，此类实现说明留在文档中。合并后的长提示仍可聚焦滚动或悬停查看，不因错误或等待状态改变画面高度。

固定高度由Vue组件实现，不改变输入期限或任务保护。内容容器匹配当前Naive UI组件实际类名 `.n-card-content`（组件生成的CSS类），确保弹性布局真实生效。截图与输入并行改造后的独立无设备浏览器夹具在1254×800、998×540、674×600三种实际视窗内测量9种状态，浮层、画面及预留区域的位置／尺寸差异均不超过0.5像素，底栏保持在浮层内；同时验证截图尚未返回时可以点击当前有效画面，重复点击不会追加输入。它验证真实浏览器布局和前端交互，不替代设备交互测试。

本轮界面验收使用真实Tauri后端的Debug开发窗口“INX 远程协助 · 热更新验证”，沿用独立验收标识及已有隔离数据。本机Vite开发服务地址为 `http://127.0.0.1:1422`，不启用模拟适配器；前端页面、样式和文案通过热更新生效，无需重新打包。开发窗口和前端服务均需保持运行；Rust或原生组件修改仍需重新编译并重启Debug程序。此前的验收ZIP为静态产物，不会随源码热更新，最终打包应在界面验收后统一进行。

## 8. 系统休眠后的辅助唤醒

4寸测试屏192.168.3.74的系统休眠时间为60秒。现场故障中，ADB正常返回480×480的PNG，但全部像素为黑色；电源服务明确报告休眠和关闭显示，系统日志记录因屏幕超时进入休眠。一次系统唤醒后，同一小新进程恢复非黑画面，闲置后再次休眠可复现。42和82的系统休眠时间为2147483647毫秒，与74不同。页面待机遮罩、Android系统休眠和应用卡死不能混为同一状态，本功能不改变这些设置。

原工作台在开始辅助会话时要求确认当前前台活动；系统休眠时缺少此状态，导致唤醒按钮也不可用。当前实现允许已核实身份的休眠屏开启仅唤醒模式。唤醒只发一次，在同一动作期限内只读确认亮屏、当前活动和窗口焦点，随后用新帧开放普通输入；未知状态、系统覆盖窗口或其他应用不能借历史活动获得普通输入能力。Android 10的窗口分项输出不含当前焦点，因此聚合读取使用完整窗口服务输出，两种已测固件保持相同的严格校验规则。

截图与输入仍可并行。若后台截图先报告控制已结束，前端立即禁止后续输入，但保留当前在途动作的最终回执，不能丢掉“唤醒已发送”的事实；人员主动停止、关窗或切屏则继续隔离迟到回执，不恢复旧控制。界面沿用固定高度，仅唤醒状态只启用唤醒按钮。
